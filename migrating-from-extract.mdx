`/extract` is deprecated and will be removed on Thursday, December 10, 2026, 15:00 UTC. That covers `POST /v1/extract`, `POST /v2/extract` and their `GET /extract/{id}` status routes. Every response from them already carries a `Deprecation` header and a `warnings` entry that points here. From that time on, they answer `410 Gone`.

This guide shows what to call instead, maps every `/extract` parameter to its replacement, and lists the few options that have no direct equivalent.

## Pick the replacement

| Your `/extract` call | Use instead |
| --- | --- |
| One URL, no `/*` wildcard | [`/v2/scrape`](/features/llm-extract) with a `json` format |
| Several URLs, one result per page | [`/v2/batch/scrape`](/features/batch-scrape) with a `json` format |
| Several URLs, one combined answer | [`/v2/agent`](/features/agent) with `urls` |
| A wildcard such as `https://example.com/*` | `/v2/agent` with the site URL, or [`/v2/map`](/features/map) followed by a batch scrape with a `json` format |
| `enableWebSearch`, `allowExternalLinks`, or a `prompt` with no `urls` | `/v2/agent` |
| `agent: { model: "FIRE-1" }` | Remove the option. Use `/v2/agent` when the task needs navigation across pages |

For a single URL without a wildcard, `/extract` scraped that one page and ran an LLM over it. A `json` format on `/v2/scrape` does the same thing in one synchronous request, so there is no job to poll.

## Why move

- **One request instead of a job.** `/v2/scrape` returns the extracted JSON in its response. You no longer start a job and poll `/extract/{id}`.
- **A known price per page.** `/extract` bills by tokens, so the cost of a call depends on the page and the answer. A `json` format costs a flat 5 credits per page (1 for the scrape and 4 for the JSON format). See [Billing](/billing#additional-credit-costs-for-scrape-options).
- **Every scrape option.** The `json` format runs on a normal scrape, so actions, location, proxies, caching with `maxAge`, change tracking and the other formats work in the same request.
- **Every SDK.** Scrape with a JSON format, batch scrape and agent are in all nine Firecrawl SDKs. `/extract` was only in the Python and Node SDKs.
- **A better tool for multi-page work.** `/v2/agent` searches, navigates and combines results across pages, which is what wildcard and web-search extracts were reaching for.

## Single page: /v2/scrape with a JSON format

Move `prompt` and `schema` into a `json` format object, and read the result from `data.json` instead of `data`.

**Before**

<CodeGroup>

```python Python
from firecrawl import Firecrawl

firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")

schema = {
    "type": "object",
    "properties": {
        "company_mission": {"type": "string"},
        "supports_sso": {"type": "boolean"},
    },
    "required": ["company_mission", "supports_sso"],
}

res = firecrawl.extract(
    urls=["https://firecrawl.dev"],
    prompt="Extract the company mission and whether it supports SSO.",
    schema=schema,
)
print(res.data)
```

```js Node
import { Firecrawl } from "firecrawl";

const firecrawl = new Firecrawl({ apiKey: "fc-YOUR-API-KEY" });

const schema = {
  type: "object",
  properties: {
    company_mission: { type: "string" },
    supports_sso: { type: "boolean" },
  },
  required: ["company_mission", "supports_sso"],
};

const res = await firecrawl.extract({
  urls: ["https://firecrawl.dev"],
  prompt: "Extract the company mission and whether it supports SSO.",
  schema,
});
console.log(res.data);
```

```bash cURL
curl -X POST https://api.firecrawl.dev/v2/extract \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": ["https://firecrawl.dev"],
    "prompt": "Extract the company mission and whether it supports SSO.",
    "schema": {
      "type": "object",
      "properties": {
        "company_mission": { "type": "string" },
        "supports_sso": { "type": "boolean" }
      },
      "required": ["company_mission", "supports_sso"]
    }
  }'

# Then poll GET https://api.firecrawl.dev/v2/extract/{id} until status is "completed".
```

</CodeGroup>

**After**

<CodeGroup>

```python Python
from firecrawl import Firecrawl

firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")

schema = {
    "type": "object",
    "properties": {
        "company_mission": {"type": "string"},
        "supports_sso": {"type": "boolean"},
    },
    "required": ["company_mission", "supports_sso"],
}

doc = firecrawl.scrape(
    "https://firecrawl.dev",
    formats=[{
        "type": "json",
        "prompt": "Extract the company mission and whether it supports SSO.",
        "schema": schema,
    }],
)
print(doc.json)
```

```js Node
import { Firecrawl } from "firecrawl";

const firecrawl = new Firecrawl({ apiKey: "fc-YOUR-API-KEY" });

  type: "object",
  properties: {
    company_mission: { type: "string" },
    supports_sso: { type: "boolean" },

const doc = await firecrawl.scrape("https://firecrawl.dev", {
  formats: [{
    type: "json",
    prompt: "Extract the company mission and whether it supports SSO.",
    schema,
  }],

```

```bash cURL
curl -X POST https://api.firecrawl.dev/v2/scrape \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://firecrawl.dev",
    "formats": [{
      "type": "json",
      "prompt": "Extract the company mission and whether it supports SSO.",
      "schema": {
        "type": "object",
        "properties": {
          "company_mission": { "type": "string" },
          "supports_sso": { "type": "boolean" }
        },
        "required": ["company_mission", "supports_sso"]
      }
    }]
  }'

# The response holds the result in data.json. There is nothing to poll.
```

</CodeGroup>

<Tip>
  `/v1/extract` scraped pages with `onlyMainContent: false` by default, while `/v2/scrape` defaults to `true`. If a field that lives in a header, footer or sidebar comes back empty, set `onlyMainContent: false` (`only_main_content=False` in Python).
</Tip>

### Other SDKs

The Go, Java, Rust, Ruby, PHP, .NET and Elixir SDKs never had an extract method. If you called `/extract` over HTTP from one of these languages, switch to the SDK's scrape method with a JSON format:

<CodeGroup>

```go Go
doc, err := client.Scrape(ctx, "https://firecrawl.dev", &firecrawl.ScrapeOptions{
	Formats: []string{"json"},
	JsonOptions: &firecrawl.JsonOptions{
		Prompt: "Extract the company mission and whether it supports SSO.",
		Schema: map[string]interface{}{
			"type": "object",
			"properties": map[string]interface{}{
				"company_mission": map[string]interface{}{"type": "string"},
				"supports_sso":    map[string]interface{}{"type": "boolean"},
			},
		},
	},
})
if err != nil {
	log.Fatal(err)
}
fmt.Println(doc.JSON)
```

```java Java
JsonFormat jsonFmt = JsonFormat.builder()
    .prompt("Extract the company mission and whether it supports SSO.")
    .schema(Map.of(
        "type", "object",
        "properties", Map.of(
            "company_mission", Map.of("type", "string"),
            "supports_sso", Map.of("type", "boolean")
        )
    ))
    .build();

Document doc = client.scrape(
    "https://firecrawl.dev",
    ScrapeOptions.builder()
        .formats(List.of((Object) jsonFmt))
        .build()
);
System.out.println(doc.getJson());
```


## Several URLs, one result per page: batch scrape

`/extract` merged the pages you listed into one answer. Batch scrape keeps one result per page, each with its own `json` and `metadata.sourceURL`, so you can see where every value came from. Batch scrape is asynchronous like `/extract`, and it takes a `webhook`.

<CodeGroup>

```python Python
job = firecrawl.batch_scrape(
    ["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
    formats=[{
        "type": "json",
        "prompt": "Extract the company mission and whether it supports SSO.",
        "schema": schema,
    }],
)
for doc in job.data:
    print(doc.metadata.source_url, doc.json)
```

```js Node
const job = await firecrawl.batchScrape(
  ["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
  {
    options: {
      formats: [{
        type: "json",
        prompt: "Extract the company mission and whether it supports SSO.",
        schema,
      }],
    },
  },
);
for (const doc of job.data) {
  console.log(doc.metadata?.sourceURL, doc.json);
}
```

```bash cURL
curl -X POST https://api.firecrawl.dev/v2/batch/scrape \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": ["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
    "formats": [{
      "type": "json",
      "prompt": "Extract the company mission and whether it supports SSO.",
      "schema": {
        "type": "object",
        "properties": {
          "company_mission": { "type": "string" },
          "supports_sso": { "type": "boolean" }
        }
      }
    }]
  }'

# Then poll GET https://api.firecrawl.dev/v2/batch/scrape/{id}. Each item in data has its own json.
```

</CodeGroup>

The start and status methods work the same way as their extract counterparts: `start_batch_scrape` and `get_batch_scrape_status` in Python, `startBatchScrape` and `getBatchScrapeStatus` in Node.

## One answer across pages, wildcards and web search: /v2/agent

Use `/v2/agent` when you want one combined result from several pages, when you used a `/*` wildcard, or when you set `enableWebSearch`. The agent searches, navigates and fills your schema from whatever pages it needs.

- To keep it on the URLs you list, set `strictConstrainToURLs: true`.
- For a wildcard such as `https://example.com/*`, pass `https://example.com` and leave `strictConstrainToURLs` unset, so the agent can follow links from there.
- With no `urls` at all, the agent finds its own sources, like a prompt-only `/extract` call.

<CodeGroup>

```python Python
result = firecrawl.agent(
    urls=["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
    prompt="Extract the company mission and whether it supports SSO.",
    schema=schema,
    strict_constrain_to_urls=True,
)
print(result.data)
```

```js Node
const result = await firecrawl.agent({
  urls: ["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
  prompt: "Extract the company mission and whether it supports SSO.",
  schema,
  strictConstrainToURLs: true,
});
console.log(result.data);
```

```bash cURL
curl -X POST https://api.firecrawl.dev/v2/agent \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "urls": ["https://firecrawl.dev", "https://firecrawl.dev/pricing"],
    "prompt": "Extract the company mission and whether it supports SSO.",
    "schema": {
      "type": "object",
      "properties": {
        "company_mission": { "type": "string" },
        "supports_sso": { "type": "boolean" }
      }
    },
    "strictConstrainToURLs": true
  }'

# Then poll GET https://api.firecrawl.dev/v2/agent/{id} until status is "completed".
```

</CodeGroup>

Agent pricing is dynamic, with 5 free runs a day. Set `maxCredits` to cap what one run can spend. See [Agent](/features/agent) for models, effort and pricing.

### Wildcards with a fixed cost per page

If you prefer a predictable cost per page over the agent, expand the wildcard yourself: list the site's URLs with [`/v2/map`](/features/map), keep the ones you need, then batch scrape them with a `json` format.

<CodeGroup>

```python Python
site = firecrawl.map("https://firecrawl.dev", search="pricing", limit=20)
urls = [link.url for link in site.links]

job = firecrawl.batch_scrape(
    urls,
    formats=[{"type": "json", "prompt": "Extract the plan names and prices.", "schema": schema}],
)
```

```js Node
const site = await firecrawl.map("https://firecrawl.dev", { search: "pricing", limit: 20 });
const urls = site.links.map((link) => link.url);

const job = await firecrawl.batchScrape(urls, {
  options: {
    formats: [{ type: "json", prompt: "Extract the plan names and prices.", schema }],
  },
});
```

</CodeGroup>

## Parameter mapping

| `/extract` parameter | `/v2/scrape` with `json` | `/v2/batch/scrape` with `json` | `/v2/agent` |
| --- | --- | --- | --- |
| `urls` | `url` (one URL) | `urls` | `urls` (optional) |
| `urls` with `/*` | Not supported | URLs from `/v2/map` | The site URL |
| `prompt` | `formats[].prompt` | `formats[].prompt` | `prompt` (required) |
| `schema` | `formats[].schema` | `formats[].schema` | `schema` |
| `systemPrompt` | No equivalent. Add the instructions to `prompt` | Same as scrape | Add the instructions to `prompt` |
| `scrapeOptions.*` | Top-level scrape options | Top-level scrape options (`options` in the Node SDK) | Not applicable |
| `enableWebSearch`, `allowExternalLinks` | Not supported | Not supported | The default. Set `strictConstrainToURLs: true` to turn it off |
| `includeSubdomains`, `limit`, `ignoreSitemap` | Not applicable | Use `includeSubdomains`, `limit` and `sitemap: "skip"` on `/v2/map` | Not applicable |
| `timeout` | `timeout` per page, in ms | `timeout` per page, in ms | No request timeout. Use `maxCredits`, and the SDK `timeout` for how long to wait |
| `ignoreInvalidURLs` | Not applicable | `ignoreInvalidURLs` | Not applicable |
| `webhook` | Not needed, the request is synchronous | `webhook` | `webhook` |
| `showSources`, `__experimental_showSources` | `metadata.sourceURL` | `metadata.sourceURL` on each page | No per-field sources |
| `urlTrace` | No equivalent | No equivalent | No equivalent |
| `agent` (`FIRE-1`) | Remove | Remove | Use `/v2/agent` itself |
| `threatProtection` | `threatProtection` | `threatProtection` | `threatProtection` |
| `origin`, `integration` | Same | Same | Same |
| `__experimental_streamSteps`, `__experimental_llmUsage`, `__experimental_showCostTracking`, `__experimental_cacheKey`, `__experimental_cacheMode` | Remove | Remove | Remove |

## Response mapping

| `/extract` | Replacement |
| --- | --- |
| `POST` returns an `id`, then you poll `GET /extract/{id}` | `/v2/scrape` returns the result directly. Batch scrape and agent return an `id` that you poll at `GET /v2/batch/scrape/{id}` or `GET /v2/agent/{id}` |
| `data` | `data.json` for scrape, `data[].json` for batch scrape, `data` for agent |
| `status`: `processing`, `completed`, `failed`, `cancelled` | Batch scrape: `scraping`, `completed`, `failed`, `cancelled`. Agent: `processing`, `completed`, `failed` |
| `sources` | `metadata.sourceURL` on each page |
| `expiresAt`, `creditsUsed` | Same fields on batch scrape and agent status |

## SDK methods

| Client | `/extract` methods | Replacement |
| --- | --- | --- |
| Python (`firecrawl-py`), `Firecrawl` and `AsyncFirecrawl` | `extract`, `start_extract`, `get_extract_status` | `scrape` with `formats=[{"type": "json", ...}]`, `batch_scrape`, `start_batch_scrape`, `get_batch_scrape_status`, `agent`, `start_agent`, `get_agent_status` |
| Python v1 client | `extract`, `async_extract`, `get_extract_status` | The same v2 methods |
| Node (`firecrawl`, `@mendable/firecrawl-js`), `Firecrawl` | `extract`, `startExtract`, `getExtractStatus` | `scrape` with `formats: [{ type: "json", ... }]`, `batchScrape`, `startBatchScrape`, `getBatchScrapeStatus`, `agent`, `startAgent`, `getAgentStatus` |
| Node v1 client | `extract`, `asyncExtract`, `getExtractStatus` | The same v2 methods |
| Go, Java, Rust, Ruby, PHP, .NET, Elixir | None | Scrape with a JSON format, batch scrape and agent. See the [SDK pages](/sdks/overview) |
| [MCP server](#mcp-server) | `firecrawl_extract` | `firecrawl_scrape` with a JSON format, or `firecrawl_agent`. Upgrade a local server to 3.23.7 or later |
| HTTP | `POST /v1/extract`, `POST /v2/extract`, `GET /v1/extract/{id}`, `GET /v2/extract/{id}` | `POST /v2/scrape`, `POST /v2/batch/scrape`, `POST /v2/agent` |

## MCP server

The `firecrawl_extract` tool no longer calls `/extract` in current releases of the Firecrawl MCP server. It answers with a pointer to `firecrawl_scrape` with a JSON format, for known pages, and to `firecrawl_agent`, for multi-page or open-ended research. Most MCP clients pick the replacement up from that answer.

If you run `firecrawl-mcp` yourself, with `npx`, Docker or your own build, versions before 3.23.7 still send `firecrawl_extract` calls to `/extract`, and those calls stop working when `/extract` is removed on Thursday, December 10, 2026, 15:00 UTC. To move off it:

1. Upgrade to the current release. If your client config pins a version, such as `npx -y firecrawl-mcp@3.20.0`, change the pin. See [Run MCP locally](/mcp-server/local) for the current command.
2. Or connect to the hosted server instead, which is always current. See [Get Started](/mcp-server).

## Workflow tools

If you call `/extract` through a workflow tool such as n8n, Zapier, Make or Pipedream, switch that step to the tool's Firecrawl scrape action with a JSON format, or to its agent action. If the tool has neither, call `/v2/scrape` from its HTTP request step.

## Gaps

These `/extract` features have no direct replacement:

- **`systemPrompt`.** The `json` format takes one `prompt`. Put the instructions you had in `systemPrompt` at the start of `prompt`.
- **Merging several pages into one object with batch scrape.** Batch scrape returns one result per page. Merge them in your code, or use `/v2/agent` for one combined answer.
- **`urlTrace` and per-field `sources`.** Batch scrape tells you which page each result came from through `metadata.sourceURL`. The agent does not report per-field sources.
- **The `FIRE-1` agent option.** It is not accepted by the replacement endpoints. Use `/v2/agent` for tasks that need navigation.
