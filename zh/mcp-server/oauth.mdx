<div id="connect-with-oauth">
  ## 通过 OAuth 连接
</div>

<Visibility for="humans">
  <McpClientSelector variant="human" showSeeAll={false} showHeader={false} />
</Visibility>

<Visibility for="agents">
  OAuth 服务器 URL (Streamable HTTP；客户端会启动浏览器登录) ：`https://mcp.firecrawl.dev/v2/mcp-oauth`

  * ChatGPT：设置 &gt; 启用 Developer mode &gt; Apps &amp; Connectors &gt; 创建 &gt; 身份验证：OAuth &gt; 粘贴服务器 URL。
  * Claude.ai：Settings &gt; Connectors &gt; 添加自定义连接器 &gt; 粘贴服务器 URL，并将 Client ID 和 Secret 留空。
  * Codex：`codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth`，然后运行 `codex mcp login firecrawl`
  * Claude Code：`claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth`，然后通过 `/mcp` 完成登录
  * Cursor 或任何使用 JSON 配置的客户端：`{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp-oauth"}}}`
  * OpenCode (`opencode.json`) ：`{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp-oauth", "enabled": true}}}`

  必须由真人完成浏览器登录并批准团队。请勿直接在浏览器中打开服务器 URL。
</Visibility>

<Note>
  `https://mcp.firecrawl.dev/v2/mcp-oauth` 是供 MCP 客户端使用的服务器 URL，并非可直接在浏览器中打开的页面。客户端会启动浏览器登录流程。
</Note>

需要有人在场登录、选择 Firecrawl 团队并批准访问时，请使用 OAuth。客户端会为该连接获取令牌，无需您将 Firecrawl API 密钥复制到对话中。

登录页面会要求您选择团队并批准连接。如果客户端要求提供 OAuth 客户端 ID 或客户端密钥，请将两者留空。兼容客户端会自动识别自身身份。

通过此连接发出的请求将使用所选团队。您可以在 [MCP 设置](https://www.firecrawl.dev/app/settings?tab=mcp)中查看或撤销该连接。

需要无人值守的连接？请使用 [API 密钥设置](/zh/mcp-server/keyless-api-key#add-an-api-key)。请勿将密钥粘贴到代理对话中，也不要将其放入 MCP URL。

<div id="verify-the-connection">
  ## 验证连接
</div>

开启新的客户端会话，然后尝试：

```text
进行网页搜索，查找最新的 Firecrawl 版本发布说明，并总结这些来源。
```

如果未显示任何 Firecrawl 工具，请打开客户端的 MCP 状态，确认 `firecrawl` 已通过身份验证，并检查是否只有一个 Firecrawl 服务器条目处于启用状态。

<div id="switch-an-existing-keyless-connection">
  ## 切换现有的免密钥连接
</div>

将现有的 `firecrawl` 服务器更新或替换为 OAuth 服务器 URL。请勿添加第二个 Firecrawl 条目。更改后，请先启动新的客户端会话，再重试请求。

<div id="codex">
  ### Codex
</div>

运行：

```bash
codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth
codex mcp login firecrawl
```

Codex 会替换现有的同名服务器。输入 `/mcp`，确认 `firecrawl` 已连接。

<div id="claude-code">
  ### Claude Code
</div>

Claude Code 不会覆盖同名的现有服务器。请先删除当前条目，再添加 OAuth 条目：

```bash
claude mcp remove firecrawl
claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
```

在 Claude Code 中打开 `/mcp`，然后在浏览器中完成登录。

<div id="other-clients">
  ### 其他客户端
</div>

编辑现有的 `firecrawl` 服务器，将其 URL 设置为：

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

保存配置，完成客户端发起的登录，然后开启新的客户端会话。

<div id="compatibility-and-security-details">
  ## 兼容性与安全性详情
</div>

<AccordionGroup>
  <Accordion title="迁移期间的兼容性">
    为 `/v2/mcp` 签发的现有 OAuth 令牌仍可在该端点使用。新的交互式连接使用 `/v2/mcp-oauth`，而为该账户资源签发的令牌不能用于 `/v2/mcp`。
  </Accordion>

  <Accordion title="OAuth 客户端与重定向支持">
    Firecrawl 使用带 PKCE 的 OAuth 授权码流程。兼容的客户端可通过客户端 ID 元数据文档或动态客户端注册来标识自身，因此无需客户端密钥。

    Firecrawl 支持 HTTPS 重定向地址，以及 `localhost`、`127.0.0.1` 或 `[::1]` 上的回环重定向。对于使用回环重定向的原生客户端，端口可在每次运行时变化。已注册重定向地址的其余部分必须完全匹配。
  </Accordion>

  <Accordion title="令牌范围与有效期">
    访问令牌一小时后过期。刷新令牌在成功刷新后会轮换。每个连接都绑定到其 OAuth 客户端、用户、团队、范围和 MCP 资源。

    为 `/v2/mcp-oauth` 签发的新令牌不能用于 `/v2/mcp`。受众缺失或不明确的令牌会被默认拒绝。
  </Accordion>

  <Accordion title="撤销连接">
    在 [Firecrawl Settings](https://www.firecrawl.dev/app/settings?tab=mcp) 中打开 **MCP**，然后撤销该连接。撤销操作会使其访问令牌和刷新令牌失效。从客户端重新连接以再次授权。
  </Accordion>

  <Accordion title="团队计费与访问权限">
    通过连接发出的请求会消耗登录时所选团队套餐下的额度。每个连接都会列在 [MCP 设置](https://www.firecrawl.dev/app/settings?tab=mcp) 中，可随时查看和撤销。有关 SSO 和组织级控制，请参见 [Enterprise](/zh/enterprise)。
  </Accordion>
</AccordionGroup>
