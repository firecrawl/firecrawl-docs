当你的代理通过 stdio 调用工具、需要访问本地文件，或连接到由你控制的基础设施上的 Firecrawl API 时，可在本地运行 Firecrawl MCP。MCP 服务器和 Firecrawl API 是两个独立的服务：请先选择 API 后端，再使用相应的环境变量启动 MCP。

<div id="choose-the-firecrawl-api-backend">
  ## 选择 Firecrawl API 后端
</div>

| 如果你需要              | 使用                                       |
| ------------------ | ---------------------------------------- |
| 最快的托管方案            | 使用 `FIRECRAWL_API_KEY` 的 Firecrawl Cloud |
| 对源代码或基础设施的控制权      | 使用 `FIRECRAWL_API_URL` 的已验证自托管 API       |
| 直接解析本地文件           | 连接自托管 Firecrawl API 的本地 MCP              |
| 无需自行运行此进程的安全远程 MCP | 托管的 Firecrawl MCP 服务器                    |

如果尚未启动 API，请按照[自托管 Firecrawl](/zh/contributing/self-host)进行操作，并在添加 MCP 前验证一次抓取。

<div id="install-the-prerequisites">
  ## 安装前置条件
</div>

* Node.js 22 或更高版本
* Node.js 自带的 npm 和 `npx`
* Firecrawl Cloud API 密钥或可用的自托管 Firecrawl API URL

确认 Node.js：

```bash
node --version
```

<div id="run-mcp-with-firecrawl-cloud">
  ## 使用 Firecrawl Cloud 运行 MCP
</div>

适用于将 MCP 作为本地 stdio 进程启动的客户端：

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY npx -y firecrawl-mcp@3.23.0
```

这是最轻量的托管方案。Firecrawl Cloud 提供 API 后端，MCP 进程则在你的机器上运行。

<div id="connect-mcp-to-self-hosted-firecrawl">
  ## 将 MCP 连接到自托管 Firecrawl
</div>

对于无需身份验证的受信任网络快速入门：

```bash
env FIRECRAWL_API_URL=http://localhost:3002 \
  npx -y firecrawl-mcp@3.23.0
```

对于使用兼容 API 密钥的身份验证层的自托管 API：

```bash
env FIRECRAWL_API_URL=https://firecrawl.your-domain.com \
  FIRECRAWL_API_KEY=your-api-key \
  npx -y firecrawl-mcp@3.23.0
```

仅当部署需要时才使用该 key。MCP 只能暴露该部署中已配置服务支持的工具；请参见[自托管功能支持](/zh/contributing/self-host#self-hosted-feature-support)。

<Warning>
  请勿将未经身份验证的自托管 Quickstart 暴露在公网。在使用远程 API URL
  前，请先配置 TLS、网络访问控制和受支持的身份验证方案。
</Warning>

<div id="run-mcp-over-streamable-http">
  ## 通过 Streamable HTTP 运行 MCP
</div>

对于连接到已运行 MCP 服务器的 n8n 等客户端，请使用 HTTP 传输：

```bash
env HTTP_STREAMABLE_SERVER=true \
  FIRECRAWL_API_KEY=fc-YOUR_API_KEY \
  npx -y firecrawl-mcp@3.23.0
```

将客户端连接至：

```text
http://localhost:3000/mcp
```

确认 MCP 进程已准备就绪：

```bash
curl http://localhost:3000/health
```

健康检查会返回 `ok`。本地 MCP 路由为 `/mcp`，托管版 Firecrawl 的路由为 `/v2/mcp`。

要通过 HTTP 传输使用自托管 Firecrawl，请将 `FIRECRAWL_API_KEY` 替换为上一节中的 `FIRECRAWL_API_URL` 配置，并仅在 API 要求时添加密钥。

<div id="persist-local-mcp-configuration">
  ## 持久化本地 MCP 配置
</div>

如果希望使用稳定的本地命令，可全局安装该软件包：

```bash
npm install -g firecrawl-mcp@3.23.0
```

然后运行：

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY firecrawl-mcp
```

对于 Claude Desktop，请在 `claude_desktop_config.json` 中添加本地 stdio 服务器：

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.0"],
      "env": {
        "FIRECRAWL_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}
```

对于自托管的 Firecrawl，请将 `FIRECRAWL_API_KEY` 替换为 `FIRECRAWL_API_URL`；如果 API 需要密钥，请同时提供两者。

<div id="understand-local-and-hosted-boundaries">
  ## 了解本地与远程托管的边界
</div>

* 远程托管的免密钥 MCP 仅开放 Search、Scrape 和解析，并按 IP 限流。
* 仅限本地的文件读取需要本地 MCP 进程。
* 使用 `firecrawl_parse` 直接解析本地文件时，需要将 `FIRECRAWL_API_URL` 指向自托管的 Firecrawl API。仅配置云端 API 密钥的本地 MCP 服务器无法通过该工具上传本地文件。
* 当代理必须访问您网络中的资源时，应通过本地或自托管的 MCP 配置 Webhook 和本地文件路径。
* Firecrawl API 限流仍然适用。使用云端 API 密钥可获得更高的托管限额，或者为您的自托管部署定义并监控容量。
