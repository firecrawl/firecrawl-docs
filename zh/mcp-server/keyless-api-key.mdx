<Visibility for="agents">
  免密钥服务器 URL (Streamable HTTP，无需凭证) ：`https://mcp.firecrawl.dev/v2/mcp`

  * Codex：`codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp`
  * Claude Code：`claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp`
  * Cursor 或任何支持 JSON 配置的客户端：`{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp"}}}`
  * OpenCode (`opencode.json`) ：`{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp", "enabled": true}}}`

  ChatGPT 和 Claude.ai 请改用账户登录：请参见 [OAuth](/zh/mcp-server/oauth.md)。
</Visibility>

这是 Firecrawl 的免密钥模式：无需账户或 API 密钥即可连接。可用于快速试用；当连接需要在无人值守时稳定运行，请使用 API 密钥。如果想通过浏览器登录——包括从 ChatGPT 或 Claude.ai 登录——请使用 [OAuth](/zh/mcp-server/oauth)。

免密钥 MCP 仅提供 Search、Scrape 和 Parse。它设有每日请求和额度限制，由使用同一公共 IP 地址的用户共享。同一网络中的其他人或进程可能会占用部分额度。

请使用免密钥访问来评估连接，不要将其用作身份凭证或生产环境凭证。如需了解当前额度，请参见 [免密钥限流](/zh/rate-limits#keyless-no-api-key)。

<div id="add-an-api-key">
  ## 添加 API 密钥
</div>

对于 CI、后端服务及其他无人值守连接，请使用 API 密钥。[创建 Firecrawl API 密钥](https://www.firecrawl.dev/app/api-keys)，然后将其以 `FIRECRAWL_API_KEY` 的形式提供给 MCP 客户端。

<Warning>
  人员或系统管理员必须在代理对话之外配置该密钥。切勿将密钥粘贴到代理聊天中、放入 MCP URL，或将其值提交到项目文件。配置文件中引用环境变量是安全的；密钥值本身则不安全。
</Warning>

<div id="codex">
  ### Codex
</div>

在用于启动 Codex 的环境中导出密钥：

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

将以下内容添加到 `~/.codex/config.toml`：

```toml
[mcp_servers.firecrawl]
url = "https://mcp.firecrawl.dev/v2/mcp"
bearer_token_env_var = "FIRECRAWL_API_KEY"
```

<div id="claude-code">
  ### Claude Code
</div>

启动 Claude Code 前，请先导出 API 密钥：

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

在 `.mcp.json` 中添加对环境变量的引用。请勿将 `${FIRECRAWL_API_KEY}` 替换为实际的密钥。

```json
{
  "mcpServers": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
      }
    }
  }
}
```

<div id="other-clients">
  ### 其他客户端
</div>

将客户端配置为使用：

```text
https://mcp.firecrawl.dev/v2/mcp
```

通过客户端的环境变量或密钥存储设置此请求头：

```text
Authorization: Bearer <FIRECRAWL_API_KEY>
```

保存配置后，启动新的客户端会话。打开 MCP 状态或工具列表，确认 `firecrawl` 已连接。

<div id="verify-the-connection">
  ## 验证连接
</div>

尝试运行：

```text
进行网页搜索，查找最新的 Firecrawl 版本发布说明，并总结这些来源。
```

免密钥连接会显示 `firecrawl_search`、`firecrawl_scrape` 和 `firecrawl_parse`。使用 API 密钥的连接可提供[完整工具集](/zh/mcp-server/tools)，具体取决于套餐、部署方式和团队策略。

如果显示的工具与您配置的模式不符，请移除重复的 Firecrawl 条目，重启客户端，并检查当前服务器 URL 和凭据来源。

<div id="run-in-ci-or-a-backend">
  ## 在 CI 或后端环境中运行
</div>

将 `FIRECRAWL_API_KEY` 存储在平台的密钥管理器中，并注入进程环境。MCP 配置中仅保留对环境变量的引用：

```json
{
  "url": "https://mcp.firecrawl.dev/v2/mcp",
  "headers": {
    "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
  }
}
```

请勿将该值写入版本控制系统、构建日志、prompt 或生成的配置中。更改密钥后，请启动新进程并验证 `firecrawl` 工具列表；如果密钥可能已泄露，请轮换密钥。

<div id="legacy-api-key-url-support">
  ## 旧版 API 密钥 URL 支持
</div>

<Warning>
  仅当现有配置和客户端无法发送 Authorization 请求头时，才可使用在 URL 中包含密钥的形式。请勿将其用于新连接。
</Warning>

现有配置可能使用 `https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp`。完整 URL 本身就是凭证：切勿将其粘贴到聊天、截图、issue、日志或共享配置中。请尽可能迁移到由环境变量提供的 `Authorization: Bearer` 请求头；如果 URL 已泄露，请轮换密钥。

此兼容路由仅适用于完整的 `/v2/mcp` 工具集。不适用于仅限 OAuth 的 search 资源。
