Firecrawl MCP 通过模型上下文协议，让 AI 客户端能够访问实时网页数据。若要快速完成设置，请使用托管服务器；如需本地进程或自托管 Firecrawl API，也可以[在本地运行开源服务器](/zh/mcp-server/local)。

本页面是托管 Firecrawl MCP 的官方配置指南。

<div id="setup-firecrawl-mcp-server">
  ## 设置 Firecrawl MCP 服务器
</div>

对于交互式客户端，请通过 OAuth 连接。客户端会在浏览器中打开 Firecrawl，您可登录、选择团队并授权访问，无需复制 API 密钥。

<Tabs>
  <Tab title="Codex">
    添加托管服务器并完成 OAuth 登录：

    ```bash
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp-oauth
    codex mcp login firecrawl
    ```

    启动或重启 Codex 应用、CLI 或 IDE 扩展。输入 `/mcp`，确认 `firecrawl` 已连接。
  </Tab>

  <Tab title="Claude Desktop">
    1. 打开 **设置 &gt; 连接器**。
    2. 选择 **添加自定义连接器**。
    3. 将 `https://mcp.firecrawl.dev/v2/mcp-oauth` 填入远程 MCP 服务器 URL。
    4. 选择 **连接**，然后登录 Firecrawl 并授权访问。

    <Note>
      必须通过 **设置 &gt; 连接器** 添加远程服务器。`claude_desktop_config.json` 文件仅用于本地 MCP 服务器。
    </Note>
  </Tab>

  <Tab title="Claude Code">
    添加托管服务器：

    ```bash
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    在 Claude Code 中输入 `/mcp`，选择 `firecrawl`，然后在浏览器中完成登录。
  </Tab>

  <Tab title="Cursor">
    将托管服务器添加到 `~/.cursor/mcp.json`：

    ```json
    {
      "mcpServers": {
        "firecrawl": {
          "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
        }
      }
    }
    ```

    保存文件，打开 Cursor 的 MCP 设置，然后完成 Firecrawl 登录。随后，Cursor 会向代理提供 Firecrawl 工具。
  </Tab>

  <Tab title="其他客户端">
    将支持 OAuth 的远程 MCP 客户端配置为使用：

    ```text
    https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    如果客户端要求提供 OAuth 客户端 ID 或客户端密钥，请将两者留空。兼容客户端会使用客户端 ID 元数据文档或动态客户端注册。

    如果客户端无法完成远程 OAuth，请使用下方的 API 密钥设置。如果无法发送请求标头，请[在本地运行 Firecrawl MCP](/zh/mcp-server/local)。
  </Tab>
</Tabs>

OAuth 连接获得的是短期有效、绑定资源的令牌，而非您的 Firecrawl API 密钥。您可以在 [MCP 设置](https://www.firecrawl.dev/app/settings?tab=mcp)中查看和撤销这些令牌。

<div id="set-up-with-an-api-key">
  ## 使用 API 密钥进行设置
</div>

对于无法完成浏览器 OAuth 流程的 CI、服务器、脚本或其他客户端，请使用 API 密钥。[创建 Firecrawl API 密钥](https://www.firecrawl.dev/app/api-keys)，将其存储在环境变量或密钥存储中，然后连接到完整的托管 MCP 端点。

<Tabs>
  <Tab title="Codex">
    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp \
      --bearer-token-env-var FIRECRAWL_API_KEY
    ```
  </Tab>

  <Tab title="Claude Code">
    Claude Code 会在连接时展开环境变量：

    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp \
      --header 'Authorization: Bearer ${FIRECRAWL_API_KEY}'
    ```
  </Tab>

  <Tab title="其他客户端">
    将客户端配置为以 Bearer 令牌的形式发送 API 密钥：

    ```text
    URL: https://mcp.firecrawl.dev/v2/mcp
    Authorization: Bearer <FIRECRAWL_API_KEY>
    ```

    请求头的配置方式因客户端而异。请将密钥存储在客户端的环境变量或受保护的密钥存储中。
  </Tab>
</Tabs>

<Warning>
  切勿将 API 密钥写入项目配置文件、粘贴到聊天中，或在截图或 issue 中分享。新配置应使用 OAuth 或由环境变量提供凭据的 Authorization 请求头，切勿使用包含凭据的 URL。
</Warning>

<div id="try-without-an-api-key">
  ## 无需 API 密钥即可试用
</div>

无需创建账户，即可试用 Firecrawl。只需将免密钥端点添加到任何支持远程 MCP 的客户端：

```text
https://mcp.firecrawl.dev/v2/mcp
```

免密钥 MCP 按网络进行限流，符合条件时仅提供 **Search、Scrape 和 Parse**。如需使用完整工具集或获得更高限额，请通过 OAuth 或 API 密钥连接。

<Accordion title="达到免密钥限额后怎么办？">
  MCP 错误会在可用时包含当前的重试时间。等待该时间间隔后即可继续免密钥使用，或立即通过 OAuth 或 API 密钥连接。
</Accordion>

<div id="verify-your-connection">
  ## 验证连接
</div>

打开客户端的 MCP 状态或工具列表，确认 `firecrawl` 已连接。免密钥连接会显示 `firecrawl_search`、`firecrawl_scrape` 和 `firecrawl_parse`；已认证连接可根据套餐、部署和团队策略提供[完整工具集](/zh/mcp-server/tools)。

尝试发起只读请求：

```text
进行网页搜索，查找最新的 Firecrawl 版本发布说明，并总结这些来源。
```

如果未显示任何 Firecrawl 工具，请在保存 MCP 配置后重启或重新加载客户端。若出现 `spawn npx ENOENT` 等本地进程错误，请参见[在本地运行 Firecrawl MCP](/zh/mcp-server/local#troubleshooting)。

<div id="compatibility-and-legacy-setup">
  ## 兼容性与旧版配置
</div>

<AccordionGroup>
  <Accordion title="支持旧版 API 密钥 URL">
    <Warning>
      此旧版形式仅供无法完成 OAuth 流程或无法发送自定义 Authorization 请求头的现有配置和客户端使用。不建议新集成采用此配置。
    </Warning>

    ```text
    https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
    ```

    API 密钥包含在 URL 中，因此请将完整 URL 视为密码。如发生泄露，请轮换密钥。此备用方案仅适用于完整的 `/v2/mcp` 工具集，不适用于仅支持 OAuth 的搜索资源。
  </Accordion>

  <Accordion title="现有 OAuth 连接">
    在迁移到专用账户端点期间，现有的 `/v2/mcp` OAuth 连接仍将继续受支持。新的交互式账户连接应使用 `/v2/mcp-oauth`；为该账户资源新签发的令牌无法用于 `/v2/mcp`。
  </Accordion>
</AccordionGroup>
