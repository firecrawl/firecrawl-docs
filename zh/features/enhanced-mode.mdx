Firecrawl 提供不同类型的代理服务，帮助你抓取不同复杂程度的网站。设置 `proxy` 参数，以控制请求使用哪种代理策略。

## 代理类型 {#proxy-types}

| 类型         | 描述                                      |
| ---------- | --------------------------------------- |
| `basic`    | 适用于大多数网站的标准代理                           |
| `enhanced` | 适用于复杂网站的增强代理                            |
| `auto`     | **推荐。**先尝试 `basic`，失败后再使用 `enhanced` 重试 |

如果未指定代理，Firecrawl 默认使用 `auto`。

## Firecrawl 何时升级代理 {#when-firecrawl-escalates}

Firecrawl 默认从 basic 代理开始。如果目标站点返回 **401、403 或 429**，Firecrawl 会将其视为代理不够用的信号，并通过 增强代理对同一 URL 重试。其他状态码 (包括 404 和 5xx) 不会触发升级，因为换用代理也改变不了结果。

每个请求最多只升级一次。请求一旦已在使用 增强代理，再次出现 401、403 或 429 时会直接把结果返回给你，不再重试。

你无需检测或处理这一过程。重试属于同一次请求的一部分，你收到的响应就是最终结果。

<Info>
  增强代理请求与 basic 请求成本相同——**每次请求 1 个额度**。升级后的重试不会单独计费，因此一个从 basic 开始、以 enhanced 结束的请求仍然只消耗 1 个额度。
</Info>
