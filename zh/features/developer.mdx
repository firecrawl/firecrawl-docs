Firecrawl Developer 是专为编程代理打造的索引。它涵盖 GitHub issue、已合并的 pull request、仓库 README 和精选文档站点，让代理能够基于第一手资料回答有关代码行为、库或框架、API 契约、错误消息或已知 bug 的问题，而不是依赖普通网页。

* 查找报告并修复某个 bug 的 issue 或 pull request
* 阅读 README 或文档页面中能够回答某个具体问题的相关段落
* 追溯 API 契约至修改它的 pull request
* 找出错误消息背后的讨论

<Note>
  要让您的编程代理访问开发者索引，我们推荐使用我们的 [CLI](/zh/sdks/cli) 或 [MCP 服务器](/zh/mcp-server)——两者都将其作为一等工具提供，因此代理无需被告知端点也会主动使用它。
</Note>

<div id="two-ways-in">
  ## 两种接入方式
</div>

| 入口                                              | 适用场景                          |
| ----------------------------------------------- | ----------------------------- |
| [`/search`](/zh/features/search) 中的 `developer` 类别 | 希望通过一次调用同时获取开发者结果和普通网页结果      |
| [开发者搜索端点](#developer-search-endpoint)           | 只需要按相关性排序的开发者结果，以及匹配段落和索引筛选条件 |

<div id="developer-category-on-search">
  ## `/search` 中的开发者类别
</div>

在 `/search` 的 `categories` 数组中传入 `developer`。API 会在 `web` 旁以 `developer` 分组返回开发者结果，两个 SDK 也都将该分组暴露为 `.developer`。

无需 API 密钥即可开始使用 — `/search` 接受免密钥请求，并包含 `developer` 类别，但受[免密钥额度](/zh/rate-limits#keyless-no-api-key)限制。如需更高的限流，请提供 API 密钥。

<CodeGroup>
  ```bash cURL
  # 无需 API 密钥即可开始使用；如需更高的限流，请添加 -H "Authorization: Bearer $FIRECRAWL_API_KEY"：
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(
      # 无需 API 密钥即可开始使用；如需更高的限流，请添加：
      # api_key="fc-YOUR-API-KEY",
  )

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // 无需 API 密钥即可开始使用；如需更高的限流，请添加：
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

该分组中的开发者结果包含 `url`、`title`、`description` 和 `position`，结构与网页结果相同，并额外包含 `category: "developer"`。同一响应中的网页结果不含 `category`，因此如果合并两个分组，可通过该字段进行区分。

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://example.com/blog/retry-strategies",
        "title": "Retry strategies for HTTP clients",
        "description": "An overview of backoff and retry patterns"
      }
    ],
    "developer": [
      {
        "url": "https://github.com/firecrawl/firecrawl/issues/1234",
        "title": "Retries are not applied to 429 responses",
        "description": "Reported behavior and the fix that landed",
        "position": 1,
        "category": "developer"
      }
    ]
  }
}
```

<Note>
  **SDK 用户：**开发者结果会单独分组，不在 `.web` 中。请通过 `result.developer` 获取。
</Note>

<div id="developer-search-endpoint">
  ## 开发者搜索端点
</div>

| 任务      | 端点                                                                           |
| ------- | ---------------------------------------------------------------------------- |
| 搜索开发者索引 | [`GET` 或 `POST /search/developer`](/zh/api-reference/endpoint/developer-search) |

开发者搜索每 10 条结果消耗 2 个额度，按结果数量向上取整 (1–10 条结果 = 2 个额度，11–20 条 = 4 个额度，依此类推) 。无需 API 密钥即可开始使用；提供 API 密钥可获得更高的限流。

<CodeGroup>
  ```bash cURL
  # 无需 API 密钥即可开始使用；如需更高的限流，请添加 -H "Authorization: Bearer $FIRECRAWL_API_KEY"：
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"]
    }'
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

<Note>
  Python 和 Node SDKs 可通过上方所示的 `developer` 类别访问开发者索引。它们未提供此端点的专用方法，因此请通过 HTTP、[CLI](/zh/sdks/cli) 或 [MCP](/zh/mcp-server) 调用。
</Note>

<div id="filters">
  ### 筛选条件
</div>

所有筛选条件均为可选。

| 筛选条件        | 含义                                                             |
| ----------- | -------------------------------------------------------------- |
| `k`         | 返回的排序结果数量。默认值为 20，最大值为 100                                     |
| `types`     | 要搜索的结果类型。可选值为 `doc`、`issue`、`pull_request`、`readme`。默认包含全部四种类型 |
| `repos`     | 限定范围的仓库 slug，例如 `firecrawl/firecrawl`                          |
| `sources`   | 限定范围的文档 source id，最多 20 个。请参见下文                                |
| `passages`  | 每个结果返回的匹配段落数。默认值为 1，最大值为 5                                     |
| `language`  | 仓库语言                                                           |
| `topic`     | 仓库主题                                                           |
| `license`   | 仓库许可证                                                          |
| `min_stars` | 仓库星标数下限                                                        |
| `max_stars` | 仓库星标数上限                                                        |
| `archived`  | 包含或排除已归档的仓库                                                    |
| `fork`      | 包含或排除分叉仓库                                                      |

可重复的筛选条件在 `GET` 请求中支持以下任一形式：重复的查询参数，例如 `types=issue&types=pull_request`；或单个逗号分隔的值，例如 `types=issue,pull_request`。在 `POST` 请求中，请在 JSON 请求正文中传入数组。

<div id="how-repos-and-sources-scope-a-search">
  ### `repos` 和 `sources` 如何限定搜索范围
</div>

索引分为两部分，这两个筛选条件分别独立限定各自的搜索范围：

* `repos` 限定 GitHub 部分，即 `issue`、`pull_request` 和 `readme` 类型
* `sources` 限定文档部分，即 `doc` 类型
* 同时传入两者会合并这两部分，而不是取交集，因此会返回任一部分中的匹配结果

由于每个筛选条件只适用于其中一部分，无法匹配任何请求类型的筛选条件会被拒绝，而不会静默返回空结果：

* 当 `types` 中不包含 GitHub 类型时使用 `repos`，会返回 `400`，并显示 `repos cannot match any requested type; add github types or drop repos`
* 当 `types` 中不包含 `doc` 时使用 `sources`，会返回 `400`，并显示 `sources cannot match any requested type; add doc or drop sources`

<div id="which-values-sources-accepts">
  ### `sources` 可接受的值
</div>

`sources` 不是固定的枚举值。它接受文档 source id；每个 id 均为非空字符串，最长 512 个字符，每个请求最多可传入 20 个。这些 id 对应索引中的文档站点，集合会随时间增长。

要确认某个 id 是否能解析，请传入该 id，并查看响应中新增的 `sources` 数组。该数组仅在你传入 `sources` 时出现，会按你请求时的原样列出每个 id，并说明其是否已被索引：

```json
{
  "success": true,
  "results": [],
  "sources": [
    { "source": "some-docs-site", "indexed": true },
    { "source": "unknown-docs-site", "indexed": false }
  ]
}
```

`indexed: true` 表示该 source 存在已发布的版本，因此可能会返回其中的文档证据。`indexed: false` 表示该 id 下没有任何内容可以匹配，可借此区分未在索引中的 id 与只是未找到结果的 query。

`repos` 也会以相同方式返回，作为一个 `repos` 数组，包含 `indexed` 以及按类型细分的 `issue`、`pullRequest` 和 `readme`。

<div id="response">
  ### 响应
</div>

```json
{
  "success": true,
  "results": [
    {
      "id": "issue:firecrawl/firecrawl#1234",
      "type": "issue",
      "url": "https://github.com/firecrawl/firecrawl/issues/1234",
      "title": "Retries are not applied to 429 responses",
      "passages": [
        {
          "text": "The client treats 429 as a terminal status, so the backoff never runs."
        }
      ]
    }
  ],
  "coverage": {
    "doc": "ok",
    "issue": "ok",
    "pull_request": "ok",
    "readme": "ok"
  },
  "reranked": true
}
```

* `id` 是稳定的结果 ID，例如 `issue:owner/repo#123`
* `type` 为 `doc`、`issue`、`pull_request` 或 `readme` 之一
* `title` 为可选字段，在 `doc` 结果中经常缺失，因为源页面没有可用标题。应回退到 `url`，而不要假设该字段存在
* `passages` 包含 Markdown 格式的匹配段落，因此表格和代码块能够保留
* `coverage` 按结果类型报告索引健康状况，取值为 `ok`、`degraded`、`unavailable` 或 `skipped`
* `reranked` 表示排序后的列表是否经过重排序阶段

如果缺少预期的结果类型，请检查 `coverage`。`degraded` 或 `unavailable` 状态表示缺失是由索引造成的，而非 query。

<div id="use-it-from-mcp">
  ## 通过 MCP 使用
</div>

托管的 [MCP 服务器](/zh/mcp-server)提供这两种接口，且均不会写入任何内容。请按照[连接 Firecrawl MCP](/zh/mcp-server/connect)中的说明，使用账户 OAuth 或 API 密钥进行连接。在托管的免密钥连接中，`categories: ["developer"]` 的 `firecrawl_search` 会返回开发者结果，而专用的 `firecrawl_developer_search` 工具不属于[免密钥工具接口](/zh/mcp-server/tools)，需要账户连接或 API 密钥。

<div id="developer-search-tool-firecrawl_developer_search">
  ### 开发者搜索工具 (`firecrawl_developer_search`)
</div>

独立搜索开发者索引，返回按相关性排序的结果及匹配段落。

```json
{
  "name": "firecrawl_developer_search",
  "arguments": {
    "query": "how do I configure retries",
    "k": 10
  }
}
```

<div id="developer-search-tool-options">
  #### 开发者搜索工具选项：
</div>

* `query`：搜索查询字符串 (必填)
* `k`：返回的排序结果数量，范围为 1 到 100

**最适合：** 基于一手资料回答有关代码行为、库或框架、API 契约、错误消息或已知 bug 的问题。
**返回：** 每个命中结果均以 markdown 块形式返回，包含其 id、type、url、title 和匹配段落。

该工具仅接受这两个参数。需要按结果类型、仓库或文档来源筛选条件时，请通过 HTTP 调用 [开发者搜索端点](#developer-search-endpoint)。

<div id="developer-results-from-the-search-tool-firecrawl_search">
  ### 使用 Search Tool (`firecrawl_search`) 获取开发者结果
</div>

在 `categories` 中传入 `developer`，即可在普通网页结果旁以 `developer` 分组获取开发者结果，其结构与 `/search` 中 `developer` 类别返回的结果相同。

```json
{
  "name": "firecrawl_search",
  "arguments": {
    "query": "how do I configure retries",
    "categories": ["developer"],
    "limit": 10
  }
}
```

**最适合：** 希望通过一次调用同时权衡开发者来源和普通网页时。
**返回：** 常规搜索响应，其中开发者结果归入 `developer`，且每条结果均带有 `category: "developer"`。
