<div id="best-practices">
  ## 最佳实践
</div>

<CardGroup cols={2}>
  <Card title="性能" icon="gauge-high">
    * 单个页面使用 **抓取** (速度最快) 
    * 大型网站使用带限额的 **爬取**
    * 合理设置计划，避免触发限流
    * 添加错误处理模块
  </Card>

  <Card title="成本优化" icon="piggy-bank">
    * 策略性地设置计划 (每小时/每天/每周) 
    * 使用筛选条件，避免不必要的运行
    * 设置 crawl 限额，控制 API 使用量
    * 先在 Firecrawl playground 中进行测试
  </Card>
</CardGroup>

<div id="make-vs-zapier-vs-n8n">
  ## Make、Zapier 与 n8n 对比
</div>

| 功能       | Make           | Zapier     | n8n           |
| -------- | -------------- | ---------- | ------------- |
| **部署方式** | 可视化构建器，云端      | 无代码，云端     | 自托管或云端        |
| **定价**   | 按操作次数计费        | 按任务计费      | 按执行次数计费       |
| **集成**   | 3,000+ 款应用     | 9,000+ 款应用 | 1,000+ 款应用和服务 |
| **复杂度**  | 高级工作流          | 简单工作流      | 复杂工作流         |
| **最适合**  | 可视化自动化，中等复杂度需求 | 快速实现自动化    | 开发者掌控         |
| **学习曲线** | 中等             | 简单         | 中等偏高          |

<Tip>
  **提示：** Make 擅长可视化工作流设计和复杂自动化。非常适合需要比 Zapier 更强控制力、但偏好可视化构建而非 n8n 代码优先方式的团队。
</Tip>
