将 Firecrawl 作为远程扩展接入 Goose，让 Goose 能够通过远程托管的 MCP 服务器进行网页搜索并读取页面内容。

## 前提条件 {#requirements}

* Goose 1.55 或更高版本。
* 一个 [Firecrawl API 密钥](https://www.firecrawl.dev/app/api-keys)，并已导出为环境变量 `FIRECRAWL_API_KEY`。

## 快速设置 {#quick-setup}

1. 在用于启动 Goose 的 shell 中导出你的 API 密钥：

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. 将该扩展添加到 `~/.config/goose/config.yaml` 的 `extensions` 部分：

```yaml
extensions:
  firecrawl:
    type: streamable_http
    name: firecrawl
    enabled: true
    uri: https://mcp.firecrawl.dev/v2/mcp
    headers:
      Authorization: "Bearer $FIRECRAWL_API_KEY"
    env_keys:
      - FIRECRAWL_API_KEY
    timeout: 300
```

3. 开始一个会话，让 Goose 执行搜索或抓取：

```bash
goose session
```

<Warning>
  请将标头写为 `$FIRECRAWL_API_KEY` (不加花括号) ，并保留 `env_keys`。否则 Goose 会将 `${FIRECRAWL_API_KEY}` 按字面文本原样发送，导致服务器拒绝该请求。
</Warning>

有关密钥的更多信息，请参见[配置 API 密钥](/zh/mcp-server/keyless#add-an-api-key)。

## 故障排除 {#troubleshooting}

* **提示密钥无效或已撤销：**&#x68C0;查标头中使用的是不带花括号的 `$FIRECRAWL_API_KEY`，并确认已在启动 Goose 的 shell 中导出 `FIRECRAWL_API_KEY`。
* **扩展未显示：**&#x4FDD;存文件后重新运行 `goose session`，并确认已设置 `enabled: true`。
* **调用超时：**&#x8C03;高 `timeout`。抓取大型页面耗时可能超过默认值。
* **工具未被调用：**&#x4E0D;同模型调用 MCP 工具的可靠性不一，可尝试换用其他模型。
