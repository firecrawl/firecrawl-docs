将 Firecrawl 远程托管的 MCP 服务器添加到 [Cloudflare One MCP 服务器门户](https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/)，让你的团队通过统一的门户 URL 访问 Firecrawl 的搜索和抓取工具，并受你的 Access 策略管控。

## 快速配置 {#quick-setup}

先[创建 Firecrawl API 键](https://www.firecrawl.dev/app/api-keys)，然后通过门户 API 在 Cloudflare Access 中将 Firecrawl 添加为 MCP 服务器，并以该键作为 bearer 凭据：

```bash
export CLOUDFLARE_ACCOUNT_ID=your-cloudflare-account-id
export CLOUDFLARE_API_TOKEN=your-cloudflare-api-token
export FIRECRAWL_API_KEY=fc-YOUR_API_KEY

curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/access/ai-controls/mcp/servers" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Firecrawl",
    "hostname": "https://mcp.firecrawl.dev/v2/mcp",
    "auth_type": "bearer",
    "auth_credentials": "'"$FIRECRAWL_API_KEY"'"
  }'
```

门户会以 `Authorization: Bearer <key>` 的形式将 `auth_credentials` 发送给 Firecrawl。你也可以在 Cloudflare Dashboard 中依次进入 **Zero Trust** &gt; **Access controls** &gt; **MCP Portals** &gt; **MCP servers** &gt; **Add MCP server**，使用同一 URL 添加该服务器。

接下来，将该服务器添加到门户，为其绑定 Access 策略以控制哪些用户可以看到它，然后选择要公开的工具。如何创建门户，请参见 Cloudflare 的 [MCP 服务器门户指南](https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/)。

## 试一试 {#try-it}

将 MCP 客户端连接到你的门户 URL (`https://<subdomain>.<domain>/mcp`) ，然后提问：

```text
进行网页搜索，查找最新的 Cloudflare Workers 版本发布说明，并对这些信息来源进行总结。
```

```text
抓取 https://firecrawl.dev，并说明它是做什么的。
```

## 故障排除 {#troubleshooting}

* **服务器显示同步或身份验证错误：**&#x8BF7;检查该键是否有效，以及 `auth_type` 是否为 `bearer`；如果你轮换过该键，请更新服务器的凭据。
* **门户中缺少 Firecrawl 的工具：**&#x95E8;户只会公开管理员为其选定的工具，请检查门户的工具列表。
* **用户看不到 Firecrawl：**&#x53EA;有符合该服务器上某条 Allow 策略的用户，才能看到该服务器链接。
