将 Firecrawl 作为远程 HTTP MCP 服务器接入 Crush，使 Crush 能够进行网页搜索并读取页面内容。

## 前提条件 {#requirements}

* Crush 0.98 或更高版本。
* 一个 [Firecrawl API 密钥](https://www.firecrawl.dev/app/api-keys)，并已导出为环境变量 `FIRECRAWL_API_KEY`。

## 快速设置 {#quick-setup}

1. 在用于启动 Crush 的 shell 中导出 API 密钥：

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. 将该服务器添加到项目中的 `crush.json`，若要在所有项目中使用，则添加到 `~/.config/crush/crush.json`：

```json
{
  "$schema": "https://charm.land/crush.json",
  "mcp": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer $FIRECRAWL_API_KEY"
      }
    }
  }
}
```

3. 启动 Crush，让它执行搜索或抓取。

<Accordion title="使用 crushrc 文件？">
  较新的 Crush 版本支持读取 Bash 风格的 `crushrc` 文件，在其中只需一条命令即可添加 MCP 服务器：

  ```bash
  mcp add firecrawl \
    --type http \
    --url "https://mcp.firecrawl.dev/v2/mcp" \
    --header Authorization "Bearer $FIRECRAWL_API_KEY"
  ```

  运行 `crush dirs`，即可查看 Crush 在你的机器上会从哪些位置读取配置。
</Accordion>

有关密钥的更多信息，请参见[配置 API 密钥](/zh/mcp-server/keyless#add-an-api-key)。

## 故障排除 {#troubleshooting}

* **服务器无法启动：** 请检查启动 Crush 的 shell 中是否已导出 `FIRECRAWL_API_KEY`，并确认 URL 与 `https://mcp.firecrawl.dev/v2/mcp` 完全一致。
* **标头被丢弃：** 如果某个标头的值解析为空 string，Crush 会将其移除。未设置 `FIRECRAWL_API_KEY` 时就会出现这种情况。
* **工具未被使用：** 不同模型调用 MCP 工具的可靠性各不相同，请尝试换用其他模型。
