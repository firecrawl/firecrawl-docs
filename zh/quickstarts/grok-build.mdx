通过远程托管的 MCP 服务器，将 xAI 的编程智能体 CLI [Grok Build](https://docs.x.ai/build/overview) (`grok`) 连接到 Firecrawl。推荐采用 OAuth 作为交互式配置方式。使用 OAuth 时，密钥不会出现在命令行、项目文件或对话中。

## 快速设置 {#quick-setup}

### 1. 添加 Firecrawl {#1-add-firecrawl}

运行以下命令：

```bash
grok mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
```

`https://mcp.firecrawl.dev/v2/mcp-oauth` 是填写在客户端中的配置值，并非用于直接在浏览器中打开的页面。

### 2. 登录并验证 {#2-sign-in-and-verify}

启动 Grok Build：

```bash
grok
```

输入 `/mcps`，选择 `firecrawl`，然后按 `i` 开始在浏览器中登录。选择一个团队并授权连接。Grok 会将 OAuth 令牌保存在 `~/.grok/mcp_credentials.json` 中。

确认只有一个 `firecrawl` 服务器处于启用状态，然后试试：

```text
进行网页搜索，查找最新的 Next.js 版本发布说明，并汇总各信息来源的内容。
```

```text
抓取 https://docs.firecrawl.dev，并列出其中的顶级章节。
```

## 通过 API 密钥使用本地 MCP {#local-mcp-with-an-api-key}

仅当你需要本地进程或自托管的 Firecrawl API 时，才使用本地服务器。本地包要求 Node.js 22 或更高版本。

在启动 Grok 的环境中设置 `FIRECRAWL_API_KEY`，然后将以下配置块添加到 `~/.grok/config.toml`：

```toml
[mcp_servers.firecrawl]
command = "npx"
args = ["-y", "firecrawl-mcp@3.33.2"]
env = { FIRECRAWL_API_KEY = "${FIRECRAWL_API_KEY}" }
startup_timeout_sec = 60
```

Grok 会在加载配置时展开 `${FIRECRAWL_API_KEY}`，因此密钥不会写入文件。请勿将密钥粘贴到智能体对话中，也不要提交到源代码管理系统。只保留一个 `firecrawl` 条目：先运行 `grok mcp remove firecrawl` 移除托管服务器。

有关自行托管的设置，请参见[在本地运行 MCP](/zh/mcp-server/local)。

## 其他连接模式 {#other-connection-modes}

* [试用免密钥 MCP](/zh/mcp-server/keyless#try-keyless)：无需账户或密钥即可使用搜索、抓取和解析功能。
* [配置 API 密钥](/zh/mcp-server/keyless#add-an-api-key)：以无人值守方式使用托管服务器。请勿将密钥直接写入智能体对话，而应通过环境变量引用。

## 故障排查 {#troubleshooting}

* **已存在 Firecrawl 服务器：** 运行 `grok mcp remove firecrawl`，重新添加一次所需的连接，然后开始新的会话。
* **Grok 中出现第二个 `firecrawl` 服务器：** Grok 还会从 `~/.claude.json`、`.cursor/mcp.json` 以及项目中的 `.mcp.json` 文件加载 MCP 服务器。运行 `grok inspect` 查看每个服务器的来源，然后删除重复项。
* **服务器显示 `401`：** 输入 `/mcps`，选择 `firecrawl`，然后按 `i` 重新登录。请勿将 API 密钥粘贴到对话或 OAuth URL 中。
* **本地服务器无法连接：** 运行 `grok mcp doctor firecrawl`。Grok 会将服务器错误写入 `~/.grok/logs/mcp/firecrawl.stderr.log`。如果 `npx` 在首次启动时需要下载软件包，请调大 `startup_timeout_sec`。
