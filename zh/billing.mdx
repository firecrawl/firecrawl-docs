<div id="overview">
  ## 概览
</div>

Firecrawl 采用**基于额度的计费方式**。你发起的每一次 API 调用都会消耗额度，具体消耗数量取决于你使用的端点和选项。你的方案会为你提供每月额度配额。当配额用尽时，按量付费会补充更多额度。

有关当前方案定价，请访问 [Firecrawl 定价页面](https://www.firecrawl.dev/pricing)。

<Note>
  所有 Firecrawl 发票均以**美元 (USD) **计费，无论你的账单地址或支付方式为何。
</Note>

<div id="credits">
  ## Credits
</div>

Credits 是 Firecrawl 中的用量单位。每个方案都包含每月的 Credits 配额，并会在每个计费周期开始时重置。不同的 API 端点会消耗不同数量的 Credits。

<div id="credit-costs-per-endpoint">
  ### 每个端点的额度消耗
</div>

| 端点         | 额度成本             | Notes                                                                                                                                        |
| ---------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Scrape** | 1 额度 / page             | 将单个 URL 转换为干净的 Markdown、HTML 或结构化数据。使用抓取选项时会额外消耗额度 (见下文) 。                                                                                   |
| **Crawl**  | 1 额度 / page             | 从起始 URL 跟踪链接以抓取整个网站。每个被爬取的页面都适用相同的每页抓取选项额度消耗。                                                                                                |
| **Map**    | 1 额度 / call             | 发现网站上的所有 URL，而不抓取其内容。                                                                                                                        |
| **Search** | 2 额度 / 10 results       | 搜索全网，并可选地抓取搜索结果。每 10 个结果向上取整计费 (例如，11 个结果 = 4 额度) 。对每个被抓取的结果将按页面收取额外的抓取额度。企业版 ZDR 搜索定价请参见 [此处](/zh/features/search#zero-data-retention-zdr) 。   |
| **交互**     | 2–7 额度 / browser minute | 交互式浏览器沙盒会话，按浏览器使用分钟计费，最低计费时长为一分钟。使用 `prompt` 的会话按 7 额度 / browser minute 计费；未使用 prompt (仅使用 Playwright `code`) 的会话按 2 额度 / browser minute 计费。 |
| **代理**  | Dynamic                 | 自主网页研究代理。每天前 5 次运行免费；超出部分按用量动态计费。                                                                                                            |

<div id="additional-credit-costs-for-scrape-options">
  ### 抓取选项的额外额度成本
</div>

某些抓取选项会在每页基础消耗之外额外增加额度：

| 选项                                               | Additional Cost      | 描述                                                                                                                                                                             |
| ------------------------------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PDF parsing                                      | +1 额度 / PDF page | 从 PDF 文档中提取内容                                                                                                                                                                  |
| JSON 格式 (LLM 提取)                                 | +4 额度 / page    | 使用 LLM 从页面中提取结构化 JSON 数据                                                                                                                                                       |
| Prompt 注入检查                                      | +4 额度 / page    | 面向 JSON 格式的可选 `checkPromptInjection` 防护检查 (请参见 [Prompt 注入检测](/zh/features/llm-extract#prompt-injection-detection)) 。如果检查执行后抓取失败，将收取 5 额度。请参见 [何时收取额度](#when-credits-are-charged)。 |
| 零数据保留 (ZDR)                                      | +1 额度 / page     | 确保除本次请求外不会持久保存任何数据 (参见 [Scrape ZDR](/zh/features/scrape#zero-data-retention-zdr))                                                                                                 |
| `question` 或 `query` 格式                          | +4 额度 / page    | 由 LLM 生成的针对该页面问题的答案 (参见 [Scrape](/zh/features/scrape))                                                                                                                            |
| `highlights` 格式                                  | +4 额度 / page    | 由 LLM 从页面中挑选的相关 passages (参见 [Scrape](/zh/features/scrape))                                                                                                                       |
| `audio` 格式                                       | +4 额度 / page    | 转写页面中的音频 (参见 [Scrape](/zh/features/scrape))                                                                                                                                       |
| `video` 格式                                       | +4 额度 / page    | 转写页面中的视频 (参见 [Scrape](/zh/features/scrape))                                                                                                                                       |
| PII 脱敏 (`redactPII`)                             | +4 额度 / page    | 对返回的 markdown 中的个人数据进行脱敏。每多一个 PDF 页面，会在其 +1 的解析成本之上再增加 +4 (参见 [PII 脱敏](/zh/features/pii-redaction))                                                                               |
| `lockdown` (缓存命中)                                | +4 额度 / page    | 仅从缓存提供内容，绝不请求目标站点。缓存未命中时不返回文档，并收取 1 额度 (参见 [Lockdown](/zh/features/lockdown) 及下方表格)                                                                                               |
| Enhanced proxy (`proxy: "enhanced"` 或 `auto` 升级) | +0                   | 与 basic 请求一样按 1 额度计费。升级后的重试不会单独收费 (参见 [Enhanced Mode](/zh/features/enhanced-mode))                                                                                                |

这些费用加成可以叠加。例如，同时使用 JSON 格式 和 零数据保留 抓取同一页面时，每页将消耗 **1 + 4 + 1 = 6 额度**；而 JSON 格式搭配 PII 脱敏则消耗 **1 + 4 + 4 = 9 额度**。由于 Crawl 和 Search 端点在内部会对每个页面调用 scrape，这些端点同样适用上述费用加成。

对 `x.com` 和其他 X/Twitter URL 的请求会使用 Grok API，并采用单独的定价。请参见本页底部的 [X (x.com) 计费](#x-xcom-billing)。

<div id="when-credits-are-charged">
  ### 何时扣除额度
</div>

决定是否扣费的是 Firecrawl 是否返回了文档，而不是目标站点是否返回了成功的 HTTP 状态码。

* **Firecrawl 返回了文档：每页 1 额度**，再加上上文列出的各项选项成本。这也包括那些返回错误状态码 (例如 403 Forbidden 或 404 Not Found) 的页面。目标站点做出了响应，Firecrawl 捕获了该响应，并将其作为文档返回给你。请检查响应中的 `metadata.statusCode` 字段来识别这些情况，并停止重试那些持续被封禁的 URL。
* **Firecrawl 未返回文档：0 额度。** 彻底失败的抓取不会计费，例如站点始终没有响应，或所有渲染尝试均失败。

仍有少数情况即使没有返回文档也会扣费，它们对应 Firecrawl 在抓取结束前已经为你完成的工作。

| 情况               | 扣费内容                                    |
| ---------------- | --------------------------------------- |
| 威胁防护扫描           | 每个被扫描的 URL 2 额度，包括因扫描本身而被封禁的抓取          |
| Prompt 注入检查      | 5 额度，只要 `checkPromptInjection` 防护已运行即扣费 |
| FIRE-1 代理        | 按使用量计费，对应代理已完成的导航操作                     |
| `lockdown` 缓存未命中 | 1 额度                                    |
| 监控检查             | 在检查过程中出错的页面按每页 1 额度的基础费用扣费              |
| 交互 与 Browser 会话  | 按会话的浏览器分钟数计费，最低一分钟，无论会话是否取得你期望的结果       |

对于 **batch scrape** 和 **crawl** 任务，额度是在每个页面完成处理后异步计费，而不是在提交作业时一次性计费。这意味着从提交作业到在你的账户中看到完整的额度成本，中间可能会有一段延迟。如果一个批次包含大量 URL，或者在高流量时段页面被排队处理，额度可能会在提交后持续数分钟甚至数小时内才陆续显示。轮询或查看批次状态本身不会消耗额度。

<Note>
  **爬取预检额度检查：**当你传入显式的 `limit` 时，Firecrawl 会检查该数量的请求是否被允许。如果被允许 (包括通过超额使用的方式) ，该 limit 不会被下调到你的剩余余额。如果被拒绝，Firecrawl 会尝试将 limit 降低到剩余余额，并再次检查调整后的请求。如果无法使用任何正数的 limit，或调整后的请求仍被拒绝 (包括因单个 API key 的消费上限而被拒绝) ，则会返回 402。

  省略 `limit` 并不需要预先拥有 **10,000** 额度。初始的额度检查只使用 **1 额度**；它不会为整次爬取预留额度。如果请求被允许，默认的 **10,000** limit 不会被下调以适配余额，不过其他爬取选项可能会改变实际生效的 limit。页面会在处理时逐步计费。如果你想设置页面数量上限，请传入显式的 `limit` (例如 `limit: 100`) 。
</Note>

* **API**：使用 [Credit Usage](/zh/api-reference/endpoint/credit-usage) 和 [Credit Usage Historical](/zh/api-reference/endpoint/credit-usage-historical) 端点以编程方式检查用量

<div id="plans">
  ## 方案
</div>

订阅方案支持按月或按年计费。付费自助方案还可以使用按量付费。当方案额度用尽时，按量付费会补充额度。请参见[按量付费](#pay-as-you-go)。

<div id="paid-plans">
  ### 付费方案
</div>

| 方案                   | 每月额度      | 并发浏览器 |
| -------------------- | --------- | ----: |
| **Hobby (入门)&#x20;**&#x20;| 5,000     |     5 |
| **Standard**         | 100,000   |    25 |
| **Growth**           | 500,000   |    50 |
| **Scale (扩展)&#x20;**&#x20;| 1,000,000 |   100 |

<Note>
  对于超出 Scale (扩展)  的需求，Firecrawl 提供 **Enterprise** 方案，包含自定义额度、专属支持、SLA、批量折扣、零数据保留以及 SSO。详情请访问 [Enterprise 页面](https://www.firecrawl.dev/enterprise)。
</Note>

所有付费方案均支持**月度计费**或**年度计费**。年度计费相比月度计费享有折扣。各方案的最新价格请访问 [价格页面](https://www.firecrawl.dev/pricing)。

<div id="free-plan">
  ### Free 套餐
</div>

新账户默认使用 Free 套餐。它完全免费，也无需绑定银行卡。具体包含以下内容：

* **每月 1,000 额度。** 配额在每个月度周期开始时重置，未用完的免费额度不会顺延到下一周期。
* **2 个并发浏览器**，队列任务上限与付费自助套餐相同，均为 50,000 个。
* `/scrape`、`/map` 和 `/search` 的**限流为每分钟 10 次请求**，`/crawl`、`/agent` 和 `/interact` 为**每分钟 2 次请求**。Batch scrape 与 scrape 共用限流额度，extract 与 agent 共用限流额度。完整表格请参见 [Rate Limits](/zh/rate-limits)。
* **全部核心产品端点。** Scrape、crawl、map、search、extract、batch scrape、交互 和 monitor 在 Free 套餐上均可使用。部分团队管理和企业功能按团队而非按套餐开启，包括威胁防护、SIEM 日志记录和零数据保留 search。各套餐的额度成本相同，因此上方的[各端点额度成本](#credit-costs-per-endpoint)表格同样适用。

Free 套餐不支持按量付费，因此月度配额用尽后，请求会返回 HTTP 402。请参见 [Running Out of Credits](#running-out-of-credits)。此外也不包含额度顺延、数据处理协议和 Slack 支持，仅提供社区支持。

Scrape、Search 和 交互 还可以完全不使用 API 密钥，通过免密钥免费档位调用，其上限按每个 IP 地址每天计算，而非按额度配额计算。请参见 [Keyless (no API key)](/zh/rate-limits#keyless-no-api-key)。

<div id="billing-cycle">
  ### 计费周期
</div>

* **月度方案**：额度会在每月续费日重置
* **年度方案**：按年计费，但额度仍会在每月的虚拟月度续费日重置
* **未使用的方案额度默认不会结转**：你的月度配额会在每个月重置。**年度 Scale (扩展) 方案会将未使用的方案额度结转 1 个月**，并且 **年度 Enterprise 方案会将其结转 2 个月**。

<div id="concurrent-browsers">
  ### 并发浏览器
</div>

并发浏览器表示 Firecrawl 可以同时为你处理多少个网页。你的方案决定了这一上限。如果超出该限制，额外任务会在队列中等待，直到有空闲的并发位。有关并发和 API 速率限制的完整说明，请参阅 [Rate Limits](/zh/rate-limits)。

<a id="auto-reload" />

## 按量付费 {#pay-as-you-go}

当方案额度用尽时，按量付费可确保你的请求继续运行。它会自动为你的账户添加额度。

你以 5 美元为一个增量购买额度。当额度余额降至零时，我们会为你的账户增加一个增量额度，并从已登记的银行卡扣款。

按量付费需要使用付费自助方案。Free 方案无法使用按量付费。

你也可以随时自行购买额度。在[计费设置](https://www.firecrawl.dev/app/settings?tab=billing)中点击**加载更多额度**。输入 5 美元的整数倍金额，并使用已登记的银行卡付款。无论按量付费是否开启，均可使用此方式。

### 每次增量购买的额度 {#credits-in-a-batch}

每次增量购买可获得的额度取决于你的方案。按量付费和手动购买的费率相同。

| 方案                   | 每 5 美元额度 |
| -------------------- | -------- |
| **Hobby (入门)&#x20;**&#x20;| 1,000    |
| **Standard**         | 2,000    |
| **Growth**           | 2,500    |
| **Scale (扩展)&#x20;**&#x20;| 5,000    |

### 设置每月按量付费限额 {#set-the-monthly-auto-reload-limit}

你可以在以下两个位置设置**每月按量付费限额**：

* 在你的[计费设置](https://www.firecrawl.dev/app/settings?tab=billing)的 **计费** 标签页中。
* 在[定价页面](https://www.firecrawl.dev/pricing)选择方案时。

<div id="how-the-limit-caps-your-monthly-spend">
  ### 限额如何控制每月支出
</div>

限额是按量付费在一个月内最多可消费的金额，并会向下取整为 5 美元的整数增量。

例如，限额为 25 美元时，每月可使用五个增量。限额为 22 美元时，每月可使用四个增量，因为 22 美元会向下取整为 20 美元。

手动购买的额度不计入此限额。

## API 密钥消费限额 {#api-key-spend-limits}

消费限额用于限制单个 API 密钥可使用的额度。无论团队余额有多少，该上限都只对这一个密钥生效。你可以用它来防止某个密钥把整个团队的余额用光。

你还可以重命名任意 API 密钥，包括 Firecrawl 在创建团队时自动生成的那个名为 **Default** 的密钥。

密钥所有者或团队管理员都可以执行这两项操作。在 Dashboard 中打开 [API keys 页面](https://www.firecrawl.dev/app/api-keys)，然后打开该密钥的菜单。

* 点击 **Rename** 修改 **Key Name**。
* 点击 **Set limit** 打开 **Set a spend limit**，输入 **Credit limit**，选择 **per day**、**per week** 或 **per month**，然后点击 **Save**。

限额指的是额度数量，而不是金额。限额为 `1` 表示每个周期一个额度。点击 **Remove limit** 即可清除限额。

<div id="upgrading-and-downgrading">
  ## 升级和降级
</div>

* **升级** 会立即生效。今天将按新套餐的全额收费 (不按比例计费) ，并且你的计费周期会重置。你的下一次续费时间将是升级之日起一个月或一年后。你之前套餐中任何未使用的额度都会结转，并且新的额度配额和并发限制会立即生效。
* **降级** 将在下一个续费日生效。在此之前，你会继续保留当前套餐的额度和限制，且当前套餐未使用的时长不会折算或退款。你可以在生效日期之前的任何时间，从你的[计费设置](https://www.firecrawl.dev/app/settings?tab=billing)中撤销已安排的降级。

<div id="switching-between-monthly-and-yearly-billing">
  ### 在月度计费和年度计费之间切换
</div>

* **月度 → 年度**：如果切换到相同或更高的额度档位，将视为立即升级。
* **年度 → 月度**：只有切换到严格更高的额度档位时，才会视为立即升级。

<div id="running-out-of-credits">
  ## 额度耗尽
</div>

余额归零后会发生什么，取决于你的方案以及按量付费设置。

| 方案                                             | 按量付费           | 余额为零时                                                                                                      |
| ------------------------------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------- |
| **Free**                                         | 不可用            | 消耗额度的 requests 将返回 **HTTP 402 (需要付费)&#x20;**，直到每月重置。                                                       |
| **Hobby (入门) 、Standard、Growth、Scale (扩展)&#x20;**&#x20;| 关闭 (限额设为 `0`)  | 消耗额度的 requests 将返回 **HTTP 402**，不会向你的银行卡扣款。                                                                |
| **Hobby (入门) 、Standard、Growth、Scale (扩展)&#x20;**&#x20;| 开启             | Firecrawl 会以 5 美元为一个增量向你的银行卡扣款，并为账户添加相应额度，你的 requests 继续执行。此后每次余额归零都会重复该过程，直到达到你的**每月按量付费限额**。限额留空即表示不设上限。 |

按量付费开启时，requests 并不会在余额恰好归零的那一刻被切断。你的方案附带一定的超额宽限，让突发的 requests 能在充值到账期间继续运行：**Hobby (入门) 为 1,500 额度，Standard 为 30,000，Growth 为 150,000，Scale (扩展) 为 600,000**。一旦达到每月限额且宽限用尽，requests 将返回 **HTTP 402**，直到下一个计费周期。该宽限只是缓冲空间，并非可保留的额外额度。

手动购买的额度 (**Load more credits**) 会在上述规则生效前优先消耗，且不计入每月按量付费限额。

被硬性中止后，你可以通过以下方式恢复使用：

1. 设置**每月按量付费限额**，自动购买额度。请参见 [按量付费](#pay-as-you-go)。
2. 手动升级到更高的方案
3. 等待额度在下一个计费周期重置

<div id="coupons">
  ## 优惠券
</div>

Firecrawl 支持两种类型的优惠券：

* **订阅优惠券**可用于你的方案订阅折扣 (例如按月费或年费的一定比例减免) 。这类优惠券**只能**在你首次订阅付费方案或更改方案时，于 Stripe 结账流程中使用。结账完成后，无法再使用订阅优惠券。
* **额度优惠券**会为你的账户增加额外额度。你可以在 Dashboard 的 **计费** 部分，通过 [firecrawl.dev/app/billing](https://www.firecrawl.dev/app/billing) 进行兑换。前往计费页面，找到优惠券输入框并输入代码即可使用。额度优惠券提供的额外额度独立于你方案每月分配的额度，即使你升级或降级方案，这些额度也会保留。

<div id="faqs">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="未使用的额度会结转到下个月吗？">
    **方案额度**默认不会结转：你的月度配额会在每个月重置。**年度 Scale (扩展) 方案的未使用方案额度可结转 1 个月**，**年度 Enterprise 方案可结转 2 个月**。
  </Accordion>

  <Accordion title="按量付费的额度会过期吗？">
    你购买的额度会保留在你的账户中，直到你使用为止。如果你取消订阅，这些额度会过期，因此请在离开前用完。过期时间为当前计费周期结束时，续订不会影响这些额度。
  </Accordion>

  <Accordion title="每月按量付费限额如何运作？">
    你的限额会限制按量付费每月的消费金额。它会向下取整为完整的 5 美元增量。限额为 25 美元时，每月可进行五个增量。将限额留空，按量付费将没有每月限额。将限额设为 `0`，按量付费将关闭。
  </Accordion>

  <Accordion title="我如何知道还剩多少额度？">
    在 [firecrawl.dev/app](https://www.firecrawl.dev/app) 的Dashboard中查看，或者以编程方式调用 [Credit Usage API 端点](/zh/api-reference/endpoint/credit-usage)。
  </Accordion>

  <Accordion title="在哪里使用优惠码？">
    这取决于优惠券类型。在Dashboard的计费部分中使用**额度优惠券**。你只能在订阅或更改方案时于 Stripe 结账页面使用**订阅优惠券** (即方案价格折扣)。
  </Accordion>

  <Accordion title="我需要更高的并发或定制方案，该联系谁？">
    请联系 [help@firecrawl.dev](mailto:help@firecrawl.dev)，或访问 [Enterprise 页面](https://www.firecrawl.dev/enterprise) 了解更多定制方案信息。
  </Accordion>

  <Accordion title="发票以什么货币计费？">
    所有 Firecrawl 发票均以 **美元 (USD)** 计费，无论你的账单地址或支付方式是什么。
  </Accordion>

  <Accordion title="如何管理订阅、更改方案或取消订阅？">
    前往你的 [计费设置](https://www.firecrawl.dev/app/settings?tab=billing)。团队管理员可在此管理所有事项。点击 **Manage Subscription** 打开计费门户，并更新你的支付方式、账单地址、公司名称或 VAT 税号。

    如需更改方案，请点击 **Change Plan** 并选择新的档位。升级会立即生效。降级会在当前计费周期结束时生效，在此之前可撤销。请参见 [升级和降级](#upgrading-and-downgrading)。

    如需取消订阅，请点击 **Cancel Subscription**。你的方案会保持有效直到当前计费周期结束，并且你可以在此之前恢复订阅。方案结束后，你购买的额度也会过期，因此请在取消前使用它们。
  </Accordion>

  <Accordion title="如何在发票中添加 VAT 税号、公司名称或账单地址？">
    前往你的 [计费设置](https://www.firecrawl.dev/app/settings?tab=billing)，点击 **Manage Subscriptions**，然后在 Stripe 门户中更新账单地址、公司名称和 VAT 税号。后续发票会自动包含更新后的信息。

    如需使用新信息重新生成过往已支付的发票：

    1. 先在 Stripe 门户中更新你的账单信息 (见上文) 。
    2. 在 Stripe 门户中打开 **Invoice history** 标签页，并下载你需要的发票 PDF；Stripe 会根据你当前的账单信息重新生成该发票。
    3. 如果某张发票没有带上更新后的信息，请将发票编号发送至 [help@firecrawl.dev](mailto:help@firecrawl.dev)，我们会为你重新生成。
  </Accordion>
</AccordionGroup>

<div id="x-xcom-billing">
  ## X (x.com) 计费
</div>

Firecrawl 使用来自 [xAI](https://x.ai/) 的官方 **Grok API**，提供 AI 驱动的摘要、结构化提取，以及对公开 X 内容的实时访问。对指向 `x.com`、`twitter.com` 和 `mobile.twitter.com` 上个人资料页和帖子 URL 的请求，会通过 Grok 获授权的内部工具 (`x_search`、线程获取，以及仅限 `x.com` 的网页搜索) 进行处理，而非传统的网页抓取。

<div id="credit-costs">
  ### 额度成本
</div>

| 项目               | 额度成本        | 描述                                          |
| ---------------- | ----------- | ------------------------------------------- |
| **基础成本**         | 1 额度 / 请求   | 标准抓取请求处理                                    |
| **Grok X Query** | +29 额度 / 请求 | 用于 X 内容的 Grok API 使用量 (tokens + tool calls) |

例如，处理一条典型的帖子或线程请求需要 **30 额度** (`1` 基础成本 + `29` Grok X Query) ，并会返回由 Grok 生成的结构化数据、线程上下文和摘要。如果同时启用了 JSON 格式 (LLM 提取) ，则每个请求的总成本为 **34 额度**。

这种方式通过 xAI 的合作遵循 X 公开发布的接口，提供质量更高、具备推理能力的输出，而不是直接抓取原始页面内容。

<Note>
  **其能力与标准抓取不同。** Grok 返回的是经 AI 处理的结果，可能包括摘要、关键指标、线程上下文等。若要大规模获取原始结构化数据，请使用 [官方 X Enterprise API](https://developer.x.com/)。
</Note>
