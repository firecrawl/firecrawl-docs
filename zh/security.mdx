本页解答安全或采购团队在批准使用 Firecrawl 前通常会关注的问题。如需进一步了解，请通过[企业版页面](https://www.firecrawl.dev/enterprise)联系我们的团队。

## 合规与报告 {#compliance-and-reports}

* **SOC 2 Type II**：我们的 SOC 2 Type II 审计正在进行中。
* **Trust Center**：[Firecrawl Trust Center](https://trust.firecrawl.dev) 列出了我们的合规状态和控制措施。你可以在此申请获取最新的渗透测试报告，以及我们的访问控制、数据管理、信息安全 (AUP) 和第三方管理政策。
* **持续监控**：Trust Center 持续监控多项控制措施，涵盖数据加密、渗透测试、业务连续性与灾难恢复计划、数据保留流程，以及账户关闭后的客户数据删除。

## 数据处理与零数据保留 {#data-handling-and-zero-data-retention}

零数据保留 (ZDR) 是指 Firecrawl 在请求或会话的生命周期结束后，不会持久化页面内容或提取的数据。该功能仅适用于企业版套餐，且需要为你的团队启用。

| 产品                                               | 启用方式                                         | 不保留的内容                                     | 说明                         |
| ------------------------------------------------ | -------------------------------------------- | ------------------------------------------ | -------------------------- |
| [抓取](/zh/features/scrape#zero-data-retention-zdr)   | `zeroDataRetention: true`                    | 页面内容和提取的数据                                 | ZDR 模式下不支持截图。每页额外消耗 1 个额度。 |
| [交互](/zh/features/interact#zero-data-retention-zdr) | 在首次 interact 调用中设置 `zeroDataRetention: true` | 页面内容和执行输出                                  | ZDR 模式下不支持会话录制和持久化配置文件。    |
| [搜索 (端到端 ZDR) ](/zh/features/search#end-to-end-zdr) | `enterprise: ["zdr"]`                        | 查询和结果数据 (Firecrawl 及我们的上游搜索提供商均不保留)        | 每 10 条结果消耗 10 个额度。         |
| [搜索 (匿名化 ZDR) ](/zh/features/search#anonymized-zdr) | `enterprise: ["anon"]`                       | 查询和结果数据 (Firecrawl 不保留；搜索提供商可能会缓存匿名化后的查询)  | 每 10 条结果消耗 2 个额度。          |

此外，[PII 脱敏](/zh/features/scrape#pii-redaction)可在抓取和解析输出返回给你之前，移除其中的个人身份信息。

## 合同、DPA 与子处理方 {#contracts-dpa-and-subprocessors}

* **DPA 与定制合同**：企业版客户可签署数据处理协议 (Data Processing Agreement，DPA) 及定制主服务协议 (MSA) ，我们也支持供应商安全审查与安全问卷。
* **子处理方**：当前列表已发布在 [Trust Center](https://trust.firecrawl.dev/subprocessors)。在该页面订阅后，如有新的子处理方将处理客户个人数据，您会提前收到通知。
* **隐私**：请参见[隐私政策](https://www.firecrawl.dev/privacy-policy)。

## 身份与访问控制 {#identity-and-access-control}

* **[SSO 和 SCIM](/zh/features/sso)**：支持 SAML 和 OIDC 单点登录 (Okta、Entra ID、Google Workspace 等) 以及 SCIM 目录同步，让访问权限始终与你的身份提供商保持同步。
* **静态 IP 允许列表**：通过专用 IP 地址路由流量，你可以将这些地址加入自有系统的允许列表。
* **[IP 限制](/zh/features/ip-restrictions)**：限定团队的 API 密钥只能从允许列表中的 IP 地址或 CIDR 范围调用。
* **[密钥限制](/zh/features/key-restrictions)**：将单个 API 密钥限定于特定的输出格式和端点，并在服务器端强制执行。
* **支出限额**：按 API 密钥或团队设置支出上限。

## 监控与威胁控制 {#monitoring-and-threat-controls}

* **[威胁防护](/zh/features/threat-protection)**：使用由您的组织控制且可锁定的策略，封禁 Firecrawl 对高风险 URL 的抓取。
* **[SIEM 审计日志记录](/zh/features/siem)**：将每次抓取的结构化审计事件实时推送到您的 SIEM，首先支持 Microsoft Sentinel。

## 数据驻留 {#data-residency}

Firecrawl 的所有数据均在美国处理，不提供欧盟数据驻留选项。启用零数据保留后，您抓取或搜索的内容在请求完成后不会被存储。

## 面向 AI 智能体和 MCP 用户 {#for-ai-agent-and-mcp-users}

无论通过 AI 智能体、[MCP 服务器](/zh/mcp-server)、CLI 还是 SDK 调用 Firecrawl，上述控制措施都同样适用。IP 和密钥限制、威胁防护以及 SIEM 审计日志记录均在服务器端针对你的组织强制执行，因此，仅限访问特定端点或格式的密钥，无论由哪个客户端使用，都始终受到相同限制。零数据保留适用于所有启用该功能的请求。

  <Accordion title="Firecrawl 能否通过企业安全审查？">
    可以。Firecrawl 为抓取和交互提供零数据保留，并为搜索提供两种 ZDR 模式；我们可签署 DPA，支持 SAML 或 OIDC SSO 及 SCIM，SOC 2 Type II 审计也正在进行中。借助 IP 和密钥限制、威胁防护以及 SIEM 审计日志记录等服务器端控制措施，您的安全团队可以制定并审计相关策略。
  </Accordion>

  <Accordion title="Firecrawl 是否符合 SOC 2 标准？">
    我们的 SOC 2 Type II 审计正在进行中。[Trust Center](https://trust.firecrawl.dev) 列出了我们当前的控制措施和策略。
  </Accordion>

  <Accordion title="Firecrawl 是否为搜索提供零数据保留？">
    是的。启用端到端搜索 ZDR (`enterprise: ["zdr"]`) 后，Firecrawl 和我们的上游搜索提供商都会执行零数据保留，整个流水线的任何环节都不会存储查询或结果数据。请参见 [搜索 ZDR](/zh/features/search#end-to-end-zdr)。
  </Accordion>

  <Accordion title="Firecrawl 会签署 DPA 吗？">
    会。企业版客户可以签署数据处理协议 (DPA) 和定制 MSA。数据处理在美国进行。请联系 [help@firecrawl.dev](mailto:help@firecrawl.dev)。
  </Accordion>

  <Accordion title="数据在哪里处理？">
    在美国。Firecrawl 提供美国数据驻留，不提供欧盟数据驻留。
