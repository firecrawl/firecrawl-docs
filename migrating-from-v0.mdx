<Warning>
  The v0 API is deprecated and will be shut down. After the shutdown, requests to `/v0` endpoints fail with HTTP `410 Gone`, so move to the v2 endpoints on this page now.
</Warning>

v0 is the first version of the Firecrawl API. This page maps every v0 endpoint, option, and response field to v2, and shows how to upgrade each SDK release that called v0.

<Note>
  The v0 request shapes on this page are here only so you can recognize and replace them. For new code, start from the [v2 documentation](/introduction).
</Note>

## Check whether you use v0

You are on v0 if any of these is true:

- Your code sends requests to `https://api.firecrawl.dev/v0/...`.
- You use one of the SDK releases in the table below.
- Your API responses carry a `Deprecation` header or a `warnings` array that mentions `/v0` (see [What callers see](#what-callers-see-before-and-after-the-shutdown)).

| SDK | Package | Releases that call v0 | First release without v0 | Upgrade to |
|-----|---------|-----------------------|--------------------------|------------|
| Python | `firecrawl-py` | `0.0.1` to `0.0.20`, plus `1.0.0` and `1.0.1` when created with `version="v0"` | `1.1.0` | latest `firecrawl-py` ([steps](#python)) |
| Python | `firecrawl` | `0.0.16` to `0.0.20` | `1.1.1` | latest `firecrawl` ([steps](#python)) |
| Node | `@mendable/firecrawl-js` | `0.0.1` to `0.0.36`, plus `1.0.0` to `1.0.4` when created with `version: "v0"` | `1.1.0` | latest `firecrawl` or `@mendable/firecrawl-js` ([steps](#node)) |
| Node | `firecrawl` | `0.0.28` to `0.0.30` | `1.1.0` | latest `firecrawl` ([steps](#node)) |
| Go | `github.com/mendableai/firecrawl-go` | `v0.0.1` | `v1.0.0` | `github.com/firecrawl/firecrawl/apps/go-sdk` ([steps](#go)) |
| Rust | `firecrawl` crate | `0.1.0` | `1.0.0` | `firecrawl` `2.x` ([steps](#rust)) |
| Rust | `firecrawl_rs` crate | `0.1.0` and `0.1.1` | none (continued as `firecrawl`) | `firecrawl` `2.x` ([steps](#rust)) |

The Java, Ruby, PHP, .NET, and Elixir SDKs, the CLI, and the MCP server were released after v0 and never called it.

Upgrading only to the "first release without v0" is not enough, because those releases target v1. Upgrade to the current release of each SDK, which targets v2.

## Why v2

- **Maintained SDKs.** The v0 SDK releases get no fixes. Current SDKs exist for [Python](/sdks/python), [Node](/sdks/node), [Go](/sdks/go), [Rust](/sdks/rust), [Java](/sdks/java), [Ruby](/sdks/ruby), [PHP](/sdks/php), [.NET](/sdks/dotnet), and [Elixir](/sdks/elixir).
- **One `formats` array.** Ask for `markdown`, `html`, `rawHtml`, `links`, `screenshot`, `json`, `summary`, `images`, and more in one request instead of a set of `include*` flags.
- **Structured extraction with a schema, a prompt, or both.** v0 required a schema. The v2 [`json` format](/features/llm-extract) also accepts a prompt on its own.
- **Cached results when you want them.** v2 can return a recent cached copy of a page instead of fetching it again (at most 2 days old by default). Set `maxAge: 0` to always fetch fresh. See [Faster scraping](/features/fast-scraping).
- **Crawl results while the crawl runs.** `GET /v2/crawl/{id}` returns the pages scraped so far on every poll, in pages of up to 10 MB linked by `next`, and crawls can send [webhooks](/webhooks/overview) as pages finish.
- **Endpoints v0 never had.** [Map](/features/map) lists a site's URLs without scraping them, [batch scrape](/features/batch-scrape) runs many URLs as one job, and [search](/features/search) covers web, news, and image results, with optional scraping of each result.

## Endpoint map

| v0 | v2 | What changes |
|----|----|--------------|
| `POST /v0/scrape` | [`POST /v2/scrape`](/api-reference/endpoint/scrape) | Options move to the top level, and output is chosen with `formats`. |
| `POST /v0/crawl` | [`POST /v2/crawl`](/api-reference/endpoint/crawl-post) | Crawler options move to the top level, `pageOptions` becomes `scrapeOptions`, and the response returns `id` instead of `jobId`. |
| `GET /v0/crawl/status/{jobId}` | [`GET /v2/crawl/{id}`](/api-reference/endpoint/crawl-get) | New status values and counters, and results are paginated with `next`. |
| `DELETE /v0/crawl/cancel/{jobId}` | [`DELETE /v2/crawl/{id}`](/api-reference/endpoint/crawl-delete) | Same `{"status": "cancelled"}` response. |
| `POST /v0/search` | [`POST /v2/search`](/api-reference/endpoint/search) | Results move under `data.web`, and scraping each result is opt-in. |
| `GET /v0/keyAuth` | none | Call [`GET /v2/team/credit-usage`](/api-reference/endpoint/credit-usage) to check a key. See [Key check](#key-check). |

Authentication does not change: send `Authorization: Bearer fc-YOUR-API-KEY`. The `x-idempotency-key` header works on `POST /v2/crawl` the same way it did on `POST /v0/crawl`.

## Scrape

### Request

<CodeGroup>

```bash Before (v0)
curl -X POST https://api.firecrawl.dev/v0/scrape \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://firecrawl.dev",
    "pageOptions": {
      "onlyMainContent": true,
      "includeHtml": true,
      "screenshot": true,
      "waitFor": 1000
    },
    "timeout": 30000
  }'
```

```bash After (v2)
curl -X POST https://api.firecrawl.dev/v2/scrape \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://firecrawl.dev",
    "formats": ["markdown", "html", "links", "screenshot"],
    "onlyMainContent": true,
    "waitFor": 1000,
    "timeout": 30000
  }'
```

</CodeGroup>

v0 always returned the page's links, so the v2 request asks for `links` to keep the same output.

### `pageOptions` and top-level fields

| v0 field | v2 equivalent | Notes |
|----------|---------------|-------|
| `pageOptions.includeMarkdown` | `"markdown"` in `formats` | `formats` defaults to `["markdown"]`. |
| `pageOptions.includeHtml` | `"html"` in `formats` | |
| `pageOptions.includeRawHtml` | `"rawHtml"` in `formats` | |
| `pageOptions.includeLinks` | `"links"` in `formats` | v0 always returned `linksOnPage`. v2 returns links only when you ask for them. |
| `pageOptions.screenshot` | `"screenshot"` in `formats` | |
| `pageOptions.fullPageScreenshot` | `{ "type": "screenshot", "fullPage": true }` in `formats` | |
| `pageOptions.includeExtract` | not needed | Add a `json` format. Its result is in `data.json`. |
| `pageOptions.onlyMainContent` | `onlyMainContent` | The default changed from `false` to `true`. Set `false` to keep the v0 output. |
| `pageOptions.onlyIncludeTags` | `includeTags` | Must be an array. |
| `pageOptions.removeTags` | `excludeTags` | Must be an array. |
| `pageOptions.waitFor` | `waitFor` | At most 60000 ms, and at most half of `timeout`. |
| `pageOptions.headers` | `headers` | |
| `pageOptions.parsePDF` | `parsers` | PDF parsing is on by default. To turn it off as `parsePDF: false` did, send `"parsers": []`. |
| `pageOptions.actions` | `actions` | |
| `pageOptions.geolocation.country` | `location.country` | v2 also accepts `location.languages`. |
| `pageOptions.mobile` | `mobile` | |
| `pageOptions.skipTlsVerification` | `skipTlsVerification` | |
| `pageOptions.removeBase64Images` | `removeBase64Images` | Defaults to `true`. |
| `pageOptions.useFastMode` | `fastMode` | |
| `pageOptions.replaceAllPathsWithAbsolutePaths` | none | URLs in the `links` format are already absolute. Remove the option. |
| `pageOptions.disableJsDom`, `pageOptions.atsv`, `pageOptions.fallback` | none | Remove them. |
| `pageOptions.fetchPageContent` | see [Search](#search) | Only `/v0/search` used it. |
| `timeout` | `timeout` | Milliseconds, from 1000 to 300000. The default is 60000 in both versions. |

### `extractorOptions` (LLM extraction)

LLM extraction moves to the `json` format on `/v2/scrape`. Put the schema and prompt on a format object instead of in `extractorOptions`.

| v0 field | v2 equivalent | Notes |
|----------|---------------|-------|
| `extractorOptions.mode: "markdown"` | default | Nothing to send. |
| `extractorOptions.mode` set to `"llm-extraction"`, `"llm-extraction-from-markdown"`, or `"llm-extraction-from-raw-html"` | `{ "type": "json" }` in `formats` | All three modes map to the same format. v2 has no option to pick the extraction input. |
| `extractorOptions.extractionSchema` | `schema` on the `json` format | Optional in v2. |
| `extractorOptions.extractionPrompt` | `prompt` on the `json` format | v2 has no separate system prompt. If you set both `extractionPrompt` and `userPrompt`, merge them into one `prompt`. |
| `extractorOptions.userPrompt` | `prompt` on the `json` format | |

In LLM extraction modes, v0 also forced `onlyMainContent: true` and, unless you set `timeout`, a 90-second timeout. Set `onlyMainContent` and `timeout` yourself if you relied on them.

<CodeGroup>

```bash Before (v0)
curl -X POST https://api.firecrawl.dev/v0/scrape \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://firecrawl.dev",
    "extractorOptions": {
      "mode": "llm-extraction",
      "extractionPrompt": "Extract the company mission and whether it supports SSO.",
      "extractionSchema": {
        "type": "object",
        "properties": {
          "company_mission": { "type": "string" },
          "supports_sso": { "type": "boolean" }
        },
        "required": ["company_mission", "supports_sso"]
      }
    }
  }'
```

```bash After (v2)
curl -X POST https://api.firecrawl.dev/v2/scrape \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://firecrawl.dev",
    "formats": [
      "markdown",
      {
        "type": "json",
        "prompt": "Extract the company mission and whether it supports SSO.",
        "schema": {
          "type": "object",
          "properties": {
            "company_mission": { "type": "string" },
            "supports_sso": { "type": "boolean" }
          },
          "required": ["company_mission", "supports_sso"]
        }
      }
    ],
    "onlyMainContent": true,
    "timeout": 90000
  }'
```

</CodeGroup>

The extracted object moves from `data.llm_extraction` to `data.json`. See [JSON mode](/features/llm-extract) for prompt-only extraction and more examples.

| `data.warning` | `data.warning` | |

## Crawl

### Request

<CodeGroup>

```bash Before (v0)
curl -X POST https://api.firecrawl.dev/v0/crawl \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://docs.firecrawl.dev",
    "crawlerOptions": {
      "includes": ["/features/.*"],
      "excludes": ["/features/legacy/.*"],
      "limit": 50,
      "ignoreSitemap": true,
      "allowBackwardCrawling": false
    },
    "pageOptions": { "onlyMainContent": true }
  }'
```

```bash After (v2)
curl -X POST https://api.firecrawl.dev/v2/crawl \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "url": "https://docs.firecrawl.dev",
    "includePaths": ["/features/.*"],
    "excludePaths": ["/features/legacy/.*"],
    "limit": 50,
    "sitemap": "skip",
    "crawlEntireDomain": false,
    "scrapeOptions": { "formats": ["markdown"], "onlyMainContent": true }
  }'
```

</CodeGroup>

The response changes from `{ "jobId": "..." }` to `{ "success": true, "id": "...", "url": "https://api.firecrawl.dev/v2/crawl/..." }`. Use `id` for the status and cancel calls.

### `crawlerOptions` and `pageOptions`

| v0 field | v2 equivalent | Notes |
|----------|---------------|-------|
| `crawlerOptions.includes` | `includePaths` | Regex patterns. |
| `crawlerOptions.excludes` | `excludePaths` | Regex patterns. |
| `crawlerOptions.limit`, `crawlerOptions.maxCrawledLinks` | `limit` | Defaults to 10000. |
| `crawlerOptions.maxDepth` | none | The closest option is `maxDiscoveryDepth`, which counts link hops from the start URL. To bound URL path depth, use `includePaths` and `excludePaths`. |
| `crawlerOptions.maxDiscoveryDepth` | `maxDiscoveryDepth` | |
| `crawlerOptions.allowBackwardCrawling` | `crawlEntireDomain` | |
| `crawlerOptions.allowExternalContentLinks` | `allowExternalLinks` | |
| `crawlerOptions.allowSubdomains` | `allowSubdomains` | |
| `crawlerOptions.ignoreSitemap` | `sitemap` | `true` becomes `"skip"`. `false` becomes `"include"`, the default. |
| `crawlerOptions.sitemapOnly` | `sitemap: "only"` | |
| `crawlerOptions.ignoreRobotsTxt` | `ignoreRobotsTxt` | |
| `crawlerOptions.regexOnFullURL` | `regexOnFullURL` | |
| `crawlerOptions.deduplicateSimilarURLs` | `deduplicateSimilarURLs` | |
| `crawlerOptions.ignoreQueryParameters` | `ignoreQueryParameters` | |
| `crawlerOptions.delay` | `delay` | Seconds between scrapes. |
| `crawlerOptions.returnOnlyUrls` | [`POST /v2/map`](/features/map) | Map returns a site's URLs without scraping them. |
| `crawlerOptions.mode` (`"default"` or `"fast"`) | none | Remove the option. |
| `crawlerOptions.generateImgAltText` | none | Remove the option. |
| `pageOptions` | `scrapeOptions` | Same mapping as for [scrape](#pageoptions-and-top-level-fields). `scrapeOptions.formats` defaults to `["markdown"]`. |

### Crawl status

<CodeGroup>

```bash Before (v0)
curl https://api.firecrawl.dev/v0/crawl/status/YOUR_JOB_ID \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

```bash After (v2)
curl https://api.firecrawl.dev/v2/crawl/YOUR_CRAWL_ID \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

</CodeGroup>

<CodeGroup>

```json Before (v0)
{
  "status": "active",
  "current": 12,
  "total": 40,
  "data": null,
  "partial_data": [
    {
      "content": "# Scrape\n...",
      "markdown": "# Scrape\n...",
      "linksOnPage": ["https://docs.firecrawl.dev/features/crawl"],
      "metadata": {
        "sourceURL": "https://docs.firecrawl.dev/features/scrape",
        "pageStatusCode": 200
      }
    }
  ]
}
```

```json After (v2)
{
  "success": true,
  "status": "scraping",
  "completed": 12,
  "total": 40,
  "creditsUsed": 12,
  "expiresAt": "2026-01-01T00:00:00.000Z",
  "next": "https://api.firecrawl.dev/v2/crawl/YOUR_CRAWL_ID?skip=12",
  "data": [
    {
      "markdown": "# Scrape\n...",
      "metadata": {
        "sourceURL": "https://docs.firecrawl.dev/features/scrape",
        "statusCode": 200
      }
    }
  ]
}
```

</CodeGroup>

| v0 | v2 | Notes |
|----|----|-------|
| `status`: `active`, `completed`, or `failed` | `status`: `scraping`, `completed`, `failed`, or `cancelled` | v0 reported a cancelled crawl as `failed`. |
| `current` | `completed` | Pages scraped so far. |
| `total` | `total` | |
| `data`, `null` until the crawl completes | `data` | Holds the pages scraped so far on every poll. |
| `partial_data` | `data` | |
| none | `creditsUsed`, `expiresAt`, `next` | |

Each page in `data` uses the v2 [scrape response](#response) shape.

To read a crawl to the end over HTTP:

1. Poll `GET /v2/crawl/{id}` until `status` is `completed`, `failed`, or `cancelled`.
2. While the response has a `next` URL, request it with the same `Authorization` header. Each response holds up to 10 MB of results.
3. Stop when `next` is missing or a page returns no documents.

The SDK `crawl` methods do all of this for you. See [Paging through results](/features/crawl#paging-through-results) for details.

### Cancel a crawl

<CodeGroup>

```bash Before (v0)
curl -X DELETE https://api.firecrawl.dev/v0/crawl/cancel/YOUR_JOB_ID \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

```bash After (v2)
curl -X DELETE https://api.firecrawl.dev/v2/crawl/YOUR_CRAWL_ID \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

</CodeGroup>

Both return `{"status": "cancelled"}`, and both answer `409` if the crawl has already completed.

## Search

<CodeGroup>

```bash Before (v0)
curl -X POST https://api.firecrawl.dev/v0/search \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "query": "firecrawl web scraping",
    "pageOptions": { "fetchPageContent": true, "onlyMainContent": true },
    "searchOptions": { "limit": 5 }
  }'
```

```bash After (v2)
curl -X POST https://api.firecrawl.dev/v2/search \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -d '{
    "query": "firecrawl web scraping",
    "limit": 5,
    "scrapeOptions": { "formats": ["markdown"], "onlyMainContent": true }
  }'
```

</CodeGroup>

| v0 field | v2 equivalent | Notes |
|----------|---------------|-------|
| `query` | `query` | |
| `searchOptions.limit` | `limit` | v0 returned at most 10 results. v2 defaults to 10 and accepts up to 100. |
| `searchOptions.tbs` | `tbs` | |
| `searchOptions.filter` | `filter` | |
| `searchOptions.lang` | `lang` | |
| `searchOptions.country` | `country` | |
| `searchOptions.location` | `location` | |
| `pageOptions.fetchPageContent: true`, the v0 default | `scrapeOptions` with `formats` | v2 scrapes results only when you send `scrapeOptions`, for example `{ "formats": ["markdown"] }`. |
| `pageOptions.fetchPageContent: false` | no `scrapeOptions` | Results carry `url`, `title`, and `description`. |
| `pageOptions.onlyMainContent` | `scrapeOptions.onlyMainContent` | |
| `pageOptions.includeHtml`, `pageOptions.includeRawHtml` | `"html"`, `"rawHtml"` in `scrapeOptions.formats` | |
| `pageOptions.removeTags` | `scrapeOptions.excludeTags` | |

The v0 response was `{ "success": true, "data": [ ... ] }`, a flat array of documents. In v2, results are grouped by source: `{ "success": true, "data": { "web": [ ... ] } }`. Each web result has `url`, `title`, and `description`, plus `markdown`, `metadata`, and the other requested formats when you send `scrapeOptions`. Use `sources` to add news or image results; see [Search](/features/search).

## Key check

`GET /v0/keyAuth` returned `{"success": true}` for a valid key. It goes away with the rest of v0 and has no v2 counterpart. To check a key, call `GET /v2/team/credit-usage`: it returns `200` for a valid key and `401` for an invalid one.

```bash
curl https://api.firecrawl.dev/v2/team/credit-usage \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

## v0 options with no v2 equivalent

| v0 option | What to do instead |
|-----------|--------------------|
| `crawlerOptions.maxDepth` | Use `maxDiscoveryDepth` (link hops from the start URL), or bound URL depth with `includePaths` and `excludePaths`. |
| `crawlerOptions.returnOnlyUrls` | Call [`POST /v2/map`](/features/map) to list URLs, then scrape or crawl the ones you need. |
| `crawlerOptions.mode` | Remove it. |
| `crawlerOptions.generateImgAltText` | Remove it. |
| The extraction input choice in `extractorOptions.mode` (`llm-extraction-from-raw-html` or `llm-extraction-from-markdown`) | Use the `json` format. v2 picks the extraction input. |
| A separate system prompt (`extractionPrompt` next to `userPrompt`) | Merge both into the `json` format's `prompt`. |
| `pageOptions.replaceAllPathsWithAbsolutePaths` | Remove it. URLs in the `links` format are already absolute. |
| `pageOptions.disableJsDom`, `pageOptions.atsv`, `pageOptions.fallback` | Remove them. |
| `GET /v0/keyAuth` | Call `GET /v2/team/credit-usage`. |

## SDK upgrade guides

Each guide shows how to recognize a v0 release, how to install the current one, and before and after code for scrape, crawl with status polling, and search.

### Python

**How to tell you are on v0**

- `pip show firecrawl-py` (or `pip show firecrawl`) prints a `0.0.x` version, or `1.0.0` or `1.0.1` and your code passes `version="v0"` to `FirecrawlApp`.
- Your code calls the `FirecrawlApp` methods `scrape_url(url, params)`, `crawl_url(url, params, wait_until_done, poll_interval, idempotency_key)`, `check_crawl_status(job_id)`, or `search(query, params)`, and passes `pageOptions`, `extractorOptions`, `crawlerOptions`, or `searchOptions` dictionaries.
- Results are plain dictionaries with keys such as `content`, `llm_extraction`, `jobId`, `current`, and `partial_data`.

**Upgrade**

```bash
pip install --upgrade firecrawl-py
```

The same SDK is also published as `firecrawl`. If that is the name you installed, run `pip install --upgrade firecrawl` instead. Then:

- Use the `Firecrawl` class. `FirecrawlApp` still imports as an alias of it, but `scrape_url`, `crawl_url`, and `check_crawl_status` no longer exist, and there is no `version` argument.
- Pass options as keyword arguments instead of a `params` dictionary.
- Read results as attributes in snake_case: `doc.markdown`, `doc.json`, `doc.metadata.source_url`.

**Scrape with LLM extraction**

<CodeGroup>

```python Before (v0)
from firecrawl import FirecrawlApp

app = FirecrawlApp(api_key="fc-YOUR-API-KEY")

schema = {
    "type": "object",
    "properties": {"company_mission": {"type": "string"}},
    "required": ["company_mission"],
}

data = app.scrape_url("https://firecrawl.dev", {
    "pageOptions": {"onlyMainContent": True, "includeHtml": True},
    "extractorOptions": {
        "mode": "llm-extraction",
        "extractionPrompt": "Extract the company mission.",
        "extractionSchema": schema,
    },
})
print(data["markdown"])
print(data["llm_extraction"])
```

```python After (v2)
from firecrawl import Firecrawl

firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")

schema = {
    "type": "object",
    "properties": {"company_mission": {"type": "string"}},
    "required": ["company_mission"],
}

doc = firecrawl.scrape(
    "https://firecrawl.dev",
    formats=[
        "markdown",
        "html",
        {"type": "json", "prompt": "Extract the company mission.", "schema": schema},
    ],
    only_main_content=True,
)
print(doc.markdown)
print(doc.json)
```

</CodeGroup>

**Crawl and poll for status**

<CodeGroup>

```python Before (v0)
import time
from firecrawl import FirecrawlApp

app = FirecrawlApp(api_key="fc-YOUR-API-KEY")

job = app.crawl_url(
    "https://docs.firecrawl.dev",
    params={
```

### Node

**How to tell you are on v0**

- `npm ls @mendable/firecrawl-js firecrawl` shows a `0.0.x` version, or `1.0.0` to `1.0.4` and your code passes `version: "v0"` to `new FirecrawlApp(...)`.
- Your code calls `scrapeUrl(url, params)`, `crawlUrl(url, params, waitUntilDone, pollInterval, idempotencyKey)`, `checkCrawlStatus(jobId)`, or `search(query, params)`, and passes `pageOptions`, `extractorOptions`, `crawlerOptions`, or `searchOptions` objects.
- Results have fields such as `data.llm_extraction`, `jobId`, `current`, and `partial_data`.

**Upgrade**

```bash
npm install firecrawl@latest
```

`firecrawl` and `@mendable/firecrawl-js` publish the same SDK at the same version. To keep your existing package name, run `npm install @mendable/firecrawl-js@latest` and keep importing from it. Then:

- The default export is now the v2 `Firecrawl` client. Code that imports it as `FirecrawlApp` still constructs it, but `scrapeUrl`, `crawlUrl`, and `checkCrawlStatus` are gone. Use `scrape`, `crawl`, `startCrawl`, `getCrawlStatus`, and `search`.
- Do not switch to the `.v1` namespace. Use the top-level v2 methods.
- `scrape` returns the document itself, not `{ success, data }`.

### LangChain and LlamaIndex loaders

Framework loaders call a Firecrawl SDK under the hood, so a project that pinned an old loader or SDK release may still call v0. Upgrade both the loader package and the SDK it uses.

- **LangChain (Python):** move from `FireCrawlLoader` in `langchain_community` to `FirecrawlLoader` in the official [`langchain-firecrawl`](/integrations/langchain) package, and upgrade `firecrawl-py`.
- **LangChain (JS):** the `FireCrawlLoader` in `@langchain/community` does not work with the current Firecrawl SDK. Call the [Node SDK](/sdks/node) directly and wrap the results in LangChain documents, as shown in [LangChain JS](/integrations/langchain#langchain-js).
- **LlamaIndex (Python):** upgrade `llama-index-readers-web` and `firecrawl-py` together, for example with `pip install --upgrade llama-index-readers-web 'firecrawl-py>=4.3.3'`. See [LlamaIndex](/integrations/llamaindex).

## What callers see before and after the shutdown

### Until the shutdown

Every response from `POST /v0/scrape`, `POST /v0/crawl`, `GET /v0/crawl/status/{jobId}`, `DELETE /v0/crawl/cancel/{jobId}`, and `POST /v0/search` already carries deprecation notices. For example, on `/v0/scrape`:

```text
Deprecation: @<unix-timestamp>
Link: </v2/scrape>; rel="successor-version"
Warning: 299 - "/v0/scrape is deprecated. Use /v2/scrape instead."
```

JSON responses also get a `warnings` array and a `replacement` field:

```json
{
  "success": true,
  "data": { "markdown": "..." },
  "warnings": ["/v0/scrape is deprecated. Use /v2/scrape instead."],
  "replacement": "/v2/scrape"
}
```

Log these headers or fields to find the code paths that still call v0. Once the shutdown date is set, responses also carry a `Sunset` header with that date.

### After the shutdown

Requests to these endpoints fail with HTTP `410 Gone` and a body that names the replacement:

```json
{
  "success": false,
  "code": "ENDPOINT_REMOVED",
  "error": "/v0/scrape is deprecated. Use /v2/scrape instead.",
  "detail": "/v0/scrape is deprecated. Use /v2/scrape instead.",
  "replacement": "/v2/scrape"
}
```

| Removed endpoint | `replacement` |
|------------------|---------------|
| `POST /v0/scrape` | `/v2/scrape` |
| `POST /v0/crawl` | `/v2/crawl` |
| `GET /v0/crawl/status/{jobId}` | `/v2/crawl/:jobId` (use `GET`) |
| `DELETE /v0/crawl/cancel/{jobId}` | `/v2/crawl/:jobId` (use `DELETE`) |
| `POST /v0/search` | `/v2/search` |

If you handle this error in code, check the status code and `code` rather than the message text, which can change. Old SDK releases raise a generic error that includes status code `410`.
