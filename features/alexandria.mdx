Alexandria gives agents access to structured data through Firecrawl. Discover a tool, inspect its inputs, then run it. Discovery is free; execution uses the credits listed on the tool.

[Browse providers](https://www.firecrawl.dev/app/alexandria) · [Manage provider terms](https://www.firecrawl.dev/app/settings?tab=data-sources)

## Built for agents

Install the [CLI](/sdks/cli) or connect the [MCP server](/mcp-server).

<Tabs>
  <Tab title="Firecrawl CLI">
```bash
# Find tools alongside web results.
firecrawl search "podcast conversations about AI agents" --sources web,alexandria --domain-tools --limit 2

# Inspect inputs and pricing.
firecrawl find-tools --providers particle --level tools --expand options,response

# Run the tool.
firecrawl scrape particle/podcasts/episodes/search --options '{"keyword_search":"AI agents","limit":2}'
```
    Install with `npm install -g firecrawl-cli` and sign in with `firecrawl login`.
  </Tab>
  <Tab title="MCP">
    Ask your agent: "Find Particle's podcast tools, inspect episode-search inputs and pricing, then find conversations about AI agents."

    The agent uses `firecrawl_search` to discover tools, `firecrawl_find_tools` to inspect them, and `firecrawl_scrape` to execute them.
  </Tab>
</Tabs>

## Use it from the SDKs and API

<Steps>
  <Step title="Find the right tool">
    Describe what you need. Alexandria returns relevant tools alongside your web results.

<CodeGroup>
```javascript JavaScript
const result = await firecrawl.search(
  "podcast conversations about AI agents",
  {
    sources: ["web", "alexandria"],
    limit: 2,
  },
);
```

```python Python
result = firecrawl.search(
    "podcast conversations about AI agents",
    sources=["web", "alexandria"],
    limit=2,
)
```

```bash cURL
curl https://api.firecrawl.dev/v2/search \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
  "query": "podcast conversations about AI agents",
  "sources": [
    "web",
    "alexandria"
  ],
  "limit": 2
}'
```
</CodeGroup>

    Results contain `web` pages and ranked `tools`. Each tool includes its provider, capability, inputs, response contract, and price.
  </Step>

  <Step title="Check what it needs">
    Read the selected tool's `options`, `response`, and execution price before calling it. Use [Find Tools](#find-tools) for more detail.
  </Step>

  <Step title="Get the data">
    Use `scrape` to call the tool with the inputs from its contract. Supply the provider and capability under `alexandria`; no page URL is needed.

<CodeGroup>
```javascript JavaScript
const episodes = await firecrawl.scrape({
  alexandria: {
    provider: "particle",
    capability: "podcasts/episodes/search",
    options: {
      semantic_search: "AI agents",
      limit: 2,
    },
  },
});

console.log(episodes.alexandria[0].data);
```

```python Python
episodes = firecrawl.scrape(
    alexandria={
        "provider": "particle",
        "capability": "podcasts/episodes/search",
        "options": {
            "semantic_search": "AI agents",
            "limit": 2,
        },
    },
)

print(episodes.alexandria[0].data)
```

```bash cURL
REQUEST_ID="$(uuidgen)"

curl https://api.firecrawl.dev/v2/scrape \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-request-id: $REQUEST_ID" \
  -d '{
  "alexandria": {
    "provider": "particle",
    "capability": "podcasts/episodes/search",
    "options": {
      "semantic_search": "AI agents",
      "limit": 2
    }
  }
}'
```
</CodeGroup>

    Read the result from `episodes.alexandria[0].data`. Check each tool result for errors before using its data. Raw HTTP responses wrap the SDK result in `data`.
  </Step>
</Steps>

## Find Tools

Use `findTools` / `find_tools` to browse providers and inspect their tools for free. Follow an item's `next` request for more detail; the top-level `next` paginates the catalogue.

<CodeGroup>
```javascript JavaScript
const catalogue = await firecrawl.findTools({
  providers: ["particle"],
  limit: 2,
});

// Each next request reveals another part of the catalogue.
const next = catalogue.items[0]?.next;
if (next) {
  const details = await firecrawl.scrape({ alexandria: next });
  console.log(details.alexandria[0].data);
}
```

```python Python
catalogue = firecrawl.find_tools(providers=["particle"], limit=2)

if catalogue.items and catalogue.items[0].get("next"):
    details = firecrawl.scrape(alexandria=catalogue.items[0]["next"])
    print(details.alexandria[0].data)
```
</CodeGroup>

## Use it from Agent

[Agent](/features/agent) runs can call your team's providers on their own while they research. Send `exchange: { "enabled": true }` with the request, and pin up to five providers with `toolkits` if you want. Without `exchange`, an API or SDK run uses the web only. See [Use your connected Alexandria tools](/features/agent#use-your-connected-alexandria-tools).

## Zero Data Retention (ZDR)

[Zero Data Retention](/security#data-handling-and-zero-data-retention) on an Alexandria call means Firecrawl returns the provider response to you on that request and does not keep it afterward. The activity log keeps billing metadata — whether the call succeeded, how long it took, and the credit cost — and drops the target, the call options, and any error text. This is the same `zeroDataRetention` field as [Scrape ZDR](/features/scrape#zero-data-retention-zdr). The cost and the providers that accept it are different.

A provider supports ZDR when its page in the [Alexandria app](https://www.firecrawl.dev/app/alexandria) shows a **ZDR supported** pill. Hovering the pill says ZDR costs +1 credit per request when enabled. That credit is on top of the tool's listed price. The response field `data.creditsCost` is the total for the request.

To enable ZDR, set `zeroDataRetention: true` on the scrape body, as a sibling of `alexandria`. The sample below uses this page's example tool so you can see where the field goes. Send it for a provider whose page shows the pill:

```bash cURL
curl -X POST https://api.firecrawl.dev/v2/scrape \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer fc-YOUR_API_KEY" \
  -d '{
    "alexandria": {
      "provider": "particle",
      "capability": "podcasts/episodes/search",
      "options": { "semantic_search": "AI agents", "limit": 2 }
    },
    "zeroDataRetention": true
  }'
```

`timeout`, `origin`, and `integration` may sit beside `alexandria` as well. `url`, `formats`, and other scrape options may not.

If your team has zero data retention forced on, every Alexandria call runs with ZDR, including a request that leaves `zeroDataRetention` out.

A capability that cannot honor ZDR fails the request with [`zero_data_retention_unsupported`](/api-reference/errors) (400). Check the provider page for the pill before you send the flag.

<Note>
The current JavaScript and Python SDKs do not send `zeroDataRetention` on an Alexandria scrape. JavaScript rejects any field other than `alexandria`, `requestId`, `timeout`, `integration`, and `origin`. Python forwards `timeout`, `integration`, and `request_id` only. Send the HTTP request above.
</Note>

### Retrying a ZDR call

Send an `x-request-id` header when you may retry. It is 1 to 128 characters of letters, digits, `.`, `_`, `:`, and `-`, and the response echoes it back. For a call that ran without ZDR, the same id and the same body replay the stored response and do not run the provider again.

Under ZDR the response is not stored. After the call completes, the same `x-request-id` returns [`response_not_retained`](/api-reference/errors) (409). Send a new `x-request-id` to run the call again. That is a new charge.

Reusing an `x-request-id` with a different body, including a different `zeroDataRetention` value, returns [`duplicate_request`](/api-reference/errors) (409).

Domain matching on a URL scrape (`domainTools: true`) stays unavailable with zero data retention and returns 403. See [Alexandria data tools](/features/scrape#alexandria-data-tools).

An [Agent](/features/agent#zero-data-retention-zdr) run with `zeroDataRetention` only calls Alexandria capabilities that support ZDR.

## Pricing and access

- **Tool discovery:** free. Use `sources: ["alexandria"]` for tools only, or `["web", "alexandria"]` to include paid web results.
- **Execution:** charged at the tool's listed price.
- **Zero data retention:** +1 credit per request, on top of the tool price, for providers that show **ZDR supported**. See [Zero Data Retention](#zero-data-retention-zdr).
- **Provider terms:** a `THIRD_PARTY_DATA_TERMS_REQUIRED` error includes `requiresAction.url`. An org admin must review and accept the terms there. Agents need explicit user authorization before accepting terms. [Agent](/features/agent#data-providers-that-need-terms) runs skip providers whose terms your team hasn't accepted and report them in `exchange.skippedProviders`.

## Feedback

Report issues or request capabilities with `firecrawl alexandria feedback`, or with the MCP `firecrawl_feedback` tool using `endpoint: "alexandria"`. Run `firecrawl alexandria feedback --help` for options.

Alexandria feedback must be sent within 20 minutes of your team's most recent Alexandria search, discovery, or execution. Each Alexandria call restarts the window; later feedback is rejected with `FEEDBACK_WINDOW_EXPIRED`.

Each feedback refunds 1 credit, for any rating. Refunds are capped per UTC day at 10 credits per website and 100 credits per team. Past either cap, feedback is still recorded without a refund; the response returns `websiteCapReached: true` when that website's cap is reached, and `dailyCapReached: true` when the team's cap is reached.
