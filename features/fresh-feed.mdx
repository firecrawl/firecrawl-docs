<Warning>
The Fresh Feed API is in private beta and is enabled per team. A request from a team without access to the requested feed or vertical gets a `403`. Parameters, fields, and limits may change during the beta.
</Warning>

The Fresh Feed API delivers web pages soon after their sources publish or update them. Each record carries the page's URL, its raw HTML, and what the page states about itself: title, description, author, language, and publish and update times. Records form one ordered log. You keep a cursor, ask for the records after it, and get each record once, in order.

The API supports multiple feeds and dedicated vertical endpoints under `/v2/fresh-vertical-feed`:

- **Local** (`/local/latest`): covers regional sources (such as Australia, Canada, Ireland, New Zealand, and the United Kingdom across `restaurants`, `food_venues`, `hotels_lodging`, `attractions`, `tours_events`, and `local_services`), or the feed configured for your team.
- **Curated** (`/curated/latest`): a curated multi-vertical feed, when enabled for your team.
- **Global** (`/global/latest`): the global index feed, when enabled for your team.
- **Dedicated vertical endpoints** (`/{vertical}/latest`): endpoints scoped to a single vertical (`newsroom-blogs`, `tech-support`, `gov-hqi`, plus underscore aliases `newsroom_blogs`, `tech_support`, `gov_hqi`), when multi-vertical or global access is enabled for your team.

## Endpoints

```http
GET https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest
GET https://api.firecrawl.dev/v2/fresh-vertical-feed/curated/latest
GET https://api.firecrawl.dev/v2/fresh-vertical-feed/global/latest
GET https://api.firecrawl.dev/v2/fresh-vertical-feed/{vertical}/latest
Authorization: Bearer fc-YOUR_API_KEY
```

| Endpoint | Scope | Access |
| --- | --- | --- |
| `/v2/fresh-vertical-feed/local/latest` | Local feed, or the feed configured for your team. | Enabled for teams with Fresh Feed access. |
| `/v2/fresh-vertical-feed/curated/latest` | Curated multi-vertical feed. | Enabled for teams with curated or global feed access (`403` otherwise). |
| `/v2/fresh-vertical-feed/global/latest` | Global index feed. | Enabled for teams with global feed access (`403` otherwise). |
| `/v2/fresh-vertical-feed/{vertical}/latest` | Scoped to one vertical: `newsroom-blogs`, `tech-support`, or `gov-hqi` (underscore aliases `newsroom_blogs`, `tech_support`, and `gov_hqi` are also accepted). | Enabled for teams with curated or global feed access (`403` otherwise; unknown verticals return `404`). |

Calling a dedicated vertical endpoint scopes results to that vertical's `subcategory`. Passing a conflicting or repeated `subcategory` query parameter returns `400`. If your team's access is scoped to specific verticals or filters, requesting a vertical outside your scope returns `403`, and sending a conflicting query filter returns `400`.

Only `GET` is supported; `HEAD` on a valid feed or vertical endpoint returns `405` with `Allow: GET`. The SDKs don't wrap these endpoints yet, so the examples on this page call them over HTTP.

## Try it

The five newest records from the local feed, without their HTML:

```bash
curl -s --compressed "https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest?limit=5&content=false" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

Records from UK restaurant sources written in the last six hours, oldest first:

```bash
curl -s --compressed "https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest?after=0&since=6h&country=GB&subcategory=restaurants" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

Records from a dedicated vertical endpoint written in the last 30 minutes, without HTML:

```bash
curl -s --compressed "https://api.firecrawl.dev/v2/fresh-vertical-feed/newsroom-blogs/latest?after=0&since=30m&limit=5&content=false" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

Records filtered to a domain and its subdomains on the curated feed:

```bash
curl -s --compressed "https://api.firecrawl.dev/v2/fresh-vertical-feed/curated/latest?after=0&since=1h&domain=example.com" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

## Stay in sync

Read any feed or vertical endpoint with the `after` cursor:

1. Send `after=0` with a `since` value, such as `since=15m`, `since=30m`, or `since=1h`, to start from that point instead of the beginning of the feed.
2. Save the records in the order they arrive, which is oldest first.
3. Send the response's `next_after` as `after` on your next request.
4. While `more` is `true`, request again right away to drain the backlog. When `more` is `false`, wait before the next poll — 1 minute for near-real-time consumers, or 15–60 minutes for scheduled batch polling.

Records are written in cursor order, so no record can appear behind a cursor you've already passed. Save the cursor only after you've saved the records it covers, and a retry with the same cursor is always safe. Cursor values aren't consecutive, so treat them as opaque numbers, and track cursors separately for each endpoint or filter combination you poll.

While your cursor is still `0`, keep sending `since`. An answer with no records leaves `next_after` at `0`, and `after=0` on its own starts from the beginning of the feed. To backfill the whole feed, do exactly that: start at `after=0` without `since`.

<CodeGroup>

```python Python
import os
import time

import requests

# Swap in /curated/latest, /global/latest, or /{vertical}/latest as needed
FEED_URL = "https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest"
HEADERS = {
    "Authorization": f"Bearer {os.environ['FIRECRAWL_API_KEY']}",
    "Accept-Encoding": "gzip",
}


def save(record):
    print(record["id"], record["url"])  # replace with your own storage


cursor = 0  # persist this between runs

while True:
    params = {"after": cursor}
    if cursor == 0:
        params["since"] = "1h"  # start an hour back, not at the beginning of the feed
    response = requests.get(FEED_URL, headers=HEADERS, params=params, timeout=60)
    if response.status_code in (429, 502, 503, 504):
        time.sleep(int(response.headers.get("Retry-After", "5")))
        continue
    response.raise_for_status()
    page = response.json()
    for record in page["events"]:
        save(record)
    cursor = page["next_after"]  # advance only after the records are saved
    if not page["more"]:
        time.sleep(60)  # or 900–3600 seconds for 15–60 minute batch polling
```

```js Node
// Swap in /curated/latest, /global/latest, or /{vertical}/latest as needed
const FEED_URL = "https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest";
const headers = {
  Authorization: `Bearer ${process.env.FIRECRAWL_API_KEY}`,
  "Accept-Encoding": "gzip",
};
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function save(record) {
  console.log(record.id, record.url); // replace with your own storage
}

let cursor = 0; // persist this between runs

while (true) {
  const params = new URLSearchParams({ after: String(cursor) });
  if (cursor === 0) params.set("since", "1h"); // start an hour back, not at the beginning of the feed
  const response = await fetch(`${FEED_URL}?${params}`, { headers });
  if ([429, 502, 503, 504].includes(response.status)) {
    await sleep(Number(response.headers.get("retry-after") ?? 5) * 1000);
    continue;
  }
  if (!response.ok) throw new Error(`${response.status}: ${await response.text()}`);
  const page = await response.json();
  for (const record of page.events) save(record);
  cursor = page.next_after; // advance only after the records are saved
  if (!page.more) await sleep(60_000); // or 900_000–3_600_000 ms for 15–60 minute batch polling
}
```

## Query parameters

Every parameter is optional. A request with an unknown parameter, a parameter sent twice, or a value that conflicts with the endpoint or your team's feed scope gets a `400` that names the problem.

| Parameter | Values | Description |
| --- | --- | --- |
| `after` | A cursor | Records written after this cursor, oldest first. Start with `0`, then send the `next_after` of the previous response. Can't be sent with `before`. |
| `before` | A cursor | Records written before this cursor, newest first. Send the `next_before` of the previous response to page back. Can't be sent with `after`. |
| `since` | An age or a time | Only records written since then: an age such as `15m`, `30m`, `1h`, `6h`, or `2d`, or an ISO 8601 time such as `2026-11-14T00:00:00Z`. A time without an offset is read as UTC. |
| `limit` | `1` to `500` | The most records in one response. Defaults to `50`. With `content=true`, the maximum is `50`; with `content=false`, up to `500`. |
| `content` | `true` or `false` | Defaults to `true`. With `false`, every record's `html` is `null`, responses are far smaller, and `limit` can go up to `500`. |
| `stream` | `default` or `full` | Defaults to `default`. `stream=full` returns every record in the feed. `stream=default` is the standard view; today it returns the same records as `full`. |
| `subcategory` | `1` to `50` comma-separated subcategories supported by the feed | Filter parameter only (not emitted on individual records). Returns only records from sources in any listed subcategory: on Local, `restaurants`, `food_venues`, `hotels_lodging`, `attractions`, `tours_events`, `local_services`; on Curated and Global, vertical subcategories such as `newsroom_blogs`, `tech_support`, `gov_hqi`. Conflicting values on `/{vertical}/latest` return `400`. |
| `country` | `1` to `50` comma-separated ISO 3166-1 alpha-2 country codes (or `ZZ`) supported by the feed | Only records from sources in any listed country (for example `AU`, `CA`, `GB`, `IE`, or `NZ` on Local; the United Kingdom is `GB`). On Curated and Global feeds, include `ZZ` to match global or multi-country sources alongside ISO alpha-2 codes such as `AU` or `GB`. |
| `region` | `1` to `50` comma-separated ISO 3166-2 subdivision codes for countries in the feed | Only records from any listed region, such as `NZ-AUK` or `GB-ENG`. |
| `domain` | `1` to `50` comma-separated domains or hostnames, such as `example.com` or `example.co.uk` | Only records whose `url` host matches any listed domain or any of its subdomains (for example, `domain=example.com` matches `example.com`, `www.example.com`, and `blog.example.com`). Pass the parent domain rather than `www.` when you want all subdomains included. |
| `host` | `1` to `50` comma-separated hosts, such as `www.example.com` | Only records whose `url` has an exact host match with any listed host. |
| `agents` | `1` to `4` comma-separated robots.txt user-agent names (product tokens), such as `ExampleBot,example-agent` | AND filter: keeps a record only when its site's robots.txt allows it for every named user-agent (leaves it out if disallowed for any of them). Each token is 1 to 64 characters of ASCII letters, `-`, and `_`. See below. |

Without `after` or `before`, a response starts at the newest record. `country`, `subcategory`, `region`, `domain`, and `host` each accept up to `50` comma-separated values (matching any listed value), and `agents` accepts `1` to `4` comma-separated user-agent names (requiring every named agent to be allowed); exceeding these limits returns `400`.

### Filter by robots.txt

With `agents`, the feed checks each record's URL against the most recently fetched robots.txt of its site using AND semantics — a record is kept only when every named user-agent token is allowed, and left out if any named token is disallowed:

- A robots.txt that returned HTTP `404` or `410` is treated as allowing all agents.
- A robots.txt that couldn't be read for another reason, such as a `401`, `403`, `429`, `5xx`, or a redirect, disallows all agents.
- A record whose site has no stored robots.txt is kept.

Records left out this way still move the cursor forward, so a response can hold fewer records than `limit`.

When an account has a configured default `agents` filter, requests can omit `agents` (the configured agent filter applies automatically) or pass a superset that includes the configured agent(s) alongside additional user-agent names (up to `4` total, checked with AND semantics). Passing a narrower `agents` list that omits a required agent returns `400`. When no default `agents` filter is configured, omitting `agents` leaves responses unchanged.

```bash
curl -s --compressed "https://api.firecrawl.dev/v2/fresh-vertical-feed/local/latest?after=0&since=1h&agents=ExampleBot,example-agent" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY"
```

## Response

An example response to a request with `after`, with the HTML shortened:

```json
{
  "feed": "local",
  "events": [
    {
      "id": "evt_3f9c2a7d1e8b4c6f0a2d5e71",
      "url": "https://www.example.com/whats-on/winter-night-market",
      "html": "<!DOCTYPE html><html lang=\"en-GB\">…</html>",
      "status_code": 200,
      "content_type": "text/html; charset=utf-8",
      "crawl_time": 1794615150,
      "updated_time": 1794614280,
      "published_time": 1794613200,
      "title": "Winter Night Market returns to the riverside",
      "description": "Street food, makers and live music every Friday in December.",
      "category": "local",
      "author": "Jane Smith",
      "country_code": "GB",
      "language_code": "en"
    }
  ],
  "next_after": 2187341,
  "more": false
}
```

| Field | Description |
| --- | --- |
| `feed` | The feed's name (for example, `local`, `curated`, or `global`). |
| `events` | The records. Oldest first with `after`, otherwise newest first. |
| `next_after` | Only with `after`. Send it as `after` on your next request. |
| `more` | Only with `after`. `true` when more records may be waiting, so request again right away. |
| `next_before` | Only without `after`. Send it as `before` to get older records. `null` when there are no older records. |

A response stops before 8 MiB, so it can hold fewer records than `limit` while more are waiting. `more` and `next_before` account for that.

### Record fields

Each record carries these fields (plus `region_code` when a region is available). Times are Unix seconds, UTC.

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | `evt_` followed by 24 hex characters. Unique per record. |
| `url` | string | The page's canonical URL when it's on the source's site, otherwise the URL the page was fetched from after redirects. Tracking parameters are removed. |
| `html` | string or null | The page's raw HTML as fetched, up to 4 MiB. `null` with `content=false`. |
| `status_code` | integer or null | The HTTP status of the fetch. |
| `content_type` | string or null | The `Content-Type` of the fetch. |
| `crawl_time` | integer | When the page was fetched. |
| `updated_time` | integer or null | When the page last changed: the modified time the page states (`article:modified_time`, `og:updated_time`, or `dateModified`), else its sitemap's `lastmod` (`null` when neither is present). When the two are more than an hour apart, the earlier one. |
| `published_time` | integer or null | When the page was published, as explicit page markup states (`null` otherwise). A date from the URL, an RSS/Atom feed, or a listing is never used. |
| `title` | string | The page's `og:title`, else its `<title>`, else the title its source listed. Can be an empty string. |
| `description` | string or null | The page's meta description, else its `og:description`. |
| `category` | string | The feed's category (`local`, `curated`, or `global`). Identifies the feed rather than a vertical or subcategory. |
| `author` | string or null | The page's author. `null` when the page names none, or when the author is an organization, such as the site or business naming itself. |
| `country_code` | string | The source's two-letter ISO 3166-1 alpha-2 country code (for example `AU`, `CA`, `GB`, `IE`, or `NZ` on Local), or `ZZ` for global or multi-country sources on Curated and Global feeds. |
| `region_code` | string (optional) | ISO 3166-2 subdivision code (such as `NZ-AUK`) when available for the record. Omitted when absent. |
| `language_code` | string or null | The primary subtag of the page's stated language, in lower case, such as `en` or `fr`. |

`published_time` and `updated_time` are populated only when explicit page markup or sitemap timestamps exist (`published_time` uses page markup only; `updated_time` can also fall back to a sitemap `lastmod`), and are `null` otherwise. Both are also `null` unless the timestamp gives a full time of day with a time zone (bare dates and exact-midnight timestamps aren't used), or when that time is before 1990 or later than `crawl_time`.

Each record's `category` field reflects the feed (`local`, `curated`, or `global`), while `subcategory` is a query filter parameter and is not emitted on individual record objects. `country_code`, and the `country` and `subcategory` filters, describe the source the page came from rather than the page itself. Filter by `subcategory` or poll a dedicated `/{vertical}/latest` endpoint (`newsroom-blogs`, `tech-support`, or `gov-hqi`) when you need records scoped to a specific vertical.

## New pages and updates

- A page enters the feed when its source first lists it. Pages a source already listed when the feed started reading it aren't sent.
- It enters again when its source lists a later modified time for it and the page's main content has changed. The new record has a new `id` and the same `url`, so keep the latest record for each `url`.
- A change outside the main content, such as ads, navigation, or a cookie banner, doesn't add a record. Neither does a sitemap that re-dates pages without changing them.

## What the feed leaves out

A page is delivered with its content or not at all. The feed skips a page when:

- the page fails to load, or the site blocks the request;
- the page is paywalled;
- its HTML is larger than 4 MiB;
- its site's robots.txt disallows it for the crawler token set for your feed;
- a `robots` meta tag, or one named for that crawler token, says `none`, `noindex`, `noarchive`, `noai`, or `noimageai`, or the page reserves text and data mining with a `tdm-reservation` meta tag;
- it's screened out by the feed's content-safety filters (such as adult content and illegal hard drugs; additional screening rules, such as online gambling promotions, vary by feed).

## Compression

Records carry raw HTML, so responses are large. Send an `Accept-Encoding` header (such as `Accept-Encoding: gzip`) and the response comes back compressed with `gzip`, `zstd`, or `br`: the one your header weights highest, or in that order when it weights them the same. Most HTTP clients send the header and decompress for you. With curl, add `--compressed`. A very small response, such as one with no records, can come back uncompressed. A request whose header refuses an uncompressed body and accepts none of the three gets a `406`.

## Errors

Every error except `405` (and `404` on `HEAD` for an unknown vertical) has a JSON body with an `error` message.

| Status | Meaning |
| --- | --- |
| `400` | A query parameter is invalid, unknown, repeated, or conflicts with the endpoint or your team's feed scope (such as a conflicting `subcategory` on a vertical route, sending `before` and `after` together, or an `after` cursor above the feed's newest cursor). The `error` names the problem. |
| `401` | The API key is missing or invalid. |
| `402` | Insufficient credits for the request. On credit-billed feeds, the pre-check requires credits for up to `limit` records (`50` max with `content=true`, `500` max with `content=false`), and billing charges per returned record. |
| `403` | The Fresh Feed API, requested feed endpoint, or vertical isn't enabled for your team. |
| `404` | Unknown vertical on `/v2/fresh-vertical-feed/{vertical}/latest`. |
| `405` | The request used `HEAD` on a valid feed or vertical endpoint (`Allow: GET`). Use `GET`. |
| `406` | `Accept-Encoding` accepts none of the codings the feed sends. |
| `429` | Your team is over its rate limit. Wait for the number of seconds in the `Retry-After` header. |
| `502` | The request couldn't be completed. Retry with the same cursor. |
| `503` | The feed is temporarily unavailable. Retry the same request after the seconds in `Retry-After` (if present) or after a short backoff. |
| `504` | The response didn't start within 30 seconds. Retry with the same cursor. |

## Rate limits

During the beta, each team can make 100 requests a minute across Fresh Feed endpoints by default, shared by all of its API keys. A sync loop that waits a minute between quiet polls — or 15 to 60 minutes for batch polling — uses a small part of that.
