Firecrawl Exchange takes your agent beyond the web. Plenty of the data an agent
needs is not on a page at all: it sits behind a specialist API you would
otherwise have to find, sign up for, get a key from, and wire up as its own
service. Exchange puts those providers behind the contract you already use.

You find providers and call them through [`/search`](/api-reference/endpoint/search), with the same API
key as every other Firecrawl request. Every provider publishes a contract
describing what it returns, what options it takes, and what a call costs.

<Note>
Searching the catalog adds no credits to a request. Credits are charged when a
capability is executed; a web query alongside it bills as an ordinary search.
</Note>

## How it works

A provider is a data source: FullEnrich for professional profiles, Finnhub for
market data, and so on. A capability is one thing that provider can do, such as
enriching a contact or looking up a quote. Each capability publishes a JSON
Schema for its options, a schema for its response, and a price in credits. The
[provider catalogue](https://www.firecrawl.dev/exchange) lists everything
currently available.

## Using Exchange

<Steps>
  <Step title="Find a provider">
    Exchange has no separate catalog endpoint. Set `sources` to `exchange` on
    [`/search`](/api-reference/endpoint/search) and matching capabilities come back alongside your web
    results, shaped like any other result. Searching the catalog adds no credits.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      query: "company funding data",
      sources: ["exchange"],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "query": "company funding data",
        "sources": ["exchange"],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "company funding data",
        "sources": ["exchange"]
      }'
    ```
    </CodeGroup>

    Matches arrive under `data.providers`, best first. The `description` tells you
    what the capability does and what it costs, `provider` and `capability` are the
    keys you call it with, and the `url` resolves to its full request and response
    contract as Markdown:

    ```json
    {
      "providers": [
        {
          "url": "https://www.firecrawl.dev/exchange/providers/acme/company-search",
          "title": "Acme — Company search",
          "description": "Find companies by funding stage, location, and headcount. 25 credits per call. Fetch the url for the full request and response contract.",
          "provider": "acme",
          "capability": "company-search",
          "creditsPerCall": 25
        },
        {
          "url": "https://www.firecrawl.dev/exchange/providers/northstar/company-profile",
          "title": "Northstar — Company profile",
          "description": "Firmographics and ownership for a domain. 15 credits per call. Fetch the url for the full request and response contract.",
          "provider": "northstar",
          "capability": "company-profile",
          "creditsPerCall": 15
        }
      ]
    }
    ```

    Ranking weights a capability name above a provider blurb that merely mentions
    the words, so the closest match to your query comes first.

    To see the full list rather than search it, browse the
    [provider catalogue](https://www.firecrawl.dev/exchange).
  </Step>

  <Step title="Narrow the search (optional)">
    Use the object form of the source to scope discovery. `categories` limits it to
    a cohort, `providers` to named providers, and `capabilities` to specific
    `provider/capability` pairs. They compose, so a cohort plus a provider narrows
    further.

    Filters work with or without a query. Drop the query to browse everything in a
    cohort; add one to rank within it.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      sources: [
        {
          type: "exchange",
          categories: ["people", "finance"],
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "sources": [
            {
                "type": "exchange",
                "categories": ["people", "finance"],
            }
        ],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "enrich a contact",
        "sources": [
          { "type": "exchange", "categories": ["people", "finance"] }
        ]
      }'
    ```
    </CodeGroup>

    <Note>
    Discovery is additive. If the catalog is unavailable the request still returns
    your web results rather than failing.
    </Note>
  </Step>

  <Step title="Call the provider">
    Providers are called through [`/search`](/api-reference/endpoint/search). Add an `exchange` array with the
    `provider`, the `capability`, and the `options` its input schema requires.

    `query` is optional. Omit it to call providers only, or include it to get web
    results and provider results back together in one request.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      exchange: [
        {
          provider: "acme",
          capability: "company-search",
          options: { domain: "firecrawl.dev" },
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "exchange": [
            {
                "provider": "acme",
                "capability": "company-search",
                "options": {"domain": "firecrawl.dev"},
            }
        ]
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "exchange": [
          {
            "provider": "acme",
            "capability": "company-search",
            "options": { "domain": "firecrawl.dev" }
          }
        ]
      }'
    ```
    </CodeGroup>

    Provider results arrive under `data.exchange`, and each call is reported
    separately so one failure does not discard the rest:

    ```json
    {
      "success": true,
      "data": {
        "exchange": [
          {
            "provider": "acme",
            "capability": "company-search",
            "delivery": "direct",
            "creditsCost": 25,
            "data": { "company": { "name": "Firecrawl" } }
          }
        ]
      },
      "creditsUsed": 25,
      "id": "0198f3c2-..."
    }
    ```

    A call that fails carries an `error` object with a `code`, a `message`, and
    `retryable` instead of `data`.
  </Step>
</Steps>

## One call, many providers

The `exchange` array takes up to ten calls, and a `query` runs a web search
alongside them. So a single request can enrich a contact, pull a market quote,
and search the web at once. Each call is reported separately, so one failure
does not discard the others.

<CodeGroup>
```js Node
const result = await firecrawl.search({
  query: "acme corp recent coverage",
  exchange: [
    {
      provider: "fullenrich",
      capability: "contact-enrichment",
      options: { person: { linkedin_url: "https://linkedin.com/in/jane-doe" } },
    },
    {
      provider: "finnhub",
      capability: "quote",
      options: { symbol: "ACME" },
    },
  ],
});

result.web; // web results
result.exchange; // one entry per provider call
```

```python Python
result = firecrawl.search({
    "query": "acme corp recent coverage",
    "exchange": [
        {
            "provider": "fullenrich",
            "capability": "contact-enrichment",
            "options": {"person": {"linkedin_url": "https://linkedin.com/in/jane-doe"}},
        },
        {
            "provider": "finnhub",
            "capability": "quote",
            "options": {"symbol": "ACME"},
        },
    ],
})
```

```bash cURL
curl -X POST "https://api.firecrawl.dev/v2/search" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "acme corp recent coverage",
    "exchange": [
      {
        "provider": "fullenrich",
        "capability": "contact-enrichment",
        "options": { "person": { "linkedin_url": "https://linkedin.com/in/jane-doe" } }
      },
      {
        "provider": "finnhub",
        "capability": "quote",
        "options": { "symbol": "ACME" }
      }
    ]
  }'
```
</CodeGroup>

Provider results arrive under `data.exchange`, next to `data.web`, `data.news`,
and `data.images`.

## Bring your own key

Some providers are published as bring-your-own-key. You already have an account
with the provider, so you send your own credential and Firecrawl routes the
call. Pass it as `providerApiKey` on the call:

```js Node
const result = await firecrawl.search({
  exchange: [
    {
      provider: "acme",
      capability: "company-search",
      options: { domain: "firecrawl.dev" },
      providerApiKey: process.env.ACME_API_KEY,
    },
  ],
});
```

Bring-your-own-key capabilities cost zero Firecrawl credits; the provider bills
you directly. The credential is forwarded to the provider for that one call and
is never stored.

## Pricing

Searching the catalog adds no credits. Running a capability costs the
`creditsPerCall` published in its contract, and you are charged only for calls
that succeed. Discovery results carry the price, so you can check before
calling.

Bring-your-own-key capabilities cost zero Firecrawl credits; the provider bills
you directly.
