Firecrawl Exchange gives your agent access to specialist data providers without
integrating each one. Every provider publishes a contract describing what it
returns, what options it takes, and what a call costs.

There is no separate Exchange API. You find providers and call them through
`POST /v2/search`, using the same API key as every other Firecrawl request.

<Note>
Discovery is free; credits are charged only when a capability is executed.
</Note>

## How it works

A provider is a data source. A capability is one thing that provider can do,
such as searching companies or enriching a contact. Each capability publishes a
JSON Schema for its options, a schema for its response, and a price in credits.

## Find a provider

Exchange has no separate catalog endpoint. Set `sources` to `exchange` on
`POST /v2/search` and matching capabilities come back alongside your web
results, shaped like any other result. Discovery costs no credits.

<CodeGroup>
```js Node
const result = await firecrawl.search({
  query: "company funding data",
  sources: ["exchange"],
});
```

```python Python
result = firecrawl.search({
    "query": "company funding data",
    "sources": ["exchange"],
})
```

```bash cURL
curl -X POST "https://api.firecrawl.dev/v2/search" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "company funding data",
    "sources": ["exchange"]
  }'
```
</CodeGroup>

Matches arrive under `data.providers`, best first. Each carries the capability's
purpose plus `provider`, `capability`, and `creditsPerCall`, so you know the
price before you call:

```json
{
  "providers": [
    {
      "url": "https://www.firecrawl.dev/exchange/acme",
      "title": "Acme — Company search",
      "description": "Find companies by funding stage, location, and headcount. 25 credits per call.",
      "provider": "acme",
      "capability": "company-search",
      "creditsPerCall": 25
    },
    {
      "url": "https://www.firecrawl.dev/exchange/acme",
      "title": "Acme — Funding rounds",
      "description": "List funding rounds and investors for a company. 25 credits per call.",
      "provider": "acme",
      "capability": "funding-rounds",
      "creditsPerCall": 25
    },
    {
      "url": "https://www.firecrawl.dev/exchange/northstar",
      "title": "Northstar — Company profile",
      "description": "Firmographics and ownership for a domain. 15 credits per call.",
      "provider": "northstar",
      "capability": "company-profile",
      "creditsPerCall": 15
    }
  ]
}
```

Ranking weights a capability name above a provider blurb that merely mentions
the words, so the closest match to your query comes first.

### Narrowing the search

Use the object form of the source to scope discovery. `categories` limits it to
a cohort, `providers` to named providers, and `capabilities` to specific
`provider/capability` pairs. They compose, so a cohort plus a provider narrows
further.

<CodeGroup>
```js Node
const result = await firecrawl.search({
  query: "enrich a contact",
  sources: [
    {
      type: "exchange",
      categories: ["people", "finance"],
    },
  ],
});
```

```python Python
result = firecrawl.search({
    "query": "enrich a contact",
    "sources": [
        {
            "type": "exchange",
            "categories": ["people", "finance"],
        }
    ],
})
```

```bash cURL
curl -X POST "https://api.firecrawl.dev/v2/search" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "enrich a contact",
    "sources": [
      { "type": "exchange", "categories": ["people", "finance"] }
    ]
  }'
```
</CodeGroup>

<Note>
Discovery is additive. If the catalog is unavailable the request still returns
your web results rather than failing.
</Note>

## Call a provider

Providers are called through `POST /v2/search`. Add an `exchange` array with the
`provider`, the `capability`, and the `options` its input schema requires.

`query` is optional. Omit it to call providers only, or include it to get web
results and provider results back together in one request.

<CodeGroup>
```js Node
const result = await firecrawl.search({
  exchange: [
    {
      provider: "acme",
      capability: "company-search",
      options: { domain: "firecrawl.dev" },
    },
  ],
});
```

```python Python
result = firecrawl.search({
    "exchange": [
        {
            "provider": "acme",
            "capability": "company-search",
            "options": {"domain": "firecrawl.dev"},
        }
    ]
})
```

```bash cURL
curl -X POST "https://api.firecrawl.dev/v2/search" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "exchange": [
      {
        "provider": "acme",
        "capability": "company-search",
        "options": { "domain": "firecrawl.dev" }
      }
    ]
  }'
```
</CodeGroup>

Provider results arrive under `data.exchange`, and each call is reported
separately so one failure does not discard the rest:

```json
{
  "success": true,
  "data": {
    "exchange": [
      {
        "provider": "acme",
        "capability": "company-search",
        "delivery": "direct",
        "creditsCost": 25,
        "data": { "company": { "name": "Firecrawl" } }
      }
    ]
  },
  "creditsUsed": 25,
  "id": "0198f3c2-..."
}
```

A call that fails carries an `error` object with a `code`, a `message`, and
`retryable` instead of `data`.

<Note>
Add an optional `idempotencyKey` to a call to make retries safe. Sending the same
key again returns the original result instead of calling the provider and billing
a second time. Without one, a repeated request re-executes, exactly like a
repeated web search.
</Note>

### Alongside web results

Include a `query` to get both in one request. Provider results appear under
`data.exchange`, next to `data.web`, `data.news`, and `data.images`.

<CodeGroup>

  query: "firecrawl funding",
  exchange: [

      provider: "acme",
      capability: "company-search",

  ],

## Bring your own key

Some providers are published as bring-your-own-key. You already have an account
with the provider, so you send your own credential and Firecrawl routes the call
without reselling their data. Pass it as `providerApiKey` on the call:

```js Node
const result = await firecrawl.search({
  exchange: [
    {
      provider: "acme",
      capability: "company-search",
      options: { domain: "firecrawl.dev" },
      providerApiKey: process.env.ACME_API_KEY,
    },
  ],
});
```

Bring-your-own-key capabilities cost zero Firecrawl credits; the provider bills
you directly. The credential is forwarded to the provider for that one call and
is never stored.

## Pricing

Finding a provider costs nothing. Running a capability costs the
`creditsPerCall` published in its contract, and you are charged only for calls
that succeed. Discovery results carry the price, so you can check before
calling.

Bring-your-own-key capabilities cost zero Firecrawl credits; the provider bills
you directly.

## Errors

Failures are reported per call rather than failing the whole request.

| Code | Meaning |
| --- | --- |
| `exchange_capability_not_supported` | The capability is not available through the direct beta. |
| `terms_acceptance_required` | Your organization must accept the provider's data terms first. |
| `capability_disabled` | Firecrawl has temporarily disabled this capability. |
| `provider_not_published` | The provider or capability is not published. |
| `byok_credential_required` | The capability needs a `providerApiKey`. |
| `exchange_price_changed` | The published price changed before execution; retry to use the new price. |

## List your data on Exchange

If you have an API you want agents to reach, you can publish it as a provider.
Upload an OpenAPI specification and Firecrawl derives your capabilities from it,
then walks you through pricing, categorisation, and ownership verification.
Every listing is reviewed before it becomes public.
