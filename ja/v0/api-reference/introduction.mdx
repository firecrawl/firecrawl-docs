<div id="base-url">
  ## ベースURL {#base-url}
</div>

すべてのリクエストは次のベースURLを使用します：

```bash
https://api.firecrawl.dev 
```

## 認証 {#authentication}

認証には、Authorization ヘッダーを含める必要があります。ヘッダーには `Bearer fc_123456789` を指定し、`fc_123456789` の部分はご自身の API キーに置き換えてください。

```bash
Authorization: Bearer fc_123456789
```

​

## レスポンスコード {#response-codes}

Firecrawl は、リクエストの結果を示すために標準的な HTTP ステータスコードを使用します。

一般に、2xx のステータスコードは成功、4xx はユーザー側に起因するエラー、5xx はインフラ側の問題を示します。

| ステータス | 説明                        |
| ----- | ------------------------- |
| 200   | リクエストが成功しました。             |
| 400   | パラメータが正しいか確認してください。       |
| 401   | API キーが指定されていません。         |
| 402   | 支払いが必要です                  |
| 404   | 要求されたリソースが見つかりませんでした。     |
| 429   | レート制限を超過しました。             |
| 5xx   | Firecrawl 側のサーバーエラーを示します。 |

発生しうる API エラーの詳細については、エラーコードのセクションを参照してください。

​

<div id="rate-limit">
  ## レート制限 {#rate-limit}
</div>

Firecrawl API には、サービスの安定性と信頼性を確保するためのレート制限があります。レート制限はすべてのエンドポイントに適用され、一定時間内のリクエスト数に基づいています。

レート制限を超えると、ステータスコード 429 が返されます。
