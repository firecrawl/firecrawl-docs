Firecrawl Developer は、コーディングエージェント向けに構築されたインデックスです。GitHub Issue、マージ済みのプルリクエスト、リポジトリの README、厳選されたドキュメントサイトを対象としており、エージェントは一般的な Web ページではなく一次ソースに基づいて、コードの動作、ライブラリやフレームワーク、API 契約、エラーメッセージ、既知のバグに関する質問に回答できます。

* バグが報告され修正された Issue またはプルリクエストを見つける
* 特定の質問への回答が記載された README またはドキュメントページの本文箇所を読む
* API 契約を変更したプルリクエストまでたどる
* エラーメッセージの背景にある議論を確認する

<Note>
  コーディングエージェントに Developer Index へのアクセスを付与するには、[CLI](/ja/sdks/cli) または [MCP サーバー](/ja/mcp-server) を推奨します。どちらもこれを主要なツールとして提供するため、エージェントはエンドポイントを指示されなくても利用できます。
</Note>

<div id="two-ways-in">
  ## 2つの利用方法
</div>

| 方法                                               | 次の場合に使用                                         |
| ------------------------------------------------ | ----------------------------------------------- |
| [`/search`](/ja/features/search) の `developer` カテゴリ | 1回の呼び出しで、通常のウェブ検索結果と開発者向け結果を取得したい場合             |
| [開発者検索エンドポイント](#developer-search-endpoint)       | 一致した本文箇所とインデックスフィルタを含む、順位付けされた開発者向け結果のみを取得したい場合 |

<div id="developer-category-on-search">
  ## `/search` のdeveloperカテゴリ
</div>

`/search` の `categories` 配列に `developer` を指定します。APIは `web` と並ぶ `developer` グループに開発者向けの結果を返し、両SDKではこのグループを `.developer` として公開しています。

開始するのにAPIキーは不要です。`/search` はAPIキーなしのリクエストを受け付け、`developer` カテゴリも[APIキーなしの利用枠](/ja/rate-limits#keyless-no-api-key)の範囲で利用できます。より高いレート制限を利用するにはキーを送信してください。

<CodeGroup>
  ```bash cURL
  # 開始するのにAPIキーは不要です。より高いレート制限を利用するには -H "Authorization: Bearer $FIRECRAWL_API_KEY" を追加してください:
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(
      # 開始するのにAPIキーは不要です。より高いレート制限を利用するには追加してください:
      # api_key="fc-YOUR-API-KEY",
  )

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // 開始するのにAPIキーは不要です。より高いレート制限を利用するには追加してください:
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

このグループの開発者向け結果には、web結果と同じ形式の `url`、`title`、`description`、`position` に加え、`category: "developer"` が含まれます。同じレスポンス内のweb結果には `category` がないため、2つのグループを統合する場合はこのフィールドを判別に使用します。

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://example.com/blog/retry-strategies",
        "title": "Retry strategies for HTTP clients",
        "description": "An overview of backoff and retry patterns"
      }
    ],
    "developer": [
      {
        "url": "https://github.com/firecrawl/firecrawl/issues/1234",
        "title": "Retries are not applied to 429 responses",
        "description": "Reported behavior and the fix that landed",
        "position": 1,
        "category": "developer"
      }
    ]
  }
}
```

<Note>
  **SDK ユーザー:** developer の結果は `.web` ではなく、専用のグループとして返されます。`result.developer` から取得してください。
</Note>

<div id="developer-search-endpoint">
  ## 開発者検索エンドポイント
</div>

| タスク                 | エンドポイント                                                                        |
| ------------------- | ------------------------------------------------------------------------------ |
| Developer Index を検索 | [`GET` または `POST /search/developer`](/ja/api-reference/endpoint/developer-search) |

開発者検索は、結果10件ごとに2 creditsかかります (切り上げ) 。結果1～10件は2 credits、11～20件は4 creditsで、以降も同様です。開始に APIキー は不要です。より高い レート制限 を利用するには、APIキー を送信してください。

<CodeGroup>
  ```bash cURL
  # 開始に APIキー は不要です。より高い レート制限 を利用するには、-H "Authorization: Bearer $FIRECRAWL_API_KEY" を追加してください:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"]
    }'
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

<Note>
  Python および Node SDK は、上記の `developer` カテゴリを通じて Developer Index にアクセスします。このエンドポイント専用のメソッドは提供していないため、HTTP、[CLI](/ja/sdks/cli)、または [MCP](/ja/mcp-server) 経由で呼び出してください。
</Note>

<div id="filters">
  ### フィルター
</div>

すべてのフィルターは任意です。

| フィルター       | 意味                                                                   |
| ----------- | -------------------------------------------------------------------- |
| `k`         | 返すランク付け済み結果の数。デフォルトは20、最大100                                         |
| `types`     | 検索対象の結果の種類。`doc`、`issue`、`pull_request`、`readme` のいずれか。デフォルトでは4種類すべて |
| `repos`     | 対象を絞り込むリポジトリスラッグ。例: `firecrawl/firecrawl`                            |
| `sources`   | 対象を絞り込むドキュメントのソース ID。最大20件。以下を参照                                     |
| `passages`  | 結果ごとに返す一致した本文箇所。デフォルトは1、最大5                                          |
| `language`  | リポジトリの言語                                                             |
| `topic`     | リポジトリのトピック                                                           |
| `license`   | リポジトリのライセンス                                                          |
| `min_stars` | リポジトリのスター数の下限                                                        |
| `max_stars` | リポジトリのスター数の上限                                                        |
| `archived`  | アーカイブ済みリポジトリを含めるか除外するか                                               |
| `fork`      | フォークを含めるか除外するか                                                       |

繰り返し指定可能なフィルターは、`GET` では `types=issue&types=pull_request` のようにクエリパラメータを繰り返す形式、または `types=issue,pull_request` のように1つのカンマ区切り値として指定する形式のいずれかを使用できます。`POST` では、JSON ボディで配列を渡します。

<div id="how-repos-and-sources-scope-a-search">
  ### `repos` と `sources` による検索範囲の指定
</div>

インデックスは2つの部分で構成されており、これら2つのフィルターはそれぞれ独立して検索範囲を指定します。

* `repos` は GitHub 側、つまり `issue`、`pull_request`、`readme` タイプを対象にします
* `sources` はドキュメント側、つまり `doc` タイプを対象にします
* 両方を指定すると、2つの部分は積集合ではなく結合されるため、どちらか一方から一致する結果が得られます

各フィルターは一方の部分にのみ適用されるため、指定されたどのタイプにも一致し得ないフィルターは、何も返さずに処理されるのではなく拒否されます。

* `types` に GitHub タイプが含まれていない状態で `repos` を指定すると、`400` と `repos cannot match any requested type; add github types or drop repos` が返されます
* `types` に `doc` が含まれていない状態で `sources` を指定すると、`400` と `sources cannot match any requested type; add doc or drop sources` が返されます

<div id="which-values-sources-accepts">
  ### `sources` に指定できる値
</div>

`sources` は固定の列挙型ではありません。ドキュメントのソース ID を指定でき、各 ID は最大 512 文字の空でない文字列です。1 リクエストあたり最大 20 個指定できます。ID はインデックス内のドキュメントサイトを反映しており、その一覧は時間とともに増えていきます。

ID が有効かどうかを確認するには、その ID を指定し、レスポンスに追加される `sources` 配列を確認します。この配列は `sources` を送信した場合にのみ含まれ、指定したとおりの各 ID と、インデックスに登録されているかどうかを返します。

```json
{
  "success": true,
  "results": [],
  "sources": [
    { "source": "some-docs-site", "indexed": true },
    { "source": "unknown-docs-site", "indexed": false }
  ]
}
```

`indexed: true` は、ソースに公開済みの世代があることを意味し、そのソースのドキュメント上の根拠が表示される場合があります。`indexed: false` は、その id の内容はいずれも一致しないことを意味し、インデックスに存在しない id と、単に何も見つからなかった query を区別します。

`repos` も同様に返され、`indexed` と、タイプ別の `issue`、`pullRequest`、`readme` の内訳を含む `repos` 配列として返されます。

<div id="response">
  ### レスポンス
</div>

```json
{
  "success": true,
  "results": [
    {
      "id": "issue:firecrawl/firecrawl#1234",
      "type": "issue",
      "url": "https://github.com/firecrawl/firecrawl/issues/1234",
      "title": "Retries are not applied to 429 responses",
      "passages": [
        {
          "text": "The client treats 429 as a terminal status, so the backoff never runs."
        }
      ]
    }
  ],
  "coverage": {
    "doc": "ok",
    "issue": "ok",
    "pull_request": "ok",
    "readme": "ok"
  },
  "reranked": true
}
```

* `id` は、`issue:owner/repo#123` のような安定した結果 ID です
* `type` は、`doc`、`issue`、`pull_request`、`readme` のいずれかです
* `title` は任意であり、ソースページに使用可能なタイトルがない `doc` 結果では存在しないことがよくあります。フィールドが存在すると想定せず、代わりに `url` を使用してください
* `passages` には一致した本文箇所が Markdown 形式で格納されるため、表やコードブロックも保持されます
* `coverage` は結果タイプごとのインデックスの健全性を示します。値は `ok`、`degraded`、`unavailable`、`skipped` のいずれかです
* `reranked` は、ランク付けされたリストが再ランキング処理を経たかどうかを示します

想定していた結果タイプが見つからない場合は、`coverage` を確認してください。status が `degraded` または `unavailable` の場合、その欠落は query ではなくインデックスに起因します。

<div id="use-it-from-mcp">
  ## MCP から使用する
</div>

ホスト型の [MCP サーバー](/ja/mcp-server) では両方の機能を利用でき、どちらも書き込みは行いません。[Firecrawl MCP への接続](/ja/mcp-server/connect)で説明されているとおり、アカウント OAuth または APIキーで接続します。ホスト型のAPIキーなし接続では、`categories: ["developer"]` を指定した `firecrawl_search` は開発者向け検索結果を返します。一方、専用の `firecrawl_developer_search` ツールは[APIキーなしのツール機能](/ja/mcp-server/tools)には含まれておらず、アカウント接続または APIキーが必要です。

<div id="developer-search-tool-firecrawl_developer_search">
  ### Developer Search Tool (`firecrawl_developer_search`)
</div>

Developer Index を単独で検索し、一致した本文箇所を含むランク付け済み結果を取得します。

```json
{
  "name": "firecrawl_developer_search",
  "arguments": {
    "query": "how do I configure retries",
    "k": 10
  }
}
```

<div id="developer-search-tool-options">
  #### Developer Search Tool のオプション:
</div>

* `query`: 検索クエリ文字列 (必須)
* `k`: 返すランク付け済み結果の数 (1〜100)

**最適な用途:** コードの動作、ライブラリやフレームワーク、API 契約、エラーメッセージ、既知のバグについて、一次ソースに基づいて質問に回答する場合。
**戻り値:** 各ヒットは、id、type、url、title、一致した本文箇所を含む Markdown ブロックとして返されます。

このツールが受け取る引数はこの 2 つのみです。結果タイプ、リポジトリ、ドキュメントソースで絞り込む必要がある場合は、HTTP 経由で[開発者検索エンドポイント](#developer-search-endpoint)を呼び出してください。

<div id="developer-results-from-the-search-tool-firecrawl_search">
  ### Search Tool (`firecrawl_search`) の開発者向け結果
</div>

`categories` に `developer` を指定すると、通常のWeb検索結果と並んで `developer` グループに開発者向け結果が返されます。形式は `/search` の `developer` カテゴリの戻り値と同じです。

```json
{
  "name": "firecrawl_search",
  "arguments": {
    "query": "how do I configure retries",
    "categories": ["developer"],
    "limit": 10
  }
}
```

**最適な用途：** 開発者向けソースと一般的なウェブページをまとめて検索したい場合。
**戻り値：** 通常の検索レスポンス。開発者向けの検索結果は `developer` にグループ化され、それぞれに `category: "developer"` が含まれます。
