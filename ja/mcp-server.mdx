Firecrawl MCP は、Model Context Protocol (MCP) を通じて、AI クライアントが最新のウェブデータにアクセスできるようにします。最も簡単にセットアップするにはホスト型サーバーを使用し、ローカルプロセスやセルフホスト型 Firecrawl API が必要な場合は、[オープンソースサーバーをローカルで実行](/ja/mcp-server/local)してください。

このページは、ホスト型 Firecrawl MCP の正規セットアップガイドです。

<div id="setup-firecrawl-mcp-server">
  ## Firecrawl MCP サーバー をセットアップする
</div>

対話型クライアントでは、OAuth で接続します。クライアントがブラウザで Firecrawl を開くため、API キーをコピーすることなく、サインイン、チームの選択、アクセスの承認を行えます。

<Tabs>
  <Tab title="Codex">
    ホスト型サーバーを追加し、OAuth サインインを完了します。

    ```bash
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp-oauth
    codex mcp login firecrawl
    ```

    Codex アプリ、CLI、または IDE 拡張機能を起動または再起動します。`/mcp` を入力し、`firecrawl` が接続されていることを確認します。
  </Tab>

  <Tab title="Claude Desktop">
    1. **設定 &gt; コネクタ** を開きます。
    2. **カスタムコネクタを追加** を選択します。
    3. リモート MCP サーバーの URL として `https://mcp.firecrawl.dev/v2/mcp-oauth` を入力します。
    4. **接続** を選択し、Firecrawl にサインインしてアクセスを承認します。

    <Note>
      リモートサーバーは **設定 &gt; コネクタ** から追加する必要があります。`claude_desktop_config.json` ファイルはローカル MCP サーバー用です。
    </Note>
  </Tab>

  <Tab title="Claude Code">
    ホスト型サーバーを追加します。

    ```bash
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    Claude Code で `/mcp` を入力し、`firecrawl` を選択してブラウザでのサインインを完了します。
  </Tab>

  <Tab title="Cursor">
    ホスト型サーバーを `~/.cursor/mcp.json` に追加します。

    ```json
    {
      "mcpServers": {
        "firecrawl": {
          "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
        }
      }
    }
    ```

    ファイルを保存し、Cursor の MCP 設定を開いて Firecrawl へのサインインを完了します。すると、Cursor の Agent で Firecrawl ツールを利用できるようになります。
  </Tab>

  <Tab title="その他のクライアント">
    OAuth 対応のリモート MCP クライアントで、次の URL を指定します。

    ```text
    https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    OAuth クライアントIDまたはクライアントシークレットの入力を求められた場合は、どちらも空欄のままにします。対応クライアントでは、クライアントIDメタデータドキュメントまたは動的クライアント登録が使用されます。

    クライアントでリモート OAuth を完了できない場合は、以下の API キー設定を使用します。リクエストヘッダーを送信できない場合は、[Firecrawl MCP をローカルで実行](/ja/mcp-server/local)してください。
  </Tab>
</Tabs>

OAuth 接続では、Firecrawl APIキーの代わりに、有効期間が短くリソースに紐づいたトークンが発行されます。これらは [MCP 設定](https://www.firecrawl.dev/app/settings?tab=mcp)で確認および取り消しできます。

<div id="set-up-with-an-api-key">
  ## APIキーを使用して設定する
</div>

CI、サーバー、スクリプト、またはブラウザーでのOAuthを完了できないその他のクライアントでは、APIキーを使用します。[Firecrawl APIキーを作成](https://www.firecrawl.dev/app/api-keys)し、環境変数またはシークレットストアに保管して、フルホスト型MCPエンドポイントに接続します。

<Tabs>
  <Tab title="Codex">
    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp \
      --bearer-token-env-var FIRECRAWL_API_KEY
    ```
  </Tab>

  <Tab title="Claude Code">
    Claude Codeは接続時に環境変数を展開します。

    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp \
      --header 'Authorization: Bearer ${FIRECRAWL_API_KEY}'
    ```
  </Tab>

  <Tab title="その他のクライアント">
    APIキーをベアラートークンとして送信するよう、クライアントを設定します。

    ```text
    URL: https://mcp.firecrawl.dev/v2/mcp
    Authorization: Bearer <FIRECRAWL_API_KEY>
    ```

    ヘッダーの設定方法はクライアントによって異なります。キーはクライアントの環境変数または保護されたシークレットストレージに保管してください。
  </Tab>
</Tabs>

<Warning>
  APIキーをプロジェクトの構成ファイルに記載したり、チャットに貼り付けたり、スクリーンショットやissueで共有したりしないでください。新しい構成ではOAuthまたは環境変数を使用するAuthorizationヘッダーを使用し、認証情報を含むURLは絶対に使用しないでください。
</Warning>

<div id="try-without-an-api-key">
  ## API キーなしで試す
</div>

アカウントを作成せずに Firecrawl を試すには、リモート MCP に対応した任意のクライアントにキーレスエンドポイントを追加します。

```text
https://mcp.firecrawl.dev/v2/mcp
```

キーレス MCP はネットワークごとにレート制限されており、利用条件を満たしている場合は **Search、Scrape、Parse** のみを利用できます。すべてのツール群やより高い上限が必要な場合は、OAuth または API キーで接続してください。

<Accordion title="キーレスの上限に達するとどうなりますか？">
  利用可能な場合、MCP エラーには現在の再試行可能時間が含まれます。キーレスでの利用を続けるにはその時間待つか、OAuth または API キーで直ちに接続してください。
</Accordion>

<div id="verify-your-connection">
  ## 接続を確認する
</div>

クライアントのMCPステータスまたはツール一覧を開き、`firecrawl`が接続されていることを確認します。キーレスの接続では`firecrawl_search`、`firecrawl_scrape`、`firecrawl_parse`が表示されます。認証済みの接続では、プラン、デプロイ、チームポリシーに応じて[利用可能なすべてのツール](/ja/mcp-server/tools)が公開されます。

読み取り専用のリクエストを試します。

```text
最新のFirecrawlのリリースノートをウェブで検索し、そのソースを要約してください。
```

Firecrawl ツールが表示されない場合は、MCP 構成を保存した後にクライアントを再起動するか、再読み込みしてください。`spawn npx ENOENT` などのローカルプロセスエラーについては、[Firecrawl MCP をローカルで実行する](/ja/mcp-server/local#troubleshooting)を参照してください。

<div id="compatibility-and-legacy-setup">
  ## 互換性とレガシー設定
</div>

<AccordionGroup>
  <Accordion title="レガシー API キー URL のサポート">
    <Warning>
      このレガシー形式は、OAuth を完了できない、またはカスタム Authorization ヘッダーを送信できない既存の構成やクライアント向けにのみ提供されています。新しいインテグレーションでの使用は推奨されません。
    </Warning>

    ```text
    https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
    ```

    API キーは URL の一部であるため、URL 全体をパスワードと同様に扱ってください。漏洩した場合は、キーをローテーションしてください。このフォールバックは `/v2/mcp` のすべての機能にのみ適用されます。OAuth 専用の検索リソースでは利用できません。
  </Accordion>

  <Accordion title="既存の OAuth 接続">
    専用アカウントエンドポイントへの移行期間中も、既存の `/v2/mcp` OAuth 接続は引き続きサポートされます。新しい対話型アカウント接続には `/v2/mcp-oauth` を使用してください。このアカウントリソース用に新たに発行されたトークンは `/v2/mcp` では受け付けられません。
  </Accordion>
</AccordionGroup>
