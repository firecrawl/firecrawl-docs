このページでは、セキュリティ部門や調達部門が Firecrawl の導入を承認する前に確認する事項についてお答えします。詳しくは、[エンタープライズ向けページ](https://www.firecrawl.dev/enterprise)から担当チームまでお問い合わせください。

## コンプライアンスとレポート {#compliance-and-reports}

* **SOC 2 Type II**: 現在、SOC 2 Type II 監査を実施中です。
* **Trust Center**: [Firecrawl Trust Center](https://trust.firecrawl.dev) では、当社のコンプライアンスステータスと統制を公開しています。最新のペネトレーションテスト結果や、アクセス制御、データ管理、情報セキュリティ (AUP) 、第三者管理の各ポリシーもこちらからリクエストできます。
* **継続的な監視**: Trust Center では、データ暗号化、ペネトレーションテスト、事業継続計画および災害復旧計画、データ保持手順、アカウント解約時の顧客データ削除に関する統制を継続的に監視しています。

## データの取り扱いとゼロデータ保持 {#data-handling-and-zero-data-retention}

データ保持ゼロ (ZDR) とは、Firecrawl がページのコンテンツや抽出データを、リクエストまたはセッションの終了後に永続化しないことを指します。この機能はエンタープライズプランで利用でき、チームごとに有効化する必要があります。

| 製品                                                     | 有効化の方法                                           | 保持されないもの                                                     | 備考                                                  |
| ------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------------- |
| [スクレイピング](/ja/features/scrape#zero-data-retention-zdr)    | `zeroDataRetention: true`                        | ページのコンテンツと抽出データ                                              | ZDR モードではスクリーンショットを利用できません。1 ページあたり 1 クレジットが追加されます。 |
| [Interact](/ja/features/interact#zero-data-retention-zdr) | 最初の interact 呼び出しで `zeroDataRetention: true` を指定 | ページのコンテンツと実行出力                                               | ZDR モードではセッションの録画と永続プロファイルを利用できません。                 |
| [検索 (エンドツーエンド ZDR) ](/ja/features/search#end-to-end-zdr)  | `enterprise: ["zdr"]`                            | クエリと結果データ (Firecrawl および上流の検索プロバイダーの双方で保持されません)              | 結果 10 件あたり 10 クレジット。                                |
| [検索 (匿名化 ZDR) ](/ja/features/search#anonymized-zdr)       | `enterprise: ["anon"]`                           | Firecrawl におけるクエリと結果データ (検索プロバイダーが匿名化されたクエリをキャッシュする場合があります)  | 結果 10 件あたり 2 クレジット。                                 |

また、[個人識別情報のマスキング](/ja/features/scrape#pii-redaction)を使用すると、スクレイピングおよび解析の出力から、ユーザーに届く前に個人を特定できる情報を除去できます。

## 契約、DPA、サブプロセッサー {#contracts-dpa-and-subprocessors}

* **DPA とカスタム契約**: Enterprise のお客様は、データ処理契約 (DPA) およびカスタム MSA を締結できます。また、ベンダーによるセキュリティ審査やセキュリティ質問票にも対応しています。
* **サブプロセッサー**: 最新の一覧は [Trust Center](https://trust.firecrawl.dev/subprocessors) で公開しています。Trust Center で通知を登録すると、新しいサブプロセッサーがお客様の個人データの処理を開始する前に、事前通知を受け取れます。
* **プライバシー**: [プライバシーポリシー](https://www.firecrawl.dev/privacy-policy)を参照してください。

## ID とアクセス制御 {#identity-and-access-control}

* **[SSO と SCIM](/ja/features/sso)**: SAML および OIDC によるシングルサインオン (Okta、Entra ID、Google Workspace など) と SCIM によるディレクトリ同期に対応し、アクセス権を ID プロバイダーと連動させます。
* **静的 IP の許可リスト登録**: トラフィックを専用 IP アドレス経由でルーティングし、自社システム側でそれらの IP を許可リストに登録できます。
* **[IP制限](/ja/features/ip-restrictions)**: Team の APIキーを、許可リストに登録した IP アドレスまたは CIDR 範囲からのみ利用できるよう制限します。
* **[キー制限](/ja/features/key-restrictions)**: 個々の APIキーで利用できる出力形式とエンドポイントを限定します。制限はサーバーサイドで強制適用されます。
* **利用額の上限**: APIキーごと、または Team ごとに利用額の上限を設定できます。

## 監視と脅威対策 {#monitoring-and-threat-controls}

* **[脅威保護](/ja/features/threat-protection)**: 組織が管理・ロックできるポリシーを使用して、Firecrawl による危険な URL の取得をブロックします。
* **[SIEM監査ログ記録](/ja/features/siem)**: スクレイピングごとに構造化された監査イベントを SIEM へストリーミングします。まずは Microsoft Sentinel に対応しています。

## データレジデンシー {#data-residency}

Firecrawl はすべてのデータを米国内で処理しており、EU 域内でのデータレジデンシーには対応していません。ゼロデータ保持を有効にすると、スクレイピングや検索で取得したコンテンツは、リクエストの完了後に保存されません。

## AIエージェントおよびMCPユーザー向け {#for-ai-agent-and-mcp-users}

Firecrawl を AIエージェント、[MCP サーバー](/ja/mcp-server)、CLI、SDK のいずれから呼び出す場合でも、同じ制御が適用されます。IP およびキーの制限、脅威保護、SIEM監査ログ記録は組織単位でサーバーサイドで強制適用されます。そのため、特定のエンドポイントやフォーマットに制限されたキーは、どのクライアントから使用しても制限が維持されます。ゼロデータ保持は、これを有効にしたすべてのリクエストに適用されます。

  <Accordion title="Firecrawl はエンタープライズのセキュリティ審査に対応できますか？">
    はい。Firecrawl はスクレイピングと Interact でゼロデータ保持を提供し、検索では 2 つの ZDR モードを用意しています。また、DPA の締結に応じ、SCIM 対応の SAML または OIDC による SSO をサポートしているほか、SOC 2 Type II 監査も実施中です。IP やキーの制限、脅威保護、SIEM 監査ログ記録などのサーバーサイドの制御により、セキュリティチームがポリシーを設定・監査できます。

  <Accordion title="Firecrawl は SOC 2 に準拠していますか？">

  </Accordion>

  <Accordion title="Firecrawl は検索でゼロデータ保持を提供していますか？">
    はい。エンドツーエンドの検索 ZDR (`enterprise: ["zdr"]`) では、Firecrawl と上流の検索プロバイダーの両方がゼロデータ保持を適用するため、パイプライン内のどこにもクエリや結果のデータは保存されません。詳しくは [検索 ZDR](/ja/features/search#end-to-end-zdr) を参照してください。
  </Accordion>

  <Accordion title="Firecrawl は DPA を締結できますか？">

  </Accordion>

  <Accordion title="データはどこで処理されますか？">
    米国内で処理されます。Firecrawl は米国でのデータレジデンシーに対応していますが、EU でのデータレジデンシーには対応していません。
