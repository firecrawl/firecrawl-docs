---

エージェントが stdio 経由でツールを起動する場合、ローカルファイルへのアクセスが必要な場合、または自ら管理するインフラ上の Firecrawl API に接続する場合は、Firecrawl MCP をローカルで実行します。MCP サーバーと Firecrawl API は別個のサービスです。まず API バックエンドを選択し、対応する環境変数を設定してから MCP を起動します。

<div id="choose-the-firecrawl-api-backend">
  ## Firecrawl API バックエンドを選択する
</div>

| 必要なもの                         | 使用するもの                                      |
| ----------------------------- | ------------------------------------------- |
| 最速のマネージド環境                    | `FIRECRAWL_API_KEY` を使用する Firecrawl Cloud   |
| ソースコードまたはインフラの制御              | `FIRECRAWL_API_URL` を使用する、動作確認済みのセルフホスト型 API |
| ローカルファイルの直接解析                 | セルフホスト型 Firecrawl API に接続したローカル MCP         |
| このプロセスを運用せずに安全なリモート MCP を使用する | ホスト型 Firecrawl MCP server                   |

まだ API を起動していない場合は、[Firecrawl のセルフホスティング](/ja/contributing/self-host) に従い、MCP を追加する前にスクレイピングが正常に動作することを確認してください。

<div id="install-the-prerequisites">
  ## 前提条件をインストールする
</div>

* Node.js 22 以降
* Node.js に含まれる npm と `npx`
* Firecrawl Cloud APIキー、または動作するセルフホスト型 Firecrawl API の URL

Node.js を確認します。

```bash
node --version
```

<div id="run-mcp-with-firecrawl-cloud">
  ## Firecrawl Cloud で MCP を実行
</div>

MCP をローカルの stdio プロセスとして起動するクライアントの場合：

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY npx -y firecrawl-mcp@3.23.0
```

これは最も手軽なマネージド構成です。Firecrawl Cloud が API バックエンドを提供し、MCP プロセスはお使いのマシンで実行されます。

<div id="connect-mcp-to-self-hosted-firecrawl">
  ## MCP をセルフホスト型の Firecrawl に接続する
</div>

認証不要の信頼済みネットワーク向けクイックスタート:

```bash
env FIRECRAWL_API_URL=http://localhost:3002 \
  npx -y firecrawl-mcp@3.23.0
```

API キー互換の認証レイヤーを備えたセルフホスト型 API の場合：

```bash
env FIRECRAWL_API_URL=https://firecrawl.your-domain.com \
  FIRECRAWL_API_KEY=your-api-key \
  npx -y firecrawl-mcp@3.23.0
```

デプロイで必要な場合にのみキーを使用してください。MCP で公開できるのは、そのデプロイで設定されたサービスがサポートするツールのみです。[セルフホスト機能のサポート](/ja/contributing/self-host#self-hosted-feature-support)を参照してください。

<Warning>
  認証なしのセルフホスティング Quickstart を公開しないでください。リモート API URL を
  使用する前に、TLS、ネットワーク制御、サポートされている認証方式を導入してください。
</Warning>

<div id="run-mcp-over-streamable-http">
  ## Streamable HTTP 経由で MCP を実行する
</div>

n8n などのクライアントがすでに起動している MCP サーバーに接続する場合は、HTTP トランスポートを使用します。

```bash
env HTTP_STREAMABLE_SERVER=true \
  FIRECRAWL_API_KEY=fc-YOUR_API_KEY \
  npx -y firecrawl-mcp@3.23.0
```

クライアントを次に接続します。

```text
http://localhost:3000/mcp
```

MCP プロセスの準備ができていることを確認します。

```bash
curl http://localhost:3000/health
```

ヘルスチェックの戻り値は `ok` です。ローカル MCP ルートは `/mcp`、ホスト型の Firecrawl ルートは `/v2/mcp` です。

セルフホスト型 Firecrawl で HTTP トランスポートを使用するには、`FIRECRAWL_API_KEY` を前のセクションの `FIRECRAWL_API_URL` 構成に置き換え、API で必要な場合にのみキーを追加します。

<div id="persist-local-mcp-configuration">
  ## ローカルMCP構成を永続化
</div>

安定したローカルコマンドを使いたい場合は、パッケージをグローバルにインストールします。

```bash
npm install -g firecrawl-mcp@3.23.0
```

次を実行します。

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY firecrawl-mcp
```

Claude Desktop では、`claude_desktop_config.json` にローカルの stdio サーバーを追加します。

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.0"],
      "env": {
        "FIRECRAWL_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}
```

セルフホスト型の Firecrawl では、`FIRECRAWL_API_KEY` を `FIRECRAWL_API_URL` に置き換えるか、API キーが必要な場合は両方を指定します。

<div id="understand-local-and-hosted-boundaries">
  ## ローカルとホスト型の境界を理解する
</div>

* ホスト型のキーなし MCP では、Search、Scrape、Parse のみが利用可能で、IP アドレスごとにレート制限が適用されます。
* ローカル専用のファイル読み取りには、ローカル MCP プロセスが必要です。
* `firecrawl_parse` によるローカルファイルの直接解析には、セルフホスト型 Firecrawl API を指す `FIRECRAWL_API_URL` が必要です。Cloud API キーのみで設定されたローカル MCP サーバーでは、そのツールを介してローカルファイルをアップロードできません。
* Agent がネットワーク上のリソースにアクセスする必要がある場合は、webhook とローカルファイルパスをローカルまたはセルフホスト型 MCP で設定してください。
* Firecrawl API のレート制限は引き続き適用されます。より高いマネージド上限を利用するには Cloud API キーを使用するか、セルフホスト環境の容量を定義して監視してください。
