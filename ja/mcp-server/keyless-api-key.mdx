  ## すぐに試す
</div>

<Visibility for="agents">
  キーレスサーバー URL (Streamable HTTP、認証情報不要) : `https://mcp.firecrawl.dev/v2/mcp`

  * Codex: `codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp`
  * Claude Code: `claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp`
  * Cursor または任意の JSON 設定クライアント: `{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp"}}}`
  * OpenCode (`opencode.json`) : `{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp", "enabled": true}}}`

  ChatGPT と Claude.ai では、代わりにアカウントにサインインします。[OAuth](/ja/mcp-server/oauth.md) を参照してください。
</Visibility>

これは Firecrawl のキーレスモードです。アカウントや API キーなしで接続できます。手軽な試用にはこちらを使用し、ユーザー操作なしで確実に接続を実行する必要がある場合は API キーを使用してください。ChatGPT や Claude.ai からの利用を含め、ブラウザ経由でサインインする場合は [OAuth](/ja/mcp-server/oauth) を使用してください。

キーレス MCP で利用できるのは Search、スクレイピング、解析のみです。同じパブリック IP アドレスを使用するユーザー間で共有される、1 日あたりのリクエスト数とクレジット数の上限があります。同じネットワーク上の別の人間やプロセスが、この利用枠の一部を使用する可能性があります。

キーレスアクセスは接続の評価に使用し、ID や本番環境用の認証情報としては使用しないでください。現在の利用枠については、[キーレスのレート制限](/ja/rate-limits#keyless-no-api-key) を参照してください。

<div id="add-an-api-key">
  ## APIキーを追加する
</div>

CI、バックエンドサービス、その他のユーザー操作なしで接続する場合は、APIキーを使用します。[Firecrawl APIキーを作成](https://www.firecrawl.dev/app/api-keys)し、MCPクライアントで`FIRECRAWL_API_KEY`として利用できるようにします。

<Warning>
  人間またはシステム管理者は、エージェントとの会話外でキーを設定する必要があります。キーをエージェントチャットに貼り付けたり、MCP URLに含めたり、値をプロジェクトファイルにコミットしたりしないでください。設定ファイル内で環境変数を参照するのは安全ですが、シークレットの値自体は安全ではありません。
</Warning>

<div id="codex">
  ### Codex
</div>

Codex を起動する環境でキーをエクスポートします。

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

`~/.codex/config.toml` に以下を追加します：

```toml
[mcp_servers.firecrawl]
url = "https://mcp.firecrawl.dev/v2/mcp"
bearer_token_env_var = "FIRECRAWL_API_KEY"
```

<div id="claude-code">
  ### Claude Code
</div>

Claude Code を起動する前に、キーをエクスポートします：

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

`.mcp.json` に環境変数への参照を追加します。`${FIRECRAWL_API_KEY}` は実際のキーに置き換えないでください。

```json
{
  "mcpServers": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
      }
    }
  }
}
```

<div id="other-clients">
  ### その他のクライアント
</div>

クライアントの接続先：

```text
https://mcp.firecrawl.dev/v2/mcp
```

クライアントの環境変数またはシークレットストレージでこのヘッダーを設定します。

```text
Authorization: Bearer <FIRECRAWL_API_KEY>
```

構成を保存した後、新しいクライアントセッションを開始します。MCPのステータスまたはツール一覧を開き、`firecrawl` が接続されていることを確認します。

<div id="verify-the-connection">
  ## 接続を確認する
</div>

次を試してください：

```text
Firecrawlの最新のリリースノートをウェブで検索し、ソースを要約してください。
```

キーレス接続では、`firecrawl_search`、`firecrawl_scrape`、`firecrawl_parse` が表示されます。API キーを使用する接続では、プラン、デプロイ、チームポリシーに応じて[利用可能なすべてのツール](/ja/mcp-server/tools)が公開されます。

ツールが設定したモードと一致しない場合は、重複する Firecrawl エントリを削除し、クライアントを再起動して、使用中のサーバー URL と認証情報の取得元を確認してください。

<div id="run-in-ci-or-a-backend">
  ## CI またはバックエンドで実行する
</div>

`FIRECRAWL_API_KEY` はプラットフォームのシークレットマネージャーに保存し、プロセス環境に注入します。MCP 構成には環境変数への参照のみを記述します。

```json
{
  "url": "https://mcp.firecrawl.dev/v2/mcp",
  "headers": {
    "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
  }
}
```

値をソース管理、ビルドログ、プロンプト、生成された構成に含めないでください。シークレットを変更した後はプロセスを再起動し、`firecrawl` のツール一覧を確認してください。漏洩の可能性がある場合はキーをローテーションしてください。

<div id="legacy-api-key-url-support">
  ## 従来の API キー URL サポート
</div>

<Warning>
  URL にキーを含める形式は、既存の構成および Authorization ヘッダーを送信できないクライアント向けにのみ用意されています。新しい接続には使用しないでください。
</Warning>

既存の構成では、`https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp` を使用している場合があります。URL 全体が認証情報となるため、チャット、スクリーンショット、issue、ログ、共有構成には絶対に貼り付けないでください。可能な場合は、環境変数で管理する `Authorization: Bearer` ヘッダーに移行し、URL が漏洩した場合はキーをローテーションしてください。

この互換性ルートは、`/v2/mcp` のすべての機能にのみ適用されます。OAuth 専用の検索リソースでは使用できません。
