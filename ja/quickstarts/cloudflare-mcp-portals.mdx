Firecrawl のホスト型MCPサーバーを [Cloudflare One の MCP サーバーポータル](https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/) に追加すると、チームは Access ポリシーで保護された単一のポータル URL から、Firecrawl の検索ツールとスクレイピングツールを利用できるようになります。

## クイックセットアップ {#quick-setup}

[Firecrawl APIキーを作成](https://www.firecrawl.dev/app/api-keys)します。次に、ポータル API を使用して Cloudflare Access に Firecrawl を MCP サーバーとして追加します。その際、作成したキーを Bearer 認証情報として使用します。

```bash
export CLOUDFLARE_ACCOUNT_ID=your-cloudflare-account-id
export CLOUDFLARE_API_TOKEN=your-cloudflare-api-token
export FIRECRAWL_API_KEY=fc-YOUR_API_KEY

curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/access/ai-controls/mcp/servers" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Firecrawl",
    "hostname": "https://mcp.firecrawl.dev/v2/mcp",
    "auth_type": "bearer",
    "auth_credentials": "'"$FIRECRAWL_API_KEY"'"
  }'
```

ポータルは `auth_credentials` を `Authorization: Bearer <key>` として Firecrawl に送信します。Cloudflare のダッシュボードで **Zero Trust** &gt; **Access controls** &gt; **MCP Portals** &gt; **MCP servers** &gt; **Add MCP server** を開き、同じ URL を使用してサーバーを追加することもできます。

次に、サーバーをポータルに追加し、表示対象のユーザーを決める Access ポリシーを割り当てて、公開するツールを選択します。ポータルの作成方法については、Cloudflare の [MCP サーバーポータルガイド](https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/)を参照してください。

## 試してみる {#try-it}

MCP クライアントをポータル URL (`https://<subdomain>.<domain>/mcp`) に接続し、次のように質問してみてください。

```text
ウェブを検索して最新の Cloudflare Workers のリリースノートを探し、ソースを要約してください。
```

```text
https://firecrawl.dev をスクレイピングして、どのようなサービスか説明してください。
```

## トラブルシューティング {#troubleshooting}

* **サーバーに同期エラーまたは認証エラーが表示される:** キーが有効であること、および `auth_type` が `bearer` に設定されていることを確認してください。キーをローテーションした場合は、サーバーの認証情報を更新してください。
* **ポータルに Firecrawl のツールが表示されない:** ポータルでは管理者が選択したツールのみが公開されます。ポータルのツール一覧を確認してください。
* **ユーザーに Firecrawl が表示されない:** サーバーのリンクは、そのサーバーの許可 (Allow) ポリシーに該当するユーザーにのみ表示されます。
