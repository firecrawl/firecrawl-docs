ホスト型MCPサーバーを介して、Firecrawl を Kiro に接続します。ブラウザーでの sign-in は Kiro が自動で処理するため、手動で登録する必要はありません。Kiro IDE と Kiro CLI は同じ構成ファイルを使用します。

<Note>
  Kiro CLI は Amazon Q Developer CLI の後継です。以前に `q` を使用していた場合も、このページの内容がそのまま当てはまります。
</Note>

## クイックセットアップ {#quick-setup}

1. ユーザーレベルの構成ファイル `~/.kiro/settings/mcp.json` を開きます。IDE の場合は、コマンドパレットから **Kiro: Open user MCP config (JSON)** を実行します。特定のプロジェクトのみで使用する場合は、代わりにワークスペース内の `.kiro/settings/mcp.json` を使用してください。
2. Firecrawl を追加し、ファイルを保存します。

```json
{
  "mcpServers": {
    "firecrawl": {
      "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
    }
  }
}
```

3. 保存すると Kiro が再接続し、ブラウザーで Firecrawl の認可ページが開きます。サインインしてアクセスを承認してください。
4. Kiro パネルの MCP servers タブを開くか、`kiro-cli mcp status --name firecrawl` を実行して、Firecrawl のツールが利用可能になっていることを確認します。

<Accordion title="APIキーを使用する場合">
  Kiro のリモートサーバーではヘッダーを指定できます。シェルで `FIRECRAWL_API_KEY` をエクスポートしてから、次の設定を使用します。

  ```json
  {
    "mcpServers": {
      "firecrawl": {
        "url": "https://mcp.firecrawl.dev/v2/mcp",
        "headers": {
          "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
        }
      }
    }
  }
  ```

  Kiro が展開するのは、承認済みの環境変数のみです。`FIRECRAWL_API_KEY` に関するセキュリティ警告が表示されたら承認するか、設定の **Mcp Approved Env Vars** に追加してください。
</Accordion>

<Accordion title="CLI を使用する場合">
  ```bash
  kiro-cli mcp add --name firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth --scope global
  ```
</Accordion>

詳細は [OAuth 接続ガイド](/ja/mcp-server/oauth) を参照してください。ユーザー操作なしで使用する場合は、[APIキーを設定](/ja/mcp-server/keyless#add-an-api-key)してください。

## トラブルシューティング {#troubleshooting}

* **MCP サポートが無効になっている:** IDE で `Cmd/Ctrl + ,` を押して設定を開き、「MCP」を検索して有効にします。
* **サーバーに接続できない:** URL が `https://mcp.firecrawl.dev/v2/mcp-oauth` と完全に一致していることを確認し、ファイルを保存し直して再接続させます。
* **OAuth スコープのエラーが表示される:** サーバーのエントリに `"oauth": { "oauthScopes": [] }` を追加します。
* **ワークスペースとユーザーの両方のファイルで `firecrawl` が定義されている:** Kiro は両方をマージし、ワークスペースのファイルが優先されます。エントリは 1 つだけにしてください。
