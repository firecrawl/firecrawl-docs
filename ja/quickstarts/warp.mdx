ホスト型MCPサーバー経由で Firecrawl を Warp のローカルエージェントに接続し、Firecrawl アカウントでサインインします。

## クイックセットアップ {#quick-setup}

1. Warp で **Settings** → **Agents** → **MCP サーバー** の順に開きます。コマンドパレットで **Open MCP Servers** を検索して開くこともできます。
2. **+ Add** を選択し、次の構成を貼り付けます：

```json
{
  "mcpServers": {
    "firecrawl": {
      "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
    }
  }
}
```

3. サーバーを起動します。Warp が Firecrawl の sign-in 用のブラウザーページを開きます。アクセスを承認すると、Warp が認証情報をデバイスに保存します。
4. MCP サーバー一覧で `firecrawl` が実行中になっていることを確認し、エージェントに検索やスクレイピングを依頼します。

<Accordion title="ファイルベースの構成を使いたい場合">
  Warp は、全プロジェクト共通の `~/.warp/.mcp.json`、またはプロジェクトルートの `.warp/.mcp.json` からもサーバーを読み込みます。上記と同じ JSON を使用してください。プロジェクトファイルで定義されたサーバーは、起動前にユーザーの承認が必要です。
</Accordion>

<Accordion title="APIキーを使いたい場合">
  Warp は URL サーバーでカスタムヘッダーを使用できます。URL に `https://mcp.firecrawl.dev/v2/mcp` を指定し、`"headers": { "Authorization": "Bearer fc-YOUR-API-KEY" }` を追加してください。詳しくは[APIキーを構成する](/ja/mcp-server/keyless#add-an-api-key)を参照してください。
</Accordion>

詳しくは [OAuth 接続ガイド](/ja/mcp-server/oauth)を参照してください。

## トラブルシューティング {#troubleshooting}

* **sign-in ページが開かない：** MCP サーバーページからサーバーを再度開始してください。
* **sign-in が何度も失敗する：** `rm -rf ~/.mcp-auth` を実行して保存済みの MCP トークンを削除してから、サーバーを再度開始してください。この操作では、すべての MCP サーバーのトークンが削除されます。
* **サーバーが開始できない：** サーバーの **View Logs** を選択して、エラー内容を確認してください。
* **ツールが使用されない：** MCP ツールを呼び出す安定性はモデルによって異なります。エージェントピッカーで別のモデルを試してください。
