Firecrawl をリモート拡張機能として Goose に接続し、ホスト型MCPサーバー経由で Goose がウェブを検索してページを読み取れるようにします。

## 前提条件 {#requirements}

* Goose 1.55 以降
* [Firecrawl APIキー](https://www.firecrawl.dev/app/api-keys) (環境変数 `FIRECRAWL_API_KEY` としてエクスポートしておくこと)

## クイックセットアップ {#quick-setup}

1. Goose を起動するシェルで、APIキーをエクスポートします：

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. `~/.config/goose/config.yaml` の `extensions` セクションに拡張機能を追加します：

```yaml
extensions:
  firecrawl:
    type: streamable_http
    name: firecrawl
    enabled: true
    uri: https://mcp.firecrawl.dev/v2/mcp
    headers:
      Authorization: "Bearer $FIRECRAWL_API_KEY"
    env_keys:
      - FIRECRAWL_API_KEY
    timeout: 300
```

3. セッションを開始し、Goose に検索やスクレイピングを依頼します：

```bash
goose session
```

<Warning>
  ヘッダーは波かっこを付けずに `$FIRECRAWL_API_KEY` と記述し、`env_keys` はそのまま残してください。波かっこを付けると、Goose は `${FIRECRAWL_API_KEY}` をそのままの文字列として送信するため、サーバーにリクエストが拒否されます。
</Warning>

キーの詳細については、[APIキーを設定する](/ja/mcp-server/keyless#add-an-api-key)を参照してください。

## トラブルシューティング {#troubleshooting}

* **キーが無効または失効していると表示される:** ヘッダーで `$FIRECRAWL_API_KEY` を波括弧なしで使用していること、および Goose を起動するシェルで `FIRECRAWL_API_KEY` がエクスポートされていることを確認してください。
* **拡張機能が表示されない:** ファイルを保存してから `goose session` を再実行し、`enabled: true` になっていることを確認してください。
* **呼び出しがタイムアウトする:** `timeout` の値を大きくしてください。大きなページのスクレイピングには、デフォルトより時間がかかる場合があります。
* **ツールが使用されない:** MCP ツールをどの程度確実に呼び出せるかはモデルによって異なります。別のモデルを試してください。
