## Vue d&#39;ensemble {#overview}

Firecrawl for Platforms permet à votre plateforme de créer et de gérer des clés API Firecrawl pour vos utilisateurs directement depuis votre propre backend. Vos utilisateurs peuvent ainsi effectuer des recherches, extraire des données et interagir avec le web grâce à Firecrawl, l&#39;API de contexte pour les agents IA, sans quitter votre plateforme.

<Note>
  Configurez vous-même Firecrawl for Platforms dans le [tableau de bord Firecrawl](https://www.firecrawl.dev/app/partner-api). Tout administrateur ou membre d&#39;une organisation peut créer une intégration : nommez-la, choisissez un type d&#39;intégration, acceptez l&#39;accord correspondant à ce type, puis copiez la clé de plateforme. La clé n&#39;est affichée qu&#39;une seule fois. Vous pouvez ensuite générer et révoquer des clés dans Settings. Aucune candidature ni approbation n&#39;est requise.
</Note>

Il existe deux types d&#39;intégration. Tous deux provisionnent les comptes de la même manière, via les points de terminaison ci-dessous et avec la même clé de plateforme ; ils diffèrent uniquement par la partie qui paie l&#39;utilisation :

* **Standard** : vos utilisateurs paient Firecrawl. Chaque compte provisionné conserve sa propre offre et sa propre facturation Firecrawl, et effectue ses mises à niveau directement auprès de Firecrawl. Consultez la section [Crédits des comptes provisionnés](#credits-for-provisioned-accounts) pour savoir de quoi dispose un nouveau compte au départ.
* **Gateway** : votre organisation prend en charge l&#39;utilisation de vos utilisateurs. Les comptes créés par votre intégration sont inscrits à Gateway : leur utilisation éligible est donc facturée à votre organisation. Consultez la section [Gateway](#gateway) ci-dessous.

Le type d&#39;intégration se choisit lors de la création de l&#39;intégration. Il est difficile de le modifier par la suite ; nous vous recommandons donc d&#39;examiner attentivement les deux options avant d&#39;accepter l&#39;accord. Pour une vue d&#39;ensemble, consultez la [page Firecrawl for Platforms](https://www.firecrawl.dev/firecrawl-for-platforms).

Certaines offres partenaires incluent des crédits promotionnels pour les utilisateurs provisionnés ; le cas échéant, la page [Partner Credits](/fr/partner-credits) décrit ce que reçoit l&#39;utilisateur.

### Gateway {#gateway}

Gateway est un type d&#39;intégration, et non une API distincte : la clé de plateforme et les points de terminaison restent les mêmes. Voici ce qui change pour une intégration Gateway :

* Les comptes sont créés exclusivement pour votre intégration et sont accessibles uniquement via l&#39;API, sans connexion propre au tableau de bord. Une requête n&#39;est jamais rattachée à un compte Firecrawl existant, même si l&#39;e-mail correspond à celui d&#39;un compte.
* L&#39;utilisation éligible est facturée à votre organisation. Consultez [Crédits des comptes provisionnés](#credits-for-provisioned-accounts) pour savoir dans quels cas les crédits de l&#39;utilisateur sont consommés en premier.
* Les réponses de `POST /partner/v1/accounts` contiennent un champ `gatewayStatus`.
* L&#39;intégration accepte la version Gateway de l&#39;accord lors de sa création.

## URL de base {#base-url}

```
https://integrations.firecrawl.dev
```

## Authentification {#authentication}

Toutes les requêtes à l&#39;API Platforms nécessitent un en-tête `Authorization` contenant votre clé de plateforme :

```bash
Authorization: Bearer <platform key>
```

Les clés de plateforme sont distinctes des clés API Firecrawl standard. Vous les créez et les révoquez depuis Settings &gt; Firecrawl for Platforms dans le [tableau de bord Firecrawl](https://www.firecrawl.dev/app/partner-api).

## Exigences de sécurité {#security-requirements}

* **Côté serveur uniquement** : les clés de plateforme doivent être utilisées exclusivement dans du code côté serveur. N&#39;exposez jamais une clé de plateforme dans du code frontend, du JavaScript côté client ou une application mobile.
* **Conditions d&#39;utilisation** : avant d&#39;appeler `POST /partner/v1/accounts`, votre plateforme doit inviter l&#39;utilisateur à accepter les [Conditions d&#39;utilisation](https://www.firecrawl.dev/terms-of-service) de Firecrawl.

## Crédits des comptes provisionnés {#credits-for-provisioned-accounts}

Les comptes créés par votre intégration ne disposent d&#39;aucun crédit gratuit, sauf si Firecrawl a vérifié votre plateforme ou si vous avez signé un accord avec Firecrawl. D&#39;ici là :

* Un compte **Standard** démarre sans crédit inclus. L&#39;utilisateur peut à tout moment ajouter un mode de paiement ou choisir une offre dans le tableau de bord Firecrawl.
* Un compte **Gateway** facture l&#39;intégralité des crédits à votre organisation.

Une fois votre plateforme vérifiée, les comptes nouveaux comme existants bénéficient des crédits mensuels du Forfait gratuit ; pour les comptes Gateway, ces crédits sont consommés avant toute facturation à votre organisation. La vérification est effectuée manuellement par Firecrawl. Lorsque votre intégration est en production, ou si vous créez une application destinée à la production, écrivez à [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev) en indiquant l&#39;ID de votre intégration.

## Limites {#limits}

La création de comptes est limitée par intégration, à la fois en nombre de comptes qu&#39;une intégration peut créer et en rythme de création. Ces limites augmentent à mesure que la relation de votre organisation avec Firecrawl se développe et n&#39;affectent jamais les comptes que vous avez déjà créés. Un appel répété pour un utilisateur que vous avez déjà provisionné renvoie le compte existant et n&#39;est pas pris en compte dans la limite de comptes. Pour un compte Standard, l&#39;adresse que vous envoyez doit permettre à votre utilisateur de recevoir des e-mails.

Si vous atteignez une limite, ou si vous prévoyez une intégration en production, écrivez à [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev) en indiquant l&#39;ID de votre intégration et le volume prévu. Si Firecrawl suspend votre intégration, écrivez à [help@firecrawl.com](mailto:help@firecrawl.com).

## Points de terminaison {#endpoints}

### Créer un utilisateur {#create-user}

Crée un compte Firecrawl pour l&#39;un de vos utilisateurs, identifié par son adresse e-mail, et renvoie sa clé API.

```
POST /partner/v1/accounts
```

#### Comportement {#behavior}

Avec une intégration **Standard** :

* Si l&#39;utilisateur n&#39;a pas encore de compte Firecrawl, un nouvel utilisateur et une nouvelle équipe sont créés.
* Si l&#39;utilisateur a déjà un compte Firecrawl mais aucune équipe associée à votre intégration, une nouvelle équipe associée à votre intégration est créée.
* Si l&#39;utilisateur a déjà un compte Firecrawl et une équipe associée à votre intégration, l&#39;équipe existante est renvoyée.

Avec une intégration **Gateway** :

* Chaque compte est créé exclusivement pour votre intégration. Une requête n&#39;est jamais rattachée à un compte Firecrawl existant, même si l&#39;e-mail correspond à celui d&#39;un compte. L&#39;e-mail est enregistré comme adresse de contact du compte et ne sert pas à rechercher des comptes.
* Des appels répétés avec le même e-mail renvoient le même compte et sa clé API.

Si votre intégration inclut des crédits promotionnels, ils sont appliqués une seule fois, à la création du compte.

#### Requête {#request}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/accounts" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com"}'
```

**Corps**

| Champ   | Type   | Obligatoire | Description                                                                                                                                    |
| ------- | ------ | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `email` | string | Oui         | L&#39;adresse e-mail de l&#39;utilisateur. Dans le cas d&#39;une intégration Gateway, elle est enregistrée comme adresse de contact du compte. |

#### Réponse {#response}

**`200 OK`**

```json
{
  "apiKey": "fc-...",
  "alreadyExisted": false
}
```

Pour une intégration Gateway, la réponse contient également l&#39;état de l&#39;inscription :

```json
{
  "apiKey": "fc-...",
  "alreadyExisted": false,
  "gatewayStatus": "enrolled"
}
```

| Champ            | Type    | Description                                                                                                                                          |
| ---------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apiKey`         | string  | La clé API Firecrawl de l&#39;équipe que votre intégration a provisionnée pour cet utilisateur                                                       |
| `alreadyExisted` | boolean | `true` si votre intégration avait déjà provisionné un compte pour cet e-mail. N&#39;indique pas si l&#39;e-mail est utilisé ailleurs dans Firecrawl. |
| `gatewayStatus`  | string  | Intégrations Gateway uniquement. `enrolled` lors de l&#39;appel qui crée le compte, `already_enrolled` lors des appels suivants pour le même e-mail. |

#### Erreurs {#errors}

| État  | Description                                                                                                                                                                                                                                                                                                           |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400` | Requête incorrecte : le champ `email` est manquant ou mal formé                                                                                                                                                                                                                                                       |
| `401` | Non autorisé : la clé de plateforme est incorrecte ou invalide                                                                                                                                                                                                                                                        |
| `403` | Refusé : le champ `error.code` du corps en précise la raison, à savoir `partner_account_cap_reached` (l’intégration a atteint sa limite de comptes), `partner_provisioning_email_rejected` (l’adresse ne peut pas être utilisée pour un compte Firecrawl) ou `partner_integration_suspended`. Voir [Limites](#limits) |
| `429` | Trop de requêtes : `rate_limit_exceeded` ; ralentissez le rythme, puis réessayez                                                                                                                                                                                                                                      |
| `502` | Firecrawl n’a pas pu joindre son provider de facturation lors de la création du compte : réessayez la requête                                                                                                                                                                                                         |
| `503` | Firecrawl n’a pas pu vérifier la limite de débit : réessayez dans quelques instants                                                                                                                                                                                                                                   |
| `500` | Erreur interne du serveur : ces erreurs sont surveillées par Firecrawl                                                                                                                                                                                                                                                |

### Valider une clé API {#validate-api-key}

Valide une clé API Firecrawl et renvoie le nom de l&#39;équipe associée ainsi que l&#39;adresse e-mail de l&#39;utilisateur. La clé API n&#39;est reconnue comme valide que si elle a été créée via votre intégration.

```
POST /partner/v1/api-keys/validate
```

#### Remarques importantes {#important-notes}

* Les clés API Firecrawl n&#39;ont ni autorisations ni date d&#39;expiration.
* Les utilisateurs peuvent supprimer manuellement leurs clés API à tout moment.
* La suppression d&#39;une clé API est définitive (pas de suppression logique). Firecrawl ne peut pas distinguer une clé supprimée d&#39;une clé qui n&#39;a jamais existé.

#### Requête {#request-2}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/api-keys/validate" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "fc-..."}'
```

**Corps**

| Champ    | Type   | Obligatoire | Description          |
| -------- | ------ | ----------- | -------------------- |
| `apiKey` | string | Oui         | La clé API à valider |

#### Réponse {#response-2}

**`200 OK`**

```json
{
  "teamName": "Example Team",
  "email": "user@example.com"
}
```

| Champ      | Type   | Description                                                                                                                                             |
| ---------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `teamName` | string | Le nom de l&#39;équipe associée à cette clé API                                                                                                         |
| `email`    | string | L&#39;adresse e-mail utilisée lors de la création du compte. Pour les comptes Gateway, il s&#39;agit de l&#39;adresse de contact que vous avez fournie. |

#### Erreurs {#errors-2}

| État  | Description                                                                                         |
| ----- | --------------------------------------------------------------------------------------------------- |
| `400` | Requête incorrecte - la clé API est mal formée                                                      |
| `401` | Non autorisé - la clé de plateforme est incorrecte ou non valide                                    |
| `404` | Impossible d’identifier la clé API - la clé n’existe pas ou n’a pas été créée via votre intégration |
| `500` | Erreur interne du serveur - ces erreurs sont surveillées par Firecrawl                              |

### Renouveler la clé API {#rotate-api-key}

Supprime une clé API Firecrawl existante et en crée une nouvelle pour le même utilisateur et la même équipe.

```
POST /partner/v1/api-keys/rotate
```

#### Requête {#request-3}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/api-keys/rotate" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "fc-..."}'
```

**Corps**

| Champ    | Type   | Obligatoire | Description                           |
| -------- | ------ | ------ | ------------------------------------- |
| `apiKey` | string | Oui    | La clé API à supprimer et à remplacer |

#### Réponse {#response-3}

**`200 OK`**

```json
{
  "apiKey": "fc-..."
}
```

| Champ    | Type   | Description                 |
| -------- | ------ | --------------------------- |
| `apiKey` | string | La nouvelle clé API générée |

#### Erreurs {#errors-3}

| État  | Description                                                                                         |
| ----- | --------------------------------------------------------------------------------------------------- |
| `401` | Non autorisé - la clé de plateforme est incorrecte ou non valide                                    |
| `404` | Impossible d’identifier la clé API - la clé n’existe pas ou n’a pas été créée via votre intégration |
| `500` | Erreur interne du serveur - ces erreurs sont surveillées par Firecrawl                              |

## Démarrer {#get-started}

Créez votre intégration dans le [tableau de bord Firecrawl](https://www.firecrawl.dev/app/partner-api) : connectez-vous, choisissez Standard ou Gateway, acceptez l&#39;accord, puis copiez votre clé de plateforme. Le type d&#39;intégration étant difficile à modifier par la suite, vérifiez bien votre choix avant d&#39;accepter l&#39;accord. Appelez ensuite les points de terminaison ci-dessus depuis votre serveur. Des questions sur votre configuration ? Écrivez à [help@firecrawl.com](mailto:help@firecrawl.com). Vous envisagez une intégration de plus grande envergure ? Écrivez à [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev).

## Programme partenaire {#partner-program}

Les plateformes qui provisionnent des comptes Firecrawl pour leurs utilisateurs peuvent candidater au programme partenaire Firecrawl (Firecrawl Partner Program). Les partenaires approuvés bénéficient d&#39;un partage des revenus sur l&#39;utilisation payante des utilisateurs qu&#39;ils apportent, d&#39;actions de co-marketing et d&#39;une présence dans notre annuaire de partenaires, d&#39;un accès anticipé aux nouveaux points de terminaison, d&#39;une ligne directe avec notre équipe pour le support technique, ainsi que de limites plus élevées pour leurs utilisateurs. L&#39;accès au programme se fait sur candidature, et nous répondons sous une semaine.

En contrepartie, les partenaires affichent « Powered by Firecrawl » dans leur produit, avec un lien vers firecrawl.dev incluant leur balise `?ref=<partner>`.

Le partage des revenus s&#39;applique uniquement aux nouveaux clients payants que vous apportez après l&#39;approbation de votre candidature, sans aucun effet rétroactif. Il couvre la première année de chaque client sur les offres self-serve ; les offres Scale et Enterprise en sont exclues. Chaque partenaire est examiné et approuvé par notre équipe.

[Candidater au programme partenaire](https://www.firecrawl.dev/firecrawl-for-platforms/partner-program?source=docs)

Vous écrivez sur Firecrawl ou publiez des liens vers notre site ? Le [programme d&#39;affiliation](https://www.firecrawl.dev/affiliates) est plus adapté.
