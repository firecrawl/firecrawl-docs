## Vue d&#39;ensemble {#overview}

La facturation Firecrawl est **basée sur des crédits**. Chaque appel à l&#39;API que vous effectuez consomme des crédits. Le nombre de crédits dépend du point de terminaison et des options que vous utilisez. Votre offre vous donne droit à un quota mensuel de crédits. Le paiement à l&#39;usage ajoute des crédits supplémentaires lorsque le quota est épuisé.

Pour consulter les tarifs actuels, rendez-vous sur la [page de tarification Firecrawl](https://www.firecrawl.dev/pricing).

<Note>
  Toutes les factures Firecrawl sont émises en **dollars américains (USD)**, quelle que soit votre adresse de facturation ou votre mode de paiement.
</Note>

## Crédits {#credits}

Les crédits sont l’unité d’utilisation dans Firecrawl. Chaque offre inclut un quota mensuel de crédits qui est réinitialisé au début de chaque cycle de facturation. Différents endpoints d’API consomment un nombre de crédits différent.

### Coût en crédits par point de terminaison {#credit-costs-per-endpoint}

| Point de terminaison | Coût en crédits                    | Notes                                                                                                                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Scrape**           | 1 crédit / page                    | Convertit une URL unique en markdown propre, HTML ou données structurées. Des crédits supplémentaires s’appliquent lors de l’utilisation des options d’extraction (voir ci-dessous).                                                                                                                                                                              |
| **Crawl**            | 1 crédit / page                    | Scrape un site web entier en suivant les liens à partir d’une URL de départ. Les mêmes coûts des options d’extraction par page s’appliquent à chaque page explorée.                                                                                                                                                                                               |
| **Map**              | 1 crédit / appel                   | Découvre toutes les URL d’un site web sans scraper leur contenu.                                                                                                                                                                                                                                                                                                  |
| **Search**           | 2 crédits / 10 résultats           | Recherche sur le web et, en option, scrape les résultats. Arrondi à la tranche supérieure par groupe de 10 résultats (par ex., 11 résultats = 4 crédits). Des coûts supplémentaires de scraping par page s’appliquent à chaque résultat qui est scrapé. Voir [ici](/fr/features/search#zero-data-retention-zdr) pour la tarification de la recherche ZDR Enterprise. |
| **Interact**         | 2–7 crédits / minute de navigateur | Session de bac à sable navigateur interactive, facturée par minute de navigateur avec un minimum d’une minute. Les sessions qui utilisent un `prompt` sont facturées à 7 crédits / minute de navigateur ; les sessions sans prompt (uniquement du `code` Playwright) sont facturées à 2 crédits / minute de navigateur.                                           |
| **Agent**            | Dynamique                          | Agent autonome de recherche web. 5 exécutions quotidiennes gratuites ; tarification à l’usage au-delà de ce quota.                                                                                                                                                                                                                                                |

### Coûts en crédits supplémentaires pour les options d’extraction {#additional-credit-costs-for-scrape-options}

Certaines options d’extraction ajoutent des crédits en plus du coût de base par page :

| Option                                                | Coût supplémentaire  | Description                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PDF parsing                                           | +1 crédit / page PDF | Extraire le contenu de documents PDF                                                                                                                                                                                                                                                                                   |
| format JSON (extraction LLM)                          | +4 crédits / page    | Utiliser un LLM pour extraire des données JSON structurées à partir de la page                                                                                                                                                                                                                                         |
| Vérification d’injection de prompt                    | +4 crédits / page    | Protection facultative `checkPromptInjection` pour le format JSON (voir [Détection d’injection de prompt](/fr/features/llm-extract#prompt-injection-detection)). Si l’extraction échoue après l’exécution de la vérification, 5 crédits sont facturés. Voir [Quand les crédits sont facturés](#when-credits-are-charged). |
| Zero Data Retention (ZDR)                             | +1 crédit / page     | Garantit qu’aucune donnée n’est conservée au-delà de la requête (voir [Scrape ZDR](/fr/features/scrape#zero-data-retention-zdr))                                                                                                                                                                                          |
| format `question` ou `query`                          | +4 crédits / page    | Réponse générée par LLM à une question portant sur la page (voir [Scrape](/fr/features/scrape))                                                                                                                                                                                                                           |
| format `highlights`                                   | +4 crédits / page    | Passages pertinents de la page sélectionnés par un LLM (voir [Scrape](/fr/features/scrape))                                                                                                                                                                                                                               |
| format `audio`                                        | +4 crédits / page    | Transcrire l’audio présent sur la page (voir [Scrape](/fr/features/scrape))                                                                                                                                                                                                                                               |
| format `video`                                        | +4 crédits / page    | Transcrire la vidéo présente sur la page (voir [Scrape](/fr/features/scrape))                                                                                                                                                                                                                                             |
| Masquage des PII (`redactPII`)                        | +4 crédits / page    | Masquer les données personnelles du markdown retourné. Chaque page PDF supplémentaire ajoute +4 crédits, en plus de son coût de parsing de +1 (voir [Masquage des PII](/fr/features/pii-redaction))                                                                                                                       |
| `lockdown` (hit du cache)                             | +4 crédits / page    | Servir uniquement depuis le cache, sans jamais interroger la cible. Un défaut de cache ne retourne aucun document et facture 1 crédit (voir [Lockdown](/fr/features/lockdown) et le tableau ci-dessous)                                                                                                                   |
| Proxy avancé (`proxy: "enhanced"` ou escalade `auto`) | +0                   | Facturé au même tarif d’1 crédit qu’une requête basic. Une nouvelle tentative après escalade n’est pas facturée séparément (voir [Mode avancé](/fr/features/enhanced-mode))                                                                                                                                               |

Ces modificateurs se cumulent. Par exemple, scraper une page avec à la fois le format JSON et Zero Data Retention coûte **1 + 4 + 1 = 6 crédits** par page, et le format JSON avec masquage des PII coûte **1 + 4 + 4 = 9 crédits**. Ces mêmes modificateurs s’appliquent aux points de terminaison Crawl et Search, puisqu’ils utilisent `scrape` en interne pour chaque page.

Les requêtes vers `x.com` et les autres URL X/Twitter utilisent l’API Grok et font l’objet d’une tarification distincte. Voir [la facturation de X (x.com)](#x-xcom-billing) en bas de cette page.

### Quand les crédits sont débités {#when-credits-are-charged}

Ce qui détermine la facturation, c’est le fait que Firecrawl ait renvoyé un document, et non que le site cible ait renvoyé un code d’état HTTP de succès.

* **Firecrawl a renvoyé un document : 1 crédit par page**, plus les éventuels coûts d’options ci-dessus. Cela inclut les pages renvoyées avec un état d’erreur tel que 403 Forbidden ou 404 Not Found. La cible a répondu, Firecrawl a capturé cette réponse, et vous la récupérez sous forme de document. Vérifiez le champ `metadata.statusCode` dans la réponse pour repérer ces cas et cesser de relancer des URL systématiquement bloquées.
* **Firecrawl n’a renvoyé aucun document : 0 crédit.** Un scrape qui échoue complètement, par exemple parce que le site n’a jamais répondu ou que toutes les tentatives de rendu ont échoué, n’est pas facturé.

Quelques cas sont malgré tout facturés lorsqu’aucun document n’est renvoyé. Ils couvrent le travail que Firecrawl a déjà effectué pour vous avant la fin du scrape.

| Cas                                   | Ce qui est facturé                                                                                            |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Scan de protection contre les menaces | 2 crédits par URL scannée, y compris pour un scrape que le scan lui-même a bloqué                             |
| Vérification d’injection de prompt    | 5 crédits, dès que la protection `checkPromptInjection` a été exécutée                                        |
| FIRE-1 agent                          | À l’usage, pour la navigation déjà effectuée par l’agent                                                      |
| Défaut de cache `lockdown`            | 1 crédit                                                                                                      |
| Vérification du monitor               | Une page en erreur pendant une vérification est facturée au tarif de base de 1 crédit par page                |
| Sessions Interact et Browser          | Facturées par minute de navigateur de session, avec un minimum d’une minute, que la session ait abouti ou non |

Pour les tâches de **batch scrape** et de **crawl**, les crédits sont facturés de manière asynchrone à mesure que chaque page est traitée, et non au moment où la tâche est soumise. Cela signifie qu’il peut y avoir un délai entre l’envoi d’une tâche et le moment où le coût total en crédits apparaît sur votre compte. Si un batch contient de nombreuses URL ou si des pages sont mises en file d’attente pendant des périodes de fort trafic, des crédits peuvent continuer à être débités et à apparaître minutes ou heures après la soumission. Le polling ou la consultation de l’état d’un batch ne consomment pas de crédits.

<Note>
  **Vérification préalable des crédits pour le crawl :** Lorsque vous transmettez un `limit` explicite, Firecrawl vérifie si la requête est autorisée pour ce montant. Si elle est autorisée, y compris via un dépassement, la limite n’est pas ramenée à votre solde restant. Si elle est refusée, Firecrawl tente d’abaisser la limite au niveau du solde restant et vérifie à nouveau la requête ajustée. Un 402 est renvoyé si aucune limite positive ne peut être utilisée ou si la requête ajustée est refusée, y compris en raison d’un plafond de dépenses par clé d’API.

  Omettre `limit` n’exige pas de disposer de **10,000** crédits à l’avance. La vérification initiale des crédits utilise **1 crédit** ; elle ne réserve pas de crédits pour l’intégralité du crawl. Si la requête est autorisée, la limite par défaut de **10,000** n’est pas réduite pour s’ajuster au solde, bien que d’autres options de crawl puissent modifier la limite effective. Les pages sont facturées à mesure qu’elles sont traitées. Transmettez un `limit` explicite lorsque vous souhaitez définir un nombre maximal de pages (par exemple, `limit: 100`).
</Note>

* **API** : utilisez les points de terminaison [Credit Usage](/fr/api-reference/endpoint/credit-usage) et [Credit Usage Historical](/fr/api-reference/endpoint/credit-usage-historical) pour vérifier votre consommation par programmation

## Offres {#plans}

Les offres d’abonnement sont facturées au mois ou à l’année. Les offres payantes en libre-service peuvent aussi utiliser le paiement à l’usage. Le paiement à l’usage ajoute des crédits lorsque le quota de votre offre est épuisé. Consultez [Paiement à l’usage](#pay-as-you-go).

### Offres payantes {#paid-plans}

| Offre        | Crédits mensuels | Navigateur concurrent |
| ------------ | ---------------- | --------------------: |
| **Hobby**    | 5,000            |                     5 |
| **Standard** | 100,000          |                    25 |
| **Growth**   | 500,000          |                    50 |
| **Scale**    | 1,000,000        |                   100 |

<Note>
  Pour des besoins au‑delà de Scale, Firecrawl propose des offres **Enterprise** avec des crédits personnalisés, une assistance dédiée, des SLA, des remises sur volume, aucune rétention de données et le SSO. Consultez la [page Enterprise](https://www.firecrawl.dev/enterprise) pour plus de détails.
</Note>

Toutes les offres payantes sont disponibles avec une facturation **mensuelle** ou **annuelle**. La facturation annuelle propose une remise par rapport au paiement mensuel. Pour les tarifs actuels de chaque offre, consultez la [page de tarification](https://www.firecrawl.dev/pricing).

### Offre Free {#free-plan}

Les nouveaux comptes démarrent sur l&#39;offre Free. Elle est gratuite et ne nécessite aucune carte bancaire. Voici ce qu&#39;elle inclut :

* **1 000 crédits par mois.** Le quota est réinitialisé au début de chaque cycle mensuel. Les crédits gratuits non utilisés ne sont pas reportés.
* **2 navigateurs concurrents**, avec le même maximum de 50 000 tâches en file d&#39;attente que les offres payantes en libre-service.
* **Des limites de débit de 10 requêtes par minute** sur `/scrape`, `/map` et `/search`, et de **2 requêtes par minute** sur `/crawl`, `/agent` et `/interact`. Le batch scrape partage la limite du scrape et extract partage celle de l&#39;agent. Consultez les [limites de débit](/fr/rate-limits) pour le tableau complet.
* **Tous les points de terminaison principaux du produit.** Scrape, crawl, map, search, extract, batch scrape, interact et monitor fonctionnent tous avec l&#39;offre Free. Certaines fonctionnalités d&#39;administration d&#39;équipe et d&#39;entreprise sont activées par équipe plutôt que par offre, notamment la protection contre les menaces, la journalisation SIEM et la recherche zero data retention. Les coûts en crédits sont identiques sur toutes les offres : le tableau des [coûts en crédits par point de terminaison](#credit-costs-per-endpoint) ci-dessus s&#39;applique donc tel quel.

L&#39;offre Free n&#39;inclut pas le paiement à l&#39;usage : les requêtes renvoient donc un HTTP 402 dès que le quota mensuel est épuisé. Consultez [Épuisement des crédits](#running-out-of-credits). Elle n&#39;inclut pas non plus le report de crédits, d&#39;accord de traitement des données, ni de support Slack. Le support est assuré par la communauté.

Scrape, Search et Interact fonctionnent également sans aucune API key, via le niveau gratuit sans clé, plafonné par adresse IP et par jour plutôt que par un quota de crédits. Consultez [Sans clé (aucune API key)](/fr/rate-limits#keyless-no-api-key).

### Cycle de facturation {#billing-cycle}

* **Offres mensuelles** : les crédits sont réinitialisés à votre date de renouvellement mensuelle
* **Offres annuelles** : vous êtes facturé une fois par an, mais les crédits sont tout de même réinitialisés chaque mois à votre date de renouvellement mensuelle virtuelle
* **Par défaut, les crédits d’offre inutilisés ne sont pas reportés** : votre quota mensuel est réinitialisé chaque mois. **Les offres annuelles Scale reportent les crédits d’offre inutilisés pendant 1 mois**, et **les offres annuelles Enterprise les reportent pendant 2 mois**.

### Navigateurs concurrents {#concurrent-browsers}

Les navigateurs concurrents correspondent au nombre de pages web que Firecrawl peut traiter en parallèle pour vous. Votre offre détermine cette limite. Si vous la dépassez, les tâches supplémentaires attendent dans une file d’attente jusqu’à ce qu’un créneau se libère. Consultez [Limites de débit](/fr/rate-limits) pour tous les détails sur la concurrence et les limites de débit de l’API.

## Paiement à l’usage {#pay-as-you-go}

Le paiement à l’usage permet à vos requêtes de continuer à s&#39;exécuter lorsque les crédits de votre offre sont épuisés. Il ajoute automatiquement des crédits à votre compte.

Vous achetez des crédits par incréments de 5 USD. Lorsque votre solde de crédits atteint zéro, nous ajoutons un incrément à votre compte et débitons la carte enregistrée.

Le paiement à l’usage nécessite une offre en libre-service payante. Vous ne pouvez pas l&#39;utiliser avec l&#39;offre gratuite.

Vous pouvez également acheter des crédits vous-même à tout moment. Utilisez **Charger plus de crédits** dans vos [paramètres de facturation](https://www.firecrawl.dev/app/settings?tab=billing). Saisissez un multiple de 5 USD et payez avec la carte enregistrée. Cela fonctionne, que le paiement à l’usage soit activé ou désactivé.

### Crédits par incrément {#credits-in-a-batch}

Le nombre de crédits par incrément dépend de votre offre. Le paiement à l&#39;usage et les achats manuels appliquent le même tarif.

| Offre        | Crédits pour 5 USD |
| ------------ | ------------------ |
| **Hobby**    | 1 000              |
| **Standard** | 2 000              |
| **Growth**   | 2 500              |
| **Scale**    | 5 000              |

### Définir la limite mensuelle de paiement à l’usage {#set-the-monthly-auto-reload-limit}

Définissez votre **limite mensuelle de paiement à l’usage** à l’un des deux endroits suivants :

* Dans vos [paramètres de facturation](https://www.firecrawl.dev/app/settings?tab=billing), dans l’onglet **Facturation**.
* Sur la [page de tarification](https://www.firecrawl.dev/pricing), lorsque vous choisissez une offre.

### Comment la limite plafonne vos dépenses mensuelles {#how-the-limit-caps-your-monthly-spend}

Votre limite correspond au montant maximal que le paiement à l&#39;usage peut dépenser chaque mois. Elle est arrondie à l&#39;inférieur au multiple de 5 USD le plus proche.

Par exemple, une limite de 25 USD autorise cinq incréments par mois. Une limite de 22 USD autorise quatre incréments, car elle est arrondie à l&#39;inférieur à 20 USD.

Les crédits achetés manuellement ne sont pas pris en compte dans cette limite.

## Limites de dépense des API keys {#api-key-spend-limits}

Une limite de dépense plafonne les crédits qu&#39;une API key peut consommer. Ce plafond ne s&#39;applique qu&#39;à cette key, quel que soit le solde de votre équipe. Utilisez-la pour éviter qu&#39;une seule key n&#39;épuise tout le solde de l&#39;équipe.

Vous pouvez également renommer n&#39;importe quelle API key, y compris la key nommée **Default** que Firecrawl crée avec votre équipe.

Le propriétaire de la key ou un administrateur de l&#39;équipe peut effectuer ces deux opérations. Ouvrez la [page API keys](https://www.firecrawl.dev/app/api-keys) dans le tableau de bord, puis ouvrez le menu de la key.

* Cliquez sur **Rename** pour modifier le **Key Name**.
* Cliquez sur **Set limit** pour ouvrir **Set a spend limit**. Saisissez un **Credit limit**, choisissez **per day**, **per week** ou **per month**, puis cliquez sur **Save**.

Une limite s&#39;exprime en nombre de crédits, et non en montant monétaire. Une limite de `1` signifie un crédit par période. Cliquez sur **Remove limit** pour supprimer la limite.

## Mise à niveau et rétrogradation {#upgrading-and-downgrading}

* Les **mises à niveau** prennent effet immédiatement. Le prix complet de la nouvelle offre vous est facturé aujourd’hui (sans prorata), et votre cycle de facturation est réinitialisé. Votre prochain renouvellement aura lieu un mois ou un an après la date de mise à niveau. Tous les crédits inutilisés de votre offre précédente sont reportés, et votre nouveau quota de crédits ainsi que vos limites de concurrence s’appliquent immédiatement.
* Les **rétrogradations** sont programmées pour prendre effet à votre prochaine date de renouvellement. Vous conservez les crédits et limites de votre offre actuelle jusqu’à cette date, et le temps inutilisé sur votre offre actuelle n’est ni crédité ni remboursé. Vous pouvez annuler une rétrogradation programmée depuis vos [paramètres de facturation](https://www.firecrawl.dev/app/settings?tab=billing) à tout moment avant la date d’effet.

### Basculer entre la facturation mensuelle et annuelle {#switching-between-monthly-and-yearly-billing}

* **Mensuel → Annuel** au même niveau de crédits ou à un niveau supérieur est considéré comme une mise à niveau immédiate.
* **Annuel → Mensuel** est considéré comme une mise à niveau immédiate uniquement si vous passez à un niveau de crédits strictement supérieur.

## Épuisement des crédits {#running-out-of-credits}

Ce qui se passe lorsque votre solde atteint zéro dépend de votre offre et de votre paramètre de paiement à l’usage.

| Offre                              | Paiement à l’usage         | À solde nul                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Free**                           | Non disponible                 | Les requêtes qui consomment des crédits renvoient **HTTP 402 (Payment Required)** jusqu&#39;au reset mensuel.                                                                                                                                                                                                            |
| **Hobby, Standard, Growth, Scale** | Désactivé (limite fixée à `0`) | Les requêtes qui consomment des crédits renvoient **HTTP 402**. Votre carte n&#39;est pas débitée.                                                                                                                                                                                                                       |
| **Hobby, Standard, Growth, Scale** | Activé                         | Firecrawl débite votre carte d&#39;un incrément de 5 USD et ajoute les crédits correspondants. Vos requêtes se poursuivent. L&#39;opération se répète chaque fois que le solde atteint zéro, jusqu&#39;à ce que votre **limite mensuelle de paiement à l’usage** soit atteinte. Laissez la limite vide pour ne fixer aucun plafond. |

Lorsque le paiement à l’usage est activé, les requêtes ne sont pas interrompues dès que le solde atteint zéro. Votre offre inclut une marge de dépassement afin qu&#39;un pic de requêtes puisse continuer à s&#39;exécuter pendant qu&#39;un rechargement se règle : **1 500 crédits sur Hobby, 30 000 sur Standard, 150 000 sur Growth et 600 000 sur Scale**. Une fois la limite mensuelle atteinte et la marge consommée, les requêtes renvoient **HTTP 402** jusqu&#39;au billing cycle suivant. Cette marge est une réserve temporaire, et non des crédits supplémentaires que vous conservez.

Les crédits achetés manuellement (**Charger plus de crédits**) sont dépensés en premier, avant que tout cela ne s&#39;applique, et ne sont pas comptabilisés dans la limite mensuelle de paiement à l’usage.

Pour reprendre votre usage après un arrêt complet, vous pouvez :

1. Définir une **limite mensuelle de paiement à l’usage** pour acheter des crédits automatiquement. Voir [Paiement à l&#39;usage](#pay-as-you-go).
2. Effectuer manuellement une mise à niveau vers une offre supérieure
3. Attendre le reset de vos crédits au prochain billing cycle

## Coupons {#coupons}

Firecrawl prend en charge deux types de coupons :

* **Les coupons d’abonnement** appliquent une réduction à votre abonnement (par ex. un pourcentage de réduction sur votre tarif mensuel ou annuel). Ils peuvent **uniquement** être appliqués pendant le processus de paiement Stripe, lorsque vous souscrivez pour la première fois à une offre payante ou changez d’offre. Vous ne pouvez pas appliquer un coupon d’abonnement une fois le paiement terminé.
* **Les coupons de crédit** ajoutent des crédits bonus à votre compte. Ils peuvent être utilisés depuis la section **Facturation** de votre tableau de bord à l’adresse [firecrawl.dev/app/billing](https://www.firecrawl.dev/app/billing). Recherchez le champ de saisie du coupon sur la page de facturation pour appliquer votre code. Les crédits bonus issus des coupons de crédit sont distincts du quota mensuel de votre offre et sont conservés même si vous passez à une offre supérieure ou inférieure.

## Facturation X (x.com) {#x-xcom-billing}

Firecrawl utilise l&#39;**API Grok** officielle de [xAI](https://x.ai/) pour fournir une synthèse par IA, une extraction structurée et un accès en temps réel au contenu public de X. Les requêtes visant des URL de profils et de publications sur `x.com`, `twitter.com` et `mobile.twitter.com` sont traitées via les outils internes autorisés de Grok (`x_search`, récupération de fils et recherche web limitée à x.com) plutôt que par du scraping web traditionnel.

### Coût en crédits {#credit-costs}

| Composant        | Coût en crédits       | Description                                                            |
| ---------------- | --------------------- | ---------------------------------------------------------------------- |
| **Coût de base** | 1 crédit / requête    | Traitement standard d’une requête de scraping                          |
| **Grok X Query** | +29 crédits / requête | Utilisation de l’API Grok (tokens + appels d’outils) pour le contenu X |

Par exemple, le traitement d’une requête typique sur une publication ou un fil coûte **30 crédits** (`1` de base + `29` Grok X Query) et renvoie des données structurées générées par Grok, le contexte du fil et des résumés. Si le format JSON (extraction LLM) est également activé, le total est de **34 crédits** par requête.

Cette méthode respecte les interfaces publiées par X dans le cadre de son partenariat avec xAI et fournit des résultats de meilleure qualité, plus réfléchis, plutôt qu’un simple scraping brut de la page.

<Note>
  **Les capacités diffèrent du scraping standard.** Grok renvoie des résultats traités par l’IA, qui peuvent inclure des résumés, des indicateurs clés, le contexte du fil, etc. Pour obtenir des données structurées brutes à grande échelle, utilisez [l’API officielle X Enterprise](https://developer.x.com/).
</Note>
