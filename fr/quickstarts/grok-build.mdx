Connectez [Grok Build](https://docs.x.ai/build/overview), la CLI d&#39;agent de codage de xAI (`grok`), à Firecrawl via le serveur MCP hébergé. OAuth est la méthode de configuration interactive recommandée : avec OAuth, la clé n&#39;apparaît ni dans la ligne de commande, ni dans les fichiers du projet, ni dans la conversation.

## Configuration rapide {#quick-setup}

### 1. Ajouter Firecrawl {#1-add-firecrawl}

Exécutez :

```bash
grok mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
```

`https://mcp.firecrawl.dev/v2/mcp-oauth` est une valeur de configuration côté client, et non une page à ouvrir directement dans un navigateur.

### 2. Connexion et vérification {#2-sign-in-and-verify}

Démarrez Grok Build :

```bash
grok
```

Saisissez `/mcps`, sélectionnez `firecrawl`, puis appuyez sur `i` pour démarrer la connexion dans le navigateur. Choisissez une équipe, puis autorisez l&#39;accès. Grok stocke les jetons OAuth dans `~/.grok/mcp_credentials.json`.

Vérifiez qu&#39;un seul serveur `firecrawl` est actif, puis essayez :

```text
Recherche sur le Web les dernières notes de version de Next.js et résume les sources.
```

```text
Extrais https://docs.firecrawl.dev et liste les sections de premier niveau.
```

## MCP local avec une clé API {#local-mcp-with-an-api-key}

N&#39;utilisez le serveur local que si vous avez besoin d&#39;un processus local ou d&#39;une API Firecrawl auto-hébergée. Le paquet local nécessite Node.js 22 ou une version ultérieure.

Définissez `FIRECRAWL_API_KEY` dans l&#39;environnement à partir duquel vous démarrez Grok. Ajoutez ensuite ce bloc à `~/.grok/config.toml` :

```toml
[mcp_servers.firecrawl]
command = "npx"
args = ["-y", "firecrawl-mcp@3.33.2"]
env = { FIRECRAWL_API_KEY = "${FIRECRAWL_API_KEY}" }
startup_timeout_sec = 60
```

Grok substitue la valeur de `${FIRECRAWL_API_KEY}` au chargement de la configuration : la clé n&#39;est donc pas écrite dans le fichier. Ne partagez pas ce secret dans le chat de l&#39;agent et ne le versionnez pas. N&#39;utilisez qu&#39;une seule entrée `firecrawl` : supprimez d&#39;abord le serveur hébergé avec `grok mcp remove firecrawl`.

Pour les paramètres self-hosted, voir [Exécuter MCP en local](/fr/mcp-server/local).

## Autres modes de connexion {#other-connection-modes}

* [Essayez le MCP sans clé](/fr/mcp-server/keyless#try-keyless) pour la recherche, l&#39;extraction et l&#39;analyse, sans compte ni clé.
* [Configurez une clé API](/fr/mcp-server/keyless#add-an-api-key) pour utiliser le serveur hébergé sans intervention. Ne communiquez pas le secret dans le chat de l&#39;agent : utilisez plutôt une référence à une variable d&#39;environnement.

## Dépannage {#troubleshooting}

* **Un serveur Firecrawl existe déjà :** exécutez `grok mcp remove firecrawl`, ajoutez une seule fois la connexion souhaitée, puis démarrez une nouvelle session.
* **Grok affiche un second serveur `firecrawl` :** Grok charge également les serveurs MCP depuis `~/.claude.json`, `.cursor/mcp.json` et les fichiers `.mcp.json` du projet. Exécutez `grok inspect` pour identifier l’origine de chaque serveur, puis supprimez le doublon.
* **Le serveur affiche `401` :** saisissez `/mcps`, sélectionnez `firecrawl`, puis appuyez sur `i` pour vous reconnecter. Ne collez jamais de clé API dans la conversation ni dans l’URL OAuth.
* **Le serveur local ne se connecte pas :** exécutez `grok mcp doctor firecrawl`. Grok consigne les erreurs du serveur dans `~/.grok/logs/mcp/firecrawl.stderr.log`. Si `npx` télécharge le paquet au premier démarrage, augmentez `startup_timeout_sec`.
