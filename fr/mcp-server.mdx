Firecrawl MCP permet aux clients IA d&#39;accéder à des données web en temps réel via le Model Context Protocol. Utilisez le serveur hébergé pour une configuration plus rapide, ou [exécutez localement le serveur open source](/fr/mcp-server/local) si vous avez besoin d&#39;un processus local ou d&#39;une API Firecrawl auto-hébergée.

Cette page constitue le guide de configuration de référence pour Firecrawl MCP hébergé.

<div id="setup-firecrawl-mcp-server">
  ## Configurer le serveur MCP Firecrawl
</div>

Pour un client interactif, connectez-vous via OAuth. Le client ouvre Firecrawl dans votre navigateur afin que vous puissiez vous connecter, choisir une équipe et autoriser l’accès sans avoir à copier de clé API.

<Tabs>
  <Tab title="Codex">
    Ajoutez le serveur hébergé et terminez la connexion OAuth :

    ```bash
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp-oauth
    codex mcp login firecrawl
    ```

    Démarrez ou redémarrez l’application Codex, l’interface CLI ou l’extension IDE. Saisissez `/mcp` pour vérifier que `firecrawl` est connecté.
  </Tab>

  <Tab title="Claude Desktop">
    1. Ouvrez **Paramètres &gt; Connecteurs**.
    2. Sélectionnez **Ajouter un connecteur personnalisé**.
    3. Saisissez `https://mcp.firecrawl.dev/v2/mcp-oauth` comme URL du serveur MCP distant.
    4. Sélectionnez **Se connecter**, puis connectez-vous à Firecrawl et autorisez l’accès.

    <Note>
      Les serveurs distants doivent être ajoutés depuis **Paramètres &gt; Connecteurs**. Le fichier `claude_desktop_config.json` est destiné aux serveurs MCP locaux.
    </Note>
  </Tab>

  <Tab title="Claude Code">
    Ajoutez le serveur hébergé :

    ```bash
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    Saisissez `/mcp` dans Claude Code, choisissez `firecrawl`, puis terminez la connexion dans le navigateur.
  </Tab>

  <Tab title="Cursor">
    Ajoutez le serveur hébergé à `~/.cursor/mcp.json` :

    ```json
    {
      "mcpServers": {
        "firecrawl": {
          "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
        }
      }
    }
    ```

    Enregistrez le fichier, ouvrez les paramètres MCP de Cursor et terminez la connexion à Firecrawl. Cursor met ensuite les outils Firecrawl à la disposition de l’Agent.
  </Tab>

  <Tab title="Autres clients">
    Configurez un client MCP distant compatible OAuth avec l’URL suivante :

    ```text
    https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    Si le client demande un Client ID ou un Client Secret OAuth, laissez les deux champs vides. Les clients compatibles utilisent des documents de métadonnées Client ID ou l’enregistrement dynamique des clients.

    Si le client ne peut pas effectuer OAuth à distance, utilisez la configuration par clé API ci-dessous. S’il ne peut pas envoyer d’en-têtes de requête, [exécutez Firecrawl MCP localement](/fr/mcp-server/local).
  </Tab>
</Tabs>

Les connexions OAuth reçoivent des jetons de courte durée liés à une ressource, plutôt que votre clé API Firecrawl. Vous pouvez les consulter et les révoquer dans les [paramètres MCP](https://www.firecrawl.dev/app/settings?tab=mcp).

<div id="set-up-with-an-api-key">
  ## Configurer avec une clé API
</div>

Utilisez une clé API pour l’intégration continue, les serveurs, les scripts ou tout autre client ne pouvant pas effectuer OAuth dans le navigateur. [Créez une clé API Firecrawl](https://www.firecrawl.dev/app/api-keys), stockez-la dans une variable d’environnement ou un gestionnaire de secrets, puis connectez-vous au point de terminaison MCP hébergé complet.

<Tabs>
  <Tab title="Codex">
    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp \
      --bearer-token-env-var FIRECRAWL_API_KEY
    ```
  </Tab>

  <Tab title="Claude Code">
    Claude Code développe la variable d’environnement lors de la connexion :

    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp \
      --header 'Authorization: Bearer ${FIRECRAWL_API_KEY}'
    ```
  </Tab>

  <Tab title="Autres clients">
    Configurez le client pour envoyer la clé API comme bearer token :

    ```text
    URL: https://mcp.firecrawl.dev/v2/mcp
    Authorization: Bearer <FIRECRAWL_API_KEY>
    ```

    La configuration de l’en-tête varie selon le client. Conservez la clé dans l’environnement du client ou dans un stockage de secrets protégé.
  </Tab>
</Tabs>

<Warning>
  Ne placez jamais une clé API dans un fichier de configuration de projet, ne la collez pas dans une discussion et ne la partagez pas dans un screenshot ou un ticket. Les nouvelles configurations doivent utiliser OAuth ou un en-tête Authorization basé sur une variable d’environnement, jamais une URL contenant des identifiants.
</Warning>

<div id="try-without-an-api-key">
  ## Essayer sans clé API
</div>

Pour essayer Firecrawl sans créer de compte, ajoutez le point de terminaison sans clé à n’importe quel client prenant en charge MCP à distance :

```text
https://mcp.firecrawl.dev/v2/mcp
```

Le MCP sans clé est soumis à des limites de débit par réseau et donne accès uniquement à **Recherche, Scrape et Parse** tant que vous y êtes éligible. Connectez-vous via OAuth ou avec une clé API si vous avez besoin de l’ensemble complet d’outils ou de limites plus élevées.

<Accordion title="Que se passe-t-il lorsque j’atteins la limite du mode sans clé ?">
  Lorsqu’il est disponible, le message d’erreur MCP indique le délai avant de pouvoir réessayer. Attendez ce délai pour continuer à utiliser le mode sans clé, ou connectez-vous immédiatement via OAuth ou avec une clé API.
</Accordion>

<div id="verify-your-connection">
  ## Vérifiez votre connexion
</div>

Ouvrez l’état MCP ou la liste des outils de votre client et vérifiez que `firecrawl` est connecté. Une connexion sans clé affiche `firecrawl_search`, `firecrawl_scrape` et `firecrawl_parse` ; une connexion authentifiée peut donner accès à l’[ensemble complet des outils](/fr/mcp-server/tools), selon l’offre, le déploiement et la politique de l’équipe.

Essayez une requête en lecture seule :

```text
Recherche sur le web les dernières notes de version de Firecrawl et résume les sources.
```

Si aucun outil Firecrawl n’apparaît, redémarrez ou rechargez le client après avoir enregistré sa configuration MCP. En cas d’erreur de processus local, par exemple `spawn npx ENOENT`, consultez [Exécuter Firecrawl MCP localement](/fr/mcp-server/local#troubleshooting).

<div id="compatibility-and-legacy-setup">
  ## Compatibilité et configuration héritée
</div>

<AccordionGroup>
  <Accordion title="Prise en charge des URL héritées avec clé API">
    <Warning>
      Ce format hérité est uniquement destiné aux configurations et clients existants qui ne peuvent pas effectuer OAuth ni envoyer un en-tête Authorization personnalisé. Il n’est pas recommandé pour les nouvelles intégrations.
    </Warning>

    ```text
    https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
    ```

    La clé API fait partie de l’URL : traitez donc l’URL complète comme un mot de passe. Si elle est exposée, effectuez une rotation de la clé. Cette solution de repli s’applique uniquement à l’ensemble de la surface `/v2/mcp`. Elle ne fonctionne pas pour la ressource de recherche réservée à OAuth.
  </Accordion>

  <Accordion title="Connexions OAuth existantes">
    Les connexions OAuth existantes à `/v2/mcp` restent prises en charge pendant la migration vers le point de terminaison dédié au compte. Les nouvelles connexions de compte interactives doivent utiliser `/v2/mcp-oauth` ; les nouveaux jetons pour cette ressource de compte ne sont pas acceptés par `/v2/mcp`.
  </Accordion>
</AccordionGroup>
