Firecrawl Developer est un index conçu pour les agents de codage. Il couvre les tickets GitHub, les pull requests fusionnées, les README de dépôts et des sites de documentation sélectionnés, afin qu’un agent puisse répondre, à partir de sources primaires plutôt que d’une page web générale, à une question sur le comportement du code, une bibliothèque ou un framework, un contrat d’API, un message d’erreur ou un bug connu.

* Trouvez le ticket ou la pull request dans lequel un bug a été signalé et corrigé
* Lisez les passages d’un README ou d’une page de documentation qui répondent à une question précise
* Remontez d’un contrat d’API à la pull request qui l’a modifié
* Retrouvez la discussion à l’origine d’un message d’erreur

<Note>
  Pour donner à votre agent de codage accès à l’Index Developer, nous recommandons notre [CLI](/fr/sdks/cli) ou notre [serveur MCP](/fr/mcp-server) — les deux l’exposent comme un outil natif, afin que l’agent y recoure sans qu’on lui indique le point de terminaison.
</Note>

<div id="two-ways-in">
  ## Deux façons d’y accéder
</div>

| Interface                                                                            | À utiliser lorsque                                                                                                                        |
| ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| La catégorie `developer` sur [`/search`](/fr/features/search)                           | Vous souhaitez obtenir, en un seul appel, des résultats pour développeur et des résultats web classiques                             |
| Le [point de terminaison de recherche pour développeurs](#developer-search-endpoint) | Vous souhaitez uniquement des résultats pour développeur classés par pertinence, avec les passages correspondants et les filtres d’index |

<div id="developer-category-on-search">
  ## Catégorie développeur sur `/search`
</div>

Passez `developer` dans le tableau `categories` de `/search`. L’API renvoie les résultats pour développeur dans un groupe `developer`, à côté de `web`, et les deux SDK exposent ce groupe via `.developer`.

Aucune clé API n’est nécessaire pour commencer : `/search` accepte les requêtes sans clé, y compris la catégorie `developer`, dans la limite du [quota sans clé](/fr/rate-limits#keyless-no-api-key). Utilisez une clé pour bénéficier de limites de débit plus élevées.

<CodeGroup>
  ```bash cURL
  # Aucune clé API n’est nécessaire pour commencer ; ajoutez -H "Authorization: Bearer $FIRECRAWL_API_KEY" pour bénéficier de limites de débit plus élevées :
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(
      # Aucune clé API n’est nécessaire pour commencer ; ajoutez-en une pour bénéficier de limites de débit plus élevées :
      # api_key="fc-YOUR-API-KEY",
  )

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // Aucune clé API n’est nécessaire pour commencer ; ajoutez-en une pour bénéficier de limites de débit plus élevées :
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

Les résultats pour développeur de ce groupe contiennent `url`, `title`, `description` et `position`. Ils ont la même structure qu’un résultat web, avec en plus `category: "developer"`. Les résultats web de la même réponse n’ont pas de champ `category` : utilisez donc ce champ si vous fusionnez les deux groupes.

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://example.com/blog/retry-strategies",
        "title": "Retry strategies for HTTP clients",
        "description": "An overview of backoff and retry patterns"
      }
    ],
    "developer": [
      {
        "url": "https://github.com/firecrawl/firecrawl/issues/1234",
        "title": "Retries are not applied to 429 responses",
        "description": "Reported behavior and the fix that landed",
        "position": 1,
        "category": "developer"
      }
    ]
  }
}
```

<Note>
  **Utilisateurs du SDK :** les résultats pour développeur sont regroupés séparément, et non dans `.web`. Accédez-y avec `result.developer`.
</Note>

<div id="developer-search-endpoint">
  ## Point de terminaison de recherche pour développeurs
</div>

| Tâche                               | Point de terminaison                                                          |
| ----------------------------------- | ----------------------------------------------------------------------------- |
| Rechercher dans l’Index Developer | [`GET` ou `POST /search/developer`](/fr/api-reference/endpoint/developer-search) |

Une recherche pour développeurs coûte 2 crédits par tranche de 10 résultats, avec arrondi à l’entier supérieur (1 à 10 résultats = 2 crédits, 11 à 20 = 4 crédits, etc.). Aucune clé API n’est nécessaire pour commencer ; fournissez-en une pour bénéficier de limites de débit plus élevées.

<CodeGroup>
  ```bash cURL
  # No API key needed to get started; add -H "Authorization: Bearer $FIRECRAWL_API_KEY" for higher rate limits:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"]
    }'
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

<Note>
  Les SDK Python et Node accèdent à l’Index Developer via la catégorie `developer` indiquée ci-dessus. Ils n’exposent pas de méthode dédiée pour ce point de terminaison ; appelez-le donc via HTTP, la [CLI](/fr/sdks/cli) ou [MCP](/fr/mcp-server).
</Note>

<div id="filters">
  ### Filtres
</div>

Tous les filtres sont facultatifs.

| Filtre      | Signification                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `k`         | Nombre de résultats classés à renvoyer. Valeur par défaut : 20 ; maximum : 100                                   |
| `types`     | Types de résultats à rechercher : `doc`, `issue`, `pull_request` ou `readme`. Par défaut, les quatre sont inclus |
| `repos`     | Slugs des dépôts auxquels limiter la recherche, par exemple `firecrawl/firecrawl`                                |
| `sources`   | Identifiants des sources de documentation auxquels limiter la recherche, avec un maximum de 20. Voir ci-dessous  |
| `passages`  | Passages correspondants à renvoyer par résultat. Valeur par défaut : 1 ; maximum : 5                             |
| `language`  | Langue du dépôt                                                                                                  |
| `topic`     | Sujet du dépôt                                                                                                   |
| `license`   | Licence du dépôt                                                                                                 |
| `min_stars` | Nombre minimal d&#39;étoiles du dépôt                                                                            |
| `max_stars` | Nombre maximal d&#39;étoiles du dépôt                                                                            |
| `archived`  | Inclure ou exclure les dépôts archivés                                                                           |
| `fork`      | Inclure ou exclure les forks                                                                                     |

Les filtres pouvant être répétés acceptent l&#39;un ou l&#39;autre format avec `GET` : un paramètre de requête répété, tel que `types=issue&types=pull_request`, ou une valeur unique séparée par des virgules, telle que `types=issue,pull_request`. Avec `POST`, transmettez un tableau dans le corps JSON.

<div id="how-repos-and-sources-scope-a-search">
  ### Comment `repos` et `sources` définissent le périmètre d’une recherche
</div>

L’index est divisé en deux parties, et ces deux filtres définissent indépendamment leur périmètre :

* `repos` définit le périmètre de la partie GitHub, c’est-à-dire les types `issue`, `pull_request` et `readme`
* `sources` définit le périmètre de la partie documentation, c’est-à-dire le type `doc`
* Passer les deux combine les deux parties au lieu de les croiser : vous obtenez donc des résultats correspondants de l’une ou l’autre

Comme chaque filtre ne s’applique qu’à une seule partie, un filtre qui ne peut correspondre à aucun type demandé est rejeté plutôt que de ne rien renvoyer silencieusement :

* `repos` sans type GitHub dans `types` renvoie `400` avec `repos cannot match any requested type; add github types or drop repos`
* `sources` sans `doc` dans `types` renvoie `400` avec `sources cannot match any requested type; add doc or drop sources`

<div id="which-values-sources-accepts">
  ### Valeurs acceptées par `sources`
</div>

`sources` n’est pas une énumération fixe. Il accepte des identifiants de sources de documentation, chacun étant une chaîne non vide d’au plus 512 caractères, avec un maximum de 20 par requête. Les identifiants reflètent les sites de documentation présents dans l’index, et cet ensemble s’agrandit au fil du temps.

Pour vérifier qu’un identifiant est résolu, transmettez-le et consultez le tableau `sources` ajouté à la réponse. Il n’apparaît que lorsque vous avez envoyé `sources` et indique chaque identifiant exactement tel que vous l’avez demandé, ainsi que s’il est indexé :

```json
{
  "success": true,
  "results": [],
  "sources": [
    { "source": "some-docs-site", "indexed": true },
    { "source": "unknown-docs-site", "indexed": false }
  ]
}
```

`indexed: true` signifie que la source possède une génération publiée ; des éléments probants issus de sa documentation peuvent donc apparaître. `indexed: false` signifie qu&#39;aucun élément associé à cet identifiant ne peut correspondre, ce qui permet de distinguer un identifiant absent de l’index d&#39;une query qui n&#39;a simplement renvoyé aucun résultat.

`repos` est renvoyé de la même manière, sous la forme d&#39;un tableau `repos` indiquant `indexed` ainsi qu&#39;une répartition par type entre `issue`, `pullRequest` et `readme`.

<div id="response">
  ### Réponse
</div>

```json
{
  "success": true,
  "results": [
    {
      "id": "issue:firecrawl/firecrawl#1234",
      "type": "issue",
      "url": "https://github.com/firecrawl/firecrawl/issues/1234",
      "title": "Retries are not applied to 429 responses",
      "passages": [
        {
          "text": "The client treats 429 as a terminal status, so the backoff never runs."
        }
      ]
    }
  ],
  "coverage": {
    "doc": "ok",
    "issue": "ok",
    "pull_request": "ok",
    "readme": "ok"
  },
  "reranked": true
}
```

* `id` est un identifiant de résultat stable, par exemple `issue:owner/repo#123`
* `type` est l’un des suivants : `doc`, `issue`, `pull_request` ou `readme`
* `title` est facultatif et souvent absent des résultats `doc`, lorsque la page source ne comporte aucun titre utilisable. Utilisez plutôt `url` sans supposer que ce champ est présent
* `passages` contient les passages correspondants au format Markdown, afin de préserver les tableaux et les blocs de code
* `coverage` indique l’état de l’index pour chaque type de résultat : `ok`, `degraded`, `unavailable` ou `skipped`
* `reranked` indique si la liste classée est passée par l’étape de reclassement

Vérifiez `coverage` lorsqu’un type de résultat attendu est absent. Un état `degraded` ou `unavailable` signifie que l’absence est due à l’index plutôt qu’à la requête.

<div id="use-it-from-mcp">
  ## Utilisation depuis MCP
</div>

Le [serveur MCP](/fr/mcp-server) hébergé expose les deux interfaces, sans effectuer aucune écriture. Connectez-vous via OAuth de compte ou avec une clé API, comme décrit dans [Connecter Firecrawl MCP](/fr/mcp-server/connect). Avec une connexion hébergée sans clé, `firecrawl_search` avec `categories: ["developer"]` renvoie des résultats pour développeur, tandis que l’outil dédié `firecrawl_developer_search` ne fait pas partie de l’[ensemble d’outils sans clé](/fr/mcp-server/tools) et nécessite une connexion de compte ou une clé API.

<div id="developer-search-tool-firecrawl_developer_search">
  ### outil de recherche pour développeurs (`firecrawl_developer_search`)
</div>

Recherchez uniquement dans l’Index Developer et obtenez des résultats classés avec les passages correspondants.

```json
{
  "name": "firecrawl_developer_search",
  "arguments": {
    "query": "how do I configure retries",
    "k": 10
  }
}
```

<div id="developer-search-tool-options">
  #### Options de l’outil de recherche pour développeurs :
</div>

* `query` : Chaîne de requête de recherche (obligatoire)
* `k` : Nombre de résultats classés à renvoyer, de 1 à 100

**Idéal pour :** Répondre, à partir de sources primaires, à une question sur le comportement du code, une bibliothèque ou un framework, un contrat d’API, un message d’erreur ou un bogue connu.
**Renvoie :** Chaque résultat sous forme de bloc Markdown contenant son id, son type, son URL, son titre et les passages correspondants.

L’outil n’accepte que ces deux arguments. Utilisez le [point de terminaison de recherche pour développeurs](#developer-search-endpoint) via HTTP lorsque vous avez besoin de filtres sur le type de résultat, le dépôt ou la source de documentation.

<div id="developer-results-from-the-search-tool-firecrawl_search">
  ### Résultats pour développeurs de l’outil de recherche (`firecrawl_search`)
</div>

Passez `developer` dans `categories` pour obtenir des résultats pour développeurs dans un groupe `developer`, à côté des résultats web classiques, avec la même structure que celle renvoyée par la catégorie `developer` sur `/search`.

```json
{
  "name": "firecrawl_search",
  "arguments": {
    "query": "how do I configure retries",
    "categories": ["developer"],
    "limit": 10
  }
}
```

**Idéal pour :** un seul appel lorsque vous souhaitez pondérer ensemble des sources pour développeurs et des pages web généralistes.
**Renvoie :** la réponse de recherche habituelle, avec les résultats pour développeurs regroupés sous `developer` et comportant chacun `category: "developer"`.
