Firecrawl propose différents types de proxy pour vous aider à effectuer du scraping sur des sites web de complexité variable. Définissez le paramètre `proxy` pour choisir la stratégie de proxy utilisée pour une requête.

## Types de proxy {#proxy-types}

| Type       | Description                                                                          |
| ---------- | ------------------------------------------------------------------------------------ |
| `basic`    | Proxies standard adaptés à la plupart des sites                                      |
| `enhanced` | Proxies avancés pour les sites complexes                                             |
| `auto`     | **Recommandé.** Essaie d’abord `basic`, puis réessaie avec `enhanced` en cas d’échec |

Si vous ne spécifiez pas de proxy, Firecrawl utilise `auto` par défaut.

## Quand Firecrawl procède à une escalade {#when-firecrawl-escalates}

Firecrawl démarre sur des proxys basic. Si la target répond avec un code **401, 403 ou 429**, Firecrawl y voit le signe que le proxy n&#39;était pas suffisant et réessaie la même URL via des proxys avancés. Les autres codes d&#39;état, y compris 404 et 5xx, ne déclenchent aucune escalade, car un autre proxy ne changerait rien à la réponse.

L&#39;escalade a lieu au maximum une fois par requête. Dès lors qu&#39;une requête utilise déjà des proxys avancés, un nouveau 401, 403 ou 429 vous est renvoyé comme résultat au lieu de faire l&#39;objet d&#39;un nouvel essai.

Vous n&#39;avez rien à détecter ni à gérer. Le réessai fait partie de la même requête, et la réponse que vous recevez est la réponse finale.

<Info>
  Les requêtes avec proxy avancé coûtent autant que les requêtes basic — **1 crédit par requête**. Un réessai après escalade n&#39;est pas facturé séparément : une requête qui démarre en basic et se termine en avancé coûte donc toujours 1 crédit.
</Info>
