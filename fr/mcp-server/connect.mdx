Utilisez le service Firecrawl MCP hébergé dans l’un des trois modes. Choisissez selon qu’une personne peut se connecter et que le client peut stocker une clé API de façon sécurisée.

<div id="connect-an-account">
  ## Connecter un compte
</div>

Utilisez ce mode pour un client interactif compatible OAuth, tel que Claude ou Codex. Ajoutez cette URL au client : il détectera les métadonnées d’autorisation de Firecrawl, ouvrira le navigateur et vous demandera d’approuver l’équipe à utiliser.

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

Le client reçoit des jetons de courte durée associés à des ressources, plutôt que votre clé API Firecrawl. Vous pouvez consulter et révoquer les accès dans les [paramètres MCP](https://www.firecrawl.dev/app/settings?tab=mcp).

<Tip>
  Si le client demande un ID client OAuth ou un secret client, laissez ces deux champs vides. Les clients compatibles utilisent des documents de métadonnées d’ID client ou l’enregistrement dynamique des clients.
</Tip>

<div id="run-unattended">
  ## Exécuter sans intervention
</div>

Utilisez ce mode pour l’intégration continue, les serveurs, les scripts ou tout environnement d’exécution sans navigateur. Stockez la clé API dans une variable d’environnement ou un gestionnaire de secrets, puis envoyez-la dans l’en-tête Authorization.

```text
https://mcp.firecrawl.dev/v2/mcp
Authorization: Bearer <FIRECRAWL_API_KEY>
```

Cela utilise l’ensemble des outils MCP de Firecrawl. Les nouvelles configurations ne doivent pas inclure de clé API dans l’URL ni la valider dans un fichier de configuration du projet.

<div id="try-keyless">
  ## Essayer sans clé API
</div>

Utilisez ce mode pour essayer Firecrawl sans compte ni clé API :

```text
https://mcp.firecrawl.dev/v2/mcp
```

Le MCP sans clé est limité par adresse IP et donne accès uniquement à **Recherche, Scrape et Parse** tant que vous êtes éligible. Connectez un compte ou utilisez une clé API si vous avez besoin de l’ensemble complet d’outils ou de limites plus élevées.

<div id="when-you-reach-the-free-limit">
  ## Lorsque vous atteignez la limite Free
</div>

L&#39;accès sans clé est soumis à une limite glissante par réseau. Lorsqu&#39;il est disponible, le message d&#39;erreur MCP indique le délai avant la prochaine tentative ; attendez ce délai pour continuer à utiliser recherche, Scrape et Parse sans compte.

Pour continuer immédiatement, choisissez l&#39;une des options suivantes :

* **OAuth interactif :** connectez le point de terminaison de compte, `https://mcp.firecrawl.dev/v2/mcp-oauth`. Pour Claude Code :

  ```bash
  claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
  ```

  Exécutez ensuite `/mcp` et authentifiez-vous dans le Browser.
* **Clé API sans intervention :** créez une clé dans le [tableau de bord Firecrawl](https://www.firecrawl.dev/app/api-keys) et configurez `Authorization: Bearer <FIRECRAWL_API_KEY>`.

<div id="pick-the-right-mode">
  ## Choisissez le bon mode
</div>

| Mode              | Point de terminaison | Outils disponibles                                                                                | Idéal pour                                                                       | Identifiants                                |
| ----------------- | -------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------- |
| Compte            | `/v2/mcp-oauth`      | Ensemble complet d’outils MCP, sous réserve de la disponibilité des offres et des fonctionnalités | Clients interactifs pouvant terminer l’authentification OAuth dans le navigateur | Jetons OAuth gérés par le client            |
| Sans intervention | `/v2/mcp`            | Ensemble complet d’outils MCP, sous réserve de la disponibilité des offres et des fonctionnalités | CI, serveurs et scripts                                                          | `Authorization: Bearer <FIRECRAWL_API_KEY>` |
| Sans clé          | `/v2/mcp`            | Recherche, Scrape et Parse uniquement                                                             | Essai limité                                                                     | Aucun                                       |

Consultez [Outils et opérations](/fr/mcp-server/tools) pour connaître l’inventaire actuel des outils et les notes concernant leur disponibilité en local ou en auto-hébergement.

<div id="client-specific-help">
  ## Aide spécifique au client
</div>

Consultez la [configuration du client](/fr/mcp-server/clients) pour des exemples de configuration. Si votre client ne peut pas effectuer un flux OAuth à distance, utilisez plutôt la configuration sans intervention basée sur des en-têtes ou le mode sans clé. S’il ne peut pas non plus envoyer d’en-têtes personnalisés, consultez la solution de repli héritée ci-dessous.

<div id="legacy-api-key-url-support">
  ## Prise en charge héritée des URL avec clé API
</div>

<Warning>
  Cette forme héritée est uniquement destinée aux configurations et clients existants qui ne peuvent pas finaliser OAuth ni envoyer un en-tête Authorization personnalisé. Elle n’est pas recommandée pour les nouvelles intégrations.
</Warning>

```text
https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
```

La clé API fait partie de l’URL : traitez l’URL complète comme un mot de passe. Privilégiez l’OAuth de compte ou un en-tête `Authorization: Bearer` alimenté par des variables d’environnement, lorsque le client prend en charge l’une ou l’autre de ces options. Si cette URL est exposée, renouvelez la clé API. Ne la collez jamais dans un chat, des captures d’écran, des tickets ou une configuration partagée.

Cette solution de repli s’applique uniquement à l’ensemble de l’interface `/v2/mcp`. Elle ne fonctionne pas pour la ressource de recherche accessible uniquement via OAuth.

<div id="compatibility-during-migration">
  ## Compatibilité pendant la migration
</div>

Les connexions OAuth existantes à `/v2/mcp` restent prises en charge lors de la migration vers le point de terminaison dédié aux comptes. Les nouvelles connexions interactives à un compte doivent utiliser `/v2/mcp-oauth` ; les nouveaux jetons associés à cette ressource de compte ne sont pas acceptés par `/v2/mcp`.
