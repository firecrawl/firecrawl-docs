<div id="connect-with-oauth">
  ## Se connecter avec OAuth
</div>

<Visibility for="humans">
  <McpClientSelector variant="human" showSeeAll={false} showHeader={false} />
</Visibility>

<Visibility for="agents">
  URL du serveur OAuth (Streamable HTTP ; le client lance la connexion dans le navigateur) : `https://mcp.firecrawl.dev/v2/mcp-oauth`

  * ChatGPT : Paramètres &gt; activer le mode développeur &gt; Apps &amp; Connectors &gt; Créer &gt; Authentification : OAuth &gt; collez l’URL du serveur.
  * Claude.ai : Paramètres &gt; Connecteurs &gt; Ajouter un connecteur personnalisé &gt; collez l’URL du serveur et laissez ID client et secret client vides.
  * Codex : `codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth` puis `codex mcp login firecrawl`
  * Claude Code : `claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth` puis terminez la connexion via `/mcp`
  * Cursor ou tout client avec une configuration JSON : `{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp-oauth"}}}`
  * OpenCode (`opencode.json`) : `{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp-oauth", "enabled": true}}}`

  Une personne doit terminer la connexion dans le navigateur et approuver une équipe. N’ouvrez pas directement l’URL du serveur dans un navigateur.
</Visibility>

<Note>
  `https://mcp.firecrawl.dev/v2/mcp-oauth` est une URL de serveur destinée à votre client MCP. Il ne s’agit pas d’une page à ouvrir directement dans un navigateur. Votre client lance le flux de connexion dans le navigateur.
</Note>

Utilisez OAuth lorsqu’une personne est présente pour se connecter, choisir une équipe Firecrawl et approuver l’accès. Le client reçoit des jetons pour cette connexion au lieu de vous demander de copier une clé API Firecrawl dans la conversation.

La page de connexion vous demande de choisir une équipe et d’approuver la connexion. Si le client vous demande un ID client OAuth ou un secret client, laissez les deux champs vides. Les clients compatibles s’identifient automatiquement.

Les requêtes effectuées via cette connexion utilisent l’équipe sélectionnée. Vous pouvez consulter ou révoquer la connexion depuis les [paramètres MCP](https://www.firecrawl.dev/app/settings?tab=mcp).

Vous avez besoin d’une connexion sans intervention ? Utilisez la [configuration par clé API](/fr/mcp-server/keyless-api-key#add-an-api-key). Ne collez pas la clé dans une conversation avec un agent et ne l’insérez pas dans l’URL MCP.

<div id="verify-the-connection">
  ## Vérifiez la connexion
</div>

Démarrez une nouvelle session client, puis essayez :

```text
Recherche sur le web les dernières notes de release de Firecrawl et résume les sources.
```

Si aucun outil Firecrawl n’apparaît, ouvrez l’état MCP du client, vérifiez que `firecrawl` est authentifié et qu’une seule entrée de serveur Firecrawl est active.

<div id="switch-an-existing-keyless-connection">
  ## Basculer une connexion keyless existante
</div>

Mettez à jour ou remplacez le serveur `firecrawl` existant par l’URL du serveur OAuth. N’ajoutez pas de deuxième entrée Firecrawl. Après cette modification, démarrez une nouvelle session client avant de réessayer la requête.

<div id="codex">
  ### Codex
</div>

Exécutez :

```bash
codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth
codex mcp login firecrawl
```

Codex remplace le serveur existant du même nom. Saisissez `/mcp` et vérifiez que `firecrawl` est connecté.

<div id="claude-code">
  ### Claude Code
</div>

Claude Code n’écrase pas un serveur existant portant le même nom. Supprimez l’entrée actuelle, puis ajoutez l’entrée OAuth :

```bash
claude mcp remove firecrawl
claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
```

Ouvrez `/mcp` dans Claude Code et connectez-vous via le navigateur.

<div id="other-clients">
  ### Autres clients
</div>

Modifiez le serveur `firecrawl` existant et définissez son URL sur :

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

Enregistrez la configuration, terminez la connexion initiée par le client, puis ouvrez une nouvelle session cliente.

<div id="compatibility-and-security-details">
  ## Détails de compatibilité et de sécurité
</div>

<AccordionGroup>
  <Accordion title="Compatibilité pendant la migration">
    Les jetons OAuth existants émis pour `/v2/mcp` restent pris en charge par ce point de terminaison. Les nouvelles connexions interactives utilisent `/v2/mcp-oauth`, et les jetons émis pour cette ressource de compte ne sont pas acceptés par `/v2/mcp`.
  </Accordion>

  <Accordion title="Prise en charge des clients OAuth et des redirections">
    Firecrawl utilise le flux OAuth avec code d’autorisation et PKCE. Les clients compatibles peuvent s’identifier à l’aide d’un document de métadonnées d’ID client ou de l’enregistrement dynamique des clients, et n’ont donc pas besoin de secret client.

    Firecrawl accepte les URI de redirection HTTPS et les redirections loopback sur `localhost`, `127.0.0.1` ou `[::1]`. Pour un client natif utilisant une redirection loopback, le port peut changer d’une exécution à l’autre. Le reste de l’URI de redirection enregistrée doit correspondre exactement.
  </Accordion>

  <Accordion title="Portée et durée de vie des jetons">
    Les jetons d’accès expirent après une heure. Les jetons de rafraîchissement sont renouvelés après un rafraîchissement réussi. Chaque connexion est associée à son client OAuth, son utilisateur, son équipe, sa portée et sa ressource MCP.

    Un nouveau jeton émis pour `/v2/mcp-oauth` n’est pas accepté par `/v2/mcp`. Les jetons dont l’audience est absente ou ambiguë sont refusés par défaut.
  </Accordion>

  <Accordion title="Révoquer une connexion">
    Ouvrez **MCP** dans les [paramètres Firecrawl](https://www.firecrawl.dev/app/settings?tab=mcp), puis révoquez la connexion. La révocation invalide ses jetons d’accès et de rafraîchissement. Reconnectez-vous depuis le client pour l’autoriser à nouveau.
  </Accordion>

  <Accordion title="Facturation et accès de l’équipe">
    Les requêtes effectuées via une connexion consomment les crédits de l’équipe sélectionnée lors de la connexion, conformément à l’offre de cette équipe. Chaque connexion est répertoriée dans les [paramètres MCP](https://www.firecrawl.dev/app/settings?tab=mcp), où elle peut être consultée et révoquée à tout moment. Pour le SSO et les contrôles à l’échelle de l’organisation, consultez [Enterprise](/fr/enterprise).
  </Accordion>
</AccordionGroup>
