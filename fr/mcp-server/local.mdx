Exécutez Firecrawl MCP en local lorsque votre agent lance des outils via stdio, doit accéder à des fichiers locaux ou se connecte à une API Firecrawl sur une infrastructure que vous contrôlez. Le serveur MCP et l&#39;API Firecrawl sont des services distincts : choisissez d&#39;abord le backend de l&#39;API, puis démarrez MCP avec les variables d&#39;environnement correspondantes.

<div id="choose-the-firecrawl-api-backend">
  ## Choisissez le backend de l’API Firecrawl
</div>

| Si vous avez besoin de                                  | Utilisez                                                |
| ------------------------------------------------------- | ------------------------------------------------------- |
| La solution gérée la plus rapide                        | Firecrawl Cloud avec `FIRECRAWL_API_KEY`                |
| Contrôler le code source ou l’infrastructure            | Une API auto-hébergée vérifiée avec `FIRECRAWL_API_URL` |
| Parse direct de fichiers locaux                         | Un MCP local connecté à une API Firecrawl auto-hébergée |
| Un MCP distant sécurisé sans avoir à gérer ce processus | Le serveur MCP Firecrawl hébergé                        |

Si vous n’avez pas encore démarré l’API, suivez [Self-hosting Firecrawl](/fr/contributing/self-host) et vérifiez un scrape avant d’ajouter MCP.

<div id="install-the-prerequisites">
  ## Installez les prérequis
</div>

* Node.js 22 ou version ultérieure
* npm et `npx`, inclus avec Node.js
* Une clé API Firecrawl Cloud ou une URL d’API Firecrawl auto-hébergée fonctionnelle

Vérifiez Node.js :

```bash
node --version
```

<div id="run-mcp-with-firecrawl-cloud">
  ## Exécuter MCP avec Firecrawl Cloud
</div>

Pour les clients qui lancent MCP en tant que processus stdio local :

```bash
env FIRECRAWL_API_KEY=VOTRE_CLÉ_API npx -y firecrawl-mcp@3.23.0
```

C’est l’option gérée la plus simple. Firecrawl Cloud fournit le backend de l’API, tandis que le processus MCP s’exécute sur votre machine.

<div id="connect-mcp-to-self-hosted-firecrawl">
  ## Connecter MCP à une instance auto-hébergée de Firecrawl
</div>

Pour le démarrage rapide sans authentification sur un réseau de confiance :

```bash
env FIRECRAWL_API_URL=http://localhost:3002 \
  npx -y firecrawl-mcp@3.23.0
```

Pour une API auto-hébergée avec une couche d&#39;authentification compatible avec les clés API :

```bash
env FIRECRAWL_API_URL=https://firecrawl.your-domain.com \
  FIRECRAWL_API_KEY=your-api-key \
  npx -y firecrawl-mcp@3.23.0
```

Utilisez la clé uniquement si votre déploiement l’exige. MCP ne peut exposer que les outils pris en charge par les services configurés dans ce déploiement ; consultez la [prise en charge des fonctionnalités auto-hébergées](/fr/contributing/self-host#self-hosted-feature-support).

<Warning>
  N’exposez pas publiquement le démarrage rapide d’auto-hébergement sans authentification. Ajoutez TLS,
  des contrôles réseau et un mécanisme d’authentification pris en charge avant d’utiliser une
  URL d’API distante.
</Warning>

<div id="run-mcp-over-streamable-http">
  ## Exécuter MCP via Streamable HTTP
</div>

Utilisez le transport HTTP lorsqu’un client tel que n8n se connecte à un serveur MCP déjà en cours d’exécution :

```bash
env HTTP_STREAMABLE_SERVER=true \
  FIRECRAWL_API_KEY=VOTRE_CLÉ_API \
  npx -y firecrawl-mcp@3.23.0
```

Connectez le client à :

```text
http://localhost:3000/mcp
```

Vérifiez que le processus MCP est prêt :

```bash
curl http://localhost:3000/health
```

La vérification d’état renvoie `ok`. La route MCP locale est `/mcp` ; `/v2/mcp` est la route Firecrawl hébergée.

Pour utiliser le transport HTTP avec Firecrawl auto-hébergé, remplacez `FIRECRAWL_API_KEY` par la configuration `FIRECRAWL_API_URL` de la section précédente et ajoutez une clé uniquement lorsque l’API en exige une.

<div id="persist-local-mcp-configuration">
  ## Enregistrer la configuration MCP locale
</div>

Installez le package globalement si vous préférez disposer d’une commande locale stable :

```bash
npm install -g firecrawl-mcp@3.23.0
```

Ensuite, exécutez :

```bash
env FIRECRAWL_API_KEY=VOTRE_CLÉ_API firecrawl-mcp
```

Pour Claude Desktop, ajoutez un serveur stdio local dans `claude_desktop_config.json` :

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.0"],
      "env": {
        "FIRECRAWL_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}
```

Pour Firecrawl auto-hébergé, remplacez `FIRECRAWL_API_KEY` par `FIRECRAWL_API_URL`, ou incluez les deux si votre API requiert une clé.

<div id="understand-local-and-hosted-boundaries">
  ## Comprendre les limites entre les environnements locaux et hébergés
</div>

* Le MCP hébergé sans clé n’expose que Search, Scrape et Parse et est soumis à une limite de débit par adresse IP.
* La lecture de fichiers locaux nécessite un processus MCP local.
* L’analyse directe de fichiers locaux avec `firecrawl_parse` nécessite que `FIRECRAWL_API_URL` pointe vers une API Firecrawl auto-hébergée. Un serveur MCP local configuré uniquement avec une clé API cloud ne peut pas téléverser un fichier local via cet outil.
* Les Webhooks et les chemins de fichiers locaux doivent être configurés à partir d’un MCP local ou auto-hébergé lorsque l’agent doit accéder aux ressources de votre réseau.
* Les limites de débit de l’API Firecrawl s’appliquent toujours. Utilisez une clé API cloud pour bénéficier de limites gérées plus élevées, ou définissez et surveillez la capacité de votre déploiement auto-hébergé.
