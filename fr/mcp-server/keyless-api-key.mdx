<Visibility for="agents">
  URL du serveur sans clé (Streamable HTTP, sans identifiants) : `https://mcp.firecrawl.dev/v2/mcp`

  * Codex : `codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp`
  * Claude Code : `claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp`
  * Cursor ou tout client configuré en JSON : `{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp"}}}`
  * OpenCode (`opencode.json`) : `{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp", "enabled": true}}}`

  ChatGPT et Claude.ai nécessitent plutôt une connexion à un compte : consultez [OAuth](/fr/mcp-server/oauth.md).
</Visibility>

Voici le mode sans clé de Firecrawl : connectez-vous sans compte ni clé API. Utilisez-le pour un essai rapide, puis utilisez une clé API lorsque la connexion doit fonctionner de manière fiable sans intervention humaine. Si vous préférez vous connecter via un Browser, y compris depuis ChatGPT ou Claude.ai, utilisez [OAuth](/fr/mcp-server/oauth).

Le MCP sans clé expose uniquement Search, Scrape et Parse. Il applique des limites quotidiennes de requêtes et de crédits, partagées entre les utilisateurs ayant la même adresse IP publique. Une autre personne ou un autre processus sur le même réseau peut utiliser une partie de ce quota.

Utilisez l&#39;accès sans clé pour évaluer la connexion, et non comme identité ou identifiant de production. Pour connaître le quota actuel, consultez les [limites de débit sans clé](/fr/rate-limits#keyless-no-api-key).

<div id="add-an-api-key">
  ## Ajouter une clé API
</div>

Utilisez une clé API pour la CI, les services back-end et les autres connexions sans intervention. [Créez une clé API Firecrawl](https://www.firecrawl.dev/app/api-keys), puis mettez-la à la disposition du client MCP sous le nom de `FIRECRAWL_API_KEY`.

<Warning>
  L’opérateur humain ou système doit configurer la clé en dehors de la conversation avec l’agent. Ne collez jamais la clé dans le chat de l’agent, ne l’ajoutez pas à l’URL MCP et ne validez pas sa valeur dans un fichier de projet. Une référence à une variable d’environnement dans un fichier de configuration est sûre ; la valeur secrète ne l’est pas.
</Warning>

<div id="codex">
  ### Codex
</div>

Exportez la clé dans l’environnement depuis lequel Codex est lancé :

```bash
export FIRECRAWL_API_KEY=fc-VOTRE-CLÉ-API
```

Ajoutez ce qui suit à `~/.codex/config.toml` :

```toml
[mcp_servers.firecrawl]
url = "https://mcp.firecrawl.dev/v2/mcp"
bearer_token_env_var = "FIRECRAWL_API_KEY"
```

<div id="claude-code">
  ### Claude Code
</div>

Exportez la clé avant de démarrer Claude Code :

```bash
export FIRECRAWL_API_KEY=fc-VOTRE-CLÉ-API
```

Ajoutez une référence à une variable d’environnement dans `.mcp.json`. Ne remplacez pas `${FIRECRAWL_API_KEY}` par la clé API elle-même.

```json
{
  "mcpServers": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
      }
    }
  }
}
```

<div id="other-clients">
  ### Autres clients
</div>

Configurez le client pour utiliser :

```text
https://mcp.firecrawl.dev/v2/mcp
```

Configurez cet en-tête dans l’environnement ou le stockage de secrets du client :

```text
Authorization: Bearer <FIRECRAWL_API_KEY>
```

Démarrez une nouvelle session client après avoir enregistré la configuration. Ouvrez l’état du MCP ou la liste des outils, puis vérifiez que `firecrawl` est connecté.

<div id="verify-the-connection">
  ## Vérifier la connexion
</div>

Essayez :

```text
Cherche sur le web les dernières notes de version de Firecrawl et résume les sources.
```

Une connexion sans clé affiche `firecrawl_search`, `firecrawl_scrape` et `firecrawl_parse`. Une connexion avec une clé API peut donner accès à l’[ensemble complet des outils](/fr/mcp-server/tools), selon l’offre, le déploiement et la politique de l’équipe.

Si les outils ne correspondent pas au mode que vous avez configuré, supprimez les éventuelles entrées Firecrawl en double, redémarrez le client et vérifiez l’URL du serveur actif ainsi que la source des identifiants.

<div id="run-in-ci-or-a-backend">
  ## Exécution dans une CI ou un backend
</div>

Stockez `FIRECRAWL_API_KEY` dans le gestionnaire de secrets de la plateforme et injectez-la dans l’environnement du processus. Ne conservez que la référence à la variable d’environnement dans la configuration MCP :

```json
{
  "url": "https://mcp.firecrawl.dev/v2/mcp",
  "headers": {
    "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
  }
}
```

Ne stockez pas cette valeur dans le contrôle de version, les journaux de compilation, les prompts ou la configuration générée. Après avoir modifié le secret, démarrez un nouveau processus, vérifiez la liste des outils `firecrawl` et renouvelez la clé si elle a pu être exposée.

<div id="legacy-api-key-url-support">
  ## Prise en charge héritée des URL avec clé API
</div>

<Warning>
  Le format avec clé dans l’URL existe uniquement pour les configurations et clients existants qui ne peuvent pas envoyer d’en-tête d’autorisation. Ne l’utilisez pas pour une nouvelle connexion.
</Warning>

Les configurations existantes peuvent utiliser `https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp`. L’URL complète constitue un identifiant : ne la collez jamais dans un chat, des captures d’écran, des tickets, des journaux ou une configuration partagée. Lorsque possible, migrez vers un en-tête `Authorization: Bearer` alimenté par des variables d’environnement et renouvelez la clé si l’URL a été exposée.

Cette route de compatibilité s’applique uniquement à l’ensemble de la surface `/v2/mcp`. Elle ne fonctionne pas pour la ressource de recherche réservée à OAuth.
