[Docker Sandboxes](https://docs.docker.com/ai/sandboxes/) run coding agents in isolated environments. The Firecrawl kit lets an agent search, scrape, and crawl through Firecrawl's API while the sandbox keeps the API key on the host.

The kit is published in two formats. Choose the format that matches the workload you run; v2 kits and v3 kits cannot be combined.

<Note>
Docker marks Kits as experimental. Commands and kit formats may change; check the current [Docker Sandboxes documentation](https://docs.docker.com/ai/sandboxes/) before upgrading.
</Note>

| Kit | Use with | Image |
| --- | --- | --- |
| v2 | Docker's built-in agent shortcuts, such as `claude` and `codex` | [`firecrawl/firecrawl-docker-sandbox`](https://hub.docker.com/r/firecrawl/firecrawl-docker-sandbox) |
| v3 | A v3 workload, such as Docker's shell kit | [`firecrawl/sbx-kit-firecrawl:1.0.0`](https://hub.docker.com/r/firecrawl/sbx-kit-firecrawl) |

For more detail, see Docker's [Firecrawl kit guide](https://docs.docker.com/guides/firecrawl-sandbox-kit/) and the [kit repository](https://github.com/firecrawl/firecrawl-docker-sandbox).

## Prerequisites

- Install the [`sbx` CLI](https://docs.docker.com/ai/sandboxes/install/) and sign in with `sbx login`.
- Use `sbx` v0.45 or later for the v2 kit, and v0.46 or later for v3.
- Initialize a network policy once with `sbx policy init balanced` if you have not already.
- Get a Firecrawl API key from the [Firecrawl dashboard](https://www.firecrawl.dev/app/api-keys).

## Store the API key

Store the key on the host. `sbx` prompts for it without placing it in shell history:

```bash
sbx secret set firecrawl
```

The first time you run the kit, approve its request to use the `firecrawl` credential for `api.firecrawl.dev`. The sandbox sees the placeholder `proxy-managed`; the host-side proxy adds the real key only to requests sent to the Firecrawl API.

## Use the v2 kit with a built-in agent

Clone the kit repository, then run a built-in agent such as Claude Code with the v2 kit:

```bash
git clone https://github.com/firecrawl/firecrawl-docker-sandbox.git
sbx run --kit ./firecrawl-docker-sandbox/ claude
```

Replace `claude` with another supported built-in agent, such as `codex`. See the [v2 kit README](https://github.com/firecrawl/firecrawl-docker-sandbox#2-launch-the-sandbox-with-the-kit) for the published-image and digest-pinned options.

## Use the v3 kit with a v3 workload

Add the v3 mixin to a v3 workload, such as Docker's shell kit:

```bash
sbx run docker.io/docker/sbx-kit-shell:1.0.0 \
  --name firecrawl-shell \
  --kit docker.io/firecrawl/sbx-kit-firecrawl:1.0.0
```

For another v3 agent, pass its workload and any required agent mixins with the Firecrawl kit. A v3 mixin does not work with a v2 built-in agent.

## Verify the kit

Inside the sandbox, check that the Firecrawl Python SDK is installed:

```bash
python3 -c "import importlib.metadata as m; print(m.version('firecrawl-py'))"
```

The current kit pins `firecrawl-py` 4.44.0. Then check that the credential is a proxy-managed placeholder:

```bash
echo "$FIRECRAWL_API_KEY"
```

The output should be `proxy-managed`, not an API key. To verify the full path, scrape a page through Firecrawl:

```python
from firecrawl import Firecrawl

client = Firecrawl()
page = client.scrape("https://docs.docker.com/ai/sandboxes/", formats=["markdown"])
print(page.markdown[:300])
```

This request uses Firecrawl credits. If it fails with an authorization error, check that you stored the secret under `firecrawl` and approved the kit's credential request. See the [Python SDK documentation](/sdks/python) for more ways to use Firecrawl.
