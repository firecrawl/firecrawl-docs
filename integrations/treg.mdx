## Overview

Treg gives an agent one connection to Firecrawl, other providers in its catalog, and the APIs its team connects. Use Firecrawl to find URLs, turn a page into Markdown, HTML or links, or collect a site in a bounded crawl. The same agent can then check demand for a topic it found or look up the company behind a result.

## Quick start

Install the Treg CLI in your terminal, sign in, then run `treg` to see your active team and prepaid balance. On the managed route, Treg supplies the Firecrawl key.

```bash
curl -fsSL https://treg.to/install.sh | sh
treg login
treg
```

Choose a task below. You can inspect the inputs and price of any endpoint first. For a single-page scrape, run this read-only command.

```bash
treg catalog get firecrawl.web.scrape
```

<Tabs>
<Tab title="Read a page">

Start with a public URL. This requests Markdown for one page. Replace `https://example.com` with the page your agent needs.

```bash
treg call firecrawl.web.scrape --method POST \
  --data '{"url":"https://example.com","formats":["markdown"],"maxAge":0,"parsers":[]}'
```

Read `data.markdown` for the page text. The following excerpt comes from the public catalog example.

```json
{
  "success": true,
  "data": {
    "markdown": "# Example Domain\n\nThis domain is for use in documentation examples."
  }
}
```

</Tab>
<Tab title="Find URLs">

**Start with a topic.** Search for up to three sources. Read `data.web[].url` and `data.web[].title`, then pass a URL to the single-page scrape.

```bash
treg call firecrawl.web.search --method POST \
  --data '{"query":"Firecrawl API documentation","limit":3}'
```

**Start with a site.** Map one domain to get candidate URLs. This returns up to five links in `links[].url`.

```bash
treg call firecrawl.web.map --method POST \
  --data '{"url":"https://docs.firecrawl.dev","limit":5}'
```

</Tab>
<Tab title="Collect pages">

**You have the URLs.** Batch scrape the pages you selected. This example requests Markdown from two Firecrawl guides.

```bash
treg call firecrawl.web.batch-scrape --await --method POST \
  --data '{
  "urls": [
    "https://docs.firecrawl.dev/features/scrape",
    "https://docs.firecrawl.dev/features/map"
  ],
  "formats": [
    "markdown"
  ],
  "maxAge": 0,
  "parsers": []
}'
```

**You have a starting URL.** Crawl a site when you want Firecrawl to follow links. This example includes the starting page and caps the crawl at two pages, one link deep.

```bash
treg call firecrawl.web.crawl --await --method POST \
  --data '{
  "url": "https://docs.firecrawl.dev",
  "limit": 2,
  "maxDiscoveryDepth": 1,
  "scrapeOptions": {
    "parsers": []
  }
}'
```

Both commands use `--await` to wait for the job. In the completed response, each `data[]` entry pairs `metadata.sourceURL` with `markdown`.

To submit a background job, omit `--await` and save the returned `id`. Pass it as `--query id=YOUR_JOB_ID` to `treg call firecrawl.web.batch-scrape.status` or `treg call firecrawl.web.crawl.status`, matching the operation you started.

</Tab>
</Tabs>

## What you can do

| Treg endpoint | What it does |
| --- | --- |
| [`firecrawl.web.crawl`](https://treg.to/catalog/endpoints/firecrawl.web.crawl) | Start a bounded crawl and pay for pages processed. |
| [`firecrawl.web.batch-scrape`](https://treg.to/catalog/endpoints/firecrawl.web.batch-scrape) | Start a bounded batch scrape of up to ten URLs. |
| [`firecrawl.web.map`](https://treg.to/catalog/endpoints/firecrawl.web.map) | Discover URLs on a website without scraping their content. |
| [`firecrawl.web.scrape`](https://treg.to/catalog/endpoints/firecrawl.web.scrape) | Fetch one page as Markdown, HTML or links. |
| [`firecrawl.web.search`](https://treg.to/catalog/endpoints/firecrawl.web.search) | Find up to ten web results without scraping their full pages. |
| [`firecrawl.web.batch-scrape.status`](https://treg.to/catalog/endpoints/firecrawl.web.batch-scrape.status) | Read an owned batch's status, result pages and credit usage. |
| [`firecrawl.web.crawl.status`](https://treg.to/catalog/endpoints/firecrawl.web.crawl.status) | Read an owned crawl's status, result pages and credit usage. |

## Scrape formats

| Format | What your agent gets |
| --- | --- |
| `markdown` | Readable page text for summarizing or quoting. |
| `html` | Page markup for a parser. |
| `links` | URLs to use in a follow-up step. |

## Use the results in a workflow

**Prioritize a content update.** From the Markdown returned by a scrape, pick a phrase that describes the page. Pass it in the `keywords` list for [Google keyword volume](https://treg.to/catalog/endpoints/treg.google.keywords.volume) to get monthly search volume. The search data comes from the next tool in Treg.

**Research companies from search results.** Take the hostname from a Firecrawl search result's `url` and pass it as `domain` to [company enrichment](https://treg.to/catalog/endpoints/treg.companies.enrich). Keep the source URL beside the returned company profile.

Preview the inputs and current prices for these follow-up calls for free:

```bash
treg catalog get treg.google.keywords.volume
treg catalog get treg.companies.enrich
```

Using an MCP client? Connect the [Treg server](https://treg.to/llms.txt) at `https://treg.to/mcp/`. Use `catalog_get` to inspect these same IDs and `call` to run the operation you choose. Each provider call has its own price.

## Accounts and billing

Treg can supply the Firecrawl key and charge the team's prepaid balance. If the team connects its own Firecrawl key, those calls use its Firecrawl account and limits. Check the endpoint’s quote before starting a request. For a backend, send the team token in `X-Treg-Token` and set `X-Treg-Route-Max-Cost` to your maximum USD cost per call.

## Troubleshooting

| What you see | What to check |
| --- | --- |
| The CLI is signed out or shows the wrong team | Run `treg login`, then `treg` to check the active team. |
| HTTP 402 with `insufficient_balance` | Check the team's prepaid balance before retrying. |
| HTTP 402 with `route_max_cost` | Compare the current quote with the limit your backend sent. |
