Use Agent MCP for a coding agent, CLI, or unattended harness — CI, servers, scripts, or any client without a person present to complete a browser sign-in. It starts keyless with no setup, then upgrades to the full tool surface with an API key.

Connecting a person's interactive assistant instead (Claude Desktop, Claude.ai, ChatGPT)? See [Human MCP](/mcp-server/human-mcp).

## Try keyless

Add the keyless endpoint to any client that supports remote MCP — no account required:

```text
https://mcp.firecrawl.dev/v2/mcp
```

Keyless MCP is rate-limited per network and exposes exactly **Search, Scrape, and Parse** while eligible. Add an API key when you need the full tool surface or higher limits.

<Accordion title="What happens when I reach the keyless limit?">
The MCP error includes the current retry time when it is available. Wait for that interval to continue keyless use, or add an API key immediately.
</Accordion>

## Upgrade with an API key

[Create a Firecrawl API key](https://www.firecrawl.dev/app/api-keys), keep it in an environment variable or secret store, and send it as a bearer token to the same hosted endpoint.

<Tabs>
  <Tab title="Codex">
    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp \
      --bearer-token-env-var FIRECRAWL_API_KEY
    ```
  </Tab>

  <Tab title="Claude Code">
    Claude Code expands the environment variable when it connects:

    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp \
      --header 'Authorization: Bearer ${FIRECRAWL_API_KEY}'
    ```
  </Tab>

  <Tab title="Cursor, OpenCode, Windsurf, Antigravity, Amp">
    Each of these agent harnesses also supports launching Firecrawl MCP as a local process over stdio, with `FIRECRAWL_API_KEY` in its environment. See the harness's own quickstart for exact config syntax:

    [Cursor](/quickstarts/cursor) · [OpenCode](/quickstarts/opencode) · [Windsurf](/quickstarts/windsurf) · [Antigravity](/quickstarts/antigravity) · [Amp](/quickstarts/amp)
  </Tab>

  <Tab title="Other clients">
    Configure the client to send the API key as a bearer token:

    ```text
    URL: https://mcp.firecrawl.dev/v2/mcp
    Authorization: Bearer <FIRECRAWL_API_KEY>
    ```

    Header configuration differs by client. Keep the key in the client's environment or protected secret storage.
  </Tab>
</Tabs>

<Warning>
Never put an API key in a project configuration file, paste it into chat, or share it in a screenshot or issue. New configurations should use an environment-backed Authorization header, never a credential-bearing URL.
</Warning>

## Verify your connection

Open your client's MCP status or tool list and confirm that `firecrawl` is connected. A keyless connection shows `firecrawl_search`, `firecrawl_scrape`, and `firecrawl_parse`; an API-key connection can expose the [full tool surface](/mcp-server/tools), subject to plan, deployment, and team policy.

Try a read-only request:

```text
Search the web for the latest Firecrawl release notes and summarize the sources.
```

If no Firecrawl tools appear, restart or reload the client after saving its MCP configuration. For a local-process error such as `spawn npx ENOENT`, see [Run Firecrawl MCP locally](/mcp-server/local#troubleshooting).

<Accordion title="Legacy API-key URL support">
<Warning>
This legacy form exists only for existing configurations and clients that cannot send a custom Authorization header. It is not the recommended setup for new integrations.
</Warning>

```text
https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
```

The API key is part of the URL, so treat the complete URL like a password. If it is exposed, rotate the key.
</Accordion>
