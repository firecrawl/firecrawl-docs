Firecrawl MCP exposes tools for finding, extracting, interacting with, and monitoring web content. Your MCP client receives the exact input schema for every available tool when it connects.

## Tool availability

| Connection mode | Available tools |
| --- | --- |
| Hosted OAuth | Full tool surface, subject to plan and team policy |
| Hosted API key | Full tool surface, subject to plan and team policy |
| Hosted keyless | `firecrawl_search`, `firecrawl_scrape`, and `firecrawl_parse` |
| Local with the Firecrawl cloud API | API-backed tools; direct local-file Parse is unavailable |
| Local with a self-hosted Firecrawl API | Tools supported by the services enabled in that deployment |

Start with [Get Started](/mcp-server) and pick [For Agents](/mcp-server/keyless) or [For Humans](/mcp-server/oauth). Some optional tools can be disabled by environment or team policy.

## Choose a tool

| Job | Tool | Use it when |
| --- | --- | --- |
| Read one page | `firecrawl_scrape` | You know the URL and need page content or structured fields. |
| Get fields from a known page | `firecrawl_scrape` with `formats: ["markdown"]` | You have the URL and want specific fields. Extract them from the returned content, or use `firecrawl_agent` when the pages are not known. |
| Discover site URLs | `firecrawl_map` | You need to find pages before deciding what to extract. |
| Search the web | `firecrawl_search` | You have a query rather than a known URL. |
| Get data from a third-party provider | `alexandria_library_search`, then `alexandria_library_read` | You need typed records from a provider in the [Alexandria](/features/alexandria) catalogue. Authenticated `firecrawl_search` also returns matching tools in `data.tools`. |
| Save a team skill | `firecrawl_save_skill` | You want to create or change one of your team's skills in the Alexandria library, written out or copied from a library skill. |
| Find people or companies | `people_company_search` | You need a list of people by title, seniority, function, employer, or location, or companies by industry, headcount, location, technology, or founding year. |
| Enrich known people or companies | `people_company_enrich` | You have names, domains, LinkedIn URLs, emails, or phone numbers and need profiles, firmographics, work or personal email, or mobile. |
| Find job postings | `jobs_search` | You need postings by role and place, a company's open roles from its own job board, who is hiring for a role, or whether up to 10 posting URLs are still open. |
| Parse a file | `firecrawl_parse` | You need content from a PDF, document, spreadsheet, or HTML file. |
| Extract many pages | `firecrawl_crawl` and `firecrawl_check_crawl_status` | You need to traverse a site or section. The crawl tool polls the job to a terminal state before returning. |
| Run autonomous research | `firecrawl_agent` and `firecrawl_agent_status` | The task spans multiple sources and the exact pages are not known. |
| Operate a live page | `firecrawl_interact` and `firecrawl_interact_stop` | You need clicks, form fills, navigation, or dynamic-page extraction. |
| Search scientific literature | `firecrawl_research_search_papers`, `firecrawl_research_inspect_paper`, `firecrawl_research_read_paper`, and `firecrawl_research_related_papers` | You need to find papers, read passages from inside one, or follow citations. Searches the [Research Index](/features/research) of PubMed, bioRxiv, medRxiv, and arXiv paper abstracts. |
| Look up a protein | `firecrawl_research_lookup_protein` | You have one protein in mind and need its subcellular location or function, with the evidence kind for each statement and the papers UniProt cites. Pass a UniProt accession, or a gene symbol with an organism. See [Look up a protein](/features/research#look-up-a-protein). |
| Answer a programming question | `firecrawl_developer_search` | You need primary-source answers from issues, merged pull requests, READMEs, and curated docs. |
| Answer a legal or regulatory question | `firecrawl_gov_search` | You need statutes, regulations, codes, court opinions, or other government publications from the [Firecrawl Government Index](/features/gov). |
| Monitor changes | `firecrawl_monitor_*` | You need recurring checks, diffs, and webhook or email notifications. |
| Check credit usage | `firecrawl_credit_usage` | You need the team's remaining credits, or what credits were spent on by month or day, optionally split by endpoint or API key. |
| Send product feedback | `firecrawl_search_feedback` and `firecrawl_feedback` | You want to rate search results or report endpoint-level quality. |

`firecrawl_gov_search` also accepts the optional filters `jurisdiction`, `court`, `courtType`, `cites`, and `domain` (`firecrawl-mcp` 3.34.0 or later). See [Government Index filters](/features/gov#filters).

`jobs_search`, `firecrawl_save_skill`, and `firecrawl_research_lookup_protein` are on the hosted server. The local `firecrawl-mcp` 3.40.0 release does not include them yet.

<Note>
The former Extract MCP tool is deprecated and is not part of the current tool surface. Use Scrape for a known page and extract the fields from its content, or Agent when Firecrawl must discover the sources. See [Choosing the Data Extractor](/developer-guides/usage-guides/choosing-the-data-extractor) for the full comparison.
</Note>

## Important behavior

<AccordionGroup>
  <Accordion title="Parse a local file">
    A local MCP server connected to a self-hosted Firecrawl API can read `filePath` directly. The hosted server cannot read files from your machine, so it uses a two-call handoff:

    1. Call `firecrawl_parse` with `filePath` to receive an upload command and `uploadRef`.
    2. Run the upload command on the machine that can read the file.
    3. Call `firecrawl_parse` again with the returned `uploadRef`.

    The upload command uses a short-lived signed target and does not contain your Firecrawl API key. Use `firecrawl_scrape` for a public document URL.
  </Accordion>

  <Accordion title="Check a running crawl">
    `firecrawl_crawl` normally starts a crawl and polls it to a terminal state before returning. If that wait times out, resume the job with `firecrawl_check_crawl_status` and the crawl ID. Use the same status tool for a crawl created outside the current MCP call.

    `firecrawl_agent` is asynchronous: it returns a job identifier, and `firecrawl_agent_status` checks that job until it completes or fails.
  </Accordion>

  <Accordion title="Close Interact sessions">
    Start with a `url`, or reuse the `scrapeId` from a previous Scrape call. When the workflow is finished, call `firecrawl_interact_stop` with the `scrapeId` to release the session.
  </Accordion>

  <Accordion title="Manage monitors safely">
    The `firecrawl_monitor_*` family creates, lists, updates, runs, and inspects recurring monitors. `firecrawl_monitor_delete` permanently removes a monitor and should be called only when the user explicitly intends to delete it.
  </Accordion>

  <Accordion title="Use Alexandria data tools">
    [Alexandria](/features/alexandria) tools need an authenticated session. Keyless sessions get no Alexandria tools.

    1. **Discover.** Authenticated `firecrawl_search` uses `sources: ["web", "alexandria"]` by default and returns matching tools in `data.tools`. Use `sources: ["alexandria"]` for tools only, or `sources: ["web"]` to omit semantic tool discovery.
    2. **Explore.** `alexandria_library_search` runs one read-only shell command (`ls`, `cat`, `grep`, `jq`, pipes) over the catalogue. Start with `cat /library/README.md`. Each tool has a contract at `/library/<category>/<provider>/<capability>.md` with its inputs, outputs, and the call that runs it, and recorded responses are under `/examples`. For a specific workflow a step-by-step skill may cover, such as a prospect list, a pre-call brief, or a trademark check, `cat /library/skills/search/<words>` with two or three distinctive words from the task (for example `investor-list`, not generic words such as research) lists your team's and Firecrawl's skills that share a word, your team's first. The search matches keywords in skill names and descriptions, so when no listed skill fits the task, none covers it and the data providers are the place to look.
    3. **Run.** Call `alexandria_library_read` with `calls`, an array of one to ten `{provider, capability, options}` entries, which may name different providers. Results come back in `data.alexandria` in the same order, and each has `data` or an `error`. A result too large to return inline is retained, and the returned `nextTool` reads it in slices.

    Discovery and library lookups are free. Each run costs the price listed on its tool. If a provider needs accepted terms, the tool returns `THIRD_PARTY_DATA_TERMS_REQUIRED` with `requiresAction.url`. Give that URL to an org admin, who accepts the terms in the Firecrawl dashboard. The agent must not accept terms. After the admin confirms, send the same call again.
  </Accordion>

  <Accordion title="Find and enrich people and companies">
    `people_company_search` and `people_company_enrich` run Firecrawl's provider waterfalls over [Alexandria](/features/alexandria) people and company data. They need an authenticated session and are not listed to keyless sessions.

    - **Search.** Set `entity` to `person` or `company`, then narrow with `filters` such as `titles`, `seniority`, `company_domains`, `locations`, `industries`, or `headcount`. Providers run one at a time, and only those that apply every filter you give. Rows never carry emails or phone numbers. `limit` is 1 to 100, and `max_credits` defaults to 1000.
    - **Enrich.** Send up to 10 records per call, `people` and `companies` together. People get a profile and companies get firmographics. Add `contact_fields` (`work_email`, `personal_email`, `mobile`) to find contact details for people; mobile lookups run only when you ask for them. For each field, Firecrawl tries providers in order of listed price and past success rate and stops at the first one that finds it.

    In `people_company_enrich`, a provider that finds a field is charged its listed price, and a miss is free. Without `max_credits`, an enrich call is uncapped; set it to cap what one call can spend. To call one specific provider, use `alexandria_library_read`.
  </Accordion>

  <Accordion title="Save team skills">
    Skills are step-by-step instructions an agent follows, naming Alexandria capabilities as `@provider/capability`. They live under `/library/skills`, which `alexandria_library_search` reads. `firecrawl_save_skill` needs an authenticated session and is free.

    - **Create.** Call it without `id` and give `name`, `description`, and `body`, or copy a skill with `from`: `<id>` for `/library/skills/firecrawl/<id>`, or `team:<slug>` for `/library/skills/team/<slug>`. Fields you also give override the copy. The new skill is enabled and listed at `/library/skills/team/<slug>`.
    - **Change.** Pass `id` (`team:<slug>`) and `baseVersion`, the `version:` in the skill's `SKILL.md`, to change its name, description, or body, or whether it is enabled or listed. If the skill changed since you read it, the call returns a conflict; read it again and reapply.

    Firecrawl's library skills cannot be changed; copy one instead. Skills cannot be deleted with this tool.
  </Accordion>

  <Accordion title="Search job postings">
    `jobs_search` needs an authenticated session. Give at least one of `query`, `company`, `url`, or `urls`:

    - `query` searches postings by role, with `location`, `remote`, and `posted_within_days`. Add `group_by: "employer"` to see who is hiring, or `boards_only` to search employers' own boards only.
    - `company`, a name or domain, lists the company's open roles from its own job board. Add `query` for one role there.
    - `url` reads one posting and returns its description. `urls` checks up to 10 postings in one call.

    Each row has the same fields, including `title`, `company`, `location`, `remote`, `posted_at`, `url`, `source`, `status`, and `checked_at`. `status` is `open` when Firecrawl read the posting from the employer's board or live posting page in this call, and `unverified` when it comes from a job site. A posting checked by URL can also be `closed`, `not_found`, or `error`. Each provider read is charged its listed price, and `max_credits` (default 200) caps the call.
  </Accordion>

  <Accordion title="Enable optional feedback tools">
    Set `FIRECRAWL_NO_SEARCH_FEEDBACK=1` to prevent `firecrawl_search_feedback` from being registered. Set `FIRECRAWL_NO_ENDPOINT_FEEDBACK=1` to prevent `firecrawl_feedback` from being registered.
  </Accordion>
</AccordionGroup>

## Ultrasearch answers

On the hosted server, `firecrawl_search` can answer a query with a record from an [Alexandria](/features/alexandria) data provider as well as web results. When a search clearly names exactly one person, one company, one company's open jobs, one research paper, or one to three US-listed stocks, Firecrawl looks it up and adds one provider record in a separate `answer` field. The web results in `data` stay the same.

| Route | When it applies | Record | Lookup cost per search |
| --- | --- | --- | --- |
| Person | A LinkedIn profile URL in the query always looks up that person. Otherwise, the search names one person and a LinkedIn profile among the top results matches the person, or the role and company the query names. A search that is only a person's name looks up a LinkedIn profile among the first results whose name is exactly that name. When the first source has no profile for that person, the lookup can try up to two more sources with the same LinkedIn URL | A compact profile with headline, current and previous roles, schools and links, without contact details | Up to 20 credits |
| Company | A LinkedIn company page URL in the query always looks up that company. Otherwise, the search names one company by its LinkedIn page or its own domain, in the query or the top results. A search that names only a brand, or a brand with a company fact such as funding or headcount, looks up the company when one of the first results is the brand's own site | A compact company record with description, industry, founding year, headquarters, size, revenue, funding and links | Up to 20 credits |
| Jobs | The search asks for jobs, with a word like `jobs`, `careers` or `hiring`, the top results include a jobs page, and it names one company by its LinkedIn company page, in the query or the top results. A company known only by its domain gets no jobs answer | Up to 5 open postings, each with title, location, posting date and URL | Your team's price per posting returned, up to 10 credits |
| Paper | The query has an arXiv id or a DOI. A search that asks for a paper can also take the id from one of the first results whose title matches the query | Title, authors, dates, a short abstract and the paper's page | Free |
| Stock news | The search names one to three US-listed stocks, by ticker or by company name with a word like `stock` or `shares`, or asks a finance question about one, for example `NVDA`, `$NVDA news`, `tesla stock price`, `why is Ford stock down`, `TSLA EPS` or `Verizon dividend` | Benzinga headlines chosen for what the query asks and a Fiscal.ai 15-minute-delayed price for each ticker | 2 credits when headlines are found |

Ultrasearch adds nothing in these cases:

- the query names more than one person, company or paper, or more than three stocks;
- the query asks to choose between stocks, for example `AAPL or MSFT`, or compares one stock with something else;
- the query excludes something, for example with `not`, `except` or a `-term` operator;
- the query asks not to look anything up;
- a stock query names a market or country outside the US, or a fund, an index or a cryptocurrency;
- a product name with a price word asks what the product costs, not for its parent company's stock.

In those cases, and when the provider finds no match, the search returns its web results as usual, sometimes with one short note in `agent_hints`.

### When it runs

- Ultrasearch runs only on hosted connections that sign in or use an API key. It doesn't run on keyless sessions, for teams with zero data retention, or on a local server.
- It runs when `sources` is unset or empty, or when it includes `web` or `alexandria`. A `sources` list with `news` but neither `web` nor `alexandria` gets stock answers only, at the same price. A list of only `images` turns it off.
- Stock news works on any plan with credits.
- Agents don't need an extra parameter. The server instructions tell connected agents what `answer` can hold and how it is billed.

### Billing

The provider record costs what the same lookup costs your team through Alexandria, on top of the search's usual credits. When more than one provider can answer, the cheapest one is used. If that price is above the route's ceiling per search (20 credits for a person or company, 10 for jobs), the lookup is skipped and nothing is charged for it. Person and company lookups are normally billed only when a record is found. When a person lookup tries more sources, each source costs your team's price for it only if it finds the person, and a source is tried only while the lookup stays within the 20-credit ceiling. A jobs lookup is billed per posting it returns, so a company with no open postings costs nothing. Paper lookups are free.

A stock answer with headlines costs 2 credits on top of the search. A stock lookup that finds no headlines costs nothing extra, and the delayed price is always free. `answer.credits` shows what the search and the lookup cost.

| Answer | Credits on top of the search |
| --- | --- |
| Person profile | Your team's Alexandria price for the source that found the person, typically 5, or 2 or 10 when a further source finds them, up to 20 |
| Company record | Your team's Alexandria price, typically 2, up to 20 |
| Open jobs | Your team's Alexandria price per posting, typically 2, up to 10 |
| Paper | 0 |
| Stock with headlines | 2 |
| Stock with only a price, or no match on any route | 0 |

### The answer field

`answer` sits next to `data` in the search result. An illustrative example with fake data:

```json
{
  "answer": {
    "route": "person",
    "provider": "datalegion",
    "capability": "people/enrich-base-no-contact",
    "sources": ["datalegion"],
    "attribution": null,
    "person": {
      "name": "Jane Example",
      "headline": "CTO at Example Corp",
      "summary": "Chief Technology Officer at Example Corp since 2021-03",
      "current_roles": [
        {
          "title": "Chief Technology Officer",
          "company": "Example Corp",
          "company_domain": "example.com",
          "since": "2021-03",
          "tenure": "5 yrs 8 mo"
        }
      ],
      "location": "not in this record",
      "previous_roles": [
        { "title": "VP Engineering", "company": "Sample Inc", "from": "2017-01", "to": "2021-02" }
      ],
      "education": [
        { "school": "Example University", "degree": "BS", "field": "Computer Science", "years": "2009-2013" }
      ],
      "linkedin": "https://www.linkedin.com/in/jane-example",
      "other_profiles": [],
      "company": { "name": "Example Corp", "domain": "example.com", "industry": "Software", "size": "201-500" }
    },
    "match": "high confidence",
    "credits": {
      "search": 2,
      "provider": 5,
      "uncertain": 0,
      "pending": 0,
      "max_credits": 5,
      "stop_reason": "found",
      "cap_enforced": true,
      "unresolved_requests": 0
    }
  }
}
```

For stock news, `prices` holds a delayed price for each ticker and `data` lists the headlines:

```json
{
  "answer": {
    "route": "stock",
    "provider": "benzinga",
    "capability": "news/search",
    "sources": ["benzinga", "fiscal-ai"],
    "attribution": "Powered by Benzinga Data",
    "prices": [
      {
        "ticker": "EXMP",
        "price": 123.45,
        "currency": "USD",
        "change": -1.55,
        "change_pct": -1.24,
        "as_of": "2026-11-10T14:05:00-05:00",
        "delay": "15-minute delayed"
      }
    ],
    "data": [
      {
        "title": "Example Corp Shares Rise After Product Launch",
        "created": "2026-11-10T19:20:15Z",
        "url": "https://www.benzinga.com/news/example-launch"
      },
      {
        "title": "Example Corp Names New Chief Financial Officer",
        "created": "2026-11-09T13:05:00Z",
        "url": "https://www.benzinga.com/news/example-cfo"
      },
      {
        "title": "Three Retail Stocks Moving In Tuesday's Session",
        "created": "2026-11-10T16:40:00Z",
        "url": "https://www.benzinga.com/news/example-movers",
        "focus": "tagged"
      }
    ],
    "credits": {
      "search": 2,
      "provider": 2,
      "uncertain": 0,
      "pending": 0,
      "max_credits": 2,
      "stop_reason": "found",
      "cap_enforced": true,
      "unresolved_requests": 0
    }
  }
}
```

| Field | Description |
| --- | --- |
| `route` | `person`, `company`, `jobs`, `paper` or `stock`. |
| `provider`, `capability` | The Alexandria tool that returned the record. |
| `sources` | The providers that contributed to the record. A stock answer with a price also lists `fiscal-ai`. |
| `attribution` | The provider's attribution text, when it requires one. |
| `prices` | Stock news only. One entry per ticker with `price`, `change` and `change_pct` against the previous close, `currency`, `as_of` and `delay`. See below. |
| `person` | Person only. A compact profile: `name`, `headline`, a `summary` of current roles, up to three `current_roles` with tenure, up to three `previous_roles` and schools (`education`), `location` (`not in this record` when the source has none), `linkedin`, `other_profiles` and the current `company`. |
| `match` | Person only. How confidently the source matched the profile, when it says. |
| `company` | Company only. A compact record: `name`, `domain`, a short `description`, `industry`, `founded`, `headquarters`, `employees`, `revenue`, `funding` (`not in this record` when the source has none), `linkedin`, `as_of`, and `phone`, `email` or `parent` when the source has them. For jobs, the company's `name` and `linkedin`. |
| `jobs` | Jobs only. Up to 5 open postings with `title`, `location`, `posted` and `url`. |
| `paper` | Paper only. The paper's `id` (`arxiv:` or `doi:`), `title`, `authors`, `published` and `updated` dates, a short `abstract` and its page `url`. |
| `data` | For stock news, a list of headlines with `title`, `created` (ISO 8601, UTC) and `url`. See [Stock headlines](#stock-headlines). Any other record without a compact form appears here as the source returned it. |
| `note` | Stock news only, when even the newest story is more than 7 days old. |
| `credits` | What the search (`search`) and the lookup (`provider`) cost, the most the lookup could cost (`max_credits`, from your team's quoted prices, or 2 for stock news), and any charge not settled yet (`uncertain`, `pending`, `unresolved_requests`). |

The stock price comes from Fiscal.ai and is never real time. During the trading day it is the last trade, delayed by 15 minutes (`"delay": "15-minute delayed"`). Before the day's first trade, and on days the market is closed, it is the last close (`"delay": "end-of-day close"`). `as_of` gives the time of that trade or close in New York time. If no price can be fetched, the answer carries the news alone; if no story is found but a price is, it carries the price with an empty `data` list.

### Stock headlines

The number of headlines depends on what the query asks, per ticker:

| Query asks for | Headlines per ticker |
| --- | --- |
| The price, for example `NVDA stock price` | 1 |
| Nothing else, for example `NVDA` | 2 |
| News, why the stock moved, earnings or outlook | 3 |

Headlines about the asked company come first, newest first, with the ones that fit the question, such as an earnings report or an analyst action, ahead. When there aren't enough, the newest other stories Benzinga tags with the ticker fill the rest and carry `"focus": "tagged"`. A price ask that has its price shows only headlines about the company, so it can answer with the price alone. The answer is held to a fixed size, so it may carry fewer headlines.

### Turn it off

To search without person, company, jobs or paper lookups, pass a `sources` list without `web` or `alexandria`, such as `["news"]`. A news-only search can still get a stock answer. A list of only `images` turns Ultrasearch off completely. There is no separate switch.

## Troubleshooting

- **A tool is missing:** confirm the connection mode on [Get Started](/mcp-server), reconnect or restart the client, and check whether team policy disables optional tools.
- **The client returns `401`:** check the configured server URL first.
  - If the configured URL is `/v2/mcp-oauth`, sign in again through the client.
  - If it is `/v2/mcp`, either replace the API key on that server or update the existing server URL to `/v2/mcp-oauth` and complete sign-in.
  - Start a new client session after either change.
- **The client is rate-limited:** review the current [rate limits](/rate-limits), wait for the retry interval, or move from keyless to authenticated access.
