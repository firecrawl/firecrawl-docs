Add Firecrawl to Rovo Dev CLI through the hosted MCP server. Rovo Dev CLI reads remote servers with request headers, so this setup uses a Firecrawl API key.

## Requirements

- Rovo Dev CLI, installed as an extension of the Atlassian CLI (`acli`) and signed in with `acli rovodev auth login`.
- A [Firecrawl API key](https://www.firecrawl.dev/app/api-keys).

## Quick setup

1. Run `acli rovodev mcp` to open `~/.rovodev/mcp.json` in your default editor.
2. Add Firecrawl, replace the key, and save:

```json
{
  "mcpServers": {
    "firecrawl": {
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer fc-YOUR-API-KEY"
      }
    }
  }
}
```

3. Start Rovo Dev with `acli rovodev run`, enter `/mcp`, and confirm that `firecrawl` is listed with its tools.

<Accordion title="Prefer a local server?">
Rovo Dev CLI also starts stdio servers. Use [Run MCP locally](/mcp-server/local) and define the command in the same file:

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.7"],
      "env": {
        "FIRECRAWL_API_KEY": "fc-YOUR-API-KEY"
      },
      "transport": "stdio"
    }
  }
}
```
</Accordion>

Keep the file private, because it holds your key. See [Configure an API key](/mcp-server/keyless#add-an-api-key) for more on key-based connections.

## Troubleshooting

- **`/mcp` does not list Firecrawl:** check that the JSON is valid and that `transport` is `"http"` for the hosted URL.
- **The server shows `401`:** replace the key in `mcp.json` and restart `acli rovodev run`.
- **Firecrawl is listed but disabled:** open `/mcp` and enable it, and check that it is not listed under `disabledMcpServers` in `~/.rovodev/config.yml`.
- **Server instructions are not wanted:** set `"enable_instructions": false` on the Firecrawl entry.
