Connect Firecrawl to Goose as a remote extension, so Goose can search the web and read pages through the hosted MCP server.

## Requirements

- Goose 1.55 or newer.
- A [Firecrawl API key](https://www.firecrawl.dev/app/api-keys), exported as `FIRECRAWL_API_KEY`.

## Quick setup

1. Export your API key in the shell you start Goose from:

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. Add the extension to the `extensions` section of `~/.config/goose/config.yaml`:

```yaml
extensions:
  firecrawl:
    type: streamable_http
    name: firecrawl
    enabled: true
    uri: https://mcp.firecrawl.dev/v2/mcp
    headers:
      Authorization: "Bearer $FIRECRAWL_API_KEY"
    env_keys:
      - FIRECRAWL_API_KEY
    timeout: 300
```

3. Start a session and ask Goose to search or scrape:

```bash
goose session
```

<Warning>
Write the header as `$FIRECRAWL_API_KEY` with no braces, and keep `env_keys` in place. Goose sends `${FIRECRAWL_API_KEY}` as literal text, and the server then rejects the request.
</Warning>

See [Configure an API key](/mcp-server/keyless#add-an-api-key) for more on keys.

## Troubleshooting

- **The key is reported invalid or revoked:** check that the header uses `$FIRECRAWL_API_KEY` without braces and that `FIRECRAWL_API_KEY` is exported in the shell that starts Goose.
- **The extension is missing:** run `goose session` again after saving the file, and confirm `enabled: true`.
- **Calls time out:** raise `timeout`. Scraping a large page can take longer than the default.
- **Tools are not used:** some models call MCP tools more reliably than others. Try a different model.
