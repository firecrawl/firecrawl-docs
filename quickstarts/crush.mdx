Connect Firecrawl to Crush as a remote HTTP MCP server, so Crush can search the web and read pages.

## Requirements

- Crush 0.98 or newer.
- A [Firecrawl API key](https://www.firecrawl.dev/app/api-keys), exported as `FIRECRAWL_API_KEY`.

## Quick setup

1. Export your API key in the shell you start Crush from:

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. Add the server to `crush.json` in your project, or to `~/.config/crush/crush.json` for every project:

```json
{
  "$schema": "https://charm.land/crush.json",
  "mcp": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer $FIRECRAWL_API_KEY"
      }
    }
  }
}
```

3. Start Crush and ask it to search or scrape.

<Accordion title="Using a crushrc file?">
Newer Crush releases can read a Bash-style `crushrc` file, where an MCP server is one command:

```bash
mcp add firecrawl \
  --type http \
  --url "https://mcp.firecrawl.dev/v2/mcp" \
  --header Authorization "Bearer $FIRECRAWL_API_KEY"
```

Run `crush dirs` to see where Crush looks for configuration on your machine.
</Accordion>

See [Configure an API key](/mcp-server/keyless#add-an-api-key) for more on keys.

## Troubleshooting

- **The server does not start:** check that `FIRECRAWL_API_KEY` is exported in the shell that starts Crush, and that the URL is exactly `https://mcp.firecrawl.dev/v2/mcp`.
- **The header is dropped:** Crush removes a header whose value resolves to an empty string. An unset `FIRECRAWL_API_KEY` causes this.
- **Tools are not used:** some models call MCP tools more reliably than others. Try a different model.
