Connect Firecrawl to Qwen Code as a remote HTTP MCP server, so Qwen Code can search the web and read pages.

## Requirements

- Qwen Code 0.25 or newer.
- A [Firecrawl API key](https://www.firecrawl.dev/app/api-keys), exported as `FIRECRAWL_API_KEY`.

## Quick setup

1. Export your API key in the shell you start Qwen Code from:

```bash
export FIRECRAWL_API_KEY="fc-YOUR-API-KEY"
```

2. Add the server. Single quotes keep the shell from expanding the variable, so the settings file stores the reference instead of your key:

```bash
qwen mcp add --scope user --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp \
  --header 'Authorization: Bearer $FIRECRAWL_API_KEY'
```

3. Confirm the server connects:

```bash
qwen mcp list
```

4. Start Qwen Code, run `/mcp` to see the Firecrawl tools, and ask it to search or scrape.

<Accordion title="Prefer to edit the settings file?">
Add the server to `~/.qwen/settings.json`, or to `.qwen/settings.json` in a project:

```json
{
  "mcpServers": {
    "firecrawl": {
      "httpUrl": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer $FIRECRAWL_API_KEY"
      }
    }
  }
}
```
</Accordion>

See [Configure an API key](/mcp-server/keyless#add-an-api-key) for more on keys.

## Troubleshooting

- **The server is missing in a running session:** restart Qwen Code in the same project after adding it.
- **The server shows as not connected:** run `qwen mcp list`, and check that `FIRECRAWL_API_KEY` is exported in the shell that starts Qwen Code.
- **Tool calls are rejected for an invalid key:** confirm the header value is `Bearer $FIRECRAWL_API_KEY` and that the variable holds a valid key.
- **Tools are not used:** some models call MCP tools more reliably than others. Try a different model.
