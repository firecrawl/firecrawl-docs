Choose the setup that matches how the connection will run. You do not need to decide whether you are a human or an agent.

<CardGroup cols={3}>
  <Card title="Try instantly" icon="bolt" href="/mcp-server/agent-mcp#try-keyless">
    Start without an account or API key. You get Search, Scrape, and Parse with a shared daily allowance per public IP.
  </Card>
  <Card title="Connect interactively" icon="right-to-bracket" href="/mcp-server/human-mcp">
    Sign in through your MCP client when a person is present. The client opens a browser so you can choose a team and approve access.
  </Card>
  <Card title="Agents, CI, and backend" icon="key" href="/mcp-server/agent-mcp#add-an-api-key">
    Use an API key for stable unattended access. Store the key in the client environment or a secret manager.
  </Card>
</CardGroup>

## Which option should I choose?

| Your goal | Choose | What to expect |
| --- | --- | --- |
| Test Firecrawl now | [Keyless](/mcp-server/agent-mcp#try-keyless) | No account or key. Search, Scrape, and Parse only. Shared limits apply. |
| Connect your Firecrawl account from an interactive client | [OAuth browser sign-in](/mcp-server/human-mcp) | A browser opens for sign-in, team selection, and approval. |
| Run in CI, a backend, or another unattended process | [API key](/mcp-server/agent-mcp#add-an-api-key) | Full tool access subject to plan and team policy. The operator manages the secret. |

<Warning>
Never put a Firecrawl API key in an MCP URL, an agent conversation, or a committed project file. Configure it through an environment variable or your client's secret storage.
</Warning>

If Firecrawl is already configured and you change connection mode, update or replace the existing `firecrawl` server. Do not keep two Firecrawl entries with different credentials. Start a new client session after the change so the new connection is used.
