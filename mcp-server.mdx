Choose the setup that matches how the connection will run. You do not need to decide whether you are a human or an agent.

<Card title="Try instantly with keyless MCP" icon="bolt" href="/mcp-server/agent-mcp#try-keyless">
  **Best for:** evaluating Firecrawl without an account or credential. **Access:** Search, Scrape, and Parse with a daily allowance shared by users on the same public IP. **Start keyless setup →**
</Card>

<Card title="Connect with OAuth" icon="right-to-bracket" href="/mcp-server/human-mcp">
  **Best for:** an interactive client with a person present. **Access:** sign in, choose a team, and approve the connection for the broader tool surface. **Connect with OAuth →**
</Card>

<Card title="Run with an API key" icon="key" href="/mcp-server/agent-mcp#add-an-api-key">
  **Best for:** agents, CI, backends, and other unattended processes. **Access:** the broader tool surface, subject to plan and team policy. The operator keeps the secret outside agent chat and source control. **Configure an API key →**
</Card>

The hosted keyless and API-key server URL is:

```text
https://mcp.firecrawl.dev/v2/mcp
```

<Note>
This is a server URL for your MCP client, not a page to open directly in a browser. OAuth uses a different server URL and your client starts its browser sign-in flow.
</Note>

If you choose an API key, never put it in an MCP URL, an agent conversation, or a committed project file. Configure it through an environment variable or your client's secret storage.

## Fix a broken connection

Use this section when a Firecrawl error mentions `KEYLESS_QUOTA_EXHAUSTED`, `KEYLESS_TOOL_NOT_AVAILABLE`, `CREDENTIAL_INVALID`, `OAUTH_CONNECTION_INVALID`, or a credential that is "invalid or revoked."

- **Keyless limit reached:** wait for the error's `retry_after_seconds`, or ask the human operator to connect with OAuth or configure an API key. Search, Scrape, and Parse remain available after the limit resets.
- **API key invalid or revoked:** the human or system operator must replace the key in the existing server configuration, outside the agent conversation.
- **OAuth connection invalid on `/v2/mcp`:** either add an API key to that existing server or change its URL to `https://mcp.firecrawl.dev/v2/mcp-oauth` and sign in through the client. Do not open that URL directly in a browser.
- **OAuth connection invalid on `/v2/mcp-oauth`:** sign in again through the client's account-connection flow.

After any credential or server-URL change, keep one `firecrawl` server entry, start a new client session, and retry. See [OAuth connection](/mcp-server/human-mcp#switch-an-existing-keyless-connection) or [API-key setup](/mcp-server/agent-mcp#add-an-api-key) for exact steps.
