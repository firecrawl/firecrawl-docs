Execute o Firecrawl MCP localmente quando seu agente iniciar ferramentas via stdio, precisar acessar arquivos locais ou se conectar a uma API do Firecrawl em uma infraestrutura sob seu controle. O servidor MCP e a API do Firecrawl são serviços separados: primeiro escolha o back-end da API e, depois, inicie o MCP com as variáveis de ambiente correspondentes.

<div id="choose-the-firecrawl-api-backend">
  ## Escolha o backend da API do Firecrawl
</div>

| Se você precisa de                                  | Use                                                       |
| --------------------------------------------------- | --------------------------------------------------------- |
| O caminho gerenciado mais rápido                    | Firecrawl Cloud com `FIRECRAWL_API_KEY`                   |
| Controle do código-fonte ou da infraestrutura       | Uma API auto-hospedada verificada com `FIRECRAWL_API_URL` |
| Parse direto de arquivos locais                     | MCP local conectado a uma API do Firecrawl auto-hospedada |
| MCP remoto seguro sem precisar operar esse processo | O servidor Firecrawl MCP hospedado                        |

Se você ainda não iniciou a API, siga [auto-hospedagem do Firecrawl](/pt-BR/contributing/self-host) e verifique um scraping antes de adicionar o MCP.

<div id="install-the-prerequisites">
  ## Instale os pré-requisitos
</div>

* Node.js 22 ou posterior
* npm e `npx`, incluídos no Node.js
* Uma chave de API do Firecrawl para a API em nuvem ou uma URL funcional da API do Firecrawl auto-hospedada

Verifique o Node.js:

```bash
node --version
```

<div id="run-mcp-with-firecrawl-cloud">
  ## Execute o MCP com o Firecrawl Cloud
</div>

Para clientes que iniciam o MCP como um processo stdio local:

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY npx -y firecrawl-mcp@3.23.0
```

Esta é a opção gerenciada mais simples. O Firecrawl Cloud fornece o backend da API, enquanto o processo MCP é executado na sua máquina.

<div id="connect-mcp-to-self-hosted-firecrawl">
  ## Conecte o MCP ao Firecrawl auto-hospedado
</div>

Para o guia de início rápido de rede confiável sem autenticação:

```bash
env FIRECRAWL_API_URL=http://localhost:3002 \
  npx -y firecrawl-mcp@3.23.0
```

Para uma API auto-hospedada com uma camada de autenticação compatível com chave de API:

```bash
env FIRECRAWL_API_URL=https://firecrawl.your-domain.com \
  FIRECRAWL_API_KEY=your-api-key \
  npx -y firecrawl-mcp@3.23.0
```

Use a chave apenas quando sua implantação exigir. O MCP pode expor apenas as ferramentas compatíveis com os serviços configurados nessa implantação; consulte o [suporte a recursos auto-hospedados](/pt-BR/contributing/self-host#self-hosted-feature-support).

<Warning>
  Não exponha publicamente o guia de início rápido de self-hosting sem autenticação. Configure TLS,
  controles de rede e um modelo de autenticação compatível antes de usar uma
  URL de API remota.
</Warning>

<div id="run-mcp-over-streamable-http">
  ## Executar MCP via Streamable HTTP
</div>

Use o transporte HTTP quando um cliente, como o n8n, se conecta a um servidor MCP já em execução:

```bash
env HTTP_STREAMABLE_SERVER=true \
  FIRECRAWL_API_KEY=fc-YOUR_API_KEY \
  npx -y firecrawl-mcp@3.23.0
```

Conecte o cliente a:

```text
http://localhost:3000/mcp
```

Confirme se o processo MCP está pronto:

```bash
curl http://localhost:3000/health
```

A verificação de integridade retorna `ok`. A rota MCP local é `/mcp`; `/v2/mcp` é a rota do Firecrawl hospedada.

Para usar o transporte HTTP com o Firecrawl auto-hospedado, substitua `FIRECRAWL_API_KEY` pela configuração `FIRECRAWL_API_URL` da seção anterior e adicione uma chave somente quando a API exigir uma.

<div id="persist-local-mcp-configuration">
  ## Persistir a configuração local do MCP
</div>

Instale o pacote globalmente se preferir um comando local estável:

```bash
npm install -g firecrawl-mcp@3.23.0
```

Em seguida, execute:

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY firecrawl-mcp
```

Para o Claude Desktop, adicione um servidor stdio local ao `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.0"],
      "env": {
        "FIRECRAWL_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}
```

Para o Firecrawl auto-hospedado, substitua `FIRECRAWL_API_KEY` por `FIRECRAWL_API_URL` ou inclua ambas se sua API exigir a chave.

<div id="understand-local-and-hosted-boundaries">
  ## Entenda os limites entre ambientes locais e hospedados
</div>

* O MCP hospedado sem chave expõe apenas Search, Scrape e Parse e tem limite de taxa por IP.
* A leitura de arquivos locais exige um processo MCP local.
* A análise direta de arquivos locais com `firecrawl_parse` exige que `FIRECRAWL_API_URL` aponte para uma API do Firecrawl auto-hospedada. Um servidor MCP local configurado apenas com uma API em nuvem não pode enviar um arquivo local por essa ferramenta.
* Webhooks e caminhos de arquivos locais devem ser configurados por meio de um MCP local ou auto-hospedado quando o agente precisar acessar recursos na sua rede.
* Os limites de taxa da API do Firecrawl ainda se aplicam. Use uma chave de API em nuvem para limites gerenciados mais altos ou defina e monitore a capacidade da sua implantação auto-hospedada.
