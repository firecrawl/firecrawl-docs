<div id="connect-with-oauth">
  ## Conectar-se com OAuth
</div>

<Visibility for="humans">
  <McpClientSelector variant="human" showSeeAll={false} showHeader={false} />
</Visibility>

<Visibility for="agents">
  URL do servidor OAuth (Streamable HTTP; o cliente inicia o login no navegador): `https://mcp.firecrawl.dev/v2/mcp-oauth`

  * ChatGPT: configurações &gt; ativar o Modo Desenvolvedor &gt; Apps &amp; Connectors &gt; Criar &gt; Autenticação: OAuth &gt; cole a URL do servidor.
  * Claude.ai: Configurações &gt; Connectors &gt; Adicionar conector personalizado &gt; cole a URL do servidor e deixe ID do cliente e Secret em branco.
  * Codex: `codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth` e depois `codex mcp login firecrawl`
  * Claude Code: `claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth` e depois conclua o login via `/mcp`
  * Cursor ou qualquer cliente com configuração JSON: `{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp-oauth"}}}`
  * OpenCode (`opencode.json`): `{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp-oauth", "enabled": true}}}`

  Uma pessoa deve concluir o login no navegador e aprovar uma equipe. Não abra a URL do servidor diretamente no navegador.
</Visibility>

<Note>
  `https://mcp.firecrawl.dev/v2/mcp-oauth` é uma URL de servidor para seu cliente MCP. Não é uma página para abrir diretamente no navegador. Seu cliente inicia o fluxo de login no navegador.
</Note>

Use OAuth quando houver uma pessoa disponível para fazer login, escolher uma equipe do Firecrawl e aprovar o acesso. O cliente recebe tokens para essa conexão, em vez de solicitar que você copie uma chave de API do Firecrawl para a conversa.

A página de login pede que você escolha uma equipe e aprove a conexão. Se o cliente solicitar um ID do cliente ou segredo do cliente do OAuth, deixe ambos em branco. Clientes compatíveis se identificam automaticamente.

As solicitações feitas por essa conexão usam a equipe selecionada. Você pode revisar ou revogar a conexão nas [configurações do MCP](https://www.firecrawl.dev/app/settings?tab=mcp).

Precisa de uma conexão não assistida? Use a [configuração com chave de API](/pt-BR/mcp-server/keyless-api-key#add-an-api-key). Não cole a chave em uma conversa com um agente nem a inclua na URL do MCP.

<div id="verify-the-connection">
  ## Verifique a conexão
</div>

Inicie uma nova sessão do cliente e tente:

```text
Faça uma busca na web pelas notas da versão mais recente do Firecrawl e resuma as fontes.
```

Se nenhuma ferramenta do Firecrawl for exibida, abra o status do MCP do cliente, confirme que `firecrawl` está autenticado e verifique se há apenas uma entrada de servidor Firecrawl ativa.

<div id="switch-an-existing-keyless-connection">
  ## Altere uma conexão keyless existente
</div>

Atualize ou substitua o servidor `firecrawl` existente pela URL do servidor OAuth. Não adicione uma segunda entrada do Firecrawl. Após a alteração, inicie uma nova sessão do cliente antes de tentar a solicitação novamente.

<div id="codex">
  ### Codex
</div>

Execute:

```bash
codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp-oauth
codex mcp login firecrawl
```

O Codex substitui o servidor existente com o mesmo nome. Digite `/mcp` e confirme que o `firecrawl` está conectado.

<div id="claude-code">
  ### Claude Code
</div>

O Claude Code não substitui um servidor existente com o mesmo nome. Remova a entrada atual e adicione a entrada OAuth:

```bash
claude mcp remove firecrawl
claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp-oauth
```

Abra `/mcp` no Claude Code e faça login no navegador.

<div id="other-clients">
  ### Outros clientes
</div>

Edite o servidor `firecrawl` existente e defina o URL como:

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

Salve a configuração, conclua o login iniciado pelo cliente e abra uma nova sessão no cliente.

<div id="compatibility-and-security-details">
  ## Detalhes de compatibilidade e segurança
</div>

<AccordionGroup>
  <Accordion title="Compatibilidade durante a migração">
    Os tokens OAuth existentes emitidos para `/v2/mcp` continuam sendo aceitos nesse endpoint. Novas conexões interativas usam `/v2/mcp-oauth`, e os tokens emitidos para esse recurso de conta não são aceitos por `/v2/mcp`.
  </Accordion>

  <Accordion title="Suporte a clientes OAuth e redirecionamentos">
    O Firecrawl usa o fluxo OAuth de Código de autorização com PKCE. Clientes compatíveis podem se identificar com um Documento de metadados de ID do cliente ou Registro dinâmico de cliente, dispensando um segredo do cliente.

    O Firecrawl aceita URLs de redirecionamento HTTPS e redirecionamentos de loopback em `localhost`, `127.0.0.1` ou `[::1]`. Para clientes nativos que usam redirecionamento de loopback, a porta pode mudar entre execuções. O restante da URL de redirecionamento registrada deve corresponder exatamente.
  </Accordion>

  <Accordion title="Escopo e duração dos tokens">
    Os tokens de acesso expiram após uma hora. Os tokens de atualização são rotacionados após uma atualização bem-sucedida. Cada conexão está vinculada ao cliente OAuth, usuário, equipe, escopo e recurso MCP.

    Um novo token emitido para `/v2/mcp-oauth` não é aceito por `/v2/mcp`. Tokens com público ausente ou ambíguo são rejeitados.
  </Accordion>

  <Accordion title="Revogar uma conexão">
    Abra **MCP** nas [Configurações do Firecrawl](https://www.firecrawl.dev/app/settings?tab=mcp) e revogue a conexão. A revogação invalida os tokens de acesso e atualização da conexão. Reconecte-se pelo cliente para autorizá-lo novamente.
  </Accordion>

  <Accordion title="Cobrança e acesso da equipe">
    As solicitações feitas por uma conexão consomem os créditos da equipe selecionada durante o login, de acordo com o plano dessa equipe. Cada conexão é listada nas [configurações de MCP](https://www.firecrawl.dev/app/settings?tab=mcp), onde pode ser revisada e revogada a qualquer momento. Para controles de SSO e para toda a organização, consulte [Enterprise](/pt-BR/enterprise).
  </Accordion>
</AccordionGroup>
