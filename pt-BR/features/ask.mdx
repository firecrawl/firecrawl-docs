O `/support/ask` do Firecrawl é um agente de suporte por IA disponibilizado como API. Descreva seu problema e receba um diagnóstico verificado com parâmetros de correção acionáveis — normalmente em 15–30 segundos.

**Pense no `/support/ask` como um engenheiro sênior do Firecrawl de plantão para o seu agente.**

<Info>
  A API Ask foi projetada principalmente para **chamadas feitas por agentes de IA**. Se você está criando agentes que usam o Firecrawl para scraping, rastreamento ou extração de dados, integre o `/support/ask` ao seu fluxo de tratamento de erros para resolver problemas de forma autônoma.
</Info>

## Dois endpoints {#two-endpoints}

| Endpoint                    | Autenticação                  | Para quem é                | O que faz                                               |
| --------------------------- | ----------------------------- | -------------------------- | ------------------------------------------------------- |
| `POST /support/ask`         | Sua chave de API do Firecrawl | Seus agentes e aplicativos | Ciclo completo de diagnóstico restrito à sua equipe     |
| `POST /support/docs-search` | Sua chave de API do Firecrawl | Seus agentes e aplicativos | Respostas baseadas na documentação pública do Firecrawl |

## Primeiros passos {#quick-start}

### Depurar um rastreamento que falhou {#debug-a-failing-crawl}

```bash
curl -X POST https://api.firecrawl.dev/v2/support/ask \
  -H "Authorization: Bearer fc-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "my crawl returned 3 pages but I expected 50"
  }'
```

### Pesquise na documentação {#search-the-docs}

```bash
curl -X POST https://api.firecrawl.dev/v2/support/docs-search \
  -H "Authorization: Bearer fc-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "how do I set up webhook signature verification?"
  }'
```

## Depure um job que falhou {#debug-a-failed-job}

Todo job do Firecrawl — scraping, rastreamento, extração em lote, busca, mapeamento ou extração — pode ser depurado com `/support/ask`. Descreva a falha em linguagem simples e inclua o ID do job, se tiver um; o agente consulta os logs desse job e o estado da sua conta antes de responder.

```bash
curl -X POST https://api.firecrawl.dev/v2/support/ask \
  -H "Authorization: Bearer fc-YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "debug failed job 0f8c9a1b-4e2d-47a1-9c3f-1b2d3e4f5a6b — crawl of https://example.com failed after 12 pages",
    "rationale": "user needs the full docs site indexed before their demo"
  }'
```

Inclua o máximo possível destas informações — cada uma ajuda a delimitar o diagnóstico:

| Detalhe                              | Por que ajuda                                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| ID do job                            | Permite que o agente consulte diretamente os logs, o status e os resultados por página desse job        |
| URL de destino                       | Revela bloqueios específicos do site, como proteção contra bots, renderização de JS ou regras de robots |
| Mensagem de erro ou código de status | Diferencia limites de taxa e esgotamento de créditos de falhas no nível do scraping                     |
| O que você esperava                  | Distingue uma falha completa de um job que &quot;foi bem-sucedido&quot;, mas teve conteúdo ausente      |
| `rationale`                          | Informa ao agente o que o usuário final busca para que ele priorize as evidências corretas              |

### O que o Ask verifica em falhas comuns {#what-ask-checks-for-common-failures}

| Sintoma                                                 | O que o agente investiga                                                                                |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Status do job `failed`                                  | Logs do job, status HTTP de origem, histórico de proxy e novas tentativas                               |
| O rastreamento retornou menos páginas do que o esperado | `limit`, `maxDiscoveryDepth`, `includePaths`/`excludePaths`, cobertura do sitemap, regras de robots     |
| Markdown vazio ou truncado                              | Renderização no lado do cliente, tempo de `waitFor`, `actions` necessárias, corte por `onlyMainContent` |
| Respostas `401` / `402` / `429`                         | Validade e restrições da chave de API, créditos restantes, limites de taxa do plano                     |
| Job travado ou excedendo o tempo limite                 | Estado da fila, tempos limite por página, concorrência de jobs do seu plano                             |
| Webhook nunca foi disparado                             | Tentativas de entrega, respostas do endpoint, falhas na verificação de assinatura                       |

Não tem o ID do job? Passe o cursor sobre a URL de uma linha em [Activity Logs](https://www.firecrawl.dev/app/logs) e clique em **Copy ID**, ou use o `id` retornado ao iniciar o job.

### Depurar pelos logs de atividade {#debug-from-activity-logs}

Se preferir não fazer a chamada manualmente, o painel executa o mesmo agente para você. Abra os [Logs de atividade](https://www.firecrawl.dev/app/logs) e procure o botão de brilhos na coluna **Ações** de uma linha com falha — a dica de ferramenta exibe **Depurar problema**. Ele só aparece em jobs que falharam ou terminaram com erros em solicitações filhas; portanto, jobs concluídos com êxito ou em andamento não o terão.

Ao clicar nele, o diagnóstico começa imediatamente; não há prompt para escrever. O Firecrawl envia a URL, o endpoint, o status, a mensagem de erro e os parâmetros de scraping desse job para o mesmo agente por trás de `/support/ask`, que então lê os logs do job e o estado da sua conta. O conteúdo das páginas extraídas nunca é incluído.

O painel exibido apresenta:

| Elemento          | O que é                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------- |
| Diagnóstico       | A explicação do agente sobre o que deu errado e o que alterar                               |
| Selo de confiança | Alta, média ou baixa — o grau de certeza do agente na resposta                              |
| Selo **Validado** | Exibido quando o agente testou a própria correção sugerida e o teste foi aprovado           |
| Correção sugerida | Os parâmetros corrigidos em JSON, com um botão para copiar — cole-os na sua próxima chamada |
| Fontes            | Links para as páginas da documentação nas quais a resposta se baseia                        |

Se o diagnóstico não resolver o problema, **Abrir ticket de suporte**, na parte inferior do painel, cria um ticket com a análise do agente já anexada, para que você não precise explicar a falha novamente.

<Info>
  A depuração pelo painel é limitada a 30 execuções por hora por equipe, e sua equipe precisa ter pelo menos uma chave de API — o agente é executado com sua própria chave, portanto, só vê seus jobs.
</Info>

Quando tiver um diagnóstico, aplique os `fixParameters` retornados e tente novamente — consulte o [padrão de retentativa do agente](#agent-retry-pattern) abaixo.

## Como funciona {#how-it-works}

Quando você faz uma chamada para `/support/ask`, o agente de IA:

1. **Coleta evidências** — inspeciona em paralelo os logs do seu job, o estado da conta, o uso de créditos e a documentação relevante
2. **Diagnostica o problema** — analisa todas as evidências para identificar a causa raiz
3. **Propõe uma correção** — gera `fixParameters` executáveis por máquina, que você pode aplicar diretamente na sua próxima chamada de API
4. **Valida a correção** — quando possível, testa a correção na API ativa da Firecrawl (por exemplo, repetindo um scraping com parâmetros ajustados) e informa o resultado

## Como usar o Ask no seu agente {#using-ask-in-your-agent}

O principal padrão de design: chame `/support/ask` quando sua chamada à API do Firecrawl falhar ou retornar resultados inesperados e depois use `fixParameters` para tentar novamente.

### Exemplo em Python {#python-example}

```python
import requests

FIRECRAWL_API_KEY = "fc-YOUR_API_KEY"

def diagnose_firecrawl_issue(question, rationale=None):
    """Call the Firecrawl Ask API to debug an issue."""
    payload = {"question": question}
    if rationale:
        payload["rationale"] = rationale

    response = requests.post(
        "https://api.firecrawl.dev/v2/support/ask",
        headers={
            "Authorization": f"Bearer {FIRECRAWL_API_KEY}",
            "Content-Type": "application/json",
        },
        json=payload,
    )
    return response.json()


# Exemplo: depurar um scraping que retornou conteúdo vazio
result = diagnose_firecrawl_issue(
    question="scrape returned empty markdown for https://example.com",
    rationale="user needs product pricing data for competitive analysis",
)

print(result["answer"])
print(result["fixParameters"])  # ex.: {"waitFor": 5000, "actions": [...]}
print(result["confidence"])     # "high", "medium", or "low"
```

### Exemplo de Node.js {#nodejs-example}

```javascript
async function diagnoseFirecrawlIssue(question, rationale) {
  const response = await fetch(
    "https://api.firecrawl.dev/v2/support/ask",
    {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.FIRECRAWL_API_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({ question, rationale }),
    }
  );
  return response.json();
}

// Exemplo: depurar um rastreamento que parou cedo demais
const result = await diagnoseFirecrawlIssue(
  "my crawl returned 3 pages but I expected 50",
  "user is on their third failed crawl attempt today"
);

console.log(result.answer);
console.log(result.fixParameters);
```

### Padrão de retentativa do agente {#agent-retry-pattern}

```python
from firecrawl import Firecrawl

client = Firecrawl(api_key="fc-YOUR_API_KEY")

# Passo 1: Tentar o scraping
doc = client.scrape("https://example.com/pricing", formats=["markdown"])

if not doc.markdown or len(doc.markdown) < 100:
    # Passo 2: Pedir ajuda para depuração
    diagnosis = diagnose_firecrawl_issue(
        question=f"scrape returned only {len(doc.markdown or '')} chars of markdown for https://example.com/pricing",
    )

    # Passo 3: Aplicar parâmetros de correção e tentar novamente
    if diagnosis.get("fixParameters"):
        doc = client.scrape(
            "https://example.com/pricing",
            formats=["markdown"],
            **diagnosis["fixParameters"],
        )
```

## Parâmetros {#parameters}

### `/support/ask` {#supportask}

| Parâmetro   | Tipo   | Obrigatório | Descrição                                                                                                             |
| ----------- | ------ | ----------- | --------------------------------------------------------------------------------------------------------------------- |
| `question`  | string | Sim         | O que depurar (1–8.000 caracteres)                                                                                    |
| `rationale` | string | Não         | Recomendado para clientes de IA. O que o usuário final está tentando fazer. Ajuda a priorizar a coleta de evidências. |
| `context`   | object | Não         | Metadados arbitrários do seu agente, incluídos no prompt de depuração                                                 |

### `/support/docs-search` {#supportdocs-search}

| Parâmetro  | Tipo   | Obrigatório | Descrição                                               |
| ---------- | ------ | ----------- | ------------------------------------------------------- |
| `question` | string | Sim         | A pergunta que deve ser respondida (1–8.000 caracteres) |

## Resposta {#response}

### resposta de `/support/ask` {#supportask-response}

```json
{
  "requestId": "req_...",
  "answer": "<2-4 sentence prose diagnosis of the issue plus the recommended fix.>",
  "confidence": "high",
  "fixParameters": { "<param>": "<value>" },
  "validation": {
    "tested": true,
    "result": "success",
    "evidence": "<short summary of the validation tool call the agent ran to confirm the fix>"
  },
  "feedback": null,
  "durationMs": 18432
}
```

Os valores reais de `answer`, `fixParameters` e `validation.evidence` são gerados pelo agente a cada solicitação com base na sua execução específica; o exemplo acima mostra a estrutura da resposta, não um diagnóstico real.

### resposta do `/support/docs-search` {#supportdocs-search-response}

```json
{
  "requestId": "req_...",
  "answer": "The signature is sent in the X-Firecrawl-Signature header...",
  "evidence": [
    { "pathOrUrl": "webhooks/security.mdx#L1-L52", "reason": "..." }
  ],
  "usage": { "inputTokens": 4356, "outputTokens": 688, "totalTokens": 5044 },
  "durationMs": 11252
}
```
