O Firecrawl Developer é um índice criado para agentes de programação. Ele abrange issues, pull requests mesclados e READMEs de repositórios públicos de código, além de sites de documentação selecionados, para que um agente possa responder a perguntas sobre o comportamento de código, uma biblioteca ou framework, um contrato de API, uma mensagem de erro ou um bug conhecido com base em fontes primárias, em vez de páginas web genéricas.

* Encontre a issue ou o pull request em que um bug foi relatado e corrigido
* Leia as passagens de um README ou de uma página de documentação que respondem a uma pergunta específica
* Rastreie um contrato de API até o pull request que o alterou
* Recupere a discussão por trás de uma mensagem de erro

<Note>
  Para dar ao seu agente acesso ao Índice para desenvolvedores, recomendamos fortemente usar nossa [CLI](/pt-BR/sdks/cli) ou o [MCP](/pt-BR/mcp-server), juntamente com nossa [**skill dedicada para desenvolvedores**](https://github.com/firecrawl/skills/blob/main/skills/firecrawl-developer-index/SKILL.md), que você pode instalar com:

  ```bash
  npx skills add firecrawl/skills@firecrawl-developer-index
  ```
</Note>

<div id="search-the-developer-index">
  ## Pesquise no índice para desenvolvedores
</div>

Envie uma pergunta em linguagem natural e receba resultados para desenvolvedor ranqueados, com as passagens correspondentes. Use este endpoint quando quiser apenas fontes para desenvolvedores, com filtros para tipo de resultado, repositório e fonte de documentação.

Uma busca para desenvolvedores custa 2 créditos por 10 resultados, arredondado para cima (1–10 resultados = 2 créditos, 11–20 = 4 créditos e assim por diante). Não é necessária uma chave de API para começar; envie uma para obter limites de taxa mais altos.

<CodeGroup>
  ```bash cURL
  # Não é necessária uma chave de API para começar; adicione -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obter limites de taxa mais altos:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

`POST` está disponível no mesmo endpoint e é a forma mais simples quando você quiser enviar filtros de array como JSON:

```bash cURL
# Não é necessário chave de API para começar; adicione -H "Authorization: Bearer $FIRECRAWL_API_KEY" para limites de taxa maiores:
curl -X POST https://api.firecrawl.dev/v2/search/developer \
  -H "Content-Type: application/json" \
  -d '{
    "query": "how do I configure retries",
    "k": 10,
    "types": ["issue", "pull_request"]
  }'
```

Cada resultado contém um `id` estável, como `issue:owner/repo#123`, um `type` de `doc`, `issue`, `pull_request` ou `readme`, uma `url` e os `passages` correspondentes em markdown, preservando tabelas e blocos de código. Muitas vezes, `title` está ausente em resultados `doc`, quando a página de origem não tem um título utilizável. Nesses casos, use a `url` em vez de presumir que o campo está presente.

Além dos resultados, `coverage` informa o status de cada tipo de resultado, e `reranked` informa se a lista ranqueada passou pela etapa de reordenação. Verifique `coverage` quando um tipo de resultado esperado estiver ausente: `skipped` significa que o valor de `types` não solicitou esse tipo, enquanto `degraded` ou `unavailable` significa que a ausência se deve ao índice ou a um filtro, e não à consulta.

Filtros opcionais restringem a busca:

* `k` define quantos resultados são retornados, com padrão de 10, e `passages` define quantas passagens correspondentes cada resultado inclui
* `types` seleciona quais entre `doc`, `issue`, `pull_request` e `readme` devem ser pesquisados
* `repos` restringe a parte do índice referente ao repositório, e `sources` restringe a parte da documentação
* `skills` definido como `only` limita a busca a arquivos de skills de agentes indexados
* `language`, `topic`, `license`, `min_stars`, `max_stars`, `archived` e `fork` filtram atributos do repositório, como `language=Rust`, `topic=async` ou `license=MIT`

Esses sete filtros descrevem um repositório de código. Portanto, enviar um deles sem restringir `sources` não retorna resultados `doc` e informa `doc` como `unavailable` em `coverage`. Leia [como os filtros de repositório restringem uma busca](/pt-BR/api-reference/endpoint/developer-search#how-the-repository-filters-scope-a-search) antes de usar um deles.

Consulte a [referência da busca para desenvolvedores](/pt-BR/api-reference/endpoint/developer-search) para ver o tipo e os limites de cada filtro, como `repos` e `sources` restringem uma busca e o esquema completo da resposta.

<Note>
  Os SDKs de Python e Node acessam o índice para desenvolvedores pela categoria `developer` mostrada abaixo. Eles não expõem um método dedicado para este endpoint; portanto, chame-o por HTTP, pela [CLI](/pt-BR/sdks/cli) ou pelo [MCP](/pt-BR/mcp-server).
</Note>

<div id="add-developer-results-to-a-web-search">
  ## Adicione resultados para desenvolvedores a uma busca na web
</div>

Passe `developer` no array `categories` de `/search` quando você já estiver chamando `/search` e quiser que os resultados para desenvolvedores sejam ponderados junto com os resultados web comuns em uma única chamada. A API os retorna em um grupo `developer` ao lado de `web`, e ambos os SDKs expõem esse grupo como `.developer`.

Nenhuma chave de API é necessária para começar — `/search` aceita solicitações sem chave, e a categoria `developer` vem incluída, sujeita à [cota sem chave](/pt-BR/rate-limits#keyless-no-api-key). Envie uma chave para limites de taxa mais altos.

<CodeGroup>
  ```bash cURL
  # Nenhuma chave de API é necessária para começar; adicione -H "Authorization: Bearer $FIRECRAWL_API_KEY" para limites de taxa mais altos:
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```bash CLI
  firecrawl search "how do I configure retries" --categories developer --limit 10
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // Nenhuma chave de API é necessária para começar; adicione uma para limites de taxa mais altos:
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

Os resultados para desenvolvedor nesse grupo contêm `url`, `title`, `description` e `position`, com a mesma estrutura de um resultado web, além de `category: "developer"`. Os resultados web na mesma resposta não têm `category`; portanto, use esse campo para distinguir os dois grupos caso você os mescle. Os resultados para desenvolvedor vêm em seu próprio grupo, não em `web`; os usuários dos SDKs os acessam com `result.developer`.

Esta interface retorna a estrutura de resultado web, não a estrutura de resultado para desenvolvedor ranqueado. Para as passagens correspondentes e os filtros de índice, use o [endpoint de busca para desenvolvedores](#search-the-developer-index).

<Note>
  O [servidor MCP](/pt-BR/mcp-server) hospedado expõe ambas as interfaces, e nenhuma delas grava nada. Consulte as [ferramentas MCP](/pt-BR/mcp-server/tools) para saber mais sobre `firecrawl_developer_search`, sobre resultados para desenvolvedor por meio de `firecrawl_search` e sobre qual das duas o conjunto de ferramentas sem chave inclui.
</Note>
