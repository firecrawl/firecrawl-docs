O Firecrawl Developer é um índice criado para agentes de programação. Ele abrange issues do GitHub, pull requests mesclados, READMEs de repositórios e sites de documentação selecionados, permitindo que um agente responda a perguntas sobre o comportamento de código, uma biblioteca ou framework, um contrato de API, uma mensagem de erro ou um bug conhecido com base em fontes primárias, em vez de páginas web genéricas.

* Encontre a issue ou o pull request em que um bug foi relatado e corrigido
* Leia os trechos de um README ou de uma página de documentação que respondem a uma pergunta específica
* Rastreie um contrato de API até o pull request que o alterou
* Recupere a discussão por trás de uma mensagem de erro

<Note>
  Para dar ao seu agente de programação acesso ao Índice para desenvolvedores, recomendamos nossa [CLI](/pt-BR/sdks/cli) ou o [servidor MCP](/pt-BR/mcp-server) — ambos o expõem como uma ferramenta de primeira classe, para que o agente recorra a ele sem que seja necessário informar o endpoint.
</Note>

<div id="two-ways-in">
  ## Duas formas de acesso
</div>

| Interface                                                              | Use quando                                                                                                        |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| A categoria `developer` em [`/search`](/pt-BR/features/search)               | Você quiser resultados para desenvolvedores junto com resultados comuns da web em uma única chamada               |
| O [endpoint de busca para desenvolvedores](#developer-search-endpoint) | Você quiser apenas resultados ranqueados para desenvolvedores, com trechos correspondentes e os filtros de índice |

<div id="developer-category-on-search">
  ## Categoria Developer no `/search`
</div>

Passe `developer` no array `categories` de `/search`. A API retorna resultados para desenvolvedor em um grupo `developer` ao lado de `web`, e ambos os SDKs expõem esse grupo como `.developer`.

Nenhuma chave de API é necessária para começar — `/search` aceita solicitações sem chave, e a categoria `developer` vem incluída, sujeita à [cota sem chave](/pt-BR/rate-limits#keyless-no-api-key). Envie uma chave para limites de taxa mais altos.

<CodeGroup>
  ```bash cURL
  # Nenhuma chave de API é necessária para começar; adicione -H "Authorization: Bearer $FIRECRAWL_API_KEY" para limites de taxa mais altos:
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(
      # Nenhuma chave de API é necessária para começar; adicione uma para limites de taxa mais altos:
      # api_key="fc-YOUR-API-KEY",
  )

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // Nenhuma chave de API é necessária para começar; adicione uma para limites de taxa mais altos:
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

Os resultados para desenvolvedor nesse grupo contêm `url`, `title`, `description` e `position`, com a mesma estrutura de um resultado web, além de `category: "developer"`. Os resultados web na mesma resposta não têm `category`; portanto, use esse campo para distinguir os dois grupos caso você os mescle.

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://example.com/blog/retry-strategies",
        "title": "Retry strategies for HTTP clients",
        "description": "An overview of backoff and retry patterns"
      }
    ],
    "developer": [
      {
        "url": "https://github.com/firecrawl/firecrawl/issues/1234",
        "title": "Retries are not applied to 429 responses",
        "description": "Reported behavior and the fix that landed",
        "position": 1,
        "category": "developer"
      }
    ]
  }
}
```

<Note>
  **Usuários do SDK:** os resultados para desenvolvedor vêm em seu próprio grupo, não em `.web`. Acesse-os com `result.developer`.
</Note>

<div id="developer-search-endpoint">
  ## Endpoint de busca para desenvolvedores
</div>

| Tarefa                                   | Endpoint                                                                      |
| ---------------------------------------- | ----------------------------------------------------------------------------- |
| Pesquisar no índice para desenvolvedores | [`GET` ou `POST /search/developer`](/pt-BR/api-reference/endpoint/developer-search) |

Uma busca para desenvolvedores custa 2 créditos a cada 10 resultados, arredondando para cima (1–10 resultados = 2 créditos, 11–20 = 4 créditos e assim por diante). Não é necessária uma chave de API para começar; envie uma para obter limites de taxa mais altos.

<CodeGroup>
  ```bash cURL
  # Não é necessária uma chave de API para começar; adicione -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obter limites de taxa mais altos:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"]
    }'
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

<Note>
  Os SDKs de Python e Node acessam o índice para desenvolvedores pela categoria `developer` mostrada acima. Eles não disponibilizam um método dedicado para esse endpoint; portanto, chame-o por HTTP, pela [CLI](/pt-BR/sdks/cli) ou pelo [MCP](/pt-BR/mcp-server).
</Note>

<div id="filters">
  ### Filtros
</div>

Todos os filtros são opcionais.

| Filtro      | Significado                                                                                        |
| ----------- | -------------------------------------------------------------------------------------------------- |
| `k`         | Número de resultados ranqueados a retornar. O padrão é 20, com máximo de 100                       |
| `types`     | Tipos de resultado a buscar: `doc`, `issue`, `pull_request` ou `readme`. O padrão inclui os quatro |
| `repos`     | Slugs dos repositórios aos quais restringir a busca, como `firecrawl/firecrawl`                    |
| `sources`   | IDs das fontes de documentação às quais restringir a busca, no máximo 20. Veja abaixo              |
| `passages`  | Trechos correspondentes a retornar por resultado. O padrão é 1, com máximo de 5                    |
| `language`  | Linguagem do repositório                                                                           |
| `topic`     | Tópico do repositório                                                                              |
| `license`   | Licença do repositório                                                                             |
| `min_stars` | Limite inferior de estrelas do repositório                                                         |
| `max_stars` | Limite superior de estrelas do repositório                                                         |
| `archived`  | Incluir ou excluir repositórios arquivados                                                         |
| `fork`      | Incluir ou excluir forks                                                                           |

Filtros repetíveis aceitam qualquer uma das formas em `GET`: um parâmetro de query repetido, como `types=issue&types=pull_request`, ou um único valor separado por vírgulas, como `types=issue,pull_request`. Em `POST`, passe um array no corpo JSON.

<div id="how-repos-and-sources-scope-a-search">
  ### Como `repos` e `sources` restringem uma busca
</div>

O índice tem duas partes, e esses dois filtros restringem cada uma delas de forma independente:

* `repos` restringe a parte do GitHub, ou seja, os tipos `issue`, `pull_request` e `readme`
* `sources` restringe a parte da documentação, ou seja, o tipo `doc`
* Informar ambos combina as duas partes, em vez de cruzá-las, para que você receba resultados correspondentes de qualquer uma delas

Como cada filtro se aplica apenas a uma das partes, um filtro que não pode corresponder a nenhum tipo solicitado é rejeitado, em vez de não retornar nada silenciosamente:

* `repos` sem nenhum tipo do GitHub em `types` retorna `400` com `repos cannot match any requested type; add github types or drop repos`
* `sources` sem `doc` em `types` retorna `400` com `sources cannot match any requested type; add doc or drop sources`

<div id="which-values-sources-accepts">
  ### Quais valores `sources` aceita
</div>

`sources` não é uma enumeração fixa. Aceita IDs de fontes de documentação, cada um uma string não vazia de no máximo 512 caracteres, com no máximo 20 por solicitação. Os IDs refletem os sites de documentação no índice, e o conjunto cresce ao longo do tempo.

Para confirmar que um ID é reconhecido, informe-o e consulte o array `sources` adicionado à resposta. Ele só aparece quando você envia `sources` e informa cada ID exatamente como foi solicitado, além de indicar se está indexado:

```json
{
  "success": true,
  "results": [],
  "sources": [
    { "source": "some-docs-site", "indexed": true },
    { "source": "unknown-docs-site", "indexed": false }
  ]
}
```

`indexed: true` significa que a fonte tem uma geração publicada; portanto, evidências dessa documentação podem aparecer. `indexed: false` significa que nada desse id pode corresponder, o que diferencia um id que não está no índice de uma query que simplesmente não encontrou nada.

`repos` é retornado da mesma forma, como um array `repos` que informa `indexed` e uma divisão por tipo entre `issue`, `pullRequest` e `readme`.

<div id="response">
  ### Resposta
</div>

```json
{
  "success": true,
  "results": [
    {
      "id": "issue:firecrawl/firecrawl#1234",
      "type": "issue",
      "url": "https://github.com/firecrawl/firecrawl/issues/1234",
      "title": "Retries are not applied to 429 responses",
      "passages": [
        {
          "text": "The client treats 429 as a terminal status, so the backoff never runs."
        }
      ]
    }
  ],
  "coverage": {
    "doc": "ok",
    "issue": "ok",
    "pull_request": "ok",
    "readme": "ok"
  },
  "reranked": true
}
```

* `id` é um ID de resultado estável, como `issue:owner/repo#123`
* `type` pode ser `doc`, `issue`, `pull_request` ou `readme`
* `title` é opcional e frequentemente está ausente em resultados `doc`, nos quais a página de origem não tem um título utilizável. Use `url` como alternativa em vez de presumir que o campo está presente
* `passages` contém os trechos correspondentes em markdown, preservando tabelas e blocos de código
* `coverage` informa a integridade do índice para cada tipo de resultado: `ok`, `degraded`, `unavailable` ou `skipped`
* `reranked` informa se a lista ranqueada passou pela etapa de reranqueamento

Verifique `coverage` quando um tipo de resultado esperado estiver ausente. Um status `degraded` ou `unavailable` indica que a lacuna se deve ao índice, e não à query.

<div id="use-it-from-mcp">
  ## Use pelo MCP
</div>

O [servidor MCP](/pt-BR/mcp-server) hospedado expõe ambas as interfaces, e nenhuma delas realiza gravações. Conecte-se usando o OAuth da conta ou uma chave de API, conforme descrito em [Conectar o Firecrawl MCP](/pt-BR/mcp-server/connect). Em uma conexão hospedada sem chave, `firecrawl_search` com `categories: ["developer"]` retorna resultados para desenvolvedor, enquanto a ferramenta dedicada `firecrawl_developer_search` não faz parte do [conjunto de ferramentas sem chave](/pt-BR/mcp-server/tools) e requer uma conexão de conta ou uma chave de API.

<div id="developer-search-tool-firecrawl_developer_search">
  ### Ferramenta de Busca para Desenvolvedores (`firecrawl_developer_search`)
</div>

Pesquise o Índice para Desenvolvedores de forma independente e receba resultados ranqueados com os trechos correspondentes.

```json
{
  "name": "firecrawl_developer_search",
  "arguments": {
    "query": "how do I configure retries",
    "k": 10
  }
}
```

<div id="developer-search-tool-options">
  #### Opções da Ferramenta de Busca para Desenvolvedores:
</div>

* `query`: A string da consulta de busca (obrigatória)
* `k`: Número de resultados ranqueados a retornar, de 1 a 100

**Ideal para:** Responder a perguntas sobre o comportamento de código, uma biblioteca ou framework, um contrato de API, uma mensagem de erro ou um bug conhecido com base em fontes primárias.
**Retorna:** Cada resultado como um bloco Markdown contendo seu ID, tipo, URL, título e trechos correspondentes.

A ferramenta aceita apenas esses dois argumentos. Chame o [endpoint de busca para desenvolvedores](#developer-search-endpoint) via HTTP quando precisar de filtros por tipo de resultado, repositório ou fonte de documentação.

<div id="developer-results-from-the-search-tool-firecrawl_search">
  ### Resultados para desenvolvedores na Ferramenta de Busca (`firecrawl_search`)
</div>

Passe `developer` em `categories` para obter resultados para desenvolvedores em um grupo `developer`, ao lado dos resultados comuns da web, no mesmo formato retornado pela categoria `developer` em `/search`.

```json
{
  "name": "firecrawl_search",
  "arguments": {
    "query": "how do I configure retries",
    "categories": ["developer"],
    "limit": 10
  }
}
```

**Ideal para:** Uma única chamada quando você quiser combinar fontes para desenvolvedores e páginas gerais da web.
**Retorna:** A resposta de busca padrão, com resultados para desenvolvedores agrupados em `developer` e cada um com `category: "developer"`.
