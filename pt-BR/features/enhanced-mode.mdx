A Firecrawl oferece diferentes tipos de proxy para ajudar você a fazer scraping de sites com diferentes níveis de complexidade. Defina o parâmetro `proxy` para controlar qual estratégia de proxy será usada em uma requisição.

## Tipos de proxy {#proxy-types}

| Tipo       | Descrição                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------- |
| `basic`    | Proxies padrão adequados para a maioria dos sites                                           |
| `enhanced` | Proxies aprimorados para sites complexos                                                    |
| `auto`     | **Recomendado.** Tenta `basic` primeiro e, em caso de falha, tenta novamente com `enhanced` |

Se você não especificar um proxy, o Firecrawl usa `auto` por padrão.

## Quando o Firecrawl escala {#when-firecrawl-escalates}

O Firecrawl começa com proxies basic. Se o target responder com **401, 403 ou 429**, o Firecrawl interpreta isso como sinal de que o proxy não foi suficiente e tenta novamente a mesma URL usando proxies aprimorados. Outros códigos de status, incluindo 404 e 5xx, não disparam a escalada, porque um proxy diferente não mudaria a resposta.

A escalada acontece no máximo uma vez por requisição. Quando uma requisição já está usando proxies aprimorados, um novo 401, 403 ou 429 é devolvido a você como resultado, em vez de gerar outra tentativa.

Você não precisa detectar nem tratar isso. A nova tentativa faz parte da mesma requisição, e a resposta que você recebe é a definitiva.

<Info>
  Requisições com proxy aprimorado custam o mesmo que requisições basic — **1 crédito por requisição**. A nova tentativa após a escalada não é cobrada à parte, então uma requisição que começa em basic e termina em aprimorado ainda custa 1 crédito.
</Info>
