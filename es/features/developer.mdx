Firecrawl Developer es un índice diseñado para agentes de programación. Incluye issues, pull requests fusionadas, archivos README de repositorios de código públicos, junto con sitios de documentación seleccionados, para que un agente pueda responder preguntas sobre el comportamiento del código, una biblioteca o un framework, un contrato de API, un mensaje de error o un error conocido a partir de fuentes primarias, en lugar de una página web general.

* Encuentra el issue o pull request en el que se informó y corrigió un error
* Lee los pasajes de un README o una página de documentación que respondan una pregunta concreta
* Rastrea un contrato de API hasta el pull request que lo modificó
* Recupera la discusión relacionada con un mensaje de error

<Note>
  Para dar a tu agente acceso al Índice para desarrolladores, recomendamos encarecidamente usar nuestra [CLI](/es/sdks/cli) o [MCP](/es/mcp-server), junto con nuestra [**skill específica para desarrolladores**](https://github.com/firecrawl/cli/tree/main/skills/firecrawl-developer-index), que puedes instalar con:

  ```bash
  npx -y firecrawl-cli@latest setup developer-index
  ```
</Note>

<div id="search-the-developer-index">
  ## Busca en el índice para desarrolladores
</div>

Envía una pregunta en lenguaje natural y recibe resultados para desarrolladores ordenados por relevancia, junto con los pasajes coincidentes. Usa esta ruta cuando solo quieras fuentes para desarrolladores, con filtros disponibles por tipo de resultado, repositorio y fuente de documentación.

Una búsqueda para desarrolladores cuesta 2 créditos por cada 10 resultados, redondeando hacia arriba (1–10 resultados = 2 créditos, 11–20 = 4 créditos, y así sucesivamente). No necesitas una clave de API para empezar; añade una para obtener límites de tasa más altos.

<CodeGroup>
  ```bash cURL
  # No API key needed to get started; add -H "Authorization: Bearer $FIRECRAWL_API_KEY" for higher rate limits:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

`POST` está disponible en la misma ruta y es más práctico cuando quieres pasar filtros de array como JSON:

```bash cURL
# No hace falta una clave de API para empezar; añade -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obtener límites de tasa más altos:
curl -X POST https://api.firecrawl.dev/v2/search/developer \
  -H "Content-Type: application/json" \
  -d '{
    "query": "how do I configure retries",
    "k": 10,
    "types": ["issue", "pull_request"]
  }'
```

Cada resultado incluye un `id` estable, como `issue:owner/repo#123`, una `url` y los `passages` coincidentes en Markdown, para conservar las tablas y los bloques de código. El tipo de artefacto está codificado en el prefijo de `id`: `doc:`, `issue:`, `pull_request:` o `readme:`. En los resultados `doc`, `title` suele estar ausente cuando la página de origen no tiene un título utilizable; en ese caso, use `url` como alternativa en lugar de asumir que el campo está presente.

Cuando acota una búsqueda con `sources` o `repos`, la respuesta los devuelve con una marca `indexed` por entrada, para que pueda distinguir un id que no está en el índice de una consulta que simplemente no encontró nada. Consulte la [referencia de búsqueda para desarrolladores](/es/api-reference/endpoint/developer-search) para conocer la estructura de esta respuesta.

Los filtros opcionales acotan la búsqueda:

* `k` establece cuántos resultados se devuelven; el valor predeterminado es 10, y `passages` indica cuántos pasajes coincidentes incluye cada resultado
* `types` selecciona en cuáles de `doc`, `issue`, `pull_request` y `readme` buscar
* `repos` acota la parte de repositorios del índice y `sources` la parte de documentación
* `skills` establecido en `only` limita la búsqueda a archivos de skills de agente indexados
* `language`, `topic`, `license`, `min_stars`, `max_stars`, `archived` y `fork` filtran por atributos del repositorio, como `language=Rust`, `topic=async` o `license=MIT`

Estos siete filtros describen un repositorio de código, por lo que enviar uno sin acotar `sources` no devuelve resultados `doc`. Lea [cómo los filtros de repositorio acotan una búsqueda](/es/api-reference/endpoint/developer-search#how-the-repository-filters-scope-a-search) antes de enviar uno.

Consulte la [referencia de búsqueda para desarrolladores](/es/api-reference/endpoint/developer-search) para conocer el tipo y los límites de cada filtro, cómo `repos` y `sources` acotan una búsqueda y el esquema completo de respuesta.

<Note>
  Los SDK de Python y Node acceden al índice para desarrolladores mediante la categoría `developer` que se muestra a continuación. No exponen un método específico para este endpoint, así que llámelo mediante HTTP, a través de la [CLI](/es/sdks/cli) o de [MCP](/es/mcp-server).
</Note>

<div id="add-developer-results-to-a-web-search">
  ## Añade resultados para desarrolladores a una búsqueda web
</div>

Pasa `developer` como única entrada en el array `categories` de `/search`. La respuesta devuelve resultados para desarrolladores en el grupo estándar `web`, cada uno etiquetado con `category: "developer"`. La categoría `developer` no se puede combinar con otras categorías.

No se necesita una clave de API para empezar: `/search` acepta solicitudes sin clave e incluye la categoría `developer`, sujeta al [límite de uso sin clave](/es/rate-limits#keyless-no-api-key). Envía una clave para obtener límites de tasa más altos.

<CodeGroup>
  ```bash cURL
  # No se necesita una clave de API para empezar; añade -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obtener límites de tasa más altos:
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```bash CLI
  firecrawl search "how do I configure retries" --categories developer --limit 10
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.web or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // No se necesita una clave de API para empezar; añade una para obtener límites de tasa más altos:
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.web ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

Los resultados para desarrolladores incluyen `url`, `title`, `description` y `position`, con la misma estructura que un resultado web, además de `category: "developer"`. Los usuarios del SDK acceden a ellos desde `result.web`.

Esta interfaz devuelve la estructura de resultado web, no la estructura de resultados para desarrolladores clasificados. Para los pasajes coincidentes y los filtros de índice, usa el [endpoint de búsqueda para desarrolladores](#search-the-developer-index).

<Note>
  El [MCP Server](/es/mcp-server) alojado expone ambas interfaces y ninguna realiza escrituras. Consulta [herramientas MCP](/es/mcp-server/tools) para `firecrawl_developer_search`, para obtener resultados para desarrolladores mediante `firecrawl_search` y para saber cuál de las dos interfaces de herramientas está disponible sin clave.
</Note>
