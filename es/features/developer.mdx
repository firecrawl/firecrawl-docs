Firecrawl Developer es un índice diseñado para agentes de programación. Incluye issues de GitHub, pull requests fusionadas, archivos README de repositorios y sitios de documentación seleccionados, para que un agente pueda responder preguntas sobre el comportamiento del código, una biblioteca o un framework, un contrato de API, un mensaje de error o un error conocido a partir de fuentes primarias, en lugar de una página web general.

* Encuentra el issue o pull request en el que se informó y corrigió un error
* Lee los pasajes de un README o una página de documentación que respondan una pregunta concreta
* Rastrea un contrato de API hasta el pull request que lo modificó
* Recupera la discusión relacionada con un mensaje de error

<Note>
  Para dar a tu agente de programación acceso al Índice para desarrolladores, recomendamos nuestra [CLI](/es/sdks/cli) o el [MCP Server](/es/mcp-server): ambos lo exponen como una herramienta de primera clase, para que el agente lo use sin que se le indique el endpoint.
</Note>

<div id="two-ways-in">
  ## Dos formas de acceder
</div>

| Superficie                                                                 | Úsalo cuando                                                                                                                   |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| La categoría `developer` en [`/search`](/es/features/search)                  | Quieres resultados para desarrolladores junto con resultados web generales en una sola llamada                                 |
| El [endpoint de búsqueda para desarrolladores](#developer-search-endpoint) | Quieres únicamente resultados ordenados para desarrolladores, con pasajes coincidentes y los filtros del índice |

<div id="developer-category-on-search">
  ## Categoría `developer` en `/search`
</div>

Pasa `developer` en el array `categories` de `/search`. La API devuelve resultados para desarrolladores en un grupo `developer` junto a `web`, y ambos SDK exponen ese grupo como `.developer`.

No se necesita una clave de API para empezar: `/search` acepta solicitudes sin clave e incluye la categoría `developer`, sujeta al [límite de uso sin clave](/es/rate-limits#keyless-no-api-key). Envía una clave para obtener límites de tasa más altos.

<CodeGroup>
  ```bash cURL
  # No se necesita una clave de API para empezar; añade -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obtener límites de tasa más altos:
  curl -X POST https://api.firecrawl.dev/v2/search \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "categories": ["developer"],
      "limit": 10
    }'
  ```

  ```python Python
  from firecrawl import Firecrawl

  firecrawl = Firecrawl(
      # No se necesita una clave de API para empezar; añade una para obtener límites de tasa más altos:
      # api_key="fc-YOUR-API-KEY",
  )

  result = firecrawl.search(
      "how do I configure retries",
      categories=["developer"],
      limit=10,
  )
  for item in result.developer or []:
      print(item.url, item.title)
  ```

  ```js Node
  import { Firecrawl } from "firecrawl";

  const firecrawl = new Firecrawl({
    // No se necesita una clave de API para empezar; añade una para obtener límites de tasa más altos:
    // apiKey: "fc-YOUR-API-KEY",
  });

  const result = await firecrawl.search("how do I configure retries", {
    categories: ["developer"],
    limit: 10,
  });
  for (const item of result.developer ?? []) {
    console.log(item.url, item.title);
  }
  ```
</CodeGroup>

Los resultados para desarrolladores de este grupo incluyen `url`, `title`, `description` y `position`, con la misma estructura que un resultado web, además de `category: "developer"`. Los resultados web de la misma respuesta no tienen `category`, por lo que debes usar ese campo si fusionas ambos grupos.

```json
{
  "success": true,
  "data": {
    "web": [
      {
        "url": "https://example.com/blog/retry-strategies",
        "title": "Retry strategies for HTTP clients",
        "description": "An overview of backoff and retry patterns"
      }
    ],
    "developer": [
      {
        "url": "https://github.com/firecrawl/firecrawl/issues/1234",
        "title": "Retries are not applied to 429 responses",
        "description": "Reported behavior and the fix that landed",
        "position": 1,
        "category": "developer"
      }
    ]
  }
}
```

<Note>
  **Usuarios del SDK:** los resultados de desarrolladores se incluyen en su propio grupo, no en `.web`. Acceda a ellos con `result.developer`.
</Note>

<div id="developer-search-endpoint">
  ## Endpoint de búsqueda para desarrolladores
</div>

| Tarea                                    | Endpoint                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| Buscar en el índice para desarrolladores | [`GET` o `POST /search/developer`](/es/api-reference/endpoint/developer-search) |

Una búsqueda para desarrolladores cuesta 2 créditos por cada 10 resultados, redondeando hacia arriba (de 1 a 10 resultados = 2 créditos; de 11 a 20 = 4 créditos, y así sucesivamente). No necesitas una clave de API para empezar; envía una para obtener límites de tasa más altos.

<CodeGroup>
  ```bash cURL
  # No necesitas una clave de API para empezar; añade -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obtener límites de tasa más altos:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"]
    }'
  ```

  ```bash CLI
  firecrawl developer "how do I configure retries" --limit 10
  ```
</CodeGroup>

<Note>
  Los SDK de Python y Node acceden al índice para desarrolladores mediante la categoría `developer` mostrada arriba. No exponen un método específico para este endpoint, así que llámalo mediante HTTP, a través de la [CLI](/es/sdks/cli) o de [MCP](/es/mcp-server).
</Note>

<div id="filters">
  ### Filtros
</div>

Todos los filtros son opcionales.

| Filtro      | Significado                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `k`         | Número de resultados ordenados que se devolverán. El valor predeterminado es 10; el máximo es 100                               |
| `types`     | Tipos de resultados en los que buscar: `doc`, `issue`, `pull_request` o `readme`. De forma predeterminada, se buscan los cuatro |
| `repos`     | Slugs de repositorios a los que acotar la búsqueda, como `firecrawl/firecrawl`                                                 |
| `sources`   | IDs de fuentes de documentación a los que acotar la búsqueda; máximo 20. Consulta la sección siguiente                         |
| `passages`  | Pasajes coincidentes que se devolverán por resultado. El valor predeterminado es 1; el máximo es 5                              |
| `language`  | Lenguaje principal del repositorio, como `Rust`                                                                                 |
| `topic`     | Tema del repositorio, como `async`                                                                                              |
| `license`   | Licencia del repositorio, como `MIT`                                                                                            |
| `min_stars` | Límite inferior de estrellas del repositorio                                                                                    |
| `max_stars` | Límite superior de estrellas del repositorio                                                                                    |
| `archived`  | Incluir o excluir repositorios archivados                                                                                       |
| `fork`      | Incluir o excluir bifurcaciones                                                                                                 |

Los filtros repetibles aceptan cualquiera de los dos formatos en `GET`: un parámetro de consulta repetido, como `types=issue&types=pull_request`, o un único valor separado por comas, como `types=issue,pull_request`. En `POST`, pasa un array en el cuerpo JSON.

Los filtros `language`, `topic`, `license`, `min_stars`, `max_stars`, `archived` y `fork` describen un repositorio de GitHub. No acotan el índice como lo hacen `repos` y `sources`. Lee [cómo los filtros de repositorio acotan una búsqueda](#how-the-repository-filters-scope-a-search) antes de enviar alguno.

<div id="how-repos-and-sources-scope-a-search">
  ### Cómo `repos` y `sources` acotan una búsqueda
</div>

El índice se divide en dos partes, y estos filtros acotan cada una de forma independiente:

* `repos` acota la parte de GitHub, es decir, los tipos `issue`, `pull_request` y `readme`
* `sources` acota la parte de documentación, es decir, el tipo `doc`
* Al pasar ambos, se combinan las dos partes en lugar de intersectarse, por lo que obtienes resultados coincidentes de cualquiera de las dos

Como cada filtro solo se aplica a una parte, se rechaza cualquier filtro que no pueda coincidir con ninguno de los tipos solicitados, en lugar de no devolver resultados de forma silenciosa:

* `repos` sin ningún tipo de GitHub en `types` devuelve `400` con `repos cannot match any requested type; add github types or drop repos`
* `sources` sin `doc` en `types` devuelve `400` con `sources cannot match any requested type; add doc or drop sources`

<div id="which-values-sources-accepts">
  ### Valores que acepta `sources`
</div>

`sources` no es un enum fijo. Acepta IDs de fuentes de documentación: cada uno debe ser una cadena no vacía de hasta 512 caracteres, con un máximo de 20 por solicitud. Los IDs reflejan los sitios de documentación del índice y el conjunto crece con el tiempo.

Para confirmar que un ID se resuelve, envíalo y consulta el array `sources` que añade la respuesta. Solo aparece si enviaste `sources` e indica cada ID exactamente como lo solicitaste, junto con si está indexado:

```json
{
  "success": true,
  "results": [],
  "sources": [
    { "source": "some-docs-site", "indexed": true },
    { "source": "unknown-docs-site", "indexed": false }
  ]
}
```

`indexed: true` significa que la fuente tiene una generación publicada, por lo que puede aparecer documentación procedente de ella. `indexed: false` significa que nada de ese id puede coincidir, lo que distingue un id que no está en el índice de una query que simplemente no encontró resultados.

`repos` se devuelve de la misma forma, como un array `repos` que indica `indexed` y un desglose por tipo de `issue`, `pullRequest` y `readme`.

<div id="how-the-repository-filters-scope-a-search">
  ### Cómo los filtros de repositorio acotan una búsqueda
</div>

Los siete filtros de repositorio — `language`, `topic`, `license`, `min_stars`, `max_stars`, `archived` y `fork` — describen un repositorio de GitHub. La mayoría de las páginas de documentación del índice proceden de un sitio web rastreado sin un repositorio asociado. Ningún dato del repositorio puede incluir ni excluir una página de este tipo.

Por lo tanto, una solicitud que envía uno de estos filtros sin un ámbito de `sources` no obtiene resultados de tipo `doc`. Su respuesta solo contiene evidencia de GitHub: los tipos `issue`, `pull_request` y `readme`. El mapa de `coverage` muestra `doc` como `unavailable`, porque la parte de documentación del índice no se ejecutó. Esto es intencional, no un fallo del índice.

Para conservar los resultados de documentación, elimina los filtros de repositorio. También puedes acotar la parte de documentación con `sources` y consultar `coverage` para confirmar que el tipo `doc` respondió.

<CodeGroup>
  ```bash cURL
  # No necesitas una clave de API para empezar; añade -H "Authorization: Bearer $FIRECRAWL_API_KEY" para obtener límites de tasa más altos:
  curl -s "https://api.firecrawl.dev/v2/search/developer?query=how%20do%20I%20configure%20retries&k=10&language=Rust&license=MIT"
  ```

  ```bash cURL (POST)
  curl -X POST https://api.firecrawl.dev/v2/search/developer \
    -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "query": "how do I configure retries",
      "k": 10,
      "types": ["issue", "pull_request"],
      "language": "Rust",
      "license": "MIT"
    }'
  ```
</CodeGroup>

<div id="response">
  ### Respuesta
</div>

```json
{
  "success": true,
  "results": [
    {
      "id": "issue:firecrawl/firecrawl#1234",
      "type": "issue",
      "url": "https://github.com/firecrawl/firecrawl/issues/1234",
      "title": "Retries are not applied to 429 responses",
      "passages": [
        {
          "text": "The client treats 429 as a terminal status, so the backoff never runs."
        }
      ]
    }
  ],
  "coverage": {
    "doc": "ok",
    "issue": "ok",
    "pull_request": "ok",
    "readme": "ok"
  },
  "reranked": true
}
```

* `id` es un identificador de resultado estable, como `issue:owner/repo#123`
* `type` puede ser `doc`, `issue`, `pull_request` o `readme`
* `title` es opcional y suele estar ausente en los resultados `doc`, donde la página de origen no tiene un título utilizable. Usa `url` como alternativa en lugar de asumir que el campo está presente
* `passages` contiene los pasajes coincidentes en Markdown para conservar las tablas y los bloques de código
* `coverage` indica el resultado para cada tipo de resultado: `ok`, `degraded`, `unavailable` o `skipped`
* `reranked` indica si la lista ordenada pasó por la fase de reordenamiento

Comprueba `coverage` si falta un tipo de resultado que esperabas. `skipped` significa que tu valor de `types` no solicitó ese tipo. Un estado `degraded` o `unavailable` significa que la ausencia se debe al índice o a un filtro, no a la query. Un filtro de repositorio es una de esas causas, como se describe en [cómo los filtros de repositorio acotan una búsqueda](#how-the-repository-filters-scope-a-search).

<div id="use-it-from-mcp">
  ## Úsalo desde MCP
</div>

El [MCP Server](/es/mcp-server) alojado expone ambas interfaces y no realiza ninguna operación de escritura. Conéctate mediante OAuth de cuenta o una clave de API como se describe en [Conectar Firecrawl MCP](/es/mcp-server/connect). En una conexión alojada sin clave, `firecrawl_search` con `categories: ["developer"]` devuelve resultados para desarrolladores, mientras que la herramienta específica `firecrawl_developer_search` no forma parte de la [superficie de herramientas sin clave](/es/mcp-server/tools) y requiere una conexión de cuenta o una clave de API.

<div id="developer-search-tool-firecrawl_developer_search">
  ### Herramienta de búsqueda para desarrolladores (`firecrawl_developer_search`)
</div>

Busca en el índice para desarrolladores de forma independiente y obtén resultados ordenados con los pasajes coincidentes.

```json
{
  "name": "firecrawl_developer_search",
  "arguments": {
    "query": "how do I configure retries",
    "k": 10
  }
}
```

<div id="developer-search-tool-options">
  #### Opciones de la herramienta de búsqueda para desarrolladores:
</div>

* `query`: Cadena de consulta de búsqueda (obligatoria)
* `k`: Número de resultados ordenados que se devolverán, de 1 a 100

**Ideal para:** Responder preguntas sobre el comportamiento del código, una biblioteca o framework, un contrato de API, un mensaje de error o un error conocido, a partir de fuentes primarias.
**Devuelve:** Cada resultado como un bloque Markdown con su id, tipo, URL, título y pasajes coincidentes.

La herramienta acepta únicamente esos dos argumentos. Usa el [endpoint de búsqueda para desarrolladores](#developer-search-endpoint) mediante HTTP cuando necesites filtrar por tipo de resultado, repositorio o fuente de documentación.

<div id="developer-results-from-the-search-tool-firecrawl_search">
  ### Resultados para desarrolladores de la herramienta de búsqueda (`firecrawl_search`)
</div>

Incluye `developer` en `categories` para obtener resultados para desarrolladores en un grupo `developer`, junto a los resultados web habituales, con la misma estructura que devuelve la categoría `developer` en `/search`.

```json
{
  "name": "firecrawl_search",
  "arguments": {
    "query": "how do I configure retries",
    "categories": ["developer"],
    "limit": 10
  }
}
```

**Ideal para:** Una sola llamada cuando quieres combinar fuentes para desarrolladores y páginas web generales.
**Devuelve:** La respuesta de búsqueda habitual, con los resultados para desarrolladores agrupados en `developer` y cada uno con `category: "developer"`.
