Firecrawl ofrece distintos tipos de proxy para ayudarte a hacer scraping de sitios web con diferentes niveles de complejidad. Configura el parámetro `proxy` para controlar qué estrategia de proxy se utiliza para una solicitud.

## Tipos de proxy {#proxy-types}

| Tipo       | Descripción                                                                             |
| ---------- | --------------------------------------------------------------------------------------- |
| `basic`    | Proxies estándar adecuados para la mayoría de los sitios                                |
| `enhanced` | Proxies mejorados para sitios complejos                                                 |
| `auto`     | **Recomendado.** Primero prueba `basic` y, si falla, vuelve a intentarlo con `enhanced` |

Si no especificas ningún proxy, Firecrawl usa `auto` de forma predeterminada.

## Cuándo escala Firecrawl {#when-firecrawl-escalates}

Firecrawl empieza con proxies basic. Si el objetivo responde con **401, 403 o 429**, Firecrawl lo interpreta como una señal de que el proxy no fue suficiente y reintenta la misma URL a través de proxies mejorados. Otros códigos de estado, incluidos 404 y 5xx, no provocan una escalada, porque cambiar de proxy no alteraría la respuesta.

La escalada ocurre como máximo una vez por solicitud. Cuando una solicitud ya está en proxies mejorados, un nuevo 401, 403 o 429 se te devuelve como resultado en lugar de reintentarse de nuevo.

No necesitas detectarlo ni gestionarlo. El reintento forma parte de la misma solicitud y la respuesta que recibes es la definitiva.

<Info>
  Las solicitudes con proxy mejorado cuestan lo mismo que las solicitudes basic: **1 crédito por solicitud**. Un reintento escalado no se cobra por separado, así que una solicitud que empieza en basic y termina en enhanced sigue costando 1 crédito.
</Info>
