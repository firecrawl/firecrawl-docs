## Descripción general {#overview}

Firecrawl for Platforms permite que tu plataforma cree y gestione claves de API de Firecrawl para tus usuarios directamente desde tu propio backend. Así, tus usuarios pueden buscar, extraer datos e interactuar con la web a través de Firecrawl, la API de contexto para agentes de IA, sin salir de tu plataforma.

<Note>
  Configura Firecrawl for Platforms por tu cuenta en el [Panel de control de Firecrawl](https://www.firecrawl.dev/app/partner-api). Cualquier administrador o miembro de una organización puede crear una integración: asígnale un nombre, selecciona un tipo de integración, acepta el acuerdo correspondiente a ese tipo y copia la clave de plataforma. La clave solo se muestra una vez. Más adelante puedes generar y revocar claves en Settings. No hace falta enviar ninguna solicitud ni esperar aprobación.
</Note>

Hay dos tipos de integración. Ambos aprovisionan cuentas de la misma forma, mediante los endpoints que se describen a continuación y con la misma clave de plataforma; la diferencia está en quién paga el uso de cada usuario:

* **Standard**: tus usuarios pagan a Firecrawl. Cada cuenta aprovisionada mantiene su propio plan y facturación de Firecrawl y cambia a un plan superior directamente con Firecrawl. Consulta [Créditos para cuentas aprovisionadas](#credits-for-provisioned-accounts) para saber con qué empieza una cuenta nueva.
* **Gateway**: tu organización cubre el uso de tus usuarios. Las cuentas que crea tu integración se inscriben en Gateway, de modo que su uso elegible se factura a tu organización. Consulta [Gateway](#gateway) más abajo.

El tipo de integración se selecciona al crearla. Cambiarlo después no es sencillo, así que te recomendamos revisar bien ambas opciones antes de aceptar el acuerdo. Consulta la [página de Firecrawl for Platforms](https://www.firecrawl.dev/firecrawl-for-platforms) para ver una descripción general.

Algunas ofertas del socio incluyen créditos promocionales para los usuarios aprovisionados; en ese caso, en [Créditos de socio](/es/partner-credits) se detalla lo que recibe el usuario.

### Gateway {#gateway}

Gateway es un tipo de integración, no una API independiente. Se usan la misma clave de plataforma y los mismos endpoints. Esto es lo que cambia en una integración Gateway:

* Las cuentas se crean exclusivamente para tu integración y son solo de API, sin acceso propio al Dashboard. Una solicitud nunca se vincula a una cuenta de Firecrawl existente, aunque el correo electrónico coincida con el de una de ellas.
* El uso elegible se factura a tu organización. Consulta [Créditos para cuentas aprovisionadas](#credits-for-provisioned-accounts) para saber cuándo se consumen primero los créditos propios del usuario.
* Las respuestas de `POST /partner/v1/accounts` incluyen un campo `gatewayStatus`.
* La integración acepta la versión Gateway del acuerdo al crearse.

## URL base {#base-url}

```
https://integrations.firecrawl.dev
```

## Autenticación {#authentication}

Todas las solicitudes a la API de Platforms requieren una cabecera `Authorization` con tu clave de plataforma:

```bash
Authorization: Bearer <platform key>
```

Las claves de plataforma no son las mismas que las claves de API estándar de Firecrawl. Puedes crearlas y revocarlas en Settings &gt; Firecrawl for Platforms, en el [Dashboard de Firecrawl](https://www.firecrawl.dev/app/partner-api).

## Requisitos de seguridad {#security-requirements}

* **Solo en el servidor**: las claves de plataforma solo deben usarse en código del lado del servidor. Nunca expongas una clave de plataforma en código de frontend, JavaScript del lado del cliente ni aplicaciones móviles.
* **Términos del servicio**: antes de llamar a `POST /partner/v1/accounts`, tu plataforma debe pedir al usuario que acepte los [Términos del servicio](https://www.firecrawl.dev/terms-of-service) de Firecrawl.

## Créditos para cuentas aprovisionadas {#credits-for-provisioned-accounts}

Las cuentas que crea tu integración no incluyen créditos gratuitos, salvo que Firecrawl haya verificado tu plataforma o tengas un acuerdo firmado con Firecrawl. Hasta entonces:

* Una cuenta **Standard** empieza sin créditos incluidos. El usuario puede añadir un método de pago o elegir un plan en el Panel de control de Firecrawl en cualquier momento.
* En una cuenta **Gateway**, todos los créditos se facturan a tu organización.

Una vez verificada tu plataforma, las cuentas nuevas y existentes incluyen los créditos mensuales del Plan gratuito; en las cuentas Gateway, estos se consumen antes de facturar a tu organización. La verificación es un paso manual que realiza Firecrawl. Cuando tu integración esté activa, o si estás desarrollando una aplicación para producción, escribe a [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev) indicando el ID de tu integración.

## Límites {#limits}

La creación de cuentas está limitada por integración, tanto en el número de cuentas que una integración puede crear como en la velocidad a la que puede hacerlo. Los límites aumentan a medida que crece la relación de tu organización con Firecrawl y nunca afectan a las cuentas que ya hayas creado. Si repites una llamada para un usuario que ya hayas aprovisionado, se devuelve la cuenta existente y no se descuenta del límite de cuentas. La dirección que envíes para una cuenta Standard debe ser una en la que tu usuario pueda recibir correo.

Si alcanzas un límite o estás planificando una integración en producción, escribe a [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev) indicando el ID de tu integración y el volumen previsto. Si Firecrawl suspende tu integración, escribe a [help@firecrawl.com](mailto:help@firecrawl.com).

## Endpoints {#endpoints}

### Crear usuario {#create-user}

Aprovisiona una cuenta de Firecrawl para uno de tus usuarios, identificado por su correo electrónico, y devuelve su clave de API.

```
POST /partner/v1/accounts
```

#### Comportamiento {#behavior}

Con una integración **Standard**:

* Si el usuario aún no tiene una cuenta de Firecrawl, se crean un nuevo usuario y un nuevo equipo.
* Si el usuario ya tiene una cuenta de Firecrawl, pero ningún equipo asociado a tu integración, se crea un nuevo equipo asociado a tu integración.
* Si el usuario ya tiene una cuenta de Firecrawl y un equipo asociado a tu integración, se devuelve el equipo existente.

Con una integración **Gateway**:

* Cada cuenta se crea exclusivamente para tu integración. Una solicitud nunca se vincula a una cuenta de Firecrawl existente, aunque el correo electrónico coincida con el de alguna. El correo electrónico se guarda como dirección de contacto de la cuenta y no se usa para buscar cuentas.
* Las llamadas repetidas con el mismo correo electrónico devuelven la misma cuenta y su clave de API.

Si tu integración incluye créditos promocionales, se aplican una sola vez, al crear la cuenta por primera vez.

#### Solicitud {#request}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/accounts" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com"}'
```

**Cuerpo**

| Campo   | Tipo   | Obligatorio | Descripción                                                                                                                    |
| ------- | ------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `email` | string | Sí          | Dirección de correo electrónico del usuario. En una integración de Gateway, se guarda como dirección de contacto de la cuenta. |

#### Respuesta {#response}

**`200 OK`**

```json
{
  "apiKey": "fc-...",
  "alreadyExisted": false
}
```

En una integración de Gateway, la respuesta también incluye el estado de inscripción:

```json
{
  "apiKey": "fc-...",
  "alreadyExisted": false,
  "gatewayStatus": "enrolled"
}
```

| Campo            | Tipo    | Descripción                                                                                                                                                    |
| ---------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apiKey`         | string  | La clave de API de Firecrawl del equipo que tu integración aprovisionó para este usuario                                                                       |
| `alreadyExisted` | boolean | `true` si tu integración ya había aprovisionado una cuenta para este correo electrónico. No indica si el correo existe en otro lugar de Firecrawl.             |
| `gatewayStatus`  | string  | Solo para integraciones Gateway. `enrolled` en la llamada que crea la cuenta y `already_enrolled` en las llamadas posteriores con el mismo correo electrónico. |

#### Errores {#errors}

| Estado | Descripción                                                                                                                                                                                                                                                                                                       |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | Solicitud incorrecta: falta `email` o su formato no es válido                                                                                                                                                                                                                                                     |
| `401`  | No autorizado: la clave de plataforma es incorrecta o no es válida                                                                                                                                                                                                                                                |
| `403`  | Rechazada: el campo `error.code` del cuerpo indica el motivo: `partner_account_cap_reached` (la integración ha alcanzado su límite de cuentas), `partner_provisioning_email_rejected` (la dirección no se puede usar para una cuenta de Firecrawl) o `partner_integration_suspended`. Consulta [Límites](#limits) |
| `429`  | Demasiadas solicitudes: `rate_limit_exceeded`; reduce la frecuencia y vuelve a intentarlo                                                                                                                                                                                                                         |
| `502`  | Firecrawl no pudo conectarse con su provider de facturación al configurar la cuenta: reintenta la solicitud                                                                                                                                                                                                       |
| `503`  | Firecrawl no pudo comprobar el límite de tasa: vuelve a intentarlo en unos instantes                                                                                                                                                                                                                              |
| `500`  | Error interno del servidor: Firecrawl supervisa estos errores                                                                                                                                                                                                                                                     |

### Validar clave de API {#validate-api-key}

Valida una clave de API de Firecrawl y devuelve el nombre del equipo asociado y la dirección de correo electrónico del usuario. La clave de API solo se considerará válida si se creó a través de tu integración.

```
POST /partner/v1/api-keys/validate
```

#### Notas importantes {#important-notes}

* Las claves de API de Firecrawl no tienen permisos ni fecha de caducidad.
* Los usuarios pueden eliminar manualmente las claves de API en cualquier momento.
* Las claves de API eliminadas no se someten a un borrado lógico (soft delete). Firecrawl no puede distinguir una clave eliminada de una que nunca existió.

#### Solicitud {#request-2}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/api-keys/validate" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "fc-..."}'
```

**Cuerpo**

| Campo    | Tipo   | Obligatorio | Descripción                     |
| -------- | ------ | ----------- | ------------------------------- |
| `apiKey` | string | Sí          | La clave de API que se validará |

#### Respuesta {#response-2}

**`200 OK`**

```json
{
  "teamName": "Example Team",
  "email": "user@example.com"
}
```

| Campo      | Tipo   | Descripción                                                                                                                        |
| ---------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `teamName` | string | El nombre del equipo asociado a esta clave de API                                                                                  |
| `email`    | string | El correo electrónico con el que se aprovisionó la cuenta. En las cuentas Gateway, es la dirección de contacto que proporcionaste. |

#### Errores {#errors-2}

| Estado | Descripción                                                                                         |
| ------ | --------------------------------------------------------------------------------------------------- |
| `400`  | Solicitud incorrecta: la clave de API tiene un formato no válido                                    |
| `401`  | No autorizado: la clave de plataforma es incorrecta o no válida                                     |
| `404`  | No se puede identificar la clave de API: la clave no existe o no se creó a través de tu integración |
| `500`  | Error interno del servidor: Firecrawl supervisa estos errores                                       |

### Rotar clave de API {#rotate-api-key}

Elimina una clave de API de Firecrawl existente y crea una nueva para el mismo usuario y equipo.

```
POST /partner/v1/api-keys/rotate
```

#### Solicitud {#request-3}

```bash cURL
curl -X POST "https://integrations.firecrawl.dev/partner/v1/api-keys/rotate" \
  -H "Authorization: Bearer <platform key>" \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "fc-..."}'
```

**Cuerpo**

| Campo    | Tipo   | Obligatorio | Descripción                                   |
| -------- | ------ | ----------- | --------------------------------------------- |
| `apiKey` | string | Sí          | La clave de API que se eliminará y sustituirá |

#### Respuesta {#response-3}

**`200 OK`**

```json
{
  "apiKey": "fc-..."
}
```

| Campo    | Tipo   | Descripción                   |
| -------- | ------ | ----------------------------- |
| `apiKey` | string | La clave de API recién creada |

#### Errores {#errors-3}

| Estado | Descripción                                                                                         |
| ------ | --------------------------------------------------------------------------------------------------- |
| `401`  | No autorizado: la clave de plataforma es incorrecta o no es válida                               |
| `404`  | No se puede identificar la clave de API: la clave no existe o no se creó a través de tu integración |
| `500`  | Error interno del servidor: Firecrawl supervisa estos errores                                       |

## Primeros pasos {#get-started}

Crea tu integración en el [Dashboard de Firecrawl](https://www.firecrawl.dev/app/partner-api): inicia sesión, selecciona Standard o Gateway, acepta el acuerdo y copia tu clave de plataforma. El tipo de integración no es fácil de cambiar más adelante, así que confirma tu elección antes de aceptar el acuerdo. Después, llama a los endpoints anteriores desde tu servidor. ¿Tienes dudas sobre tu configuración? Escribe a [help@firecrawl.com](mailto:help@firecrawl.com). ¿Estás pensando en una integración de mayor alcance? Escribe a [partnerships@firecrawl.dev](mailto:partnerships@firecrawl.dev).

## Partner Program {#partner-program}

Las plataformas que aprovisionan cuentas de Firecrawl para sus usuarios pueden solicitar su incorporación al Firecrawl Partner Program. Los socios aprobados reciben una parte de los ingresos generados por el uso de pago de los usuarios que atraen, acciones de comarketing y presencia en nuestro directorio de socios, acceso anticipado a nuevos endpoints, una línea directa con nuestro equipo para soporte técnico y límites más altos para sus usuarios. La participación en el programa es mediante solicitud, y respondemos en un plazo máximo de una semana.

A cambio, los socios muestran &quot;Powered by Firecrawl&quot; en su producto, con un enlace a firecrawl.dev que incluye su etiqueta `?ref=<partner>`.

El reparto de ingresos solo se aplica a los nuevos clientes de pago que refieras después de que se apruebe tu solicitud, nunca de forma retroactiva. Cubre el primer año de cada cliente en planes self-serve; los planes Scale y Enterprise quedan excluidos. Nuestro equipo revisa y aprueba a cada socio.

[Solicitar acceso al Partner Program](https://www.firecrawl.dev/firecrawl-for-platforms/partner-program?source=docs)
