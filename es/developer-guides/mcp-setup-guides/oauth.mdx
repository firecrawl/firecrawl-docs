---
title: "Conecta un cliente MCP a tu cuenta"
description: "Conecta un cliente MCP interactivo a tu cuenta de Firecrawl"
---

Usa el endpoint de cuenta de Firecrawl cuando haya una persona presente para iniciar sesión y autorizar el acceso. El cliente recibe tokens de corta duración vinculados a recursos en lugar de tu clave de API de Firecrawl.

Para conocer todas las opciones entre OAuth de cuenta, acceso desatendido mediante clave de API y acceso sin clave, consulta [Primeros pasos con MCP](/es/mcp-server).

<div id="connect-an-interactive-client">
  ## Conecta un cliente interactivo
</div>

Configura un cliente interactivo compatible para que apunte a:

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

Si el cliente solicita un ID de cliente OAuth o un secreto de cliente, deje ambos campos en blanco. Los clientes compatibles se identifican mediante documentos de metadatos de ID de cliente o el registro dinámico de clientes.

El cliente abrirá Firecrawl en su navegador. Inicie sesión, seleccione el equipo que debe usar el conector, revise la solicitud de consentimiento y apruebe el acceso. Las solicitudes se facturan al equipo seleccionado.

Use las guías específicas de cada cliente para [ChatGPT](/es/developer-guides/mcp-setup-guides/chatgpt) y [Claude](/es/developer-guides/mcp-setup-guides/claude-ai), ya que sus pantallas de configuración y reglas de espacio de trabajo son diferentes.

<div id="cursor-and-vs-code-redirect-support">
  ### Compatibilidad con redirecciones en Cursor y VS Code
</div>

Usa el endpoint de cuenta solo cuando la versión instalada del cliente pueda completar un flujo remoto de OAuth. Firecrawl acepta URI de redirección HTTPS y URI de redirección de loopback con `http://localhost`, `http://127.0.0.1` o `http://[::1]`. Para clientes HTTP nativos que usan loopback, el puerto puede variar en cada ejecución, pero el host y la ruta registrados deben coincidir con la URI de redirección solicitada.

Si la versión de Cursor o VS Code que usas no puede completar OAuth remoto, configura `https://mcp.firecrawl.dev/v2/mcp` con una cabecera `Authorization: Bearer <FIRECRAWL_API_KEY>`. Guarda la clave en el entorno del cliente o en un almacén seguro de secretos; nunca la incluyas en la URL.

<div id="choose-the-hosted-mode">
  ## Selecciona el modo alojado
</div>

| Endpoint                                 | Úsalo para                                            | Autenticación y herramientas disponibles                                                                                                                                                          |
| ---------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `https://mcp.firecrawl.dev/v2/mcp`       | Una prueba sin clave o un proceso desatendido         | Sin credenciales, expone solo Search, Scrape y Parse mientras sea elegible y esté sujeto a límites de frecuencia. Con `Authorization: Bearer <FIRECRAWL_API_KEY>`, expone todas las herramientas. |
| `https://mcp.firecrawl.dev/v2/mcp-oauth` | Una conexión de cuenta interactiva mediante navegador | Abre OAuth y expone todas las herramientas tras la autorización. También acepta claves de API como opción de compatibilidad.                                                                      |

Para CI, servidores, scripts y otros clientes desatendidos, usa `https://mcp.firecrawl.dev/v2/mcp` con una cabecera `Authorization: Bearer <FIRECRAWL_API_KEY>` cuyo valor provenga de una variable de entorno. No incluyas una clave de API en una URL ni en un archivo de configuración del proyecto.

<div id="manage-a-connection">
  ## Gestionar una conexión
</div>

Para desconectar un cliente, abre **MCP** en la [configuración de Firecrawl](https://www.firecrawl.dev/app/settings?tab=mcp) y revoca la conexión. Al revocarla, sus tokens de acceso y actualización quedan inutilizados; vuelve a conectarte desde el cliente para autorizarla de nuevo.

<div id="compatibility-during-migration">
  ## Compatibilidad durante la migración
</div>

* Los tokens OAuth existentes vinculados explícitamente a `/v2/mcp` siguen funcionando en `/v2/mcp`.
* Durante el período de migración, también se puede aceptar en `/v2/mcp-oauth` un token compatible existente de `/v2/mcp`.
* Un token nuevo emitido para `/v2/mcp-oauth` no se acepta en `/v2/mcp`.
* Los tokens con una audiencia ausente o ambigua se rechazan de forma predeterminada.
* Las configuraciones MCP heredadas existentes con la clave en la ruta siguen funcionando, pero las nuevas configuraciones deben usar OAuth o una cabecera Bearer.

<div id="security-properties">
  ## Propiedades de seguridad
</div>

* Los tokens de acceso caducan al cabo de una hora.
* Los tokens de actualización se rotan tras cada actualización correcta.
* Cada conexión está vinculada a su cliente OAuth, usuario, equipo, ámbito y recurso MCP.
* Los clientes OAuth usan el flujo Código de autorización con PKCE y no requieren un secreto de cliente.

<div id="supported-standards">
  ## Estándares admitidos
</div>

* Código de autorización de OAuth 2.0 con PKCE (S256)
* Metadatos del servidor de autorización RFC 8414
* Metadatos de recursos protegidos RFC 9728
* Documentos de metadatos de ID de cliente (CIMD)
* Registro dinámico de clientes (DCR) RFC 7591
* Indicadores de recursos RFC 8707

Las nuevas conexiones de cuenta deben usar este recurso exacto en las solicitudes de autorización y de token:

```text
https://mcp.firecrawl.dev/v2/mcp-oauth
```

Los metadatos del servidor de autorización están disponibles en:

```bash
curl -s "https://www.firecrawl.dev/.well-known/oauth-authorization-server" | jq .
```
