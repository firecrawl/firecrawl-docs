<Visibility for="agents">
  URL del servidor sin clave (Streamable HTTP, sin credenciales): `https://mcp.firecrawl.dev/v2/mcp`

  * Codex: `codex mcp add firecrawl --url https://mcp.firecrawl.dev/v2/mcp`
  * Claude Code: `claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp`
  * Cursor o cualquier cliente con configuración JSON: `{"mcpServers": {"firecrawl": {"url": "https://mcp.firecrawl.dev/v2/mcp"}}}`
  * OpenCode (`opencode.json`): `{"mcp": {"firecrawl": {"type": "remote", "url": "https://mcp.firecrawl.dev/v2/mcp", "enabled": true}}}`

  ChatGPT y Claude.ai usan el inicio de sesión de la cuenta: consulta [OAuth](/es/mcp-server/oauth.md).
</Visibility>

Este es el modo sin clave de Firecrawl: conéctate sin cuenta ni clave de API. Úsalo para una prueba rápida y usa una clave de API cuando la conexión deba funcionar de forma fiable sin intervención humana. Si prefieres iniciar sesión mediante un navegador —incluso desde ChatGPT o Claude.ai— usa [OAuth](/es/mcp-server/oauth).

El MCP sin clave expone únicamente Search, Scrape y Parse. Tiene límites diarios de solicitudes y créditos que comparten los usuarios con la misma dirección IP pública. Otra persona o proceso de la misma red puede consumir parte de esa asignación.

Usa el acceso sin clave para evaluar la conexión, no como identidad ni como credencial de producción. Para conocer la asignación actual, consulta [Límites de tasa sin clave](/es/rate-limits#keyless-no-api-key).

<div id="add-an-api-key">
  ## Añade una clave de API
</div>

Usa una clave de API para CI, servicios de backend y otras conexiones no atendidas. [Crea una clave de API de Firecrawl](https://www.firecrawl.dev/app/api-keys) y ponla a disposición del cliente MCP como `FIRECRAWL_API_KEY`.

<Warning>
  La persona o el operador del sistema debe configurar la clave fuera de la conversación con el agente. Nunca pegues la clave en el chat del agente, la incluyas en la URL de MCP ni confirmes su valor en un archivo del proyecto. Una referencia a una variable de entorno en un archivo de configuración es segura; el valor secreto no lo es.
</Warning>

<div id="codex">
  ### Codex
</div>

Exporta la clave en el entorno desde el que se inicia Codex:

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

Añade esto a `~/.codex/config.toml`:

```toml
[mcp_servers.firecrawl]
url = "https://mcp.firecrawl.dev/v2/mcp"
bearer_token_env_var = "FIRECRAWL_API_KEY"
```

<div id="claude-code">
  ### Claude Code
</div>

Exporta la clave antes de iniciar Claude Code:

```bash
export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
```

Agrega una referencia a una variable de entorno en `.mcp.json`. No reemplaces `${FIRECRAWL_API_KEY}` por la clave.

```json
{
  "mcpServers": {
    "firecrawl": {
      "type": "http",
      "url": "https://mcp.firecrawl.dev/v2/mcp",
      "headers": {
        "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
      }
    }
  }
}
```

<div id="other-clients">
  ### Otros clientes
</div>

Configura el cliente para que apunte a:

```text
https://mcp.firecrawl.dev/v2/mcp
```

Configure esta cabecera mediante el entorno o el almacenamiento de secretos de su cliente:

```text
Authorization: Bearer <FIRECRAWL_API_KEY>
```

Inicia una nueva sesión en el cliente después de guardar la configuración. Abre el estado de MCP o la lista de herramientas y confirma que `firecrawl` esté conectado.

<div id="verify-the-connection">
  ## Verifica la conexión
</div>

Prueba:

```text
Busca en la web las notas de la última release de Firecrawl y resume las fuentes.
```

Una conexión sin clave muestra `firecrawl_search`, `firecrawl_scrape` y `firecrawl_parse`. Una conexión con una clave de API puede exponer [todas las herramientas de Firecrawl MCP](/es/mcp-server/tools), según el plan, la implementación y las políticas del equipo.

Si las herramientas no coinciden con el modo que configuraste, elimina las entradas duplicadas de Firecrawl, reinicia el cliente y comprueba la URL del servidor activo y el origen de las credenciales.

<div id="run-in-ci-or-a-backend">
  ## Ejecuta en CI o en un backend
</div>

Guarda `FIRECRAWL_API_KEY` en el gestor de secretos de la plataforma e inyéctala en el entorno del proceso. Mantén únicamente la referencia a la variable de entorno en la configuración de MCP:

```json
{
  "url": "https://mcp.firecrawl.dev/v2/mcp",
  "headers": {
    "Authorization": "Bearer ${FIRECRAWL_API_KEY}"
  }
}
```

No incluyas el valor en el control de versiones, los registros de compilación, los prompts ni la configuración generada. Inicia un nuevo proceso después de cambiar el secreto, verifica la lista de herramientas de `firecrawl` y rota la clave si podría haberse expuesto.

<div id="legacy-api-key-url-support">
  ## Compatibilidad con URLs heredadas con clave de API
</div>

<Warning>
  La opción de incluir la clave en la URL solo existe para configuraciones y clientes existentes que no pueden enviar una cabecera de autorización. No la uses en una conexión nueva.
</Warning>

Las configuraciones existentes pueden usar `https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp`. La URL completa es una credencial: nunca la pegues en chats, capturas de pantalla, issues, registros ni configuraciones compartidas. Migra a una cabecera `Authorization: Bearer` basada en variables de entorno cuando sea posible y rota la clave si la URL quedó expuesta.

Esta ruta de compatibilidad solo se aplica a toda la superficie de `/v2/mcp`. No funciona con el recurso de búsqueda exclusivo de OAuth.
