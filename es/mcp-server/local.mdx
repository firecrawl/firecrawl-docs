Ejecuta Firecrawl MCP localmente cuando tu agente ejecute herramientas mediante stdio, necesite acceso a archivos locales o se conecte a una API de Firecrawl en una infraestructura que controlas. El MCP Server y la API de Firecrawl son servicios independientes: selecciona primero el backend de la API y, después, inicia MCP con las variables de entorno correspondientes.

<div id="choose-the-firecrawl-api-backend">
  ## Selecciona el backend de la API de Firecrawl
</div>

| Si necesitas                                           | Usa                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------ |
| La opción gestionada más rápida                        | Firecrawl Cloud con `FIRECRAWL_API_KEY`                      |
| Control del código fuente o de la infraestructura      | Una API autogestionada verificada con `FIRECRAWL_API_URL`    |
| Procesar archivos locales directamente                 | Un MCP local conectado a una API de Firecrawl autogestionada |
| Un MCP remoto seguro sin tener que operar este proceso | El MCP Server de Firecrawl alojado                           |

Si aún no has iniciado la API, sigue [Autogestionar Firecrawl](/es/contributing/self-host) y verifica un scraping antes de añadir MCP.

<div id="install-the-prerequisites">
  ## Instala los requisitos previos
</div>

* Node.js 22 o una versión posterior
* npm y `npx`, incluidos con Node.js
* Una clave de API de Firecrawl Cloud o una URL funcional de una API de Firecrawl autogestionada

Confirma Node.js:

```bash
node --version
```

<div id="run-mcp-with-firecrawl-cloud">
  ## Ejecutar MCP con Firecrawl Cloud
</div>

Para los clientes que ejecutan MCP como un proceso stdio local:

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY npx -y firecrawl-mcp@3.23.0
```

Esta es la opción administrada más sencilla. Firecrawl Cloud proporciona el backend de la API, mientras que el proceso MCP se ejecuta en tu máquina.

<div id="connect-mcp-to-self-hosted-firecrawl">
  ## Conecta MCP a Firecrawl autogestionado
</div>

Para el inicio rápido sin autenticación en una red de confianza:

```bash
env FIRECRAWL_API_URL=http://localhost:3002 \
  npx -y firecrawl-mcp@3.23.0
```

Para una API autogestionada con una capa de autenticación compatible con claves de API:

```bash
env FIRECRAWL_API_URL=https://firecrawl.your-domain.com \
  FIRECRAWL_API_KEY=your-api-key \
  npx -y firecrawl-mcp@3.23.0
```

Usa la clave solo si tu implementación lo requiere. MCP solo puede exponer las herramientas compatibles con los servicios configurados en esa implementación; consulta la [compatibilidad de funciones autogestionadas](/es/contributing/self-host#self-hosted-feature-support).

<Warning>
  No expongas públicamente el inicio rápido de autogestión sin autenticación. Añade TLS,
  controles de red y un diseño de autenticación compatible antes de usar una
  URL de API remota.
</Warning>

<div id="run-mcp-over-streamable-http">
  ## Ejecutar MCP mediante Streamable HTTP
</div>

Usa el transporte HTTP cuando un cliente como n8n se conecta a un MCP Server que ya está en ejecución:

```bash
env HTTP_STREAMABLE_SERVER=true \
  FIRECRAWL_API_KEY=fc-YOUR_API_KEY \
  npx -y firecrawl-mcp@3.23.0
```

Conecta el cliente a:

```text
http://localhost:3000/mcp
```

Confirma que el proceso MCP esté listo:

```bash
curl http://localhost:3000/health
```

La comprobación de estado devuelve `ok`. La ruta MCP local es `/mcp`; `/v2/mcp` es la ruta alojada de Firecrawl.

Para usar el transporte HTTP con Firecrawl autogestionado, reemplaza `FIRECRAWL_API_KEY` por la configuración `FIRECRAWL_API_URL` de la sección anterior y añade una clave solo cuando la API la requiera.

<div id="persist-local-mcp-configuration">
  ## Conservar la configuración local de MCP
</div>

Instala el paquete globalmente si prefieres un comando local estable:

```bash
npm install -g firecrawl-mcp@3.23.0
```

A continuación, ejecuta:

```bash
env FIRECRAWL_API_KEY=fc-YOUR_API_KEY firecrawl-mcp
```

Para Claude Desktop, añade un servidor stdio local en `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "firecrawl": {
      "command": "npx",
      "args": ["-y", "firecrawl-mcp@3.23.0"],
      "env": {
        "FIRECRAWL_API_KEY": "YOUR_API_KEY_HERE"
      }
    }
  }
}
```

Para Firecrawl autogestionado, sustituye `FIRECRAWL_API_KEY` por `FIRECRAWL_API_URL` o incluye ambas si tu API requiere una clave.

<div id="understand-local-and-hosted-boundaries">
  ## Comprende los límites entre entornos locales y alojados
</div>

* El MCP alojado sin clave expone únicamente Search, Scrape y Parse y está sujeto a límites de tasa por IP.
* La lectura de archivos locales requiere un proceso MCP local.
* El procesamiento directo de archivos locales con `firecrawl_parse` requiere que `FIRECRAWL_API_URL` apunte a una API de Firecrawl autogestionada. Un MCP Server local configurado únicamente con una clave de API en la nube no puede cargar un archivo local mediante esa herramienta.
* Los Webhooks y las rutas de archivos locales deben configurarse desde un MCP Server local o autogestionado cuando el agent deba acceder a recursos de tu red.
* Los límites de tasa de la API de Firecrawl siguen aplicándose. Usa una clave de API en la nube para obtener límites gestionados más altos, o define y supervisa la capacidad de tu implementación autogestionada.
