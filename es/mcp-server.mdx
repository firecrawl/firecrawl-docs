Firecrawl MCP ofrece a los clientes de IA acceso a datos web en tiempo real mediante el Model Context Protocol. Usa el servidor alojado para configurarlo rápidamente o [ejecuta el servidor de código abierto de forma local](/es/mcp-server/local) si necesitas un proceso local o una API de Firecrawl autogestionada.

Esta página es la guía canónica para configurar Firecrawl MCP alojado.

<div id="setup-firecrawl-mcp-server">
  ## Configurar Firecrawl MCP Server
</div>

Para un cliente interactivo, conéctate mediante OAuth. El cliente abrirá Firecrawl en tu navegador para que puedas iniciar sesión, seleccionar un equipo y autorizar el acceso sin copiar una clave de API.

<Tabs>
  <Tab title="Codex">
    Añade el servidor alojado y completa el inicio de sesión con OAuth:

    ```bash
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp-oauth
    codex mcp login firecrawl
    ```

    Inicia o reinicia la aplicación, la CLI o la extensión de IDE de Codex. Introduce `/mcp` para confirmar que `firecrawl` está conectado.
  </Tab>

  <Tab title="Claude Desktop">
    1. Abre **Settings &gt; Connectors**.
    2. Selecciona **Add custom connector**.
    3. Introduce `https://mcp.firecrawl.dev/v2/mcp-oauth` como URL del servidor MCP remoto.
    4. Selecciona **Connect**; a continuación, inicia sesión en Firecrawl y autoriza el acceso.

    <Note>
      Los servidores remotos deben añadirse desde **Settings &gt; Connectors**. El archivo `claude_desktop_config.json` es para servidores MCP locales.
    </Note>
  </Tab>

  <Tab title="Claude Code">
    Añade el servidor alojado:

    ```bash
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    Introduce `/mcp` en Claude Code, selecciona `firecrawl` y completa el inicio de sesión en el navegador.
  </Tab>

  <Tab title="Cursor">
    Añade el servidor alojado a `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "firecrawl": {
          "url": "https://mcp.firecrawl.dev/v2/mcp-oauth"
        }
      }
    }
    ```

    Guarda el archivo, abre la configuración de MCP de Cursor y completa el inicio de sesión en Firecrawl. Cursor pondrá las herramientas de Firecrawl a disposición de Agent.
  </Tab>

  <Tab title="Otros clientes">
    Configura un cliente MCP remoto compatible con OAuth para que use:

    ```text
    https://mcp.firecrawl.dev/v2/mcp-oauth
    ```

    Si el cliente solicita un Client ID o Client Secret de OAuth, deja ambos campos en blanco. Los clientes compatibles usan Client ID Metadata Documents o Dynamic Client Registration.

    Si el cliente no puede completar OAuth remoto, usa la configuración con clave de API que aparece a continuación. Si no puede enviar cabeceras de solicitud, [ejecuta Firecrawl MCP localmente](/es/mcp-server/local).
  </Tab>
</Tabs>

Las conexiones OAuth reciben tokens de corta duración vinculados a recursos, en lugar de tu clave de API de Firecrawl. Puedes revisarlos y revocarlos desde la [configuración de MCP](https://www.firecrawl.dev/app/settings?tab=mcp).

<div id="set-up-with-an-api-key">
  ## Configuración con una clave de API
</div>

Usa una clave de API para CI, servidores, scripts u otros clientes que no puedan completar el flujo OAuth en el navegador. [Crea una clave de API de Firecrawl](https://www.firecrawl.dev/app/api-keys), guárdala en una variable de entorno o un almacén de secretos y conéctate al endpoint MCP alojado completo.

<Tabs>
  <Tab title="Codex">
    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    codex mcp add firecrawl \
      --url https://mcp.firecrawl.dev/v2/mcp \
      --bearer-token-env-var FIRECRAWL_API_KEY
    ```
  </Tab>

  <Tab title="Claude Code">
    Claude Code expande la variable de entorno al conectarse:

    ```bash
    export FIRECRAWL_API_KEY=fc-YOUR-API-KEY
    claude mcp add --transport http firecrawl \
      https://mcp.firecrawl.dev/v2/mcp \
      --header 'Authorization: Bearer ${FIRECRAWL_API_KEY}'
    ```
  </Tab>

  <Tab title="Otros clientes">
    Configura el cliente para enviar la clave de API como un token Bearer:

    ```text
    URL: https://mcp.firecrawl.dev/v2/mcp
    Authorization: Bearer <FIRECRAWL_API_KEY>
    ```

    La configuración de la cabecera varía según el cliente. Guarda la clave en las variables de entorno del cliente o en un almacén de secretos protegido.
  </Tab>
</Tabs>

<Warning>
  Nunca incluyas una clave de API en un archivo de configuración del proyecto, la pegues en un chat ni la compartas en una captura de pantalla o un issue. Las nuevas configuraciones deben usar OAuth o una cabecera Authorization respaldada por una variable de entorno, nunca una URL que incluya credenciales.
</Warning>

<div id="try-without-an-api-key">
  ## Pruébalo sin una clave de API
</div>

Para probar Firecrawl sin crear una cuenta, añade el endpoint sin clave a cualquier cliente compatible con MCP remoto:

```text
https://mcp.firecrawl.dev/v2/mcp
```

El MCP sin clave está sujeto a límites de frecuencia por red y, mientras cumplas los requisitos, expone exactamente **Search, Scrape y Parse**. Conéctate mediante OAuth o una clave de API cuando necesites todas las herramientas de Firecrawl MCP o límites más altos.

<Accordion title="¿Qué sucede cuando alcanzo el límite sin clave?">
  Cuando está disponible, el error del MCP incluye el tiempo actual de reintento. Espera ese intervalo para seguir usando el modo sin clave o conéctate de inmediato mediante OAuth o una clave de API.
</Accordion>

<div id="verify-your-connection">
  ## Verifica tu conexión
</div>

Abre el estado de MCP o la lista de herramientas de tu cliente y confirma que `firecrawl` esté conectado. Una conexión sin clave muestra `firecrawl_search`, `firecrawl_scrape` y `firecrawl_parse`; una conexión autenticada puede ofrecer [todas las herramientas de Firecrawl MCP](/es/mcp-server/tools), según el plan, la implementación y la política del equipo.

Prueba una solicitud de solo lectura:

```text
Busca en la web las notas de la última release de Firecrawl y resume las fuentes.
```

Si no aparece ninguna herramienta de Firecrawl, reinicia o recarga el cliente después de guardar la configuración de MCP. Si se produce un error de proceso local, como `spawn npx ENOENT`, consulta [Ejecutar Firecrawl MCP localmente](/es/mcp-server/local#troubleshooting).

<div id="compatibility-and-legacy-setup">
  ## Compatibilidad y configuración heredada
</div>

<AccordionGroup>
  <Accordion title="Compatibilidad con URL heredada con clave de API">
    <Warning>
      Este formato heredado solo existe para configuraciones y clientes existentes que no pueden completar OAuth ni enviar una cabecera Authorization personalizada. No es la configuración recomendada para nuevas integraciones.
    </Warning>

    ```text
    https://mcp.firecrawl.dev/<FIRECRAWL_API_KEY>/v2/mcp
    ```

    La clave de API forma parte de la URL, así que trata la URL completa como si fuera una contraseña. Si queda expuesta, rota la clave. Esta alternativa solo se aplica a toda la superficie de `/v2/mcp`. No funciona con el recurso Search exclusivo de OAuth.
  </Accordion>

  <Accordion title="Conexiones OAuth existentes">
    Las conexiones OAuth existentes de `/v2/mcp` seguirán siendo compatibles durante la migración al endpoint de cuenta dedicado. Las nuevas conexiones interactivas de cuenta deben usar `/v2/mcp-oauth`; los nuevos tokens para ese recurso de cuenta no se aceptan en `/v2/mcp`.
  </Accordion>
</AccordionGroup>
